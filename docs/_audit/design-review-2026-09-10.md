# eywa 전체 탭 디자인 검수 · 2026-09-10

현재 eywa는 읽기 좋은 표와 유용한 공통 부품을 갖고 있다. 개선 효과가 큰 부분은 **요약·안내·필터·목록의 배치, 주요 정보의 너비 배분, 숫자가 뜻하는 범위**다. 큰 글자와 업무에 필요한 밀도를 유지하면서 이 부분을 정리하는 것이 이번 개선의 방향이다.

## 검수 범위와 증거

- 기준 코드: `24b599c9`, `D:\eywa_refactoring`. 현재 저장소를 실행하는 `localhost:3032`에서 인증된 브라우저로 확인했다. 다른 세션의 `3031` 서버는 변경하지 않았다.
- 대시보드를 제외한 **36개 화면 상태**를 실제 캡처하고 검토했다. 수납 8개 면, 설정 2개 면, 대표 등록 폼 3개를 포함한다. 상담 목록과 등록상담은 추가 크기에서도 확인했다.
- `/onescreen`은 현재 계정에서 `/menu`로 이동했다. 원스크린 내부는 시각 검수 완료에 포함하지 않는다. 이동 후 보인 공통 작업창과 메뉴는 참고했다.
- 라우트 목록은 정적 67개·동적 31개, 총 98개 페이지 템플릿을 분류했다. **98개 전체의 모든 상세·모달·권한·오류 상태를 브라우저에서 검증한 것은 아니다.** 주요 페이지와 공통 컴포넌트를 중심으로 소스를 대조했다.
- 기본 캡처는 브라우저 외곽 1440×1100, 추가 캡처는 980×910·1420×1016이다. OS 배율이 있는 외곽 치수이므로 CSS viewport 또는 실제 플로팅 창 최소 크기와 동일하다고 간주하지 않는다. 대부분 `embed=1`로 업무 본문을 검사했다.
- 이번 작업은 검수다. 앱 소스·운영 데이터·DB·다른 세션의 작업물을 수정하지 않았다. 저장, 발송, 결재, 체크박스 변경은 실행하지 않았다.
- [화면별 캡처와 개선안 모음](../../logs/design-audit/index.html). 캡처에는 실제 운영 정보가 있으므로 로컬 검수 자료로만 보관한다.

### 소스에서 확인한 원인

1. 등록상담: [column-cards.tsx](../../src/app/(shell)/enrollment/_components/column-cards.tsx) 256–264행 부근. `h-10` 고정 행 안의 `truncate`가 이름과 학교를 함께 감싼다. 전체 폰트를 줄이거나 4열을 탭으로 바꾸는 방식은 기존 요구에 맞지 않는다.
2. 수납: [billing-content.tsx](../../src/app/(shell)/billing/_components/billing-content.tsx) 303행의 `md:grid-cols-3 xl:grid-cols-5`. [자산 지표](../../src/app/(shell)/inventory/_components/stats-row.tsx)도 같은 3+2줄 문제가 있다. 실제 사용하는 업무 창 폭과 5열 전환 기준을 맞춰야 한다.
3. 공통 탭: [face-tabs.tsx](../../src/components/face-tabs.tsx) 58–84행. 부모 높이와 달리 안쪽 Link에 세로 높이/여백이 없다. [toolbar-controls.ts](../../src/components/toolbar-controls.ts)의 `TOOLBAR_SEG_ITEM`도 같은 유형이다. 모든 사용처가 같은 방식으로 높이를 상속하는지는 수정 시 재확인해야 한다.
4. 문서함: [queries.ts](../../src/features/documents/server/queries.ts)의 목록은 `staff_user_id IS NULL`, 폴더 수는 `document_category_counts` RPC를 사용한다. 저장소의 [0161a 마이그레이션](../../supabase/migrations/0161a_document_categories_and_links.sql) 123–134행 RPC 정의에는 이 제외 조건이 없다. 실제 DB 함수 정의를 다시 확인한 뒤 **집계 쪽을 맞춰야 한다**. 목록의 보호 조건을 제거하면 안 된다.
5. 시수 검증: [session-verification-face.tsx](../../src/app/(shell)/billing/_components/session-verification-face.tsx) 180–201행. `missingPriceRows` 안내는 강사명 옆에 있지만 차액 색은 `diffAmount === 0`만으로 결정한다. 일부 유효 단가가 있는 경우에는 계산된 금액을 보존하고 ‘일부 집계’를 함께 표시해야 한다.
6. 상담 미리보기: [consultations/page.tsx](../../src/app/(shell)/consultations/page.tsx) 396행에서 `c.summary`를 그대로 자른다. 새 상담 폼에서도 기본 양식 머리가 요약 맨 앞에 들어가는 것을 확인했다.
7. 발송 큐: [lesson-reports/page.tsx](../../src/app/(shell)/lesson-reports/page.tsx) 148–157행에서 큐를 면 전환보다 앞에 둔다. 상단 유지 의도는 살리고 [classnote-queue-card.tsx](../../src/app/(shell)/lesson-reports/_components/classnote-queue-card.tsx)의 기본 높이를 줄일 대상이다.

## 공통 디자인 기준의 정리

### 1. 현재 규칙과 변경 이력을 분리

[design-conventions.md](../design-conventions.md)에 예전 13.5/12.5px 행, 소프트 패널·그림자 규칙과 이후 v5 규칙이 함께 남아 있다. 상단의 컨트롤 채움 70% 설명도 실제 [globals.css](../../src/app/globals.css) 255행의 **0.62**와 다르다. 그림자를 제거한 기록과 다시 1px 경계를 복원한 기록도 함께 읽힌다.

현재 적용 기준을 짧은 문서로 고정하고 변경 이력은 별도 부록으로 옮긴다. 현재 사용자 선택인 흰 배경, 기본 글자 `#121212`, 큰 본문과 18px 컨트롤, 500/700 두께, 과목/상태 의미색을 기준으로 한다. 모든 화면에 회색 보조 글자나 새로운 장식색을 일괄 도입하지 않는다.

새 `/dashboard?view=one`도 통일 대상에서 제외하지 않는다. [overview.module.css](../../src/app/(shell)/dashboard/_overview/overview.module.css)에 11/12px, 450/650/750/760 두께, 별도 글자색이 남아 있다. 차트 밀도를 유지하면서 다른 탭과 어느 정도까지 공통 토큰을 따를지 정리해야 한다. 새 대시보드를 그대로 전역 표준으로 복제하면 또 다른 예외 체계가 생긴다.

### 2. 화면의 목적에 따라 네 가지 구성을 사용

| 유형 | 기본 순서 | 대상 |
|---|---|---|
| 업무 목록 | 기간·결과·주요 동작 → 짧은 지표/조치 요약 → 필터 → 표 | 원생, 상담, 회의, 수납, 직원, 자산 |
| 단계별 보드 | 기간·필터 → 단계별 수 → 고정 열의 카드 | 등록상담, 셔틀 편성 |
| 운영 행렬 | 대상·기간·범례 → 고정 신원/시간축 → 입력 격자 | 시간표, 출석부, 학습 진도, 평가 |
| 입력·문서 | 필수 정보 → 본문/상세 입력 → 필요 시 미리보기 → 고정 저장 | 등록, 상담, 설정, 계산기, 인쇄 문서 |

모든 페이지에 KPI 카드나 그래프를 붙이지 않는다. 분포를 비교할 때는 막대, 비율을 파악할 때는 비율 막대, 시간 흐름에는 추이를 사용한다. 업무 목록은 목록을 빠르게 읽고 처리하는 것이 중심이다. 이탈 방어·퇴원 분석의 차트와 MCS/ECS 진행 막대는 목적이 분명하므로 살린다.

### 3. 공통 부품의 책임을 명확히

- `FaceTabs`/세그먼트: 상위 면과 내부 선택의 위계, 일관된 클릭 높이, 현재 위치, 가로 넘침과 키보드 초점.
- `PageHeader`/`Toolbar`: 페이지 이름·기간·결과·주요 동작의 위치. `embed`에서 제목을 접는 동작은 유지한다.
- 요약: 업무 목록용 짧은 지표와 분석 화면용 큰 지표를 구분한다. 0건인 정상 상태를 큰 카드로 반복하지 않는다.
- 표: 이름/식별자 폭 보장, 숫자 정렬, 날짜·원 단위 표기, 선택/호버, 고정 열. 상세 설명은 별도 열이나 펼침에 둔다.
- 폼: 관련 필드를 함께 묶고 필수 입력을 먼저 보여준다. 현재 저장 바, 초안 복구, 미저장 경고, 동시 편집 보호를 유지한다.
- 상태: 실제 0, 미입력, 조회 실패, 해당 없음, 권한 없음, 데이터 없음의 표현을 구분한다. 색은 상태를 보조한다.

## 바꾸지 말아야 할 제약

1. 등록상담 4열·고정 카드 높이와 MCS 정규/특강 좌우 구분은 기존 사용자 요구다.
2. 시간표·30/31일 출석·학생별 진도·평가 문항·직원 명부의 가로 스크롤은 정보 구조상 필요할 수 있다. 폭을 맞추려고 글자를 일괄 축소하거나 필수 열을 숨기지 않는다.
3. [window-geometry.ts](../../src/components/workspace/window-geometry.ts)의 메뉴별 기본/최소 창과 실제 작업창을 기준으로 재검증한다. 최대화 브라우저에서만 예쁜 배치는 충분하지 않다.
4. 인쇄/A4 지면의 별도 글자 크기와 문서 구조는 화면용 글자 확대와 분리한다.
5. 신규생 관리의 과거 미완료 분홍 배경은 요청된 의미다. `waived`와 실제 `overdue`는 집계가 다르므로 범례로 구분하고 색을 임의로 없애지 않는다.
6. 현재 신규생 화면의 `0256a` 미적용 안내는 실제 체크 동작에 관한 제약이다. 디자인 수정 과정에서 경고를 숨기거나 DB 마이그레이션을 끼워 적용하지 않는다.
7. 퇴원 사유 미기재, 시수 단가 미입력, 정산 스냅샷 부재, 운행 기록 부재는 원천 데이터/업무 상태 문제다. 그래프와 상태 색으로 정상처럼 보이게 만들지 않는다.
8. 우측 하단 개발 도구 아이콘과 좌측 Next 개발 표시의 겹침은 제품 UI 결함 목록에서 제외했다. `ReactQueryDevtools`는 development에서만 표시된다. 등록상담의 ‘1 Issue’ 배지는 별도 런타임 오류 점검 대상이며 이번 시각 검수에서 원인을 확정하지 않았다.
9. 원스크린 권한 이동을 우회하지 않았다. 다른 역할 계정의 원스크린·강사 전용 화면, 전체 상세 31개, 모든 모달/인쇄 페이지는 별도 상태 검수가 필요하다.

## 적용 순서와 검수 기준

### 1차 · 공통 기준과 정보 식별

현재 디자인 기준 문서 정리 → 탭/세그먼트 높이 → 등록상담 이름 → 문서 집계 일치 → 시수 검증의 미계산 표현 → 상담 미리보기 순서. 문서 집계와 미리보기 변환은 계산/권한/원문 보존에 관한 의미 있는 테스트를 추가한다. 단순 여백 수정에 구현을 그대로 복제하는 테스트는 만들지 않는다.

### 2차 · 첫 화면의 업무 밀도

수납을 기준 화면으로 먼저 완성한다. 같은 구성을 재고·직원·회의·원생 목록으로 확장한다. 수업보고서 큐와 MCS 행을 정돈한다. 글자를 줄이지 않고 요약 반복·불필요한 줄·큰 기본 패널을 줄인다. 업무 화면마다 자연스러운 행 높이는 달라도 주요 도구의 위치는 익숙해야 한다.

### 3차 · 입력과 부가 운영 화면

신규 등록상담의 입력 시작점, 학생 등록 필드 묶음, 계산기 입력/미리보기의 실제 창 폭, 설정의 시간 입력/면 탐색, 결재·도움말·빈 상태를 정리한다. 기존 정상적인 표와 격자는 부분 수정한다.

### 완료 판정

- 실제 메뉴에서 열린 기본/최소 창, 넓힌 창, 여러 창을 나란히 둔 경우를 각각 확인한다.
- 기간·적용 중 필터·결과 수·주요 동작·첫 업무 항목을 첫 화면에서 함께 파악할 수 있다.
- 일반적인 전체 이름과 동명이인 표식, 필요한 금액, 상태를 호버 없이 식별할 수 있다. 긴 학교/반 이름의 전문에는 접근할 수 있다.
- 0/미입력/실패/권한 제한을 구분하고 집계와 목록의 범위가 일치한다.
- 저장·발송·체크·드래그·초안 복구·뒤로가기·URL 면 전환의 동작을 유지한다.
- 각 변경은 해당 모듈 단위로 나눠 검증하고 최신 main의 다른 세션 변경을 먼저 대조한다. 전역 CSS를 대량 치환하지 않는다.
- 이번 검수는 화면과 코드 대조이며 구현 변경의 typecheck/test 통과를 주장하지 않는다. 실제 수정 후 범위에 맞는 검사와 브라우저 재검수가 필요하다.

첫 구현 묶음은 **공통 탭 + 등록상담 식별성 + 수납 첫 화면**이 적합하다. 문서 집계와 미계산 표현은 별도의 정확성 수정으로 함께 추적한다.
