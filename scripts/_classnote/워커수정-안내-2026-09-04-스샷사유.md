# 연동 PC 워커 수정 적용 (2026-09-04) — 발송 실패 시 **이유가 화면에 적힙니다**

> **한 줄 요약**: 발송 동작은 **하나도 안 바뀝니다.** 실패했을 때 화면에 남는 **설명만** 자세해집니다.
> 이 zip을 풀고 **워커를 다시 시작**하면 끝입니다. `.env.local`은 **건드릴 것이 없습니다.**

## 왜 고쳤나 (2026-09-04 곽하윤 건)

곽하윤 학생 보고서가 재시도 3번을 모두 실패했는데, 화면에 남은 말은 이것 한 줄뿐이었습니다:

```
스샷 kage 업로드 실패
```

이 한 줄로는 **무엇을 해야 하는지 알 수 없습니다.** 실제로는 원인이 네 가지나 되는데 전부 같은
문장으로 뭉개져 있었거든요. 그래서 그날은 "다른 건은 다 됐고 이 건만 안 됐다"는 정황으로만
일시적인 문제라고 짐작하고 재발송했습니다(재발송은 한 번에 성공했습니다).

---

## 무엇이 달라지나

이제 실패하면 **원인에 따라 다른 문장**이 남습니다:

| 실제 원인 | 이제 화면에 뜨는 말 | 하셔야 할 일 |
|---|---|---|
| 보고서 이미지가 안 만들어짐 | …**올릴 데이터가 비어 있습니다(0바이트)**. 업로드가 아니라 캡처가 실패한 것이니… | 재발송 |
| 알림장 작성 화면이 안 열림 | …**작성폼의 첨부 칸이 열리지 않았습니다.** 폼이 덜 뜬 것이거나 ClassNote 화면 구조가 바뀐 것… | 재발송 → 계속 같으면 알려주세요(ClassNote 쪽 변경 신호) |
| ClassNote가 파일을 거부 | …**저장소가 파일을 거부했습니다(HTTP 413)**. 다시 시도해도 같으면 용량·형식을… | 재발송해도 같으면 알려주세요 |
| ClassNote가 응답을 안 함 | …**저장소가 12초 동안 응답하지 않았습니다.** 재발송으로 다시 시도하세요 | 재발송 (곽하윤 건이 이 경우로 보입니다) |

즉 **"재발송하면 되는 것"과 "재발송해도 소용없는 것"이 구분됩니다.**

🔴 **발송되는 내용·성공률·속도는 그대로입니다.** 실패했을 때 남기는 설명만 바뀝니다.
(덤으로, 보고서 이미지가 비어 있으면 12초를 기다리지 않고 곧바로 실패로 넘어갑니다.)

## 적용 방법 (연동 PC 경로 = `C:\eywa-sync-pc`)

1. zip을 풀어 **`C:\eywa-sync-pc\scripts\_classnote` 폴더 전체**를 덮어씁니다.
   ⚠️ **일부 파일만 덮지 마세요** — 워커 파일들이 서로를 불러오므로 버전이 섞이면 기동하지 못합니다.
   (이번엔 `kage-failure.mjs`라는 **새 파일**이 생겼습니다. 이 파일이 빠지면 워커가 아예 못 뜹니다.)
2. **PowerShell을 "관리자 권한으로 실행"** 한 뒤 아래를 붙여넣습니다.

```powershell
cd C:\eywa-sync-pc
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -match 'watch-classnote-queue' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Start-ScheduledTask -TaskName eywa-classnote-worker
```

3. 끝입니다. `.env.local`은 그대로 두세요.

그랬습니다(zip을 풀고 지정까지 "성공"으로 끝냈는데 일주일 전 프로세스가 그대로 살아 있었습니다).
위 2번을 **반드시** 하세요.

### 적용 확인

이 워커는 자기가 아는 기능을 하트비트에 적습니다. 새 코드가 돌고 있으면 거기에
**`kageFailReasons`** 가 실립니다 — 확인이 필요하시면 말씀만 하세요, 바로 조회해서 알려드립니다.
(눈으로 보이는 확인은 **다음 실패 때 문장이 길어지는 것**입니다. 평소엔 티가 안 납니다.)
