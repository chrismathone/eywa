## 의견 차이의 해결

1. 공용 참여 파서에 새 필드를 필수로 넣으면 구 DB와 출결 저장이 깨질 수 있다는 Claude 지적을 채택했다. 진행 조회에만 선택 계약을 더하고 기본 출결 조회는 유지한다.
2. 단순 출석 여부 대신 초안·반려·제출·인정·노쇼·인정 반전·연결된 기존 완료를 순서대로 판정한다. 기존 케이스 업무 목록과 동일 참여 집합인지 검증한다.
3. 출결 트리거에 새 사건 잠금을 넣는 Codex v3 제안은 Claude의 다중 행 잠금 순서 지적에 따라 철회했다. 0349b는 불변이고 접수·승인 쪽에서 재관측한다.
4. Claude v3의 승인 거절 권고는 Codex가 트랜잭션 전체 롤백을 지적했다. 신규 확인 항목까지 사라지는 문제를 피하려고 승인과 확인 항목·경고를 함께 커밋한다. Claude도 v4에서 앞선 거절 권고를 철회하고 동의했다. 열린 항목은 기존대로 종결을 막는다.
5. 대시보드 DB 허용 참여를 그대로 표시하는 Codex v3 문장은 철회했다. 강사 화면은 effectiveTeacherId의 이번 주 담당 반 참여와 직접 실시하는 참여만 표시해 겸직·다른 강사 뷰의 범위도 보존한다.
6. 예약 행 변경은 기존 명령과 같은 트랜잭션에서 이루어진다. ‘예약 반영 지연’ 전제를 철회했으며 출결 효과 반영 작업과 구분했다.

## 구현 때 확인할 경계

계획의25개 기준은 **아직 실행하지 않았다**. Claude도 소스 읽기만 수행했다. 운영 DB 자료·설정, 실제 병행 실행·성능, 강사 미니셸 진입, 신규 경고 화면, 변경 후 pgTAP 결과를 확인한 것으로 세지 않는다.

Claude의 최종 권고6개는 필수 승인 조건이 아닌 구현 메모로 보존한다. 관측이 잠글 전체 케이스 집합과 권한 조회를 구분하고, 후보의 ‘하루 중 유효 시수 행 존재’와 기존 관측의 ‘가장 나중 행’ 차이를 기록한다. 열린 근거 확인 항목이 있으면 거절도 먼저 항목 처리가 필요하다는 안내, 일정과 강사뷰 축의 차이, 승인 전 현재 출결 표시, 잠금 집합 재조회 중 새 건이 생기는 병행 사례도 확인한다. 자세한 근거는 [최종 Claude 보고서6·7절](claude-review-v4.md#6-권고-승인-조건-아님--구현-때-반영하면-좋은-것)에 있다.

긴 출결 트랜잭션이 접수·승인 커밋 모두를 가로지르는 경우는 이후 기존 관측/대사로 확인한다. 일부 새 참여는 기존 시간표에 투영되지 않는 한계가 있어 새 일정에서 보여준다. 기존 예약의 주 기준, 새 DB 조회의 오늘 기준, 대시보드 전 과목·한 달과 수학 일정 선택 기간의 차이를 숨기지 않는다.

복사된 승인 계획의 바이트 해시가 원본과 동일함을 확인했다. 승인 계획 본문을 수정하면 이 합의를 재사용하지 않고 새 해시로 다시 검토한다.
