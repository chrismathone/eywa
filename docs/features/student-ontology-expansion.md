## 현재 수강의 상위 관점

`/student-contribution/ontology?view=current`에 학생·반·강사·과목·학원 선택을 추가했다. 기존 월별 화면은 기본 보기로 유지한다. 현재 연결은 오늘의 수강·담임·유효 시간표·활성 위임을 읽으며 휴원도 포함한다. 일반 종료일과 반이동일은 기존 `isEnrollmentOnRosterOn`, 위임은 `isDelegationActiveOn`의 경계를 SQL과 대조했다. 배정 관계를 실제 수업 실시·강사 성과로 해석하지 않는다.

## Claude 요약

- 선택 학생의 현재 수강·최근 상담/메모·보강만 고정 조회한다. 가족·전화·금액·학부모 전체 원문·제한 문서·자유 질문은 입력에 포함하지 않는다. 자유 텍스트에 금액·연락처·계좌/카드 형태 등이 있으면 그 항목을 제외한다. 이 필터를 모든 개인정보를 식별하는 장치로 주장하지 않는다.
- 전용 키 `ANTHROPIC_API_KEY_STUDENT_ONTOLOGY`, `generateJSON`, FACT_GUARD, 라이선스·사용량 기록을 재사용한다. Claude fast/low, 다른 회사 폴백 없음. 화면 열람은 AI를 호출하지 않는다.

적용 직전 프로젝트·파일 해시·기존 표/함수 부재를 확인했다. Supabase CLI 2.121.0 `db query --db-url … --file …`의 단일 prepared statement 제약을 위해 바깥 BEGIN/COMMIT만 단일 DO 거래로 바꿔 실행했다. 그 안의 SET LOCAL·DDL·권한 본문은 동일하다. 운영 함수 세 개의 `prosrc`를 파일 본문과 대조했으며 RLS·ACL·트리거 16항목을 통과했다. 원자 한도 20회·잘못된 요청 토큰 덮어쓰기 차단·지점/학생 가드도 실제 DB 거래에서 확인 후 롤백했다.

운영 RPC는 331명·93반·17강사·2과목으로 사전 읽기 전용 대사와 같았고, 해당 호출은 네트워크 포함 약 95ms였다(단일 표본). 빈 학생 허용 범위는 명단·선택지 모두 빈 결과다. 로컬 실제 앱에서 20행 페이지 이동과 현재 연결 표시를 확인했다. 명시 버튼으로 Claude Haiku 요약 1회를 생성해 약 13초 뒤 6개 발췌가 저장·재열람됐고 각 발췌는 원문 검증을 통과했다. 개인정보와 요약 본문은 배포 로그에 남기지 않는다.

실화면 대사에서 누적 카드 172.66/추이 172.65의 차이를 발견했다. 월별 실수 점수의 덧셈 오차가 반올림 경계에서 드러난 것으로, 추이도 정수 원자료를 먼저 누적한 뒤 같은 점수 함수를 사용하도록 수정했다. 1,000원+7,500원 경계·음수 정정·빈 달 회귀 검증을 추가했다. 요약/펼침의 긴 action은 React transition에서 분리했고 요약 중 별도 화면 전환·중복 호출 방지까지 관련 5개 테스트를 통과했다.

최종 코드 리뷰 수리: 요약 요청의 성공·실패·한도 등 결과를 본문 없이 감사 기록에 남기고 한글 라벨·외부 활동 발송 제외를 연결했다. 검색 제외 또는 플래그 미확인 메모는 AI 입력에서 제외했다. 출결 담당의 열린 이력은 정본 판정을 사용하고 담임/시간표 라벨을 구분했다. 위임 근거는 실제 DB 행 ID로 통일했다. 일일 기준 요약이 날짜 변경으로 무효화될 수 있음을 안내에 명시했다. 수정 범위 83개 테스트와 선택 빌드를 통과했고 두 번째 실제 요약(5개 발췌)에서 요청자·학생·해시·결과 감사 기록과 본문 미포함을 확인했다. 실제 모델 호출은 총 2회 성공, 일일 예약도 2회다. 요약 중 다른 서버 액션은 Next의 요청 대기열을 공유하는 한계가 남지만 화면 이동은 긴 transition에 묶이지 않는다.

Claude Opus 5.5의 구현 적대적 리뷰와 수정 부분 재검토 결과는 **APPROVE**다. 차단 2건과 경미 4건을 수리했고 문서의 미적용 표기도 정리했다. 최종 관련 타입 검사·변경 파일 ESLint가 통과했다. 남은 비차단 의견(개별 권한 실패의 오류 경계, 모델 내부 재시도와 예약 횟수의 차이, 큰 명단의 선택지 전송량, 표시 반올림, 서버 액션 대기열)은 리뷰 원문과 이 문서의 운영 한계로 남긴다.

| 단계 | 로컬 증거 | 아직 통과하지 않은 운영 조건 |
|---|---|---|
| P0·P1 | 읽기 전용 인벤토리, 식별·권한·기간·근거 계약 및 회귀 테스트 | 실제 직원별 계정의 권한 대조 |

## P5 후속 입력 계약

기존 수학 계획/보고서와 대조 가능한 교재 한 종류부터 시작한다. 아래는 원자료 확보와 교사 확인을 위한 설계이며 새 DB 표나 추정 점수를 활성화한 것이 아니다.

| 대상 | 필요한 식별·근거 | 현재 경계 |
|---|---|---|
| 교육과정·교재 버전 | 제공자, 외부 ID, 판/개정, 적용 기간 | 현재 교재명 문자열만으로 서로 다른 판을 합치지 않음 |
| 개념·문항 버전 | 버전 ID, 선후 개념의 근거, 교재 페이지/문항 ID, 검토한 교사 | AI가 만든 매핑은 검토 전 제안이며 학습 사실에 포함하지 않음 |
| 학생 시도 | 학생·지점·문항 버전 ID, 실제 응시 시각, 응답/채점, 출처 ID, 취소·수정 버전 | 보고서의 차시 완료와 문항 정답을 서로 대체하지 않음 |
| 추정 | 사용한 시도 ID 집합, 계산/모델 버전, 표본 범위, 미확인 사유, 교사 검증 결과 | 근거 없는 기본 0점·한 번의 오답으로 미숙 확정 금지 |
| 검증 | 교사 확인 정답 세트, 판정 불일치, 보류/취소/재시도 사례, 교재 버전 분리 | 실제 정오답과 교사 확인이 확보되기 전 숙련도 공개 보류 |

이 계약을 채울 원자료와 활용 범위가 있어야 개념 모델을 운영할 수 있다. 그래프 DB 도입이나 AI 키 추가가 이 자료를 대신하지 않는다.
