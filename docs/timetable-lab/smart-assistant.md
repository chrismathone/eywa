# 충돌 설명과 스마트 도우미 설계

2026-10-02 · [협의 결정](decisions.md)의 D09~D20을 적용하는 상세 설계

## 사용 흐름

충돌 표식 → 무엇이 겹치는지 확인 → `가능한 자리 찾기` → 대안 카드 비교 → 바뀌는 곳 미리보기 → `이 안으로 옮기기` → 연습안만 변경.

예시 데이터는 합성이다:

```text
현재: 목요일 18:00 영어 A반
문제: 학생 가의 수학 B반(목 18:00~19:00)과 겹칩니다.

대안 1: 같은 강사 · 같은 방 · 목 19:10~20:10
  학생/강사/방 겹침 없음, 수업 1개 이동, 담당과 수업 길이 유지
대안 2: 같은 강사 · 다른 방 · 화 18:00~19:00
  방과 요일 변경 필요, 해당 블록의 다른 요일도 함께 이동
조건 변경안: 고정 담당을 바꾸면 가능한 후보가 있습니다.
  담당 변경을 허용하기 전에는 적용할 수 없습니다.
```

실제 카드의 `겹침 없음`은 현재 연습 revision과 확인된 자료 범위에서만 유효하다. 필요한 자료를 못 읽었으면 `확인 필요`라고 표시한다.

## 검사와 탐색의 구분

- **검사기**: 입력된 완성 상태가 규칙을 만족하는지와 위반 근거를 반환한다.
- **탐색기**: 옮길 수 있는 후보 명령을 만들고 검사기에 통과시킨다.
- **순위 계산기**: 통과한 후보 중 바뀌는 항목이 적고 사용자가 정한 선호를 잘 지키는 안부터 정렬한다.
- **설명기**: 검사 결과의 실제 엔티티와 시간으로 문장을 만든다. AI가 근거를 새로 추측하지 않는다.

드래그 경고·붙여넣기 경고·도우미 추천·실제 반영은 같은 규칙 계약을 사용한다. 기존 세 검사 경로는 우선 비교 시험으로 불일치를 드러내고, 동일한 규칙을 공유하는 어댑터로 단계적으로 수렴시킨다.

## 규칙 입력

`DraftState + baseline/version + effectiveDate + subject adapter + externalOccupancy + sourceCompleteness`.

- 연습안에서 바뀐 배치와 학생 배정을 모두 적용한 **최종 상태**를 사용한다.
- 외부 점유는 편집하지 않는 다른 과목의 일정과 비수업 블록이다. 영어를 편집해도 수학 학생 일정을 검사한다.
- 현재 연습안이 대체하는 원래 배치를 점유 목록에서 제외한다. 자기 원래 자리 때문에 자기 이동을 막지 않는다.
- ID와 표준화된 방/강사 정보를 비교한다. 이름/별칭/표시 순서만으로 식별하지 않는다.
- 날짜별 유효 이력, 휴원/퇴원/예정 수강, 분리등원, 미래 예약을 적용일 기준으로 해석한다.
- 적용일이 속한 한 주만 확인하지 않고 이후의 수강·배치 유효 구간 경계를 검사한다. 휴원/복귀 정보를 모르면 현재 상태를 임의로 바꿔 계산하지 않는다.
- 검사 재료는 필요한 최소 정보만 권한에 맞게 전달한다. 다른 지점과 권한 밖 학생 세부 정보를 설명에 노출하지 않는다.

## 규칙 결과

```text
ConstraintResult {
  revision, checkedAt, completenessByAxis,
  issues: [{
    code, severity, scope, entityIds,
    dates, overlapInterval, cellRefs, relatedCellRefs,
    evidence, baselineOrNew, resolutionOptions
  }]
}
```

심각도는 실제 반영을 막는 문제, 확인 가능한 경고, 정보 부족으로 분리한다. 칸 표시에는 색뿐 아니라 아이콘/문구를 사용하고 목록 선택으로 양쪽 관련 칸에 이동한다.

`completenessByAxis`는 학생/강사/방/비수업/출결마다 complete/partial/unknown과 원인을 담는다. 기존/신규/악화 문제를 구분한다. 기존 반영에서 확인을 허용한 항목과 도우미가 충돌 없는 후보로 추천할 수 있는 항목은 다르다. [D12](decisions.md)의 정책을 그대로 적용한다.

대표 이유:

| 축 | 근거 | 예외/주의 |
|---|---|---|
| 학생 | 같은 학생의 유효한 두 수업 시간 겹침 | 과목 간 검사, 분리등원, 자리 포함 |
| 강사 | 수업/회의/감독/연차의 동시 점유 | LAB/JJ를 사람 강사로 오인하지 않음 |
| 방 | 다른 강사가 같은 방 동시 사용 | 방 식별 실패는 정보 부족, 합반은 별도 경고 |
| 반 | 같은 반의 동시에 성립할 수 없는 배치 | 실제 블록 여러 행/요일과 합반 계약 구분 |
| 시간 | 교시 범위/요일/길이 유효성 | 화면 행 높이와 실제 수업 시간은 다름 |
| 학생 배정 | 불명확한 학생 연결, 수강기간 불일치 | 동명이인·예정 수강·휴원 상태를 지우지 않음 |
| 반영 | stale revision, 기록 연결, 예약 충돌, 권한 | 화면 검사 성공이 서버 반영 허가가 아님 |

## 탐색 단계

### 1. 단일 블록 재배치

고정할 항목(강사/방/요일/시간/학생)을 잠금으로 받는다. 유효한 교시와 허용 요일을 열거하고 블록 모양·길이를 보존한 후보만 만든다. 같은 담당·방을 보존하는 후보부터 검사한다. 새로 생기는 충돌이 없는 후보 중 상위 몇 개를 표시한다.

### 2. 제한된 교환

단순 이동으로 안 풀리면 두 블록 교환을 검사한다. A를 이동한 중간 상태에서 B와 겹친다고 탈락시키지 않고 A/B를 동시에 바꾼 최종 상태를 검사한다. 두 수업의 학생과 다른 과목까지 다시 본다. 변경은 하나의 명령으로 저장/Undo한다.

### 3. 조건부 대안

허용된 소프트 조건을 하나씩 완화하여 어느 조건 때문에 막혔는지 보여준다. 사용자 잠금·권한·물리적 불가능·수업 길이를 몰래 완화하지 않는다. 담당 변경/학생 재배정 등 의미가 큰 대안은 바뀌는 대상을 명시하고 명시적으로 선택할 때만 적용한다.

### 4. 더 큰 재배치

여러 블록의 연쇄 이동은 후속 단계다. 제한 깊이/노드 수/실행 시간/취소를 두고 Web Worker 또는 요청형 서버 작업으로 실행한다. 운영 UI의 드래그 응답과 분리한다. 전체 최적해 보장은 하지 않는다.

## 후보 정렬

1. 필수 검사 통과와 데이터 완전성.
2. 새로 생긴 차단 문제 0, 다른 경고가 늘어나는지 공개.
3. 움직이는 수업/학생 수와 기존 배정 변화 최소화.
4. 담당·방·요일 유지, 시간 이동량 최소화.
5. 사용자가 명시한 선호(예: 늦은 시간 피하기, 같은 강사 유지).
6. 동점은 안정적인 키로 정렬해 화면이 흔들리지 않게 한다.

초기에는 위 순서를 사전식으로 비교하고 임의 가중치 최적화를 넣지 않는다. 사용자의 명시적인 선호는 필터 또는 정렬 우선순위로 적용한다. 정답이 없는 선호를 물리적 제약과 같은 차단으로 만들지 않는다.

## 결과 유효기간과 실패

- 후보는 `draftRevision + constraintVersion + occupancyVersion + effectiveDate`에 묶는다.
- 편집/적용일 변경/운영 갱신 시 이전 검색을 취소하고 결과를 만료시킨다.
- 적용 직전에 후보 명령 전체를 다시 검사한다. 오래된 카드 클릭으로 잘못된 자리 이동을 만들지 않는다.
- 정해진 후보 공간을 전수 검사했을 때만 `현재 조건에서 가능한 자리 없음`이라고 한다.
- 중간 중단/제한 초과는 `검색 범위 안에서 아직 찾지 못함`, 데이터 누락은 `추가 확인 필요`로 구분한다.
- 서버/AI가 없어도 수동 편집·명시적 충돌 검사·연습안 저장 기능은 유지한다.

## JEV 활용 판단

기존 `src/lib/ai/jev.ts`는 선택지 분류 API다. [TypeSafe 공식 소개](https://docs.typesafe.ai/introduction) 역시 선택/평가를 중심으로 설명한다. JEV에 시간 산술, 가능 여부 확정, 최적화 탐색, 운영 쓰기를 맡기지 않는다.

검증 가치가 있는 후보는 사용자 메모 `목요일은 늦지 않았으면 좋겠어`를 이미 정의한 선호 선택지와 연결하거나, 낯선 외부 시트 헤더를 알려진 필드 후보에 연결하는 보조다. 원문 근거/불확실성/사람 확인이 필요하다.

- 사용자 명시 요청 시에만 기존 `generateJSON({ mode: "decision", meta: { tenantId, feature } })` 경유.
- 시간표 전체/개인 연락처를 보내지 않는다. 이름이 필요 없는 선호 분류는 이름 없는 입력으로 한다.
- 낮은 확신·형식 오류·시간 초과는 일반 코드 흐름으로 돌아온다. 검사 성공으로 치환하지 않는다.
- 합성/보류 자료로 비용·속도·정확도를 비교해 도입 이점이 있을 때만 활성화한다. 영어 연습실의 선행 의존성이 아니다.
