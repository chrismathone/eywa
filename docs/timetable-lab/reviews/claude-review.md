**코디네이터 4개 쟁점에 대한 입장(8장):** ① Undo는 도메인 이력 하나만. 엔진 자체 이력은 끄거나 탈락. ② 배치는 강사뷰가, 배정은 통합뷰가 소유하고 둘은 같은 저장소를 읽는다. 통합뷰의 배치 칸 편집은 같은 배치 명령으로 들어간다. ③ 일정 격자의 임의 행·열 삽입은 일정 의미가 없으므로 명시 명령으로 바꾸거나 거절하고, 자유 편집은 반영되지 않는 메모 시트로 받는다. ④ 도우미는 현재 연습 명단 + 적용일 기준 타 과목 점유(날짜 구간 포함)로 색인을 만들고, 단일 이동·교환은 전수 확인한다.

## 1. 초안이 놓친 기존 자산과 함정 (코드 근거)

### 1.1 `시간표(개발중)` 월별 계획이 이미 있다 — M1

- `supabase/migrations/s1_season1.sql#0232a_timetable_plan_slots.sql`: 원장 지시(2026-08-28 *"다음달 다다음달 시간표도 미리 만들어서 관리하고싶음"*)로 만든 **월별 계획 표**. `class_schedules`와 분리, RLS 켜고 정책 0개 + service_role 전용, 앵커 = `(tenant_id, plan_month, class_id, day_of_week, start_time)` 유니크. 주석이 "확정(적용) 경로는 **일부러 만들지 않았다**"고 적는다.
- `src/lib/navigation.ts:80` `TIMETABLE_DEV_NAV_VISIBLE = false` — 2026-08-31부터 사이드바에서 숨김. 라우트·권한은 살아 있다.
- `src/features/timetable-dev/` 3,149줄(시트→계획 변환 `lib/sheet-plan.ts`, 월 비교 `lib/compare.ts`, 게이트 `server/access.ts`, 격리 테스트 `isolation.test.ts`), `src/app/(shell)/timetable-dev/_components/`에 **본 시간표 컴포넌트 30여 개를 복사한 사본**이 있다. changelog에도 "개발 사본이라 안 건드렸다"는 기록이 여러 번 있다(사본 표류).
- 연습실과 겹치는 점: 미래 달 계획 + 운영 분리 + 시트에서 가져오기. 다른 점: 학생 배정·revision·이름 붙은 여러 안·반영이 없고, 식별이 시각 앵커라 `compare.ts`가 이동을 삭제+추가로 본다.

**요구:** 사용자에게 "개발중을 연습실로 흡수 / 연습실 출시 후 폐기" 중 하나를 받는다. 어느 쪽이든 연습실 UI는 본 시간표 컴포넌트를 **복사하지 않고** 공유 순수 모델(`teacher-grid-model.ts`, `class-grid.ts`의 `groupRichCards`)을 소비한다. 재사용할 것은 패턴뿐이다: 단일 게이트(`access.ts`) + 격리 가드 테스트(`isolation.test.ts`, `gate-wiring.test.ts`).

### 1.2 영어 시트 반영기는 이미 원자적 일괄 반영기다 — 단 의미가 다르다 — M2

`src/features/timetable/server/master-sheet-store.ts`의 `applyMasterTransaction`(157~)이 초안이 새로 만들려는 것을 대부분 이미 한다.

- serializable 트랜잭션 + 지점별 advisory lock(`:167-169`), 출결·보고서·보강 잠금(`master-sheet-attendance.ts:11-15`)
- 트랜잭션 안에서 문맥을 다시 읽고 미리보기 hash와 비교(`:175-185`), 확인 키 집합이 정확히 같을 때만 통과(`:191-202`)
- 적용일 이후 시작하는 배치·근무 블록이 있으면 거절(`:213-222`), 스냅샷·명단 이동 RPC 부분 실패 = 전체 실패(`:320-332`의 `move_enrollments_batch` 결과 검사), 출결 이관, 날짜 단위 예약 취소(`cancelMasterDate`)

그대로 연습안에 연결하면 안 되는 이유(`src/features/timetable/import/master/plan.ts`):

1. **누락 = 종강**: `:463` `closeClassIds = input.closeClassIds ?? omittedClasses.map(...)` — 시트에 없는 반이 기본 종강 대상이다. 연습안에서 반을 잠깐 비워 두거나 다른 과목 반은 대상이 아니다.
2. **명단에서 빠짐 ≠ 수강 종료**: `:594` 이후 `diff.removes`를 버리고 경고만 남긴다. 연습안의 "이 반에서 빼기"를 표현할 길이 없다.
3. **신설 반 불가**: 매핑되지 않은 반은 오류(`MANUAL_CLASS_FIX`, `:45`). 연습안에서 반 생성을 허용하면 새 능력이 필요하다.
4. **영어 전용 문맥**: `loadMasterContext`의 반·근무 블록이 `subject='english'`(`master-sheet-store.ts:63`, `:84`). 반면 배치(`:75`)와 수강(`:78`)은 과목 필터가 없어 학생 검사는 전 과목이다. 수학 어댑터 때 이 비대칭을 그대로 들고 가면 안 된다.
5. **이름 매칭이 입력 단계에 있다**: 시트 문자열 → 반/강사/학생 매칭(`buildClassMappings`, `matchRosterStudent`). 연습안은 이미 ID를 들고 있어 이 단계를 우회해야 한다. 연습안을 다시 격자 문자열로 바꿔 넣는 방식은 ID를 버리는 일이라 금지한다.

Codex의 메시지도 "부분 격자로는 재사용 불가"라고 봤다. 동의하되, 연습안은 **전체 복사본**이라 부분 격자가 아니다. 진짜 문제는 "비어 있음"을 의미로 해석하는 것이다. 해법은 재사용 포기가 아니라 플래너를 입력 파싱과 분리하는 것이다(9장).

### 1.4 `class-move.ts`를 권위 검사기로 쓰면 안 되는 이유 — M8

- **이름으로 묶는다**: `buildClassMoveIndex`가 학생은 ID로 모으지만 `BusyWindow`에 넣을 때 `cur.names.includes(name)`로 중복을 지우고 분리등원을 `daysByName[name]`에 담는다(`:273-284`). 같은 반에 학교가 다른 동명이인이 있으면, 한쪽의 요일 제한이 다른 쪽을 덮어 충돌을 놓칠 수 있다. 실데이터에서 일어났는지는 확인하지 않았다(잠재 결함으로만 보고).
- **근거가 잘린다**: 이름 4명 캡(`NAME_CAP`, `:188`), `MoveBlocker`에 ID가 없다(`:142-147`). 칸 이동·양쪽 하이라이트를 할 수 없다.
- **단건 이동 vs 스냅샷**: 판정은 "이 블록 하나가 움직이고 나머지는 페이지를 연 시점 그대로"다(`moveBlockers`가 `movingIds`만 뺀다, `:438`). 연습안처럼 여러 변경이 쌓인 **최종 상태** 검사가 아니다.
- **한 주만 본다**: 서버 재판정도 적용일이 속한 주의 슬롯만 읽는다(`move-actions.ts:152`). 다음 달 적용 연습안이면 그 뒤 수강 시작·종강·타 과목 예약을 못 본다.
- **원자성 없음**: `moveClassSlots`는 admin 클라이언트로 줄마다 넣고 마감한 뒤 실패 시 보상 일지로 되돌린다(`:226-308`). 진짜 트랜잭션이 아니고 한 번에 한 반만 받는다(`:119`). 초안이 지적한 "단건 액션 연속 호출 금지"에 동의한다.

재사용할 것은 **규칙과 순수 헬퍼**다: `placeBlock`의 모양 유지(행·요일 오프셋, 시각 차로 밀지 않음, `:16-18`), `movedEndTime` 길이 보존, `sameRoom`, `isSeatSlot`, `attendsOn`. 색인 구조와 결과 타입은 새로 만든다.

### 1.5 두 화면의 기하가 다르다 — M6

- 강사뷰 = **10분 행**(`teacher-grid-model.ts:120-121` `buildTenMinuteRows`), **슬롯 = 블록 1:1, 접기 없음**(`:126`), 열 키 = 강사 **라벨**(`teacherOf` = `slotTeacherLabel ?? teacherName`, `:73-75`), LAB 병렬 레인.
- 통합뷰·기본뷰 = **교시 행**, 같은 반의 연속 교시·같은 그룹 요일을 **한 칸으로 병합**(결정 로그: 영어 (반,요일) 121칸 전부 교시 2개 이상, 106칸이 두 요일, 2026-09-04 실측).
- 교시표 밖 시각은 격자에서 **조용히 사라진 전례**가 있다(영어 주말 유령 슬롯 2026-08-24, [[#106]] 같은 시작시각 두 교시).

결과: 강사뷰에서 16:25로 자유 배치한 수업은 통합뷰 교시 행에 대응이 없다. 통합뷰에서 월·목 블록을 끌면 4~6개 배치가 움직이지만, 강사뷰에서 한 칸을 끌면 1개만 움직여 통합뷰 병합 블록이 쪼개진다. 둘 다 정상 동작으로 정의해야 한다(3장 선택 단위, 8장 ②).

### 1.6 창(iframe)마다 별도 문서다 — M9

aywa의 메뉴는 same-origin iframe 창이다([[#55]] 창 ⇄ 배경은 별도 문서, [[#64]] 같은 탭 다중 창 + BroadcastChannel). 강사뷰 창과 통합뷰 창을 따로 열면 메모리 상태가 두 벌이다. 초안의 "같은 연습 상태의 두 표현이며 별도 저장본을 동기화하는 방식이 아니다"는 **한 문서 안에서만** 참이다.

**요구:** 1차 구현은 한 페이지 안의 분할 보기/전환(같은 저장소). 같은 연습안을 두 창에서 여는 경우는 서버 revision이 진실이고, 창 사이는 BroadcastChannel로 "새 revision 있음"만 알린 뒤 명령 단위로 다시 맞춘다. 두 창이 같은 배치를 동시에 바꾸면 뒤 명령이 CAS에서 거절되고 이유를 보인다(acceptance H03).

### 1.8 분리등원 요일의 저장 형식이 섞여 있을 수 있다 — 확인 필요

`src/features/timetable/server/student-busy.ts:74-76` 주석: "분리등원(요일 제한)은 **한글 요일로 저장돼 있다** … 이미 enum(`mon`)으로 든 저장분도 있어 `?? d`로 통과". 반면 `enrollmentAttendsOnDay`(`features/enrollments/eligibility.ts:92-97`), `class-move.ts`의 `attendsOn`(`:201-203`), 시간표 조회(`server/queries.ts:848` `attendanceDays: r.attendance_days ?? ## 2. 제품 흐름 — 수정안

```text
연습실 열기
 → 새 안: 과목(영어) · 적용일 D 선택 → 운영 상태(D 기준, D 이전 예약 포함)를 복사 → 이름 저장
   · D 이후 시작하는 예약/근무 블록이 이미 있으면 처음부터 "반영 불가 사유"로 표시(M12)
 → 편집: [강사뷰 | 통합뷰] 한 페이지 분할/전환 · 오른쪽에 검사 목록 · 도우미
 → 안 복제(A안→B안) · 이름 변경 · 보관
 → 반영 준비: 운영 최신 상태와 3-way 비교 → "운영에서 바뀐 것" 처리 → 반영 미리보기(변경·확인 항목·출결 이관)
 → 확인 체크 → 오늘 반영 / 예약 반영 → 연습안은 읽기 전용(반영됨) · 같은 기준의 다른 안은 "기준 바뀜"
 → 예약 취소는 기존 시간표 예약 배지에서(날짜 단위, 미래분만)
```

보충할 결정:

- **선택 단위**: 강사뷰는 배치 1개가 기본 단위, 통합뷰는 병합 블록(그 반의 여러 배치)이 기본 단위. 두 화면 모두 "같은 반 전체 선택" 명령을 둔다. 도우미 카드는 함께 움직이는 배치를 전부 적는다.
- **학생 배정 의도는 넷**: 유지 · 이동(수강 이동) · 추가(새 수강) · 종료(수강 종료). **종료는 명시 명령으로만** 만든다. Delete 키가 수강 종료를 만들지 않는다(운영 시간표의 Delete=오늘 수강 종료와 다르다는 점을 화면에 적는다). 연습안 안에서 Delete는 "이 반에서 빼기 = 미배정 목록으로"이고, 반영 시 미배정은 기존 시트 규칙처럼 **기존 수강 유지 + 경고**다.
- **미배정·미확인 목록**: 반을 잃은 학생, 이름만 붙여넣어 ID가 정해지지 않은 학생, 동명이인 후보를 별도 패널에 둔다. 반영 전에 0이 될 필요는 없지만 각 항목의 반영 결과(유지/오류)를 미리보기에 적는다.
- **반영 후**: 그 안은 잠근다. "다시 고치기"는 새 기준으로 새 안을 만든다.
- **하지 않을 것**: 자동 이동, 비어 있음으로 종강 추정, 이름 문자열로 반/학생 확정.

## 3. 정본(canonical) 연습안 도메인 — 제안

```ts
type LabDraft = {
  id: string; tenantId: string; name: string;
  subjects: SubjectKey[];          // 1차 ["english"]. 범위 밖 과목은 읽기 전용 외부 점유
  effectiveDate: string;           // YYYY-MM-DD, 서버 KST로 검증(오늘~+180일, effective-date.ts 규약)
  base: { capturedAt: string; fingerprints: Record<EntityKey, string> }; // 3-way 재기반용
  revision: number;
  status: "editing" | "published" | "archived";
  state: DraftState;
};

type DraftState = {
  classes: Record<ClassId, { rename?: string; homeroom?: UserId | null; close?: { on: string } }>; // 명시 명령만
  placements: Record<PlacementId, Placement>;
  assignments: Record<AssignmentId, Assignment>;
  teacherBlocks: Record<BlockId, TeacherBlock>;   // 회의·감독·연차(영어 강사 시트에 있다)
  layout: { integrationGroups: ScheduledGroup[] }; // 반영 대상(예약 스냅샷 payload.apply.integrationGroups)
  scratch?: ScratchSheet;                          // 자유 메모 시트. 반영 안 됨
};

type Placement = {
  id: PlacementId;
  origin: { scheduleId: string } | null;   // 운영 행에서 왔으면 그 id. 출결 이관·이동량 계산의 근거
  classId: ClassId;
  day: DayOfWeek; startMin: number; durationMin: number; // 길이는 명시 명령으로만 변경
  teacher: { kind: "person"; userId: UserId | null; label: string } | { kind: "seat"; seat: "LAB" | "JJ" };
  room: { classroomId: string | null; label: string | null };
  mergeGroup: string | null;               // 현재 운영 0행. 연습실이 임의로 만들지 않는다
  labSeparate: boolean | null;             // null = 원본에서 못 읽음(move-actions의 lab_separate 규약)
};

type Assignment = {
  id: AssignmentId;
  studentId: StudentId; classId: ClassId;
  origin: { enrollmentId: string } | null;
  attendanceDays: DayOfWeek[] | "all";     // enum으로 정규화(1.8)
  intent: "keep" | "move" | "add" | "end";
  matchNote?: { raw: string; candidates: StudentId[] }; // 붙여넣기 미확정. 확정 전엔 검사에서 '정보 부족'
};
```

불변 규칙:

1. 저장은 ID만. 이름·라벨·교시 이름·담임 자동 판정·화면 배치·인원은 **파생값**이다(`period_label`은 운영도 이동 시 버린다, `move-actions.ts:278-279`).
2. 자리(LAB·JJ)는 강사가 아니다. 강사뷰의 LAB/JJ 열은 `seat` 배치를 그린 것이다. 통합뷰의 `*LAB` 임시 칸(결정 로그 2026-09-11)은 표시 전용이라 연습안이 만들지 않는다.
3. 같은 반이 같은 시각에 배치 두 개를 갖는 상태는 연습 중엔 허용(자유 배치)하되 검사기가 `duplicate`로 표시한다. 0232a 유니크 제약을 연습안에 들고 오지 않는 이유다.
4. 개인 보기 설정(확대·열 폭·접기·숨김)은 연습안이 아니라 `users.ui_prefs.timetableLab`에 계정 단위로 둔다(작업 선호 "모든 뷰 세팅은 계정 귀속"). 통합뷰 줄 배치만 연습안 상태다(M13).
5. 운영 enum(과목·교시·직급)은 학원설정에서 읽는다. 교시 후보는 `weekdayTableFor(subject, config)`(`periods.ts:195`).

## 4. 저장 · 지점 격리

### 표 구성(제안)

- `timetable_lab_drafts` — 한 안 = 한 행. `state jsonb`, `base jsonb`, `revision int`, `status`, `effective_date`, `subjects text[]`, 작성/수정자, `published_snapshot_id`.
- `timetable_lab_commands` — append-only 명령 기록. `(draft_id, revision)` 유니크, `client_command_id` 유니크(재전송 멱등), `kind`, `payload`, `actor_id`.

jsonb 한 행을 고른 이유: 교환·붙여넣기 같은 다중 엔티티 명령이 **행 하나의 CAS**로 끝나고, 안을 여는 조회가 1행이라 PostgREST 1,000행 절단(B2)과 무관하다. 대가는 저장마다 큰 jsonb를 다시 쓰는 것이다. 영어 규모(배치 수백 + 배정 수백)면 수백 KB로 예상하지만 **측정 전 추정**이다. P2 수용 기준에 "통상 5배 합성 규모에서 명령 저장 p95"를 넣고, 넘으면 배치/배정을 자식 표로 나눈다.

### 격리와 권한

- 0232a와 같은 규약: RLS 켜고 정책 0개 + service_role 전용, 유일한 앱 게이트 함수 하나(예 `requireTimetableLabAccess`). 모든 admin 조회에 `tenant_id` 필터. `timetable-dev/isolation.test.ts`·`gate-wiring.test.ts`와 같은 정적 가드 + pgTAP으로 anon/authenticated 0행을 증명한다.
- **M11**: jsonb 안의 `classId/studentId/enrollmentId/userId/classroomId`는 FK가 없다. 명령 수락 시 새로 들어온 ID가 그 지점 소속인지 확인하고, 반영 트랜잭션 안에서 **전부 다시** 확인한다(acceptance D03의 서버 측 근거).
- 쓰기 게이트는 운영 반 이동과 같은 `canManageTenant("classes")`(`move-actions.ts:79`). 반영 게이트는 시트 반영의 반 일괄 관리 게이트(`canManageTimetableImport`, `master-sheet-actions.ts:60`)에서 시트 연동 조건만 뺀 것을 제안한다. 정확한 함수 선택은 Codex 확인.
- 강사(scoped)에게는 연습안을 보이지 않는다(미래 학생 이동이 담긴다). super_admin은 규약대로 자동 통과.
- 기능 스위치가 꺼진 지점에서는 메뉴·주소·서버 액션 전부 없는 것처럼(결정 로그 tenant).

### 클라이언트 보존

- 서버에 안 닿은 명령은 IndexedDB 일지에 `(사용자, 지점, 안)` 키로 둔다. 새로고침 시 서버 revision 위로 다시 보낸다. 로그아웃·지점 전환 때 지운다(acceptance H05). localStorage에 연습안 상태를 두지 않는다([[#90]] origin 단위).
- 저장 상태 표시는 `저장됨(rN) / 저장 중 / 보내지 못함 n건 / 다른 창에서 바뀜` 넷.

### 감사

생성·복제·이름 변경·보관·반영·예약 취소는 `logAction`. 편집 하나하나는 명령 기록 표가 감사 기록이다.

## 5. 검사기 계약 — `smart-assistant.md`의 `ConstraintResult`에 대한 보정

1. **완전성은 축별로**: `completeness: { students, teachers, rooms, blocks, attendance }` 각각 `complete | partial | unknown` + 사유. 하나라도 `unknown`이면 칸에 "확인 필요"를 표시하고 `충돌 0`이라고 쓰지 않는다. 기존 힌트용 fail-open 경로(`student-busy`)를 이 검사기 재료로 쓰지 않는다.
2. **근거는 ID + 날짜 구간**: 양쪽 배치 ID, 학생 ID, 겹치는 날짜 구간·시간 구간. 화면 문구는 렌더 시 이름으로 바꾼다.
3. **출처 구분**: `baseline`(기준 상태에 이미 있음) / `introduced`(이번 안이 새로 만듦) / `worsened`(기존 문제가 커짐). 확인 체크 대상은 introduced·worsened만이다(결정 로그 "체크 대상은 이번 변경이 건드린 차단 충돌뿐"과 같은 원칙).
4. **심각도 넷**: `blocking`(반영 불가: 식별 실패·권한·기준 바뀜·D 이후 예약) / `confirm`(물리 충돌·학생 겹침: 키별 확인 후 반영 가능, 기존 시트 반영과 같음 `plan.ts:544`) / `warning`(합반 모양, 손대지 않은 옛 충돌, 교시 밖 시각) / `unknown`(재료 부족: 손댄 대상이면 confirm처럼 확인 요구).
5. **시간 모델**: 연습 범위 과목의 배치는 "D 이후 예약 금지"(`plan.ts:210`, `:223`) 덕분에 D부터 일정하다. 그러나 **범위 밖 과목은 D 이후 예약이 있어도 막히지 않는다**(금지 검사가 영어 반만 본다). 학생 수강 시작·종료, 반 종강일, 근무 블록도 D 뒤에 바뀐다. 그러므로 외부 점유와 배정은 `masterStudentConflicts`처럼 날짜 구간으로 평가한다(`student-conflicts.ts:97-111` 재사용 후보).
6. **휴원생**: 기존 셋 다 제외한다. 연습안은 다음 달 기준이라 복귀가 흔할 수 있다. 제안은 `warning: 휴원 중 — 복귀하면 겹침`(사용자 결정 U3).
7. **같은 함수, 두 곳**: 화면 검사와 반영 검사는 같은 순수 함수다(#77). 화면은 Worker에서 증분으로 돌리고, 서버는 트랜잭션 안에서 전체를 돈다.

## 6. 반영 — 원자성 · 미래 적용일 · 출결 이관

### 흐름

1. **3-way 재기반(M4)**: 서버가 운영 문맥(D 기준)을 읽어 엔티티별로 `base ↔ live ↔ draft`를 비교한다.
   - live만 바뀜 → 운영 값을 따른다(연습안을 자동 갱신, "운영에서 바뀜" 알림)
   - draft만 바뀜 → 연습안 값
   - 둘 다 바뀜 → 사용자가 고른다(반영 불가 사유로 표시)
   - 2-way(draft ↔ live)로 하면 연습안을 만든 뒤 운영에서 추가된 신입 수강, 다른 사람이 옮긴 반이 반영 순간 되돌아간다.
2. **명시적 변경으로 컴파일**: 배치 종료/추가(원본 id가 있으면 마감+삽입), 반 이름·담임·종강(명시 명령만), 줄 배치, 근무 블록, 명단 이동/추가/종료, **분리등원 요일 재매핑(M7)**.
3. **플래너**: 출결 이관 계획(`planAttendanceMigration`), 확인 항목, hash(연습안 revision + 운영 문맥). 연습안은 원본 schedule id를 들고 있으므로 옛 칸 → 새 칸 대응을 추정이 아니라 확정할 수 있다. 애매함·보고서·보강 연결은 기존 규칙대로 막는다.
4. **적용**: `applyMasterTransaction` 골격 그대로 — serializable, 출결 잠금, **시트 반영과 같은 advisory lock 키**(`${tenantId}:english-master`, `master-sheet-store.ts:169`)로 시트 반영과 서로 직렬화, 트랜잭션 안 재계산 + hash 비교 + 확인 키 일치, 멱등 키 `(draftId, revision)`, 같은 트랜잭션 안에서 연습안을 `published`로.
5. **예약 취소 호환(M12)**: 스냅샷 payload를 `cancelMasterDate`(`master-sheet-store.ts:420-458`, 블록·출결 복원은 `rollbackMasterBlocks` `:388`)가 되돌릴 수 있는 모양(kind `english_structure` + `masterSource` 백업 + 명단 스냅샷)으로 쓰고 `labDraftId`를 덧붙인다. 오늘 반영은 기존처럼 되돌리지 않는다.

### 위험과 대응

- **전역 잠금**: `lock table attendance_records in share row exclusive mode`(`master-sheet-attendance.ts:13`)는 **모든 지점**의 출결 쓰기를 트랜잭션 동안 세운다. 지금 시트 반영은 이 잠금 뒤에서 문맥 전체를 다시 읽는다(`:168` → `:175`). 연습실 반영은 무거운 계산을 잠금 전에 하고 잠금 안에선 검증만 하도록 하고, 5배 규모에서 트랜잭션 시간을 측정한다(멀티테넌트 가용성, 기존 경로에도 해당).
- **운영 단건 편집과의 경합**: `moveClassSlots`와 반 수정 폼은 advisory lock을 안 잡는다. serializable 충돌(40001)이 날 수 있으니 "다른 편집과 겹쳐 다시 시도" 문구 + 재검토를 둔다(acceptance P07).
- **[[#123]] 미해결 함정**: 미래 예약 뒤 그 반을 적용일 전날 수정하면 그날 수업이 사라진다. 연습안 예약 반영도 같은 위험이므로 수용 테스트에 넣고(현재 실패가 예상됨), 반 수정 화면 경고 여부를 Codex가 확인한다.
- **[[#120]] 이름 점유**: 이름 변경은 보관 반까지 검사(시트 경로 `plan.ts`의 `held:` 규칙 재사용).
- **[[#126]] 시작시각 이동**: 출결 앵커가 바뀐다. 적용일 이후 기록이 있으면 이관 규칙만 통과시킨다.
- **반영 후 Undo**: 자동 역연산 없음. 미래분은 예약 취소, 오늘분은 새 연습안.

## 7. 스마트 도우미 — `smart-assistant.md` 보정과 추가

Codex 초안의 4단(단일 이동 → 교환 → 조건부 → 연쇄)과 결과 유효기간 규칙에 동의한다. 아래는 고칠 점과 더할 점이다.

### 7.1 후보 공간을 명시하고 전수 확인 가능한 범위를 넓힌다

| 계열 | 내용 | 분류 |
|---|---|---|
| F1 시간 이동 | 같은 강사·방·블록 모양. 과목 교시표의 시작시각 × 요일 그룹(`resolveWeekdayGroups`) | 가능/경고와 함께 가능 |
| F2 방 변경 | 같은 시각, 보관 안 된 다른 강의실(FK 기준, [[#122]]) | 조건 변경(가벼움) |
| F3 담당 변경 | 같은 시각, 다른 영어 강사(근무 블록 없음). 담임 자동 판정(`buildClassUpdates`, 한국인 강사 최다 교시)이 바뀌면 표시 | 조건 변경 |
| F4 상대 이동 | 충돌 상대 반을 F1으로 옮김 | 가능(상대가 움직임을 명시) |
| F5 교환 | 두 블록 맞바꿈, 최종 상태로 한 번에 검사 | 가능 |
| F6 학생 단위 | 겹치는 학생만 다른 반으로 / 분리등원 요일 조정 | 조건 변경 + "수업 시수·수강료 영향 가능" 경고 |
| F7 연쇄 | 깊이·노드·시간 제한 | 제한 탐색 |

F1의 크기는 요일 그룹 수 × 교시 수 수준(영어는 수십)이고 블록 하나당 검사는 요일 색인으로 짧다. F5는 반 블록 수(결정 로그 기준 영어 약 120칸) 수준이다. 그러므로 **F1~F5는 전수 확인을 목표로** 하고, 화면은 "단일 이동·교환은 모두 확인했고 가능한 자리 없음"과 "연쇄 이동은 N개까지 확인"을 따로 적는다. 이 크기 추정은 구조에서 나온 것이고 실측이 아니다(P5에서 측정).

### 7.2 시각 후보는 교시 정렬이 기본

강사뷰가 10분 단위 자유 배치를 허용해도 도우미 후보는 과목 교시표에 맞춘다. 영어 교시는 서로 겹치고 틈이 있어 분 단위 이동이 교시에 안 맞는 시각을 만든다(`class-move.ts:16-18`). 원래 교시 밖에 있던 배치만 "현재 시각 유지" 후보를 함께 만든다.

### 7.3 현재 연습 명단 + 타 과목 점유로 색인을 만든다

- 학생 축 = 연습안 배정(`intent`: end는 D부터 제외, add·move는 D부터 포함) × 연습안 배치 + 범위 밖 과목의 운영 수강 × 운영 배치(날짜 구간).
- 강사 축 = 연습안 배치 + 근무 블록 + 범위 밖 과목 배치(같은 사람이 두 과목을 가르치는 경우).
- 방 축 = 연습안 배치 + 범위 밖 과목 배치(FK 우선, 라벨 토큰 보조).
- 원래 자리는 빼고 본다(자기 자신에 막히지 않음).
- 외부 점유는 서버가 `occupancyVersion`과 함께 내려준다. 버전이 바뀌면 후보를 만료한다.

### 7.4 순위는 사전식, 설명 가능한 키로

1) 새 blocking/confirm 0 · 완전성 complete → 2) 움직이는 배치 수 → 3) 주간 일정이 바뀌는 학생 수 → 4) 담당·방 유지 → 5) 요일 그룹 유지 → 6) 시간 이동량(분) → 7) 경고 수 → 8) 고정 키(요일 순서, 시작, 강사 ID, 방 ID, 배치 ID). 카드에는 각 키 값을 그대로 보여 준다. 사용자 선호는 이 키의 가중이 아니라 **필터 또는 순서 앞당김**으로만 쓴다(물리 제약과 섞지 않음).

### 7.5 "왜 안 되나" 설명기

드래그 중이든 도우미 카드든 같은 형식: 축별로 `학생 3명(이름·그 시간의 다른 반·과목) · 강사(회의 19:00~20:00) · 방 · 같은 반 · 분리등원으로 제외된 학생 · 교시 밖 · 출결 이관 영향`. 학생 목록은 ID 기준이라 동명이인이 둘로 나온다.

### 7.6 실행 위치

Web Worker. 연습안 스냅샷을 넘기고, revision이 바뀌면 취소한다. 서버 왕복과 AI 호출 0. 카드 적용 = 명령 하나(Undo 한 번에 복구, acceptance 시나리오 A-7).

### 7.7 JEV

Codex 판단(선호 문장 → 미리 정한 선호 선택지 연결, 낯선 시트 머리글 → 알려진 필드 후보)에 동의한다. 덧붙일 것:

- **JEV가 배치 후보를 직접 고르게 하지 않는다**: 후보 중 하나를 고르는 순간 가능 여부를 암묵적으로 판단하게 된다. 선호 연결 결과는 7.4의 필터/앞당김으로만 들어간다.
- **학생·반 연결에 JEV를 쓰지 않는다**: 결정 로그가 "매핑을 기계가 정하게 하지 말 것"을 반복한다. 붙여넣기 이름은 기존 결정적 매처(`matchRosterStudent`) + 사람 확인.
- 구현 시 `FEATURE_KEY_GROUP`에 새 호출부 한 줄(가드 `key-groups.test.ts`), `meta.tenantId` 필수, 지점 AI 라이선스, 명시 버튼에서만. `jev.ts` 제약(질문 ≤12, 선택지 2~255, 입력 ≤120KB, 기본 6초, `:66-73`) 안에서 설계.
- 영어 연습실의 선행 조건이 아니다. P5 이후 A/B로 효용이 보일 때만.

## 8. 코디네이터 4개 쟁점에 대한 입장

### ① 엔진 자체 Undo vs 도메인 Undo

- **이력은 하나**다. 키보드·마우스·붙여넣기·도우미·채우기 전부 도메인 명령(역명령 포함)으로 들어가고 그 스택만 Ctrl+Z/Y를 받는다.
- 명령 종류는 둘: `domain`(연습안에 저장) / `view`(개인 보기 설정, `ui_prefs`에 저장). 같은 스택에 넣어 시트처럼 "열 폭 바꾼 것도 Ctrl+Z로 되돌림"을 유지하되, view 명령은 연습안 revision을 올리지 않는다.
- 엔진을 쓰더라도 엔진 내부 이력을 끌 수 없거나 모든 변경을 앱 명령 버스로 우회시킬 수 없으면 탈락(Codex의 탈락 기준과 같음).
- 다른 창에서 같은 대상이 바뀌어 역명령의 전제가 깨지면 Undo는 아무것도 바꾸지 않고 "다른 창에서 바뀌어 되돌릴 수 없음"을 보인다(부분 Undo 금지).
- 반영 이후 Undo는 없다(6장).

### ② 강사뷰 배치 vs 통합뷰 명단 투영

- **소유**: 배치(Placement)는 강사뷰, 배정(Assignment)·줄 배치(layout)는 통합뷰. 저장소는 하나다.
- **통합뷰 투영 규칙**: 반 카드 = 그 반의 배치를 요일 그룹·교시 행으로 접는다. 교시 매칭은 (시작, 종료) 짝 우선 + 시작시각 폴백([[#106]] `buildPeriodMatcher`, `lib/period-match.ts:13`). 맞는 교시가 없으면 **`교시 밖` 행을 그 카드에만** 만들어 보이고 경고한다(숨기지 않음, M6). 자리 배치는 자리로 표시. 명단 = 그 반 배정, 요일 열마다 분리등원으로 거른다.
- **통합뷰에서 배치를 끌면** 강사뷰와 같은 "배치 이동" 명령이 블록 단위로 나간다. 별도 값을 저장하지 않는다.
- **강사뷰의 명단**은 읽기 전용(시트의 강사별 탭에도 명단이 없다). 인원·이름은 마우스 오버/옆 패널. 거기서 배정을 바꾸면 통합뷰와 같은 배정 명령이 나간다.
- **줄(통합뷰 행) 사이로 반을 옮기는 것**은 layout 명령이지 배치 변경이 아니다.

### ③ 자유로운 행·열 편집 vs 일정 의미

| 조작 | 강사뷰 | 통합뷰 | 처리 |
|---|---|---|---|
| 행 삽입·삭제 | 시간 축(10분) | 교시 행 | **일정 격자에선 거절 + 이유**. 교시는 학원설정, 시간은 연속값. 필요하면 메모 시트에서 |
| 행 숨김·높이 | 보기 | 보기 | view 명령 |
| 열 삽입 | 강사 열 추가(강사 고르기) | 반 추가 = 새 반 | 강사 열은 빈 열 표시(view), 새 반은 별도 명령(1차 미지원, 반 관리로 연결) |
| 열 삭제 | 강사 열 | 반 | 숨김(view)과 "그 강사 배치 전부 미배정"(domain, 확인)을 고르게 함. 반 삭제 = 종강 명령(확인) |
| 열 순서 | 강사 순서 | 반 순서 | 개인 보기. 학원설정 `teacherOrder`는 연습실에서 쓰지 않는다(운영 설정 변경이 됨) |
| 채우기(Ctrl+D/R) | 배치 복제? | 학생 복제? | 일정 격자에선 "배치 복제" 명령으로만, 학생 복제는 거절(중복 수강) |
| 서식·수식·메모 | — | — | 일정 격자에선 보기 서식만. 수식·자유 서식은 메모 시트 |

자유도 요구는 **반영되지 않는 메모 시트**(연습안에 함께 저장)로 받는다. 대조표에서 이 항목들은 "일정 격자: 의미 변환/거절, 메모 시트: 지원"으로 두 줄을 적어 분모에서 빠지지 않게 한다.

### ④ 현재 연습 명단 + 타 과목 점유로 도우미

7.3에 적었다. 핵심은 운영 명단이 아니라 **연습안 배정**으로 학생 축을 만들고(acceptance S02), 범위 밖 과목은 **날짜 구간**으로 본다는 것이다.

## 9. 대안 아키텍처 — 하나의 목표 상태 파이프라인

```text
[구글 시트 강사별 + 통합 탭] --파싱·이름 매칭--> DesiredState(mode: full-replacement)
[연습안]                      --컴파일(ID 그대로)--> DesiredState(mode: explicit-delta)
                                   │
                                   ▼
          planner(DesiredState, LiveContext@D)
            → Plan { closes, inserts, roster, attendanceMigration, classUpdates, groups, blocks, issues, hash }
                                   │
                                   ▼
          applier(트랜잭션 골격: 잠금 · 재계산 · hash · 확인 키 · 멱등 · 스냅샷)  ← cancelMasterDate와 호환
                                   │
                                   ▼
          exporter(DesiredState 또는 운영 상태) → 시트 관리 탭 갱신(1단계 이후)
```

- `buildMasterPlan`을 **입력 파싱(시트 → DesiredState)** 과 **계획(DesiredState → Plan)** 으로 나눈다. 모드 차이는 "누락의 의미"(종강 기본 / 무변경)와 "명단 제거"(무시 / 명시 종료)뿐이다.
- 시트 경로는 동작이 바뀌면 안 된다. 기존 픽스처(`import/master/test-fixture.ts`, `plan.test.ts` 347줄)로 **분리 전후 Plan 동일**을 골든 테스트로 잠근다(10-01에 나간 기능이라 회귀 위험이 크다).
- 장기적으로 시트 반영은 "시트로 연습안 만들기 → 검토 → 반영"으로 합칠 수 있다. 연습실 반영이 실사용으로 검증되기 전에는 하지 않는다.

초안과의 차이: 초안은 "기존 일괄 적용 계약을 먼저 분석한다"에서 멈추고 새 반영 경로를 암시한다. 반영기를 둘로 두면 출결 이관·예약 취소·확인 체크 규칙이 두 벌이 되고 한쪽만 고쳐진다([[#112]]의 "같은 판정을 두 액션이 따로 구현하면 한쪽만 고쳐진다"). 대가는 갓 나간 기능을 손대는 위험이고, 골든 테스트로 줄인다.

## 10. 단계 재편과 수용 기준

자동 시험으로 확인할 것과 실브라우저/사람 확인이 필요한 것을 나눴다. 모두 **계획**이며 실행한 시험은 없다.

| 단계 | 내용 | 통과 조건(관찰 가능) |
|---|---|---|
| P0 결정·측정 | 1장 결정 수집, 읽기 전용 건수 확인(분리등원 형식, `timetable_plan_slots` 행 수, 과목 간 방 공유 FK 수), 합성 자료 프로토타입(IME·클립보드·큰 격자) | 결정 로그 기록 · 단축키 대조표 분모 고정 · 검사 규칙표 사용자 확인 |
| P1 시트 탭 보존 | 독립 배포(초안과 동의) | 다른 탭 값·서식·병합·메모·수식·sheetId 불변 · 관리 탭 sheetId 유지 · `drive.files.update` 전체 교체로 폴백 0회(`google-sheets.ts:154-177`) · [[#130]] 왕복 비교 |
| P2 도메인·저장·검사기(화면 없음) | 순수 함수 + 명령/CAS API + pgTAP | 아래 T-ISO, T-XTEN, T-CAS, T-PARITY, T-SIZE |
| P3 영어 강사뷰 편집 | 한 페이지, 핵심 키 | V01 · K01 · K05 · K06 · 실사용 PC 픽업 p95 |
| P4 통합뷰 투영·배정 | 같은 문서 분할 보기 | V02 · C03 · T-OFFGRID · T-SPLIT |
| P5 도우미 | F1~F5 전수, F6 조건부 | S01~S10 · T-EXH |
| P6 반영 | 플래너 분리(골든), 3-way, 적용, 취소 | P01~P07 · T-REBASE · T-DELTA · T-CANCEL · T-123 |
| P7 다중 창·접근성·성능 | 실사용 PC | H03 · H04 · K07 · K12 · 5배 규모 |
| P8 수학 어댑터 | 수학 교시·반 규칙 | 영어 회귀 0 + 수학 별도 시나리오(공통 기능만으로 완료 판정 금지, 초안과 동의) |

구체 시험(acceptance.md에 없는 것 위주):

- **T-ISO**: 안 만들기 + 무작위 명령 200개 + 반영 안 함 → `class_schedules`·`enrollments`·`attendance_records`·`timetable_snapshots`·`tenant_settings`·`audit_logs`(연습실 외 항목) 행 수와 최대 `updated_at`이 시험 전후 동일.
- **T-XTEN**: 다른 지점의 반/학생/강의실 ID를 명령 payload에 넣으면 명령 단계와 반영 트랜잭션 단계 **둘 다** 거절.
- **T-CAS**: 같은 revision에서 두 클라이언트가 같은 배치를 다르게 옮김 → 뒤 명령 거절, 상태는 앞 명령만.
- **T-PARITY**: 같은 합성 입력을 `class-move`·`conflicts.ts`·`masterStudentConflicts`·연습실 검사기에 넣은 비교표. 차이마다 "의도/결함" 표기, 의도 차이는 사용자 확인.
- **T-SIZE**: 통상 5배 합성 안의 저장 p95와 jsonb 크기 기록(목표 미달 시 자식 표 분리).
- **T-OFFGRID**: 강사뷰에서 16:25 시작 배치 → 통합뷰 해당 반 카드에 `교시 밖` 행이 보이고 경고. 숨김 0.
- **T-SPLIT**: 월·목 반에 목요일만 오는 학생 → 블록을 화·금으로 이동 → 미리보기에 "목→금" 재매핑 표시 → 반영 후 수강 요일이 금.
- **T-HOMONYM**: 학교가 다른 동명이인 둘(요일 제한 다름)이 한 반 → 검사 결과에 학생 ID 2개가 각각 나온다.
- **T-EXH**: 교환으로만 풀리는 합성 자료 → "단일 이동 전수 확인: 없음" + 교환 후보 1개 이상. 같은 입력 반복 시 후보 목록·순서 동일.
- **T-REBASE**: 안 생성 후 운영에서 (a) 학생 S 신규 수강, (b) 반 Y 배치 이동. 연습안은 반 Z만 변경 → 미리보기에 Y·S가 "운영 변경 유지"로 보이고, 반영 후 Y 이동·S 수강이 그대로.
- **T-DELTA**: 변경 0인 안 반영 → closes/inserts 0, 종강 0(시트 경로 `plan.ts:463`의 기본 종강과 대조).
- **T-CANCEL**: 미래 D로 반영 → 예약 배지에서 취소 → 배치·수강·출결·근무 블록·줄 배치가 반영 직전과 같음.
- **T-123**: 미래 D 반영 후 D-1에 그 반을 반 수정 폼으로 저장 → D에 수업이 비지 않는가. 지금은 실패가 예상되는 알려진 함정이다. 결과를 그대로 기록한다.
- **T-KEYS**: 연습실 격자 선택 상태에서 Shift+F가 팰릿을 열지 않고 입력을 시작하는가(결정 U6에 따름). Ctrl/Cmd+K·B, F1의 동작이 대조표와 같은가.

CLAUDE.md 규칙도 수용 조건에 넣는다: 파일 200줄·props 10개, B1~B7(특히 B2 1,000행 절단 — 운영 문맥 로딩은 시트 경로처럼 postgres 직결이거나 `fetchAllPaged`), raw 코드 노출 금지, `loading.tsx`, 감사 로그, 기능 스위치.

## 11. 반론 · 질문

### Grok에게

- **G1 엔진**: 나는 스프레드시트 엔진(Univer·Handsontable 등)을 **상태의 주인**으로 두는 데 반대한다. 셀 문자열이 진실이 되면 ID 분리·이력 단일화·두 화면 투영을 동기화 계층으로 다시 만들어야 하고, 초안이 피하려던 "두 저장본 동기화"가 엔진 ↔ 도메인 사이에 생긴다. 대안: 도메인 저장소 + 자체 가상화 격자 + 클립보드 직렬화(TSV/HTML)만 라이브러리. 반대 근거(엔진 이력 비활성화·변경 가로채기 가능 여부, 상용 SaaS 라이선스 범위)를 실험으로 보여 주면 재검토한다.
- **G2 전 단축키 동등성**: 서식·수식·메모·행열 구조 키는 일정 격자에서 의미가 없다. 메모 시트로 흡수하는 내 제안(8장 ③)에 동의하는지, 다른 방법이 있는지.
- **G3 성능 목표**: 운영 드래그 픽업 93ms(결정 로그 2026-09-04)를 어떤 PC에서 쟀는지 모른다. 실사용 PC 기준을 어떻게 고정할지.
- **G4 접근성**: 병합 셀이 많은 격자의 ARIA grid 의미, 스크린리더 안내 단위(배치/블록)를 무엇으로 할지.
- **G5 JEV**: 선호 연결이 결정적 필터 UI보다 실제로 나은지 측정할 방법.

### Codex에게

- **C1** 분리등원 저장 형식 건수 확인(1.8)과 한글 요일을 쓰는 쓰기 경로 조사.
- **C2** `buildMasterPlan` 분리(파싱 / 계획)가 지금 구조로 가능한지, 골든 테스트에 쓸 픽스처 범위.
- **C3** 반영 게이트 함수 선택(`canManageTimetableImport`의 정확한 의미).
- **C4** 영어 반영 금지 규칙(`plan.ts:223`)이 영어 반만 보므로, 수학 쪽 D 이후 예약이 실제로 흔한지.
- **C5** 영어·수학이 같은 강의실(FK)을 쓰는 경우가 있는지(1.3 방 축).
- **C6** advisory lock 키를 시트 반영과 공유할 때 운영 단건 편집(`moveClassSlots`, 반 수정)도 같은 키를 잡아야 하는지.
- **C7** 1차에 연습안 안 반 생성이 필요한지(시트 경로는 생성하지 않는다).
- **C8** [[#123]]에 대한 기존 경고·가드 유무.
- **C9** `acceptance.md` V04 "교시/요일 축 삽입·삭제·재정렬"은 8장 ③ 표대로 거절/변환으로 정리하는 데 동의하는지.

### 사용자에게 받을 결정(코디네이터 경유)

- **U1** `시간표(개발중)`을 연습실로 흡수할지, 연습실 출시 후 폐기할지.
- **U2** 연습실에서 같은 강사·같은 방 겹침(합반 모양)은 경고(시트 규칙)인지 차단(운영 드래그 규칙)인지. 내 기본 제안은 경고.
- **U3** 휴원 학생을 충돌 검사에 넣을지(제안: 경고).
- **U4** 연습안을 강사에게 보이지 않게 하는 것(제안: 관리자만).
- **U5** 연습안에서 반을 새로 만들 수 있어야 하는지(1차 제외 제안).
- **U6** 연습실 격자에 포커스가 있을 때 Shift+F·Ctrl/Cmd+K·Ctrl/Cmd+B를 시트 의미로 돌려줄지.

## 12. 이 검토가 하지 않은 것

- DB 조회, 실데이터 확인, 테스트 실행 없음. 1.4의 동명이인 결함과 1.8의 저장 형식은 코드상 가능성이고 실제 발생은 확인하지 않았다.
- `src/app/(shell)/timetable/page.tsx`(87KB)와 `_components/timetable-board.tsx`(80KB)는 전체를 읽지 않았다. 학생 이동 큐의 세부는 `roster-move.tsx` 머리와 `moveEnrollmentsBatch`만 봤다.
- 구글 시트 공식 단축키 목록을 직접 대조하지 않았다(Grok 영역). 1.7은 aywa 쪽 충돌만 코드로 확인했다.
- 7.1의 후보 크기는 구조에서 나온 추정이다. 실측은 P5에서 한다.
- Grok의 검토는 아직 보지 못했다. 합의를 가정하지 않았다.
