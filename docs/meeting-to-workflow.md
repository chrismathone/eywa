# 회의록 → 업무 연계 (Meeting-to-Workflow) 비전·로드맵

> 상태: **비전 문서**(2026-06-24). 1단계(화자=직원 연결)는 구현됨, 2~4단계는 미구현.
> 작성 계기: 회의록을 남기면 "처리해야 할 일·일정"이 나오는데, 그걸 **자동으로 업무 배정·캘린더 등록·대상자 알림**으로
> 잇고 싶다는 사용자 요청. 지금 당장 전부 구현은 무거워 기반(화자=직원)만 먼저 깔고 나머지를 여기 로드맵으로 남긴다.

## 큰 그림
회의 녹음 → 전사(AssemblyAI) → AI 분석(8섹션, 특히 **액션 아이템**) → **담당자(직원) 연결** → 업무/일정/알림으로 자동 연계.

```
녹음 ─ 전사 ─ AI분석(액션아이템) ─┬─ 담당자 매칭(화자/이름 → staff) ── 업무 배정
                                  ├─ 기한 파싱 ───────────────────── 캘린더 등록
                                  └─ 대상자 ────────────────────── 알림 발송(알림톡/문자)
```

## 1단계 — 화자 = 직원 연결 ✅ (구현됨, 2026-06-24)
- **무엇**: 회의 전사 화자(A/B/C)를 직원관리(`users`)의 실제 직원과 수동 매핑.
- **데이터**: `meeting_minutes.ai_speaker_roles`(표시 라벨 `{A:"김원장"}`) + `meeting_minutes.speaker_staff`(연계 기반 `{A:"<users.id>"}`, 0050a).
- **UI**: 회의 상세 전사 위 "화자 지정" — 화자별 직원 드롭다운(`SearchableSelect`) + 자유입력 폴백. 액션 `updateMeetingSpeakers`.
- **왜 기반인가**: `speaker_staff`가 있으면 "이 회의에 **누가** 참여했고, 액션 아이템의 **담당자가 어느 직원인지**"를
  ID로 안다 → 2~4단계가 이 맵을 조인해 동작.

## 2단계 — 액션 아이템 → 업무 배정 (미구현)
- **무엇**: AI 분석의 `actionItems`(예: "[박부장] 대시보드 UI 6/5까지")를 파싱해 **할 일 레코드**로 만들고 담당자(staff)에 배정.
- **필요한 것**:
  - 신규 테이블 `meeting_tasks`(tenant_id, meeting_id, assignee_user_id, title, due_date, status, source='meeting_ai').
  - 담당자 매칭: 액션 아이템 텍스트의 이름/직책 → `speaker_staff`(1단계) 또는 `users` 이름 매칭으로 `assignee_user_id` 도출.
    (약한 모델 대비 후보정 하네스 — 등록상담 `buildFormPatch` 패턴: grounding·echo·잡음 가드.)
  - 기한 파싱: "6/5까지" → date(순수 함수 + Vitest).
- **UI**: 회의 상세에 "이 회의의 할 일" 섹션(체크/완료) + 직원별 "내 업무" 목록(onescreen/staff 상세 연계).
- **의존성**: 1단계(speaker_staff). 신규 마이그레이션.

## 3단계 — 기한 → 캘린더 등록 (미구현, 캘린더 선행 필요)
- **무엇**: 기한 있는 업무/회의 결정사항을 캘린더에 자동 등록.
- **⚠️ 선행**: aywa에 **캘린더 기능이 아직 없음**(ijw는 events/일정 컬렉션 있었으나 의도적 제외). 캘린더를 먼저 구현해야 함.
- **연계**: `meeting_tasks.due_date` → 캘린더 이벤트(담당자 표시). 또는 외부(Google Calendar — 이미 `googleapis` 의존성 있음).

## 4단계 — 대상자 알림 발송 (미구현, 알림 인프라 일부 존재)
- **무엇**: 업무 배정·기한 임박 시 담당 직원에게 알림(알림톡/문자).
- **기존 인프라**: `src/lib/messaging/`(Solapi 알림톡) — 출석 키오스크에 사용 중. **단 직원 대상 발송 경로·템플릿은 미구현**
  (현재는 학부모 대상 출결 알림만). 직원 연락처는 `users.phone` 존재.
- **필요한 것**: 직원 대상 알림 템플릿 + 발송 트리거(업무 배정 시 `after()` 백그라운드). 카카오 채널·템플릿 승인은 운영 몫.
- **의존성**: 2단계(meeting_tasks) + messaging 직원 발송 경로.

## 현재 가능 / 미구현 요약
| 단계 | 상태 | 의존성 |
|---|---|---|
| 1. 화자=직원 연결 | ✅ 구현 | — |
| 2. 액션아이템 → 업무 배정 | ❌ | `meeting_tasks` 테이블 + 이름 매칭 하네스 |
| 3. 기한 → 캘린더 | ❌ | **캘린더 기능 선행** |
| 4. 대상자 알림 | ❌ | 2단계 + messaging 직원 발송 경로 |

## 설계 원칙(이식 시)
- **단일 진입점**: AI 분석은 `generateJSON`, 화자 데이터는 `speaker_staff`/`ai_speaker_roles` 단일 소스.
- **약한 모델 방어**: 액션아이템 담당자/기한 자동 추출은 반드시 후보정 하네스(grounding·enum·잡음 가드) 통과값만 DB 기입.
- **명시적 트리거 + 백그라운드**: 자동 배정/알림은 사용자 확인 또는 명시 버튼 후 `after()`로(반응속도 우선).
- **비파괴**: 자동 생성 업무·일정은 source 태그로 구분, 수동 입력 보존.
