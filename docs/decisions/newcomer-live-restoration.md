# 신입생 90일 관리 복구

2026-11-11, 운영 에이와의 별도 메뉴와 실제 입력 기능을 복구한다.

- 저장된 메뉴 설정이 `/newcomers`를 `student` 그룹으로 옮겨 `newcomers` 그룹이 비어 있었다. 해당 지점의 목적지 소속만 원래 그룹으로 되돌린다. 사용자 메뉴 편집 기능은 유지한다.
- 운영 페이지의 `sampleFollowupView` 대신 실제 학생·수강·체크·담당자·피드백을 읽는다. 학생 이름은 한 번 표시하고 과목별 관리자·담임·연락·관찰 기록을 구분한다.
- 첫 화면은 학생별 정착 관리이며 담당자별 점검과 전체 완료 체크표를 함께 제공한다. 체크표도 실행 내용·결과·실제 수행일을 기록해야 완료한다. 기존 완료일과 상담 연결은 유지한다.
- 기존 운영 표 `student_onboarding_feedback`, `student_onboarding_subject_assignments`, `student_onboarding_manager_defaults`를 사용한다. 복제 DB에만 있던 학생 공통 배정 표를 조회하지 않는다. 새 DB 구조나 권한 확대는 없다.
- 관리자 기본 배정은 수학 허은진, 영어·EiE 정유진이다. 개별 수동 배정은 우선하고, 다른 과목의 기록을 덮지 않는다.
- 메뉴 쓰기 권한과 실제 담당 반·과목을 서버에서 확인한다. 담당 범위 계정은 자기 학생·과목의 피드백만 조회·작성하고 관리자 배정·콜 완료·관리자 확인을 변경하지 못한다. 읽기 전용 보기는 저장할 수 없다.
- 담당 배정·보고·확인 변경은 기존 DB의 `onboarding_subject_audit`와 `onboarding_feedback_audit` 트리거가 같은 트랜잭션에서 `student_onboarding_followup_events`에 기록한다. 학생·지점·작성자·변경 값과 버전을 함께 남긴다. 복구 전에 해당 트리거와 서비스 전용 접근을 조회해 확인했다.
- 미해결 피드백·후속 조치는 90일 이후에도 남긴다. 학생 통합정보의 `onboardingFeedback` 섹션과 지식그래프도 같은 원본을 읽는다. 조회 실패를 0건이나 정상 상태로 확정하지 않는다.
