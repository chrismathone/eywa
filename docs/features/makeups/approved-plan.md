# AYWA 보강관리 구현계획 — 3자 합의 대상 최종안 v3

작성: 2026-10-05. 기준 HEAD: b7a43db4bfce21d866e7c1b7270dd119ef67e164.
이 파일은 Codex·Claude·Grok가 같은 내용으로 승인할 대상이다. 승인 결과는 별도 합의기록에 남긴다. 현재는 검토안이며, 원문 81개 수용 테스트는 모두 미실행이다. 앱 구현·운영 DB 이관·외부 발송·배포를 수행한 문서가 아니다.

## 1. 목표와 첫 출시

결석/휴강/추가 지도에서 접수한 보강 건을 예약 취소·기한 경과·반 이동 뒤에도 남기는 별도 보강관리 메뉴를 만든다. 원수업의 의무, 예정 회차, 실제 참여·기록, 승인된 인정량을 분리한다. 사용자가 미처리 사유와 다음 담당자를 찾고 다른 날짜로 재예약할 수 있어야 한다.

첫 운영 파일럿은 수학 소수 반부터 시작한다. 영어는 원수업 묶음과 교시별 귀속 계약을 별도 확정·검증한 뒤 확장한다. 첫 파일럿: 수동 접수·미연결 결석 후보·기존 약속 연결, 자격/분량 승인, 담당자·기한, 다른 날짜 분할 예약·변경·취소, 실제 참여 입력, 기존 보고서 연결, 실시 제출·관리자 검토·정정, 미처리 목록·작업큐·대사/복구 상태. 한 회차의 여러 학생과 한 학생의 여러 원결석 배분은 지원한다.

첫 출시에서 켜지 않는 기능: 자동 권리 발급·자동 기한소멸·자동 환불/추가청구, 학부모 전용 일정 API·셀프예약·자동 안내발송, hold/TTL, 휴강 일괄 생성, 동일 학생·동일 과목·동일 날 복수 보강. 원문의 해당 사양·수용 기준은 후속 단계로 보존한다. 기존 일반 수업보고서 발송 기능은 유지하며, 새 보강 안내 자동발송과 구분한다.

## 2. 출결·강사 귀속·보고서의 첫 파일럿 제한

현재 effectiveAttendanceRecords는 학생·반·날짜·slot_start별 최신 행만 유효하게 고르고 taught_by는 한 명이다. ensureMakeupAnchorCell은 그날 반에 출결이 있으면 새 칸을 만들지 않으며 새 칸은 slot_start가 없다. makeup::과목도 하루 한 칸이다. lesson_reports는 coalesce(class_id, subject)를 unit_key로 쓰므로 반 없는 보강 보고서는 학생·과목·날짜당 한 건이다. makeup_class_id는 표시/발송 앵커이며 보고서 유일성 키가 아니다.

따라서 신규 native 파일럿의 서버 계약은 다음과 같다. 제한은 예약 확정과 실제 출결/보고서 저장 때 모두 검사한다.

| 조합 | 첫 파일럿 계약 |
|---|---|
| 서로 다른 날짜로 나눈 보강 | 지원. 날짜별 실제 강사와 실제 분량을 각각 보존 |
| 다른 날짜에 다른 강사가 실시 | 지원. 각 날짜 출결의 taught_by로 귀속 |
| 한 학생·과목·날짜의 보강 참여 1건에 원결석 여러 건 배분 | 지원. 참여/보고서/출결은 1건, 배정·인정은 케이스별 |
| 같은 학생·앵커·날짜의 정규 출결과 새 보강 | 정규와 보강의 실제 귀속 강사가 정확히 같고 보강이 1건일 때 기존 정규 자동값+보강값 규칙으로 지원. 다른 강사/귀속 불명확이면 거절 |
| 같은 학생·과목·날짜의 둘째 보강 | 앵커·시각·강사가 달라도 거절. 다른 날짜 제안 |
| 기존의 반 없는 같은 과목 보고서/보강 세션/출결과 새 native 참여가 충돌 | 무조건 upsert하지 않고 기존 건 연결 또는 검토를 요구 |
| 다른 실제 반의 정규 수업 + 당일 보강 1건 | 다른 출결/보고서 키이고 시간·강사·장소 충돌 및 소유권 검사를 모두 통과할 때만 허용 |
| 교시별 native 복수 실시·같은 일별 칸의 복수 강사 | 시수·귀속·급여·보고서 키 전체를 수정/검증하는 후속 단계에서 지원 |

같은 강사의 정규+보강 지원은 2026-09-14/09-21 기존 결정(합침/분리)을 보존한다. 보강 참여는 별도 이행 근거가 필요하며 정규 출석만으로 인정하지 않는다. 정규 담당 변경/대체로 두 귀속이 달라지면 실제 저장 때 막는 것은 보강 효과(보강값 가산·참여 연결·귀속 변경)와 보강 보고서 저장뿐이다. 정규 출결의 상태와 정규 시수 저장은 어떤 보강 제약이나 공통 출결 명령의 실패로도 거절하거나 되돌리지 않는다(키오스크·좌석·엑셀 포함). 막히거나 실패한 보강 효과는 재조정 큐에 pending/failed로 남기고 같은 effect_key로 다시 반영한다. 이어진 여러 교시는 한 참여의 연속 구간으로 예약할 수 있다. 과목 키가 비거나 서버 검증 불가능하면 신규 native 건을 만들지 않는다. 같은 날 정규+보강의 보강값은 기존 규칙대로 그날 출결 저장 때 정규 자동값과 함께 한 번 기록된다. 이 기록은 보강 실시의 증거가 아니며 인정과 무관하다. 그 참여가 노쇼·부분·미실시로 판정되면 같은 명령이 그 출결 칸에 시수 확인 필요 대사 항목을 만든다. 시수는 자동으로 깎지 않고 권한 있는 출결 정정으로만 바꾸며 이 항목이 열려 있으면 케이스를 종결하지 않는다. 하루 상한은 원결석 사건 수가 아니라 실제 보강 참여 날짜 기준이다. 상한/보고서 충돌 오류는 세션 쓰기·upsert 전에 반환하고 성공으로 위장하지 않는다.

이미 존재하는 legacy 복수 예약·교시별 출결을 삭제/강제 병합하거나 일반 출결에 위 신규 제한을 일괄 적용하지 않는다. 표현이 충돌하는 이관 후보는 일정·기록을 보존한 검토 큐에 둔다. 신규 native 제한을 기존 직접쓰기 API로 우회할 수 없게 학생·과목·날짜 잠금과 mapped 보호를 모든 writer에 적용한다.

실제 출결 명령만 실제 날짜의 session_units/taught_by를 기록한다. 기존 수기 시수 우선·수학 시간→시수 반올림·영어 규약·휴원일 분모를 유지한다. 이미 반영된 효과는 안정된 effect_key로 한 번만 반영한다. 기존값에 매번 더하지 않으며 수기값을 조용히 덮지 않는다. 수기 시수가 이미 있으면 그 값을 그 칸의 최종값으로 두고 보강분을 더하거나 덮어쓰지 않는다. 정규 자동값과 보강값을 더한 예상과 수기값의 차이는 검토 큐에 올리고 참여에 출결 행 id와 예상 보강분을 남긴다. 차이가 있는 동안 그 참여를 자동 인정하지 않는다. 수기값이 없을 때만 기존 수학 산식으로 정규 자동값과 보강값을 한 번 기록한다. 단순 예약/legacy done/실시 검증으로 시수·급여를 추가하지 않는다. 원결석 0시수는 바꾸지 않는다. 매핑 건의 기존 완료 훅은 공통 출결 명령에 위임하고 원래 수학 시수 산식을 재사용한다. 옛 훅과 새 어댑터가 각각 돈을 쓰지 않는다. unmapped 훅은 그대로 두고 mapped 훅에서는 매핑이 확인된 한 참여(관리자 인정 검증과 무관)의 projection만 처리하여 큐에 남은 형제 예약까지 자동 done/시수 가산하지 않는다. 실제 순수 산식·단건/반복/실행순서 골든마스터를 출시 관문으로 둔다.

보고서 저장은 참여 ID→보고서 ID를 명시 연결하고 단위/학생/과목/날짜/원작성자·수정권한·발송잠금을 검증한다. class_id를 보강 앵커로 채워 정규 보고서를 덮지 않으며 makeup_class_id를 unit_key에 넣지 않는다. 현재 onescreen_daily_sessions는 0118a 이후 tenant·updated_by·student·date의 강사별 세션이다(0065a 옛 유니크를 현재 규약으로 쓰지 않는다). 학생·과목·날짜 상한은 세션표만 믿지 않고 참여·보고서·예약을 공통 검사한다. 데스크 대리입력의 actor와 실제 강사/보고서 소유자를 분리한다. 다른 사람이 저장했다고 소유권을 바꾸지 않는다. 이미 발송한 보고서는 기존 회수·수정 규칙을 유지한다.

세 장부를 분리한다: 보강 권리 잔량은 새 원장, 급여 시수/귀속은 실제 출결, 청구 회차는 기준 HEAD에서 0267a가 마지막으로 정의한 session_term_attendance다. confirmed_sessions가 없는 행과 quantity_basis가 attendance_units인 확정 행은 학생×반의 소비 시수 합이고, quantity_basis가 days인 확정 행과 확정된 채 기준이 비어 있는 호환 행만 출석 날짜 수다. 0263a 날짜 수는 현재 함수 전부가 아니다. 같은 날 정규+보강으로 칸 시수를 더하면 attendance_units 소비가 늘어난다. 이 함수를 날짜 수로 되돌리거나 보강 시수·분할·월경계·인정 반전으로 청구액/급여를 자동 변경하지 않는다. 수납 확인에는 원래 건·실시 날짜·quantity_basis·그 기준의 예상 소비를 보여준다. 운영 스키마 적용 여부는 도입 점검 때 확인하며 이번 작업에서 DB를 읽어 확인한 것은 아니다. 산식 변경은 골든마스터를 통과한 별도 결정이다.

## 3. 수량·배정·노쇼·정정·종결

첫 승인 단위는 minutes다. sessions/learning_objectives는 확장 모델로 남기되 파일럿 승인·배정 API에서 거절하고 임의 환산하지 않는다. 승인 전 target_quantity=null, outstanding/reservable도 미정이며 새 확정 예약은 금지한다. 원수업 실분과 120/180분 운영 제안은 구별하고 사람이 정책·분량을 승인한다.

O(outstanding) = target + signed_adjustments - verified_recognitions - approved_waivers.
C(commitment) = 배정 중 아직 인정으로 전환되지 않고 명시 해제되지 않은 유효 점유량.
R(reservable) = O - C. 같은 단위로 계산한다. 음수를 0으로 숨기지 않고 명령을 거절한다.

한 참여에 연결된 배정량/인정량 합계는 그 학생의 회차 분량/실제 인정 가능한 분량을 넘지 않는다. 합반은 학생마다 독립 분량이며 여러 학생의 분을 더해 한 학생의 용량으로 취급하지 않는다. 같은 participation 효과를 서로 다른 명령으로 다시 검증해도 인정은 한 번이다.

- 취소/변경: 기존 시도를 보존하고 아직 미실시인 배정·좌석을 해제한다. O는 유지한다. 변경은 새 revision과 새 회차 관계를 남긴다. 일부 학생 취소는 다른 학생의 회차를 취소하지 않는다.
- 노쇼: 사람이 기록하는 no_show 명령 안에서 자동으로 그 학생의 미검증 배정·좌석을 해제한다. 의무 O는 그대로 남아 재예약할 수 있다. 시간 경과만으로 노쇼/완료를 정하지 않는다. 정책상 권리 제한은 별도 권한·사유가 있는 결정이다.
- 실시/제출: finished/submitted만으로 점유 C를 풀지 않는다. 실제 출결·범위·지도 근거를 연결하고 검토를 기다린다. 보고서 없음은 담당자의 미기록 큐다.
- 부분 검증: 인정량 차감과 점유 전환을 하나의 트랜잭션으로 처리한다. 회차 기록을 마감하는 부분 검증 명령에서 미실시 잔여 배정은 자동 해제한다. 다른 회차 이동은 명시 선택 시 함께 처리한다. 직원이 별도 해제 클릭을 잊어 잔량이 잠기지 않게 한다. 120분 예약 중 60분 인정·60분 해제이면 O=60, C=0, R=60이다.
- 반전: 원 인정 배분을 그대로 한 번 복원하고 원기록을 보존한다. 이미 해제한 옛 좌석/배정을 되살리지 않는다. 급여/실제 출결 정정은 별도의 권한 있는 감사 명령으로 처리하며 취소나 인정 반전에 끼워 넣지 않는다.
- 면제/목표량 감소/거절: 활성 배정과 미검증 실시를 먼저 검사한다. 첫 파일럿은 연쇄 취소를 넣지 않는다. 살아있는 약속이 있으면 목록과 취소 필요를 보여주며 거절한다. 별도 일정 취소를 마친 뒤 다시 요청할 때 같은 잠금에서 재검증한다. 미검증 실제 실시는 먼저 기록/검토를 해결한다. C보다 작게 O를 줄이지 않는다. 같은 분을 adjustment와 waiver에 이중 차감하지 않는다.
- 종결: 살아있는 배정·미검증 실시·미처리 projection이 없고 잔량의 처리 사유가 확정된 경우만 허용한다. 부분 면제는 open, 실시+면제 완료는 completed_with_waiver처럼 통계 사유를 구분한다. on_hold는 종결이 아니며 잔량·약속을 보존하고 신규 배정을 멈춘다. 단순 O=0으로 실제 약속을 남긴 채 닫지 않는다.

기존 자동 이행은 출결 저장 뒤 기존 예약 done/실시 후보를 만드는 단계로 유지한다. 원문 최신 설계의 관리자 검증은 권리 인정만 결정하는 별도 단계다. 강사에게 이미 쓴 내용을 다시 입력하거나 이행 버튼을 누르게 하지 않고 기존 출결·보고서에서 실시 초안을 만들어 관리자 검토큐로 보낸다. 출석/보고서가 범위를 확정하지 못하면 검토 대상으로 남는다.

기존 약속 이관은 imported_existing_commitment로 일정 자체를 보존하며 승인 전 신규 권리를 자동 발급하지 않는다. pending/denied와 별개로 기존 약속 영향 검토가 끝날 때까지 목록에 남는다. 승인 시 목표가 기존 점유보다 작으면 승인/유지/취소 조정을 같은 검토에서 해결한다. 자격 거절만 저장하고 약속을 숨기거나 자동 취소하지 않는다.

## 4. 원사건과 이관의 중복 방지

발생 원인(reason)과 접수 경로(attendance/manual/import)는 별도 필드다. 불변 occurrence UID/키와 source alias 관계를 두고 출결 정정행·예약·이관이 같은 원수업이면 같은 케이스에 연결한다. source_type을 사건 유일성에 넣지 않는다. source_kind+source_id 유일성만으로 사건 중복이 해결됐다고 보지 않는다.

일별 수학: tenant·student·원반·원수업일·day를 초기 사건 단위로 한다. 영어 확장 전에는 실제 원교시/원수업 식별 단위와 하나의 수업에 속한 교시 목록을 대조한다. 서로 독립인 원수업 두 건은 날짜만으로 합치지 않는다. 같은 수업의 2~4교시를 각각 권리로 볼지 묶을지는 정책 확정 전 자동 접수/승인을 끄고 검토 후보로 둔다. 여러 교시를 한 수업으로 묶는 운영정책은 승인된 lesson group에만 적용한다. 교시 미상/그룹 불명확은 검토가 끝나기 전 새 의무를 확정하지 않는다.

휴강은 실제 휴강 event·학생·원수업 범위로, 원결석 없는 추가 지도는 manual event UUID로 식별한다. 같은 사건 수동 재접수는 원 UID/source와 연결해야 한다. 추가 지도에 가짜 absence_date를 넣지 않는다. 추가 지도는 실제 출결을 세울 반과 그 칸의 청구 소비(0267a quantity_basis)/급여 영향을 P0에서 확정하고 수납 확인 항목에 포함한다. 확정 전에는 접수·승인까지만 열고 예약 확정/출결 연결을 서버가 거절한다. 실시강사의 그날 칸 쓰기 허용은 legacy 예약이 아니라 native 참여로 판정한다. 예정결석→실제결석은 같은 사건에 source만 추가한다. 출석 정정은 source_conflict이며 자동 삭제/권리소멸/급여 반전이 아니다.

처음 연결한 원수업·교시 snapshot/UID는 시간표 이동·시각 변경으로 다시 만들지 않는다. 원본 revision/hash·별칭을 남기고 연결을 확실히 못 정하면 conflict 큐로 둔다. 모든 접수/이관 경로는 공통 사건 범위 잠금과 unique를 거쳐 동시에 접수해도 케이스가 1건이다. 원반 비활성/삭제로 케이스를 cascade 삭제하지 않는다.

## 5. 데이터·정책·권한 계약

개발 스키마 산출물: cases, sources/occurrence aliases, immutable policy versions, sessions, participants, allocations, fulfillments, recognitions, adjustments/waivers, commands, events, legacy maps, projection/outbox jobs, reconciliation state. N:M 배분과 추가 지도가 원문에 있어 cases/attempts 7개만으로 이를 압축하지 않는다. 개발 정의는 단계별로 적용하되 파일럿에 필요한 participants/allocations/recognitions/명령/대사 책임을 처음부터 명확히 한다. 학부모 notice/provider outbox/TTL 등 후속 전용 표·워커는 그 기능 단계에서 추가한다. outbox 외부발송은 처음에는 비활성이다. 각 표의 타입·null·상태전이·unique·FK·삭제보관·인덱스·권한을 원 데이터사전에 보완한다.

정책은 effective date·승인자·허용 사유·단위/분량·기한 예외·노쇼·자기검증 조건의 불변 버전이다. 승인 케이스에 버전을 고정하며 정책 변경이 옛 권리를 소급 소멸시키지 않는다. 기술 기본값: 자동 판정/기한소멸 off, 자기검증 off, 관리자 검토. 현재 강사뷰 익월말 쓰기 제한은 정책 승인 없이 완화하지 않는다.

메뉴 key makeups와 읽기/접수/승인/배정/참여입력/실시제출/검증/면제/정정/export 행동 권한을 실제 역할 매트릭스에 등록한다. 원장·관리자 승인/면제/검토, 매니저는 허용된 담당 운영까지(승인/면제 기본 off), 강사는 담당/배정된 업무만, 데스크 업무는 명시 허용된 접수/일정/대리입력만, 그 외 읽기 역할은 기존 권한 설정에 따른 명시 read만, 나머지 기본 none. 담임·owner·실시강사·검토자는 책임 배정이며 새 SystemRole을 만들지 않는다. 메뉴·라우트·모듈 registry·사이드바 그룹·이용 계측·권한 label까지 같이 등록한다. 관계의 판정 기준일은 원사건 읽기/현재 담당 인계/회차 실시일별로 명시하여 결석일 담당과 이번 주 담당을 섞지 않는다.

권한은 실제 로그인 actor·현재 tenant·메뉴 행동·학생/회차 범위를 매 요청 및 command result/집계/export에서 검증한다. 타강사 보기 쓰기 금지, 재배정/퇴사 후 즉시 이전 권한 해제. 실제 강사 자기검증은 actor가 데스크여도 우회되지 않도록 실시자와 검토자를 비교한다. 수납/상담 자료는 배정 학습기록 권한에 포함하지 않는다.

모든 새 표에 tenant_id+RLS를 둔다. 복합 FK/명령 검증으로 다른 tenant·학생·과목 결합을 거절한다. 서버 전용 명령표는 일반 계정 직접 쓰기를 막고 조회도 필요한 범위만 허용한다. RLS/grants를 함께 검증하고 뷰/RPC의 실행 권한·search_path를 고정한다. 일반 지점 UI·도움말·툴팁·오류·DB exception은 AGENTS.md의 내부 역할 문구 금지 규칙을 따른다.

## 6. 쓰기 단일화·충돌·호환 소비처

command UUID + actor + canonical payload hash + expected_revision을 저장한다. 같은 요청 재시도는 같은 결과, 다른 actor/payload 재사용은 충돌/권한 거절이다. stable effect_key는 command UUID와 별개이며 실제 반영의 중복을 막는다. 케이스·참여·배정·학생/강사/장소/정원 resource day를 일관된 순서로 잠근다.

원장·이벤트·감사·projection 필요 상태는 한 DB 트랜잭션으로 기록한다. 원장 커밋 후 projection 실패는 pending/failed repair로 표시하고 완전한 저장으로 위장하지 않는다. repair는 같은 effect_key로 재실행한다. 실패/워터마크 지연을 0건이나 완료로 표시하지 않는다. 실제 참여·보고서 연결/출결 효과가 불일치하면 자동 검증을 막는다.

mapped legacy 생성/변경/취소/완료 후보/삭제는 공통 명령을 통한다. 기존 완료 훅은 mapped 건에서 공통 출결 명령으로 위임하여 동일 산식을 한 번만 쓰며 형제 예약·다른 참여로 효과가 새지 않게 한다. 미실시 취소에 removeMakeupEntry를 연결하지 않는다. mapped 일정만 취소할 때 원결석 칸/사유/진도를 남긴다. 예약이 만든 예정결석 자체를 철회하는 별도 명령은 실제 실시·다른 케이스 근거·수기 기록을 검사하고 사유/감사 후에만 해당 예정 입력을 정정한다. 일반 취소의 삭제 부작용을 복사하지 않는다. 운영 모드는 on / draining / off로 구분한다. draining은 신규 접수/배정을 중지하고 열린 mapped 건 처리·복구·인계만 유지한다. off는 새 메뉴/주소/신규 API/워커를 숨기고 열린 업무 0건·대사 완료 후 전환한다. 이미 저장한 mapping의 무결성/직접삭제 보호는 off에도 남는 데이터 제약이며 신규 기능 활성화가 아니다. unmapped 기존 기능은 그대로 유지한다.

이미 그 학생·과목·날짜에 legacy 예약이 있으면 새 projection을 추가하지 않고 사람의 연결 결정을 받는다. 원결석 있고 legacy 계약으로 표현되는 건만 예약 projection을 만든다. 한 native participant에 케이스 여러 건이면 legacy 예약 1건과 allocation mapping 여러 건을 둔다. absence_date가 없는 추가 지도는 legacy 예약을 조작하지 않고 native 읽기/쓰기 어댑터를 필수 구현한다. 복수 source·불명확 done을 자동 verified로 만들지 않는다.

기존 classrooms.capacity와 실효 강의실(class_schedules.classroom_id ?? classes.classroom_id)을 재사용한다. 원반의 그 요일·교시에서 서버가 실효 강사/장소를 먼저 해결하고 불명확할 때 확인을 요구한다. 신규 예약에서 실제 강사/장소/정원이 불명확하면 확인/설정을 요구하고 안전 검사를 생략하지 않는다. 합반 여러 학생은 한 session의 capacity를 함께 점유한다. 충돌은 (1) 같은 학생이 같은 시각에 서로 다른 수업/보강에 있음, (2) 해당 시각 정규 재원 인원과 보강 참여 인원의 합이 강의실 정원을 넘음, (3) 같은 강사가 같은 시각에 서로 다른 강의실에 배정됨이다. 같은 실제 강의실에서 정규 수업 중 보강 학생을 함께 받는 것은 현행 합류/합반 흐름으로 허용하되 정원과 참여 범위는 검사한다. 별도 운영 정책으로 금지하면 신규 확정에 적용한다. 정규 시간표 writer의 공통 자원 잠금은 현재 없는 새 계약이며 P0에서 대상 경로와 보호 방식을 정한다. 예약 확정과 정규 시간표 writer가 이 공통 계약을 함께 적용한다. 보강 writer만 잠그는 것은 충분하지 않다. 정규 변경이 기존 보강과 충돌하면 그 저장 흐름에서 영향 큐와 재조정 필요 상태를 남긴다. 공통 보호 계약/충돌 큐를 구현·검증하기 전 파일럿을 열지 않는다.

P0 보완 항목: 한 참여의 복수 케이스 중 legacy 대표 결석일 선택과 나머지 원결석의 재접수 방지(linkMakeupToAbsence/noteMakeupAgainstAbsence 포함), 기존 pnpm test:rls와 pgTAP 선택/범위, 메뉴의 4단계 권한과 상세 행동 판정의 결합을 문서화한다.

## 7. 화면과 성능

보강관리 미처리 목록은 기본 활성 상태, 원수업부터 현재 진행·잔량·다음 업무·담당자를 한 행에 보여준다. 기간 상한으로 오래된 건을 숨기지 않는다. 주의 카드의 같은 필터 집계와 목록 총수는 일치하며, 여러 주의 상태가 한 건에 붙을 수 있어 카드 숫자를 단순 합산하지 않는다.

상세는 원근거/변경이력→예정 회차→실제 실시/검토를 연결한다. 담당 교사 작업큐, 관리자 검토큐, 실패·대사 큐를 분리해 다음 작업을 명확히 한다. 출결만/legacy done만으로 완료 표시하지 않는다. 안내 상태와 실제 읽음/확인 상태를 혼동하지 않는다.

모바일·키보드·포커스 복귀·미저장 경고·조회실패·0건·재시도·마지막 성공시각을 검증한다. 카드/표/ECS가 같은 참여·분량·실시 상태를 소비한다. 집계는 RPC/count, 목록은 페이지네이션, 다중 ID는 청크×페이징, cache는 tenant+권한 범위로 분리한다. 신규표 미배포/feature off 때 기존 핫패스에 존재하지 않는 컬럼 조회를 넣지 않는다.

## 9. 출시 차단 조건과 남는 운영 결정

차단: 보강 제약/효과 실패로 정규 출결 저장 거절·유실, 타지점/타학생/배정외 노출, 무흔적 삭제, 사건/인정/시수 중복, 표현 불가 강사 귀속, 보고서 덮어쓰기/소유권 변경, 정원/시간 충돌, 실제 실시 없이 완료, 노쇼 후 재예약 불가, 완료와 활성 약속 공존, 미실시 취소의 출결·진도 삭제, mapped 보호 우회, 실패를 0건/완료로 표시, 자동 정책소멸/환불.

## 10. 원안 대비 조율 근거

Codex 초기 제안의 같은 강사 당일 여러 회차 집계/영어 교시별 확장을 첫 파일럿에서 보류한다. Claude가 제시한 기존 정규+동일 강사 1보강 규약, 세 장부·청구 검토, 자동 이행과 인정 검토의 분리, draining, 현재 세션 스키마를 반영한다. Grok의 더 좁은 출결 지원 범위와 실제 보강 보고서의 과목·날짜 유일성을 함께 반영한 결정이다. 단순 native 상세를 추가해도 기존 급여/보고서 경로가 안전해지는 것은 아니므로, 후속 단계에서 모든 소비처를 바꾸고 기능을 연다.

노쇼 배정 해제와 의무 유지, 원사건과 접수경로 분리, 정책 불변 버전, mapped 쓰기 보호, 추가 소비처, 단계별 관문은 독립 제안의 공통 방향을 구체 명령·검증으로 통합했다. 표 7개/legacy 1:1만의 최소안은 N:M/추가 지도·삭제/이관 보호 사양을 충족하지 않아 채택하지 않는다. 단 후속 전용 outbox/TTL은 단계별로 미루고 실제 파일럿은 수학부터 연다. 정원/장소 충돌은 기존 모델이 있어 표시만으로 축소하지 않는다. 추가 조율: 정규 출결 fail-soft 보존, 같은 날 선반영 시수의 노쇼/부분 대사, 0267a 청구 기준, 수기 시수 차이, 자원 충돌 정의, 추가 지도 돈/앵커 결정 전 확정 차단을 반영했다. 각 모델의 최종 승인은 합의기록에서 같은 파일 hash와 연결해 남긴다.
