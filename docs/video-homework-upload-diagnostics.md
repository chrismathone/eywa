# 영상 업로드 기록과 수동 숙제 배정

## 제출 상태

- `homework_video_link_uploads`의 시작 기록은 제출 완료가 아니다. 파일 전송과 서버 등록이 완료되어 `video_id`가 연결되어야 해당 시도가 제출 완료다.
- 미완료 시도는 학생 상세에서 **미제출 · 전송 시작 후 완료되지 않음**으로 표시한다. 다른 시도로 이미 제출한 숙제와 혼동하지 않도록 각 업로드 시도의 결과임을 안내한다.
- 과거 시도에 오류 기록이 없다면 사용자 중단과 통신 오류를 구분할 수 없다. 원인을 소급해 만들어 넣지 않는다.
- 미완료 시도만으로 같은 파일 재업로드를 차단하지 않는다. 기존 시간당 10회·하루 30회 제한은 유지한다.

## 오류 관측과 알림

공개 제출 화면은 진행량, 재시도, 타임아웃, 연결 만료, 백그라운드 전환, 화면 이탈, 오프라인 및 완료 확인 오류를 기록한다. 기기의 관측값은 제출 완료 상태를 바꾸지 않는다.

기록은 토큰과 업로드 번호의 지점·링크 소유 관계를 검증한 뒤 저장한다. 사건 번호로 중복을 제거하며 업로드당 분당 30건, 최근 사건 16개를 보관한다. 원문 오류, 파일명, Drive 세션 URL, 전체 브라우저 식별자는 받지 않는다. 웹 본문 상한은 4KB다.

최종 오류 또는 완료 전 화면 이탈이 관측되면 지점 관리자 및 해당 반 담임에게 업로드당 한 번 알림을 넣는다. 학생은 오류 설명, 재시도 방법, 확인번호와 진행 기록을 본다. 관리자는 학생 상세의 **숙제 영상 → 영상 업로드 기록**에서 최근 30일·최대 30회 시도를 확인한다.

네트워크 장애 시 기기 큐에 최대 24건을 24시간 보관하고 같은 제출 링크를 다시 열거나 연결이 복구되면 재전송한다. 휴대폰 강제 종료, 기록 저장이 차단된 상태의 브라우저 종료, 다시 열지 않는 오프라인 기기는 마지막 사건을 보내지 못할 수 있다. `sendBeacon`의 반환값만으로 서버 저장을 확정하지 않는다.

## 수동 배정

영상 제출 현황의 학생 이름 아래 **영상 배정**에서 업로드가 완료된 같은 학생의 영상과 실제로 나간 숙제일을 선택하고 사유를 입력한다. 현재 담임은 본인 반으로 배정할 수 있으며, 수업보고서 전체 편집 권한은 지점 안에서 배정할 수 있다. 읽기 전용 보기와 다른 학생·지점은 서버에서 차단한다.

**영상 배정**은 조회 기간에 실제로 나간 숙제와 게시일이 30일 미만 차이인 업로드 완료 영상이 있을 때만 표시한다. 배정 창의 숙제일도 조회 기간으로 제한하며, 선택한 숙제일 기준 앞뒤 29일의 영상만 최신순으로 최대 100개 표시한다(KST 날짜 기준). 숙제일을 바꾸면 영상 선택은 초기화한다. 서버 저장도 같은 날짜 제한을 검증한다. 영상 목록은 게시일·반·연결된 숙제 열로 정렬하며 수집 출처는 표시하지 않는다.

다른 과목 게시물에 잘못 올린 영상도 선택할 수 있다. 영상 내용으로 과목을 추측하지 않는다. 게시물 번호, 원래 반과 숙제일, 재생 화면을 확인한 담당자가 정정한다. 현재 반의 잘못된 영상은 완료 집계에서 제외할 수도 있다. 원래 Drive 파일과 ClassNote 게시물은 이동하지 않는다.

수동 배정은 워커 원본과 별도 표에 저장하고 `homework_video_ledger_videos` 뷰에서 적용한다. 장부, 제출 사이트의 숙제 목록, 학생 영상 탭이 같은 배정을 읽는다. 기존 워커가 원본 경로를 다시 기록해도 배정이 되돌아가지 않는다. 변경 전후·처리자·사유가 같은 트랜잭션에서 기록되며, 동시 수정은 revision 충돌로 거절한다. 직접 체크한 수행 기록은 유지한다. 목표 숙제에 미수행 기록이 있으면 먼저 수행 상태를 수정하도록 안내한다.

## 보고서

영상 과제가 있는 보고서는 ‘오늘 과제’ 아래 **영상 숙제 ~10/9 (금)** 형식으로 수업일 + 7일을 표시한다. 발송일·재발송일로 연장하지 않는다. 학부모 링크, ClassNote 캡처, 인쇄 및 원스크린 미리보기가 같은 표시 함수를 사용한다.

## 적용과 호환

1. `0404a_video_upload_diagnostics.sql`을 적용한다.
2. `0405a_homework_video_assignment.sql`을 적용한다.
3. 검증한 웹 버전을 배포한다. 기존 PC 워커는 교체할 필요가 없다.

두 SQL은 기존 완료·수행 기록을 갱신하거나 파일을 지우지 않는다. 열·표·함수·뷰를 추가한다. 새 스키마가 없으면 기존 영상 조회를 유지하며, 오류 관측 실패는 전송을 중단시키지 않는다. 수동 배정이 생긴 뒤에는 이전 웹 버전으로 되돌리면 배정 뷰를 읽지 못하므로, 롤백 시 배정 조회를 유지하는 웹 버전이 필요하다. 수동 배정을 지우는 자동 롤백은 제공하지 않는다.

검증: 업로드/권한/반 구분/배정/보고서 관련 단위·컴포넌트 테스트, 가상 스키마에서 SQL 실행 후 전체 롤백, 모바일 폭 브라우저에서 보고서·오류·재시도·배정 동작 확인. 실제 학생의 완료 기록이나 파일을 수정하지 않고 검증했다.
