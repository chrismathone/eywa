## 커밋 전 반증 검토와 수정

- 원본 상담 삭제 후 404 때문에 종료할 수 없는 경우: 상담 원본과 독립된 `/consultations/followups/[id]` 처리 화면을 추가했다. 삭제된 원본을 조치 불필요로 닫으면 다음 스캔에서 다시 열지 않는다.
- 직접 RPC 호출·다른 학원 UUID·미담당 강사·읽기 전용 계정·오래된 버전·null 버전·가짜 완료: DB 권한·원본·버전 검사를 pgTAP으로 확인했다. 처리 보고만으로 완료되지 않는다.
- 원본 한 건 수정으로 학원 전체를 다시 스캔하던 비용: 원본 변경 경로는 해당 상담 ID로 제한했다. 전체 스캔은 정기 실행과 관리자의 명시 요청에서 수행한다.
- AI 응답의 잘못된 actions 항목: 앱과 DB에서 검증하며 화면도 안전하게 해석한다. 이름·연락처·상담 메모는 대응안 입력에서 제외했다.
- 외부 생성 응답 유실: Notion POST 전에 의도를 저장하고 사건 UUID로 재조회한다. 불확실한 생성은 자동으로 재생성하지 않는다. 전송 중인 행의 재claim과 오류 복구를 검증했다.
- 알림 저장 실패: 사건·이벤트까지 함께 롤백되어 다음 실행이 한 번만 다시 생성하는 것을 검증했다.
- 과거 캘린더 조회: 기존 최근 30일 동기화와 분리했다. 빈 페이지라도 nextPageToken을 따라가고, 제한·오류는 불완전 조회로 표시한다. 이름만 일치·취소·같은 UID 회차 중복·학년 변경·등록 근거 미확인을 구분한다.
- 다른 개발 변경 보존: 최신 입학 상담 동일인 기능을 통합하고 정규화 함수를 재사용했다. 기존 0376번 변경과 겹치지 않도록 신규 SQL은 0377a–e로 옮겼다.

## 실제 환경에서 남은 확인

- Supabase의 실제 인증 함수·계정 권한으로 적용 전 통합 테스트.
- 앱 Google 서비스 계정이 설정된 상담 캘린더를 읽을 수 있는지 확인. 연결 도구로 조회한 로그인 계정의 권한이 앱에 자동 이전되지는 않는다.
- 별도 노션 알림 DB와 기존 슬랙 계정 매핑·전달 규칙의 시험 발송은 운영 승인 후 지정한 시험 대상으로만 실행.
- 브라우저에서 실제 로그인한 직원별 표시·모바일 배치는 아직 검증하지 않았다. 이번 화면 검사는 가상 데이터를 이용한 React 상호작용 검사다.

범위와 적용 순서는 [management-agent-mvp.md](management-agent-mvp.md)를 따른다. 입학 상담의 반복 문의 후보를 자동으로 업무 배정하는 것은 이번 범위에 포함하지 않는다.
