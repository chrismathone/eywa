### 타입 스케일 v5 + 컨트롤 프리셋 — "가장 작은 창에서 글자를 최대로" (⚠️ 전역 기본값, 2026-09-03)
원장 대규모 디자인 수정 지시(2026-09-03): *"가독성이 레이아웃·여백·장식보다 항상 우선"* · *"12px 이하, 13px 이하 1차 화면 금지"* ·
*"모든 버튼 라벨 안의 텍스트는 위아래 여백이 5%씩 합 10% · 텍스트를 최대한 버튼과 라벨 안에 최대 크기로"* ·
*"다 제각각인 버튼, 라벨 등을 스타일 통일 — 지금 수정도, 앞으로 생성 시에도"*. 관리자뷰 먼저, 강사뷰는 그다음.

**① 타입 스케일 = Tailwind 토큰 한 단계 승격**(`globals.css` `@theme` — 단일 소스):
xs **14** · sm **16** · base **18** · lg **20** · xl **24** · 2xl 28 · 3xl 32 · 4xl 40. 역할: xs = 보조(단위·시각·메타)의 **바닥** /
sm = 본문·목록 1차 라벨·컨트롤 / base = 강조 본문·섹션 제목 / lg·xl = 창·화면 제목 / 2xl~4xl = 1차 핵심 수치.
헬퍼도 같이 올렸다(`.micro`·`.caption`·`.eyebrow` 14 / `.body-sm` 16 / `.body-default` 18 / `.h3` 20).
- 🔴 **화면 파일에 `text-[Npx]`를 적지 말 것** — 토큰만. 2026-09-03 코드모드로 **2,910곳(509파일)** 을 접었고
  가드 [`control-scale.test.ts`](src/components/ui/control-scale.test.ts)가 재발을 막는다(종이 서식만 허용 목록).
- **종이(A4·인쇄)는 제외** — 지면이 고정이라 글자를 올리면 장수가 는다. `@media print`가 전역으로 옛 스케일로
  되돌리고, 화면에 뜨는 A4 미리보기(견적서·지출결의서·이력서·환불요청서·`(print)` 라우트)는 루트에 **`.paper-scale`**.
  🔴 화면 컴포넌트에 "글자가 커서" 이 클래스를 붙이지 말 것.
- **글자색은 한 값 `#121212`(rgb 18,18,18)** — 2026-09-08 원장 *"모든 기본 글자색을 rgb값을 18 18 18 로"* →
  *"모든 회색계열은 18 18 18 로"*(툴바 캡처로 보조 라벨·설명문·placeholder를 지목). 3단 위계(#1d1d1f/#3f3f45/#58585e)는
  **폐기**됐고, 09-03 "배경 위 연한 회색 텍스트 삭제"의 끝점이다. 토큰 이름(`--foreground`·`--text-dim`·`--text-faint`·
  `--muted-foreground`…)은 소비처가 수백 곳이라 **남기고 값만 같게** 뒀다 — 회색을 되살리려면 globals.css 그 줄만 고친다.
  🔴 **글자 얘기다** — 테두리(`--line*`)·배경(`--bg-soft`·`--muted`·`--secondary`)의 회색은 그대로다(같이 바꾸면 화면이
  새까매진다). 🔴 종이 서식(`(print)` 라우트)의 `text-gray-*`도 그대로 — 지면 위계라 화면 규칙 밖이다.
- **예외 하나 = 플레이스홀더는 연한 회색 `--text-placeholder`**(원장 2026-10-16 *"플레이스홀더는 완전히 연하게"*) — 값과
  같은 색이면 예시를 입력된 값으로 읽는다(보호자 성함 '김영희'). 색은 globals.css 레이어 밖 `::placeholder` 한 곳이 정하니
  새 입력칸에 `placeholder:text-*` 클래스를 달 필요 없다. 글자로 그리는 placeholder(`searchable-select` 빈 값 · `select`의
  `data-placeholder`)는 `::placeholder`가 아니니 `text-text-placeholder` 유틸을 단다. 플레이스홀더는 **뭘 적어야 할지 모르는 칸에만** 둔다 — 라벨
  되풀이·예시 이름/번호(`김영희`·`010-0000-0000`)는 금지.
- 라운드: `--radius-xl/2xl/3xl` 전부 **12px**(모서리는 8~12px까지 — 알약형·큰 라운드 남발 금지). `rounded-full`은
  본문 배지에만 남는다(컨트롤엔 금지 — 툴바 캐논 그대로).

**② 컨트롤 프리셋 = 높이를 라벨에서 도출**([`control-scale.ts`](src/components/ui/control-scale.ts) 단일 소스):
`--control-label` **18px**(원장 확정 *"라벨은 18로 하자"*) → `--control-h` = **라벨 ÷ `--control-fill`(0.7)**
= 세로 채움 **70%**(원장 2026-09-08 *"라벨이나 버튼의 글자 채움을 70%로 할거야. 전부 통일"*). sm 16 · lg 22도 **같은 비율**.
- ⚠️ 옛 규칙 "라벨 + 8px"은 **고정 여백**이라 크기마다 채움이 갈렸다(sm 66.7% · 기본 69.2% · lg 73.3%) — 되돌리지 말 것.
  비율을 바꾸려면 `--control-fill` **한 줄만** 고친다(세 벌이 자동으로 따라온다).
공용 `<Button>`·툴바 상수(`toolbar-controls.ts`)·`FaceTabs`·`PeriodNav`·`SearchForm`이 전부 이 변수를 읽는다.
- 🔴 높이를 먼저 정하고 글자를 끼워 맞추지 않는다. 세로 패딩(`py-*`)으로 높이를 만들지 않는다(`leading-none` + 남는 세로 여백 30%).
- ⚠️ **`<input>`은 제 상자 안에서 글자를 자른다** — 검색 입력은 `h-full leading-normal`(상자 높이를 다 쓰고 브라우저가 세로 중앙) —
  `leading-none` 18px 줄에 18px 한글을 넣으면 위아래가 잘린다(원장 캡처 2026-09-03, 가드가 6곳을 잠근다).
- 🔴 **한 줄**(`whitespace-nowrap`) — 안 들어가면 문구를 줄이거나 버튼을 넓힌다. 줄바꿈·폰트 축소 금지.
- 아이콘은 라벨과 같은 크기(`size-[1em]`) — 아이콘 때문에 폰트를 줄이지 않는다. 아이콘만 있는 버튼은 1차 화면 금지.
- ⚠️ **09-01 "툴바 컨트롤 = h-8 고정" 캐논은 이 규칙이 대체했다** — 값을 바꾸려면 `globals.css` `--control-*` 한 곳.
  `toolbar-canon.test.ts`의 높이 가드도 `h-(--control-h)`를 본다.

**③ 탭 접힘 금지 · 창 최소 크기 강제**(원장 2026-09-03 *"창이 줄어들어도 기존 4열 스타일을 유지하는 게 오히려 가독성이
뛰어남 · 하나의 버튼이 가로로 굉장히 길어지는 최악의 가독성은 필요없음 · 앞으로도 탭접힘은 금지"*): 다열 보드(칸반)는 창이
좁아져도 **열을 유지**하고, 그 대신 **창마다 최소 크기**(`ROUTE_WINDOW_SIZE`)보다 작게 줄이지 못하게 막고 경고한다.
06-19 "큰창 그리드 / 작은창 탭" 규약은 **폐기**.
- **구현(2026-09-03)**: ① `windowMinSize(id)` = `ROUTE_WINDOW_SIZE[id] ?? DEFAULT_WINDOW` — **리사이즈 드래그·store.resizeBy가
  이 바닥에서 멈추고**(`resizeRect(…, min)`), 바닥에 닿으면 창 안 `[data-min-hint]`에 "최소 크기 1120×720"이 뜬다.
  ② 그래도 작아지는 길(스냅·타일·작은 모니터)에선 창 본문 맨 위에 [`WindowMinSizeNotice`](src/components/workspace/window-min-size-notice.tsx)

  `enrollment: 1120×720` 등록. 🔴 새 다열 보드에 `(sm|md|lg|xl):grid-cols-` + 탭바를 넣지 말 것(가드 `window-min-size.test.ts`).
  ⚠️ 새 메뉴의 `ROUTE_WINDOW_SIZE`는 이제 **기본 크기이자 최소 크기**다 — 화면을 그 크기에서 설계하고 그 아래는 안 본다.
  ⚠️ 폰(최상위 프레임)엔 창이 없어 안내가 안 뜬다 — 다열 보드는 가로 스크롤로 본다.

**④ 카드 = 헤어라인 링 하나, 그림자 없음**(원장 2026-09-03 *"링·그림자 전부 제거"* → dev에서 본 뒤 *"적당한 테두리는 있어야

수직 간격이 그린다. 🔴 블러 그림자를 다시 넣지 말 것(원장이 뺀 건 "그림자", 남긴 건 "테두리"). 새 카드에 별도 `border`를 겹치지 말 것

**⑤ 컨트롤 라벨 = 18px 확정**(원장 dev에서 16/18/20 비교 뒤 *"라벨은 18로 하자"*) — 비교용 스위치는 지웠다. 값은 globals.css `--control-label` 한 곳.

**⑥ 목록 화면 머리·필터·행 = 지시서 §10·§11 그대로**(원장 *"남은 결정사항은 지시서 그대로"*, 첫 적용 = 학생상담·등록상담 2026-09-03):

  ⚠️ **예외 = 머리글 오른쪽 끝 '화면 최대화'↔'화면 원래대로'**(셸 기능 — 원장 2026-10-01 *"파란색으로 버튼하고"*): 화면의 Primary(새 청구서 등)와 나란히 파랑으로 선다.
  셸이 그리는 것이라 화면의 Primary 개수에 세지 않는다(아래 '페이지 헤더 = 한 줄' 절).
- 필터·정렬·보기 전환은 **칩 줄이 아니라 라벨 하나**: `<FilterSelect axisLabel="기간" className="w-auto" triggerClassName={TOOLBAR_SELECT} />`
  → 트리거 `기간: 최근 7일`(축 접두, 목록 안 해제 항목은 '전체'). 🔴 축 이름을 `allLabel`에 넣지 말 것(해제 항목과 제목이 섞이고 고른 뒤 축이 사라진다 — 리뷰 확정 결함).
  서로 배타인 축(기간 ↔ 특정 달)은 `clearParams`. 툴바에 아이콘 열·아이콘 온리 버튼을 두지 않는다(연·월처럼 글자를 단다).
- 검색은 **[`SearchToggle`](src/components/search-toggle.tsx)**(눌러야 나온다, 검색어가 걸려 있으면 펼친 채) — 상시 SearchForm을 새로 놓지 말 것.

### 모바일 상단 크롬 = 한 줄 + 툴바는 가로 레일 (⚠️ 좁은 화면 기본값, 2026-07-30)
원장 제보 "모바일뷰에서 시간표가 상단 헤더 때문에 거의 보이지 않음". 실측(390×844, 시간표):

브랜드·그룹·메뉴명이 각각 2회(옛 AppHeader + MobileTopNav), 거기에 PageHeader가 제목을 3번째로.
- **상단 바는 하나다**: `MobileTopNav` 한 줄(로고·브랜드·**현재 메뉴명** … 알림·햄버거·계정). 옛
  `AppHeader`는 삭제. 강사·학생 미니셸엔 이 바가 없으므로 **헤더 둘째 줄에 메뉴명을 얹어**
  "제목은 크롬이 갖는다"는 전제를 양쪽 셸에서 참으로 만든다.
- **본문 PageHeader는 접힌다**: 위 `compact-chrome` 변형. 세로가 특히 귀한 격자 화면(시간표·ECS)은
  헤더 블록을 통째로 `compact-chrome:hidden`하고 집계·바로가기를 툴바로 내린다.
- **칩이 많은 툴바는 `.toolbar-rail`**: 좁은 화면에서 여러 줄로 감기는 대신 **가로 한 줄 스크롤**
  (실측 132px 4줄 → 46px 1줄). 컨트롤을 숨기지 않으니 전부 그대로 닿는다. 데스크톱·창은 종전대로 감긴다.
  · ⚠️ `overflow-x: auto`(scroll이면 가짜 스크롤바 — gotcha #87) · ⚠️ 스크롤 컨테이너는 자식을 클리핑하므로
  **레일 안 팝오버·다이얼로그는 반드시 Portal**(base-ui `Popover.Portal`) · 그룹 경계는 구분선이 진다
  (레일에선 감기지 않으니 구분선을 지우지 말 것 — 라벨을 감춘 상태에서 지우면 칩이 한 덩어리로 읽힌다).
- **판정 조건은 한 곳**: `compact-chrome`/`.toolbar-rail`의 미디어쿼리 = 데스크톱(`min-width:1240px and
  any-pointer:fine`)의 여집합(`(max-width: 1239.98px), not all and (any-pointer: fine)` — 같은 글자를 쓰는 곳 전부는 가드 `desktop-breakpoint.test.ts`가 대조한다). 바꾸려면 [use-is-desktop.ts](../src/components/workspace/use-is-desktop.ts)와
  layout의 `desk:`을 **함께** 고칠 것(와이드 터치 태블릿이 갈라지면 크롬만 바뀌고 헤더는 안 접힌다 · 가드 `desktop-breakpoint.test.ts`).
  🔴 '마우스'는 **`any-pointer`**(하나라도) — 주 입력만 보는 `pointer`는 터치스크린 PC를 모바일로 보낸다. 손 기기에서 감추는 버튼은 `no-mouse:`. 브라우저가 '마우스 없음'으로 고정하는 기기는 실제 움직임으로(`data-desk` · desk-detect.ts) — **새 모바일 절을 만들면 선택자마다 `:where(:root:not([data-desk]), :root[data-print])`를 붙일 것**(인쇄 중엔 종전대로 걸리게 · 가드가 다섯 곳을 대조한다).
- ⚠️ **JS로 마커를 붙이지 말 것** — 첫 페인트에 풀 헤더가 떴다가 접히는 CLS가 매 페이지 발생한다. 순수 CSS.
> 한 줄 규칙: 좁은 화면에선 제목을 크롬 한 줄이 갖고 본문 헤더는 접는다. 칩 툴바는 감지 말고 `.toolbar-rail`로 눕혀라.

  `scrollbar-gutter:stable`로 본문과 같은 거터를 갖는다. 머리글 오른쪽 묶음(`data-page-header-actions`)은 관리자 풀셸 본문에서 위 정렬 + 제목 한 줄 높이라,

  포커스는 누른 그 버튼에(같은 요소라 그대로 있다). 메뉴를 옮겨도 최대화는 유지, Esc 안 씀. 떠 있는 모서리 버튼·자리 판정 타이머는 **없앴다**.

### 상세 화면 헤더의 동작 버튼은 **여는 대상을 라벨에 적는다** (⚠️ 새 상세 화면 기본값, 2026-08-07)
원장 제보(모바일 직원 상세) *"수정이 너무 많은데? 어떤 수정인지 라벨 명확화가 필요하겠어"*. 한 화면에
'수정'이 둘이었다 — 헤더의 것은 **계정**(로그인·권한·과목·색), 인적사항 카드의 것은 **이력서**(종이 서식
전체)를 여는데 **글자가 똑같아** 눌러보기 전엔 알 수 없었다. 좁은 화면에선 둘이 나란히 붙어 더 헷갈린다.
- **규칙**: 상세 화면 **헤더**(=페이지 전체 동작처럼 읽히는 자리)의 편집·삭제 버튼은 목적어를 붙인다 —
  `반 수정`·`학생 수정`·`근무 설정`·`이력서 수정`·`상담 수정`·`문서 수정`·`퇴사 처리`. 아이콘+동사만 두지 말 것.
  ⚠️ 목적어는 **실제로 여는 것**이어야 한다 — 직원 상세 헤더는 한때 '계정 수정' 후보였다가 그 폼에
  계정 항목이 없어 폐기됐고(2026-08-07), 2026-08-25에 인적·계약 칸까지 이력서로 옮기면서 `근무 설정`이 됐다.
- **반대로, 목적어를 붙이지 않는다**: **섹션 제목 바로 옆**(같은 줄)의 버튼(`시험 목표` 옆 '추가')과
  **표 행 안**의 수정·삭제, **다이얼로그**의 저장·취소. 문맥이 이미 옆에 있어 중복이 된다.
- 판별 한 줄: **그 버튼만 잘라내 보여줬을 때 무엇에 대한 동작인지 알 수 있나?** 모르면 목적어를 붙인다.
- ⚠️ 링크의 `title`(창 제목)만 구체적이고 **보이는 글자가 "수정"뿐**인 경우가 실제로 많았다 — 툴팁은
  마우스가 있어야 보이므로 **모바일에선 없는 것과 같다**. 보이는 라벨을 고칠 것.
> **한 줄 규칙: 헤더 버튼은 목적어를 붙이고(학생 수정), 제목 옆·행 안·모달 버튼은 짧게 둔다.**

### 종이 서식 표는 좁은 화면에서 **카드로 쌓는다** — `data-label` 규약 (⚠️ 문서형 표 기본값, 2026-08-04)
원장 제보 "모바일에서 내 정보 수정 시 이력서를 적을 수 없다". 이력서(`.resume-sheet`)는 종이 서식을 그대로
재현한 **5열 표**라 375px에서 열이 20~30px로 짜부라져 **"박/소/선"처럼 글자가 세로로 한 자씩** 떨어졌다.
글씨를 줄이거나 가로 스크롤을 붙이는 건 읽기용 대책이고, **입력**은 그래도 불가능하다 → 행을 카드로 편다.
- **CSS만으로**(`globals.css`, 스코프 = 문서 클래스): `table/tbody/tr/th/td`를 `display:block`,
  `thead`는 숨기고, 각 `<td data-label="열 이름">`의 라벨을 `::before content: attr(data-label)`로 값 위에 얹는다.
  행(`tr`)이 카드가 되므로 표 테두리는 행 테두리로 옮긴다(어디까지 한 항목인지가 카드 경계로 보인다).
  `<th>`가 이미 라벨인 표(인적사항·계약사항)는 `data-label`이 필요 없다 — 라벨 위 / 값 아래로 자연히 쌓인다.
- **⚠️ `@media screen and (max-width: 639px)`** — 인쇄(A4)는 종이 서식이어야 하므로 print엔 절대 걸지 않는다.
- **⚠️ 레이어 밖(unlayered)에 둔다** — Tailwind 유틸(`w-36`·`text-center`, `@layer utilities`)을 확실히 덮는다.
  폭·정렬은 유틸과 같은 특이도라 `!important`가 필요하다(`width:auto !important`).
- **⚠️ 입력 글씨는 16px** — iOS Safari는 16px 미만 입력에 포커스하면 페이지를 자동 확대하고 되돌리지 않는다
  (한 칸 채울 때마다 화면이 튄다 = 모바일 작성 불가). 데스크톱·인쇄는 12px 그대로.
- **사진·고정폭 칸은 폭을 캡**(`max-w-[104px]`): 카드가 되면 칸이 화면 폭만큼 넓어져 증명사진만 거대해진다.
- 검증은 **양방향**으로: 규칙을 끈 상태(=≥640px·인쇄)에서 `display:table`·중앙정렬 헤더·12px가 그대로여야 한다.
> 한 줄 규칙: 문서형(종이 서식) 표는 좁은 화면에서 열을 좁히지 말고 행을 카드로 쌓아라 — `data-label` + `@media screen`(인쇄 제외) + 입력 16px.

### 열 머리가 필터인 목록 표는 폰에서 **행 카드 + 필터 칩 줄** — `.stack-rows` 규약 (⚠️ HeaderFilter 표 기본값, 2026-09-13)
원장 제보 *"수업목록 모바일뷰가 형편없는걸"* · *"원생목록도 수업목록과 비슷하네"*. 두 표는 열 머리가 곧 필터(`HeaderFilter`,
팝업이 트리거 아래 absolute)라 `DragScrollArea`로 못 싸고(팝업이 잘린다), `.stack-table`(재고관리)은 `thead`를 통째로 숨겨
폰에서 필터가 사라진다. 그래서 종전엔 `max-md:min-w-[46rem]`로 "폰은 본문이 가로로 스크롤"이었는데, 390px에서 표가
736/896px라 이름 열 뒤가 전부 화면 밖이었다.
- **`.stack-rows`**(`globals.css`, `@media screen and (max-width: 767.98px)`, unlayered, **`main:not(.embed-main)` = 최상위
  프레임만**): `thead`는 남기고 `th`를 block으로 풀어 필터 트리거들이 **칩 줄**(flex-wrap)로 흐른다. `tbody tr`은 flex-wrap
  카드 — 첫 줄 `td[data-cell="lead"]`(앞 알약) · `primary`(이름, `flex:1 1 0%`) · `status`(오른쪽 끝), `tr::after`가 줄바꿈,
  나머지 칸은 둘째 줄에 원래 순서대로, `wide`는 셋째 줄 혼자. 라벨만 있는 머리(`th[data-cell="label"]`)와 빈 칸
  (`td[data-empty="true"]`)은 감춘다. 필터 팝업은 `thead tr`을 기준으로 좌우 0(트리거가 줄 오른쪽 끝이면 화면 밖으로 나가서).
- 소비처: 원생목록(`/students`)·수업목록(`/classes` 표 보기). 새로 쓰려면 ① 래퍼에 `stack-rows` ② 칸에 `data-cell`
  (`lead`/`primary`/`status`/`wide`, 없으면 둘째 줄) ③ 빈 칸에 `data-empty="true"` ④ 라벨만 있는 `th`에 `data-cell="label"`
  ⑤ 표의 `max-md:min-w-*`는 **남긴다** — 창 안(<768 스냅)에선 그 값이 표를 지켜 가로로 스크롤하고, 폰에선 이 CSS가 덮는다.
- ⚠️ **경계가 `.stack-table`(639)과 다르다** — 768~1023(태블릿 세로)은 `max-md:min-w-*`가 안 걸리는 구간이라 표가 100%로
  들어간다(열 머리가 빠듯한 건 이 패치 전과 같다). 🔴 플로팅 창 안에서는 접지 않는다(v5 ④ "창이 좁아져도 열 유지" +
  `WindowMinSizeNotice`의 "가로 스크롤로" 안내와 일치 — min-w를 남기는 이유).
- **화면 파일에서 폰 전용 배치를 유틸로 적을 땐 `max-md:`가 아니라 `phone:`**(globals.css `@custom-variant phone` = `screen` ∧ <768px
  ∧ `.embed-main` 밖). 원생상담 창은 기본 크기가 760px이라 `max-md:`로 걸면 데스크톱 창이 폰 카드로 바뀐다(적대 리뷰 2026-09-13
  실측). 소비처: 원생상담 목록 행·제목 줄·필터 묶음, ECS 주간 시트(패널 위로 쌓기·툴바 감김). ⚠️ `main` 안 콘텐츠용 — 포털(다이얼로그·
  드롭다운)은 `.embed-main` 자손이 아니라 창 안에서도 켜진다. ⚠️ 767.98px(px) 경계는 root 16px일 때 `max-md`(48rem)와 같다.
- ⚠️ 폰에선 열 이름 글자가 사라지므로 값이 자기 설명적이어야 한다(알약·전화번호·`N명`). 대시(`—`)만 남는 빈 칸은 반드시
  `data-empty`로 감출 것 — 무엇의 빈칸인지 알 수 없다.
> 한 줄 규칙: 열 머리가 필터인 목록 표는 폰에서 `.stack-rows`로 접어라(필터는 칩 줄, 행은 두 줄 카드) — 창 안·태블릿·데스크톱은 표 그대로.

### 의미색 캐논 — "같은 뜻이면 어느 화면에서든 같은 색" (⚠️ 상태 표시 기본값, 2026-08-18)

색을 **장식이 아니라 어휘**로 쓴다. 화면마다 예쁜 색을 고르는 게 아니라 **뜻(tone)** 을 고르면 색은
[`src/lib/design/semantic-color.ts`](../src/lib/design/semantic-color.ts)가 정한다. 운영실에서 초록으로 본
"정상"이 학생목록·출석부·수납·결재에서도 초록이라, 사용자가 색만 보고 상태를 읽게 된다.

| tone | 색 | 뜻 | 예 |
|---|---|---|---|
| `positive` | green | 정상·완료·성공 | 출석 · 완납 · 승인 완료 · 재원 · 발송 완료 |
| `caution` | amber | 주의·**내가 할 일**·미완 | 지각 · 부분납 · 보고서 작성중 · 휴원 |
| `critical` | danger | 실패·위험 | 결석 · 미납/연체 · 반려 · 발송 실패 · **마감 있는 미작성** · 이탈 위험 |
| `info` | blue | 진행중·정보(**남이 하는 중**) | 수업 진행 중 · 결재 **진행중** · 상담 진행 · 예비/문의 · 조퇴 |
| `special` | purple | 예외·대체 | 보강 · 대결/전결 · 반 이동(전출) |
| `inert` | neutral | 종료·비활성 | 퇴원 · 취소 · 해당 없음 |
| `brand` | primary | (뜻이 아니라 자리) 현재 위치·기본 액션 | 활성 메뉴 · 주 버튼 |

🔑 이 배정은 새로 지어낸 게 아니라 **이미 잘 쓰던 화면에서 뽑아 굳힌 것**이다 — 출석부 팔레트
(`--att-*`: 출석 민트·지각 주황·결석 빨강·조퇴 파랑·보강 보라)와 ECS 상태 톤
([`status-tone.ts`](../src/features/class-sheets/lib/status-tone.ts): done=green·warn=amber·absent=danger)이
이미 이 조합이었다. 나머지 화면을 여기에 맞추는 것이 캐논의 일이다.
⚠️ 출석부 `--att-*`는 31칸 격자 전용 **쨍한 원색**이라 값이 다르다(같은 뜻·다른 채도) — 다른 화면에
`--att-*`를 쓰지 말고 tone(-soft 틴트)을 쓸 것.

**축이 둘이고, 섞으면 안 된다.**
- **의미(tone)** = 위 표. 앱 전역 공통, 코드 고정.
- **과목(subject)** = 학원설정 `operations.subjects[].color`. 학원마다 다르고 원장이 고른다
  ([`buildSubjectMaps`](../src/features/owner/subjects.ts)). **여기서 과목 색을 정하지 말 것.**

두 축이 같은 팔레트를 공유하므로 나란히 놓이면 겹쳐 보일 수 있다 — 실제로 학생목록에서 '재원'(구 primary
네이비)과 '수학'(blue)이 색상각 4.8° 차이라 구분이 안 됐다. 그래서 **재원을 positive(그린)로 옮겼고**,
앞으로도 상태와 과목이 한 행에 서면 **상태는 채운 배지, 과목은 옅은 배지**로 형태를 갈라 둔다.

> **한 줄 규칙: 배지·칩·강조 색을 고를 때 `PillColor`를 직접 고르지 말고 tone을 고른다. 화면 파일에
> `STATUS_META`(라벨+색 맵)를 새로 만들지 말 것 — 그 축의 단일 소스에 추가한다.**

### 메모·사유 툴팁 = **카드**(`data-tip`) (2026-09-15, ⚠️ 메모를 띄우는 모든 자리 기본값)

원장 *"왠만하면 모든 곳의 메모는 시간표에서 사진올린것처럼 생기면 좋겠네. 그냥 메모처럼하니까 너무 보기가 불편하다랄까?"* —
브라우저 기본 툴팁(`title`)의 회색 메모 상자를 **시간표 학생 hover 카드와 같은 카드**로 통일했다.

- **쓰는 법**: 칸에 `{...tipProps(메모)}` 또는 `{...tipProps({ title, meta, rows, lines })}`([`tip.ts`](../src/components/hover-tip/tip.ts)).
  그리는 것은 루트 프로바이더에 한 장 서 있는 [`HoverTipLayer`](../src/components/hover-tip/hover-tip-layer.tsx)다(창=iframe이라 창마다 한 장).
- 🔑 **왜 속성인가**: 출석부 격자는 칸이 수천 개라 칸마다 카드 컴포넌트(상태·이벤트·포털)를 달면 그게 곧 반응속도 손실이다.
  칸은 문자열 한 줄만 들고, 레이어가 위임으로 그린다.
- 🔴 **같은 값에 `title`을 함께 달지 말 것** — 카드 옆에 회색 상자가 겹쳐 뜬다(고치려던 그 모양이다).
- 🔴 **이미 hover 카드를 띄우는 줄 안에는 `data-tip`을 넣지 말 것**(시간표 학생 줄) — 카드가 둘이 된다.
  그 자리는 카드에 줄을 더한다(`StudentInfoCard`의 '자리' 줄이 그렇게 옮겨 왔다).
- ⚠️ **메모가 아닌 `title`은 그대로 둔다** — 잘린 **같은 글자**를 펼쳐 보이는 용도(이름·열 제목·창 제목)는 카드로 바꾸지 않는다.
- 🔴 **보이는 글자가 없으면 `role` + `aria-label`을 함께 준다** — 카드는 `data-*`라 화면 낭독이 못 읽고, **역할 없는
  `<span>`(generic)엔 이름을 붙여도 무시된다**(재리뷰 2026-09-15에서 실제로 걸렸다). 표식은 `role="img"`,
  곁들이는 설명은 `role="note"`. ⚠️ 잘린 글자(`truncate`·`line-clamp`)는 **DOM에 원문이 그대로** 있어 대상이 아니다
  (눈에 안 보일 뿐 낭독은 전문을 읽는다).
- ⚠️ 이름·날짜만 있는 카드는 **안 뜬다**(화면에 이미 보이는 것을 되풀이할 뿐) · 터치엔 hover가 없다(폰에서 꼭 읽혀야 하는 사실은 글자로).
- **넓은 카드** = `{ …, wide: true }`(2026-10-23) — 근거 줄이 여러 개라 기본 카드(240×320)에선 잘리는 카드만(수업보고서 평점 근거). 400×520이고 창이 작으면 창에 맞춘다. 카드는 포인터를 통과시켜 안에서 스크롤할 수 없으니, 길어질 카드는 처음부터 이걸 켤 것 · 짧은 메모엔 켜지 않는다.
- 가드: [`tip-wiring.test.ts`](../src/components/hover-tip/tip-wiring.test.ts)(옮긴 표면 목록 · `title` 되살아남 금지 · 레이어 마운트 · 껍데기 단일 소스).

> **한 줄 규칙: 메모·사유는 `tipProps`로 카드를 띄운다. 같은 값에 `title`을 함께 달지 말고, 카드를 이미 띄우는 줄엔 카드에 줄을 더한다.**

⚠️ **이미 실패한 방식**(전부 2026-08-18 실측):

### 빈 상태 일러스트 에셋 계약 (⚠️ 배경 포함 이미지 금지)

빈 상태 일러스트는 카드·페이지·워크스페이스 등 서로 다른 표면 위에서 재사용되므로 **이미지 파일에 배경색이나
바닥면을 포함하면 안 된다.** 배경색을 화면 토큰에 맞추거나 CSS 마스크로 경계를 숨기는 방식도 금지한다.

- 단일 진입점: [`EmptyState`](../src/components/empty-state.tsx)와
  [`EMPTY_STATE_IMAGES`](../src/components/empty-state-assets.ts). 화면에서 `/empty-states/...` 경로를 직접 쓰지 않는다.
- 파일 위치·이름: `public/empty-states/empty-<key>-alpha.png`.
- 규격: **640×640 RGBA PNG**, 사방 16px는 완전 투명(`alpha=0`), 전체 투명 픽셀 비율 50~90%.
- 에셋에는 배경색·그라데이션·비네트·바닥면·반사·접촉 그림자·투사 그림자를 굽지 않는다.
- 접지 그림자는 `EmptyState`의 공통 CSS `drop-shadow`만 사용한다. 에셋마다 그림자 방향·농도를 따로 만들지 않는다.
- 스타일: 무광 clay 3D, sage/cream + 소량 copper, 중앙 배치, 넉넉한 여백. 텍스트·글자·숫자·로고·워터마크 금지.
- 제작 시 sage 계열 오브젝트와 충돌하지 않는 평면 `#FF00FF` 키 배경으로 생성한 뒤 알파로 제거한다. 키 색은
  오브젝트에 사용하지 않고, 제거 후 마젠타 잔여 픽셀이 없어야 한다.
- 새 에셋 추가·교체 후 `pnpm test:assets`를 실행한다. 이 테스트는 파일 목록, 크기, 알파 채널, 투명 안전영역,
  투명 픽셀 비율, 키 색 잔여를 검사한다. 일반 `pnpm test`에도 포함된다.

검수 순서: 원본 1개 제작 → 흰색 `--card`, 아이보리 `--background`, `--bg-soft` 위 160px 합성 확인 → 나머지 제작
→ `pnpm test:assets` → 실제 빈 화면 확인. 불일치가 보이면 카드 배경 토큰을 바꾸지 말고 에셋 알파를 수정한다.

### 라운드 — 역할별 캐논 (⚠️ 새 요소 기본값, 2026-07-20 전수 통일)
스케일(`globals.css`, 2026-07-19 소프트 톤 복원): `xs 4 · sm 6 · md 8 · lg 10 · xl 14 · 2xl 18 · 3xl 22 · full 999`.
~~구 표(카드 6px·pill 4px 사각 batch)는 폐기~~ — 그 각진 스케일이 "코딩 틱함"의 진원지였다.

**라운드는 크기가 아니라 역할로 정한다.** 같은 툴바 안에서 알약 칩과 각진 버튼이 섞이는 게 부조화의 원인이었다.

| 역할 | 값 | 예 |
|---|---|---|
| 페이지 1차 표면(카드·패널) | `rounded-2xl` | 목록 카드, BigStat, 빈 상태 컨테이너 (⚠️ **툴바는 제외** — 아래 툴바 절) |
| 초대형 구획(히어로·사진) | `rounded-3xl` | PhotoCard 히어로 |
| **본문의 선택/상태 칩·배지** | `rounded-full` | Pill·상태 배지(문법 ⑦ 알약). ⚠️ **툴바 안의 컨트롤은 아님** — 아래 툴바 절 |
| 버튼·인풋(공용 `<Button>`/`<Input>`) | `rounded-lg` (기본 승계) | **className으로 덧씌우지 말 것** |
| 수제 소형 액션 버튼 | `rounded-lg` | 엑셀·시트 반영 등 border+text-xs 버튼 |
| 드롭다운/팝오버 패널 · 메뉴 아이템 | `rounded-lg` · `rounded-md` | ui/dropdown-menu 기본(불변) |
| 모달 패널 | `rounded-xl` | 공용 Dialog와 동일 |
| 스켈레톤 | 대응 실표면과 **동일** | loading.tsx는 실제 카드 라운드를 따라감 — 아래 '스켈레톤 캐논' |

- **칩 vs 버튼 판별**: 눌러서 *상태가 남으면* 칩(`full`), *동작만 하면* 버튼(`lg`).

스켈레톤이 실표면과 다른 모양이면 데이터가 도착하는 순간 화면이 튀어 **없느니만 못하다**. 그런데 치수를 px로 적어 두면

  페이지 루트에 이 마커를 달면 **창(임베드)에서만** `main.embed-main:has(.edge-to-edge)`가 좌우·아래 패딩 0 +
  `scrollbar-gutter` 해제를 준다(위 `pt-2`는 남는다). 풀셸·미니셸은 그대로. 🔴 `loading.tsx` 루트도 **같은

### 스크롤바 — 전역 하네스 (⚠️ 무조건 적용)
**모든 스크롤 영역은 디자인 톤 스크롤바로 통일한다. 옵트인 아님.** `globals.css`의 전역 규칙
(`*`, `*::-webkit-scrollbar*`)이 페이지·패널·드롭다운 팝업·textarea 등 **모든 스크롤 컨테이너에
자동 적용** — 6px, line 컬러(`rgba(13,17,16,0.18)`, hover 0.32) thumb, 투명 track, 999px radius.
- 새 스크롤 영역을 만들 때 **별도 클래스가 필요 없다** (이미 전역). `.scrollbar-thin`은 기존 사용처
  호환용 별칭으로만 남김.
- ⚠️ **네이티브 `<select>`의 옵션 팝업 스크롤바는 OS가 그려 CSS가 닿지 않는다.** 그래서 드롭다운은
  아래 "드롭다운/셀렉트 규약"대로 [`SearchableSelect`](src/components/ui/searchable-select.tsx)로 통일한다
  (styleable 팝오버 `div` → 전역 스크롤바 자동 적용).
- 회색 기본 스크롤바가 한 군데라도 보이면 위반. 새 화면 추가 시 점검.

### 버튼 크기 — 헤더 액션은 공용 `<Button>` 기본 크기로 통일 (⚠️ 새 버튼 기본값, 2026-06-24)
한 줄(페이지/상세 헤더의 액션 클러스터, 다이얼로그 푸터)에 들어가는 액션 버튼은 **크기가 제각각이면 안 된다**.
증상: 1차 액션은 공용 `<Button>`(기본 `h-8 text-sm`)인데 옆의 2차 액션("통계 보기"·"엑셀 내보내기"·"월별 급여"
등)은 손으로 깎은 `inline-flex … border px-2.5 py-1 text-xs` 작은 링크라 **나란히 두면 높이·글자크기가 따로 논다**
(사용자 제보: 학생상담 헤더 "통계 보기"(작음) ↔ "상담 추가"(큼)).

**규칙(불변): 같은 액션 행의 모든 버튼은 공용 [`Button`](src/components/ui/button.tsx)을 쓰고 크기는 기본값
(`size="default"` = `h-8 text-sm`)으로 통일한다 — "오른쪽(1차) 버튼 크기"가 표준이다.**
- **1차 액션** = `<Button>`(기본 variant=default). **2차 액션** = `<Button variant="outline">`(또는 ghost/secondary).
  variant(색)만 다르고 **size는 전부 같다**.
- **링크/네비/다운로드 버튼**도 손으로 깎지 말고 `render`로 감싼다:
  `<Button variant="outline" render={<WindowLink href=… title=… />}>` / `render={<a href=… />}`(엑셀 export). [[#2]](base-ui는 `asChild` 아닌 `render`)
- **size 변형 금지(헤더/푸터 액션)**: `size="sm"`·`text-xs`·손깎은 `px-2.5 py-1` 버튼을 1차 `<Button>` 옆에 두지 말 것
  (`CreateInvoiceTrigger`의 `size="sm"`·outline 손깎기도 기본 크기로 정규화함). 아이콘은 `className="size-4"`(또는 미지정→Button이 size-4).
- **이 규칙 밖(작은 크기 허용)**: ① **표/리스트 행 안의 인라인 액션**(행 높이에 맞춤) ② **transient 인라인 확인 플로우**
  (삭제 "예/취소" 같은 순간 폼) ③ Pill·배지처럼 버튼이 아닌 칩. 헤더 액션 클러스터에는 적용, 이 셋엔 미적용.
- 전수 적용(2026-06-24): 학생상담·학생목록(엑셀 내보내기/가져오기)·직원(월별급여/휴가관리)·수납(엑셀 내보내기/청구서 생성)·
  성적 상세(수정/삭제) 헤더를 전부 `Button` 기본 크기로 통일.

> **한 줄 규칙: 한 액션 행의 버튼은 공용 `<Button>` 기본 크기로 통일(색=variant만 차이). 손깎은 text-xs 링크·`size="sm"`를 1차 버튼 옆에 두지 말 것.**

### 저장 버튼 = 창 하단 고정 sticky 바 + 미저장 닫기 가드 (⚠️ 창 데이터입력 폼 기본값, 2026-07-03)
창(iframe)으로 열리는 **데이터 입력 폼**(생성/수정)은 저장 버튼이 폼 맨 아래에 있어 긴 폼일수록 스크롤해야 눌렀다(사용자
제보: "위치가 다 제각각"). **모든 창 폼의 저장 액션은 우하단에 sticky로 고정**해 스크롤 위치와 무관하게 항상 보이고,
같은 위치라 창마다 헷갈리지 않는다. + **작성 중(dirty)인 폼의 창을 닫으면(X/Esc) "저장하지 않고 닫을까요?" 확인**.
- **저장 바** = [`<FormActionBar>`](src/components/forms/form-action-bar.tsx)(sticky bottom-0 z-20, 우측정렬,
  **완전 불투명 `bg-background`** + 상단 헤어라인·미세 그림자). 폼의 제출 버튼(들)을 이 바로 감싼다. 손깎은 `justify-end border-t pt-N` footer는 이걸로 교체. 1·2차 버튼은 위 "버튼 크기" 규칙대로 바 안에.
  · ⚠️ **반투명+backdrop-blur 금지**(2026-07-10 사용자 제보): 스크롤되는 본문(칩·카드)이 바 뒤로 그대로 비쳐 지저분 — 초기 구현이 `bg-background/70 blur`였다가 불투명으로 교정.
  · ⚠️ **바 밀착 = `.sticky-save-bar` 마커 + `main:has()` 자동 패딩 제거**(2026-08-17 갱신, [[#110]]): `sticky bottom-0`은 스크롤포트의 **콘텐츠 박스 하단**에 붙는다 — shell `main`이 `pb`를 가지면 바가 그만큼 떠 보이고, 그 틈으로 본문이 지나간다("저장 아래로 배경이 지나감"). 2026-07-10엔 main 3곳의 pb를 아예 제거했으나 **2026-08-14 "스크롤 끝 빠듯" 여백(`pb-8 lg:pb-10`) 복원으로 깨져** 지금은 바 루트의 `sticky-save-bar` 클래스를 globals.css의 unlayered `main:has(.sticky-save-bar) { padding-bottom: 0 }`가 감지해 **저장 바 있는 화면만** pb를 0으로 만든다(바 없는 화면은 끝 여백 유지). `<FormActionBar>`는 자동 부착 — **수제 하단 고정 저장 바를 만들면 반드시 이 클래스를 붙일 것**(안 붙이면 main pb 위에 떠서 아래로 본문이 샌다).
  · ⚠️ **하지 말 것(실패한 시도)**: 음수 margin-bottom은 sticky 클램프를 못 옮긴다. 바 밑을 `after:` 불투명 밴드로 덮는 것은 절대배치라도 **스크롤 오버플로를 늘려 오히려 맨아래 점프를 유발**한다. 정답은 오직 main의 하단 패딩 제거(위 마커 경유).
- **미저장 닫기 가드** = [`useUnsavedGuard({ formRef, enabled? })`](src/components/workspace/use-unsaved-guard.ts) → `{ markSaved }`.
  · **전달 = iframe→부모 postMessage**(`eywa-window-dirty`) — winId를 경로로 추측하지 않고 부모([workspace-canvas](src/components/workspace/workspace-canvas.tsx))가
    `event.source`(=이 iframe의 contentWindow)를 iframeRegistry와 대조해 **정확한 창**을 찾는다(드릴인·복제창·새 창 안전). [[#69]]
  · dirty는 `serializeForm(formRef)` ↔ 마운트 baseline 비교. **저장 성공 확정 후 `markSaved()`** 호출(baseline 재스냅샷+dirty 해제 → 저장하고 닫아도 거짓 확인 안 뜸).
  · 부모 [floating-window](src/components/workspace/floating-window.tsx) `requestClose`가 `dirty[win.id]`면 확인 오버레이(계속 작성/저장 안 함, 닫기). Esc가 확인을 되돌린다.
- **적용 5단계**(레퍼런스 [student-form](<src/app/(shell)/students/_components/student-form.tsx>)): ① `const formRef=useRef` + `<form ref={formRef}>`(동시편집 가드가 이미 쓰면 재사용)
  ② `const {markSaved}=useUnsavedGuard({formRef})` ③ 제출 버튼을 `<FormActionBar>`로 감쌈 ④ **저장 성공(nonce/ok) effect에서 `markSaved()`** ⑤ effect deps에 markSaved.
- **적용 현황(2026-07-03)**: ✅ student·staff·class·consultation(학생상담)·enrollment 등록상담(full-form)·owner section-form + resume-sheet(편집 시 하단 바, 뷰 툴바는 인쇄/삭제만).
  ⏭️ 제외(구조가 다름) = 시험 batch-score-grid(상세 페이지 하위 섹션)·수강료 계산기(다패널 견적, 컨트롤드 state)·exam-form-dialog(모달, 자체 취소/저장).
- **⚠️⚠️ 컨트롤드 입력이 hidden input에 값을 미러하는 폼**(학원설정 section-form의 `data` jsonb·등록상담 과목점수 `subjectDetails`)은
  **React 커밋이 네이티브 `input` 리스너보다 늦어** 즉시 `serializeForm`하면 stale을 읽어 dirty를 놓친다 → 가드가 **`setTimeout(0)`으로 미뤄 커밋 후 비교**(적대리뷰 HIGH). 새 컨트롤드-미러 폼도 이 경로로 자동 커버 + **값을 hidden input에 반드시 미러**해야 스냅샷이 본다.
- **알려진 한계(수용, 데이터손실 경고는 유지)**: `배경으로 보내기`·창→배경 드래그·창 6개 초과 축출은 앱 확인을 안 거쳐 dirty 폼을 파괴할 수 있으나 드물고 의도적 제스처
  라 문서화만(기존 동시편집 가드도 미커버). 창 자체 하드리로드(⟳)·브라우저 back(전체 네비)은 iframe 네이티브 `beforeunload`가 뜬다(데이터손실 경고라 무해). 진짜 실시간 충돌방지(낙관적 동시성)는 별개.

> **한 줄 규칙: 창 폼의 저장은 `<FormActionBar>`(우하단 sticky)로, 미저장 닫기는 `useUnsavedGuard({formRef})`+저장성공시 `markSaved()`. 컨트롤드 값은 hidden input에 미러(가드가 setTimeout(0)로 커밋 후 읽음).**

### 줄바꿈 / 워드브레이크 — 한글 어절 단위 (⚠️ 전역, 좁은 창에서 특히 중요)
**텍스트가 "발표·세미 / 나" 식으로 단어 한가운데서 깨지지 않게 한다.** 플로팅 창은 폭이 좁아
(기본 480px) 이런 "얼토당토 않은 곳에서의 줄바꿈"이 흉한 뷰를 만든다. 전역 규칙이 기본을 잡는다:
- **`globals.css`의 `body { word-break: keep-all; overflow-wrap: anywhere; }`** — `keep-all`은 CJK를
  글자 사이에서 끊지 않고 **공백(어절) 경계에서만** 줄바꿈 → 한글이 자연스럽게 단어 단위로 접힌다.
  `overflow-wrap: anywhere`는 URL·긴 영문 같은 끊을 곳 없는 토큰이 넘칠 때만 강제로 끊는다. **새 화면은
  별도 클래스 없이 이미 이 동작**(옵트인 아님).
- **절대 쪼개지면 안 되는 인라인 조각**(라벨·배지·Pill·버튼 텍스트·날짜/시각·"N개 발화" 같은 메타)은
  **`whitespace-nowrap`**(flex 안이면 `shrink-0` 동반)을 붙인다. `keep-all`도 공백은 끊으므로 "AI 분석"
  처럼 공백 든 짧은 라벨은 nowrap 없으면 "AI / 분석"으로 깨진다(회의 상세 AI 헤더가 이 케이스였음).
- **좁은 창 헤더에 라벨 + 긴 부제 + 메타를 한 줄에 욱여넣지 말 것.** 긴 부제(예: 회의 유형)는 **자기
  full-width 줄로 내려** keep-all로 깔끔히 접히게 한다(라벨/메타는 윗줄에 nowrap으로 고정).
- **긴 본문에는 `whitespace-nowrap` 금지**(가로 오버플로 유발) — keep-all에 맡긴다. `truncate`/`line-clamp`는

단일 소스 = [`name-fit.ts`](../src/features/attendance/seat/name-fit.ts).
- **기본값 = [`fluidNameFontSize(name, { minPx, maxPx })`](../src/features/attendance/seat/name-fit.ts)**: 이름을 감싸는
  칸에 `@container`, 이름 `<span>`에 `style.fontSize = clamp(하한, N cqw, 24px)` — N = 채움 비율 ÷ 이름 표시 폭(em).
  세 글자 이름은 33.3cqw, `김하늘A`(3.7em)는 27cqw. 좌석표 가장 좁은 칸(내용 폭 39px)에서 13px(옛 사다리와 같다),
  135px 칸에서 24px 상한. ⚠️ `cqw`는 컨테이너 **내용 상자**(padding 제외) 기준 — 배지 자리를 남겨야 하는 칩만
  `fill`을 낮춘다(랩실 `LAB_CHIP_NAME_FILL` 0.75 + `pr-5`).
- **판정은 글자 수가 아니라 표시 폭** — 한글 1, 영문은 글자마다 다르다(`W` 1.01 · `A` 0.70 · `i` 0.28,
  Pretendard Bold 실측표, `nameDisplayWidth`). `Kristine`(8글자)이 `김하늘A`(4글자)보다 좁다.
- **하한·상한 숫자는 `name-fit.ts`에만**(`NAME_FILL_MIN_PX.{seatCell|quickTile|labChip}` · `NAME_FILL_MAX_PX` 24 = `text-xl`) —
  소비처가 `minPx: 13`을 직접 적으면 규약이 화면마다 갈린다(가드 `name-fit.test.ts`). 하한을 더 내리지 말 것(못 읽는다).
- **하한에서도 넘칠 때만** 말줄임 + 전체 이름 `title` — 그 판정은 옛 사다리 [`fitSeatName(name, ladder).clipped`](../src/features/attendance/seat/name-fit.ts)가
  그대로 준다(랩실 칩). 사다리는 이제 **하한·clipped 판정용**이지 크기를 고르는 기본값이 아니다.
- 소비처는 **줄 높이를 함께 고정**한다(`leading-none`·`leading-tight`) — 안 그러면 글자가 커질 때 칩 높이가
  들쭉날쭉해진다. 한 줄에 서는 칩은 `h-full`로 줄 높이를 채운다(상한에 닿은 칩과 긴 이름 칩의 높이가 갈리지 않게).
  배지·상태 버튼이 겹치는 자리는 `pr-*`로 미리 비운다.
- 새 이름 칸(자리·좌석표·카드 격자)은 **이 함수를 쓰고 하한 상수만 더한다** — 화면 파일에 폭 계산·px를
  복붙하지 말 것. 🔴 사다리 하나로 고정 px를 고르는 방식(옛 규약)을 새 칸에 되살리지 말 것 — 넓은 창에서 글자가 안 커진다.

> **한 줄 규칙: 격자형 이름 칸은 `@container` + `fluidNameFontSize`(칸 폭 비례, 하한·상한은 name-fit.ts) — 하한에서도 넘칠 때만 말줄임 + 툴팁.**

### 드래그-팬 (잡고 끌기) — 넘치는 영역의 기본 인터랙션 (⚠️ 새 화면 기본값)
**가로/세로로 넘치는 영역은 막대 스크롤바에만 의존하지 말고, 마우스로 빈 곳을 끌어 내용을
움직일 수 있게 한다** — 태블릿/지도 앱 느낌(놓으면 관성 글라이드 + 넘치는 가장자리 페이드).
구현체: [`src/components/ui/drag-scroll-area.tsx`](src/components/ui/drag-scroll-area.tsx)의 `<DragScrollArea>`.
- **적용**: 기존 `<div className="… overflow-auto …">{내용}</div>` →
  `<DragScrollArea className="… (overflow-auto 빼고)">{내용}</DragScrollArea>`.
  안쪽 컨테이너가 overflow를 담당하므로 바깥 className에서 `overflow-auto`는 뺀다.
- **양축 자동**: 넘치는 축만 팬. 안 넘치면 grab 커서·페이드 자동 off.
- **충돌 안전**: 터치는 네이티브 스크롤에 위임, dnd-kit draggable(`[aria-roledescription="draggable"]`)·
  폼 컨트롤 위에선 팬을 시작하지 않는다. 5px 임계값으로 "탭=클릭 / 끌기=팬"을 구분하고, 실제로
  끌었으면 뒤따르는 click 1회를 차단(카드·링크 오작동 방지). 팬을 막을 자식엔 `data-no-drag-scroll`.
- 전역 스크롤바 하네스와 **병행** — 스크롤바는 그대로 보이고 드래그가 더해질 뿐. 새 화면에서
  넓은 표·캔버스·가로 목록을 만들 땐 처음부터 `DragScrollArea`로 감쌀 것.
- **좁은 레일(높이 30px 안팎)** 은 `hideBar`(막대 감춤, `.scrollbar-hide`와 같은 조건) + `fadeTone="surface"`
  (가장자리를 **카드색으로 녹임** — 내용이 그 알약/카드 면 속으로 사라진다)로 쓴다. 막대가 내용만큼
  자리를 먹는 자리에서 **페이드가 유일한 "더 있음" 신호**가 되는 조합(하단 독 칩 레일, 2026-08-25).
  ⚠️ 일반 표엔 쓰지 말 것 — 막대가 기본이고, 페이드만으론 "얼마나 더 있는지"를 못 말한다.

### 나란히 놓인 카드는 **속살까지** 줄을 맞춘다 — `grid-rows-subgrid` (⚠️ 카드 격자 기본값, 2026-08-04)
같은 행의 카드 **높이만** 맞추면(`h-full`) 안쪽 구획이 제각각이라 표·목록이 좌우로 어긋난다
(ECS 교시 카드: 계획 줄 수가 다르면 학생 표 시작선이 42px 어긋났다 — 원장 제보).
- **규칙**: 부모 격자에 **구획 수만큼 행 트랙**을 깔고, 카드를 `grid grid-rows-subgrid row-span-N`으로 올린다.
  트랙 높이는 그 행에서 **가장 큰 카드**가 정하므로 짧은 카드의 해당 구획이 늘어나 뒤가 밀려 내려온다.
- ⚠️ **행 간격을 `gap-y`로 주지 말 것** — row-gap은 **모든** 트랙 사이에 끼어 카드 **안쪽**까지 벌어진다.
  행마다 전용 간격 트랙을 두고(`repeat(N, auto auto auto 8px)`) `rowGap: 0`으로.
- ⚠️ 카드의 **직속 자식 수 = 트랙 수**. 형제를 하나 더하면 다음 행 트랙으로 흘러 카드가 겹친다.
- ⚠️ 카드 패딩은 그대로 둬도 된다(실측) — 모든 카드가 같은 패딩이면 같은 만큼 밀려 정렬이 유지된다.
- 미지원 브라우저에선 선언이 무시돼 **예전처럼 각자 쌓인다**(정렬만 없어지고 안 깨진다).
> 한 줄 규칙: 카드끼리 줄을 맞추려면 높이(h-full)가 아니라 트랙(subgrid)을 공유하라. 간격은 전용 트랙으로.

### 늘어나는 카드 안의 **바닥 요소**(페이저·요약줄)는 고정 높이가 아니라 `flex-1` 위에 (⚠️ 2026-08-05)
격자(grid/flex)의 카드는 **그 행에서 가장 긴 카드 높이로 늘어난다.** 그런데 안쪽 목록에 **고정 높이**
(`h-[56vh]` 등)를 걸어 두면 목록은 거기서 멈추고, 그 아래 페이저는 **카드 한가운데에 떠서** 밑이 통째로 빈다
(등록상담 칸반: 페이지네이션이 없는 '대기·예약' 컬럼이 제일 길어 나머지 4개 컬럼이 전부 그렇게 보였다 — 원장 제보).
- **규칙**: 카드를 `flex flex-col`로 두고 **목록에 `flex-1`**(+ 스크롤이면 `min-h-0` 또는 명시 `min-h`),
  바닥 요소는 그 뒤에. 남는 높이를 목록이 먹으므로 페이저는 항상 카드 바닥에 붙는다.
- 높이가 들쭉날쭉해 바닥 요소가 들썩이는 게 싫으면 **고정(`h-`)이 아니라 최소(`min-h-`)** 로 — 바닥은 깔되
  위로는 늘어난다. `h-`는 두 방향을 다 막아 이 버그를 만든다.
- 화면이 **세로로 길수록 더 벌어진다** — 개발 화면에선 안 보이다가 큰 모니터에서 드러난다.
> 한 줄 규칙: 늘어나는 카드 안에서 바닥에 붙어야 할 것은 `h-` 고정이 아니라 `flex-1` + `min-h-` 위에 둔다.

### 고정 폭 표 칸의 가로 나열은 **`flex-wrap`** (⚠️ `table-fixed` 열 기본값, 2026-08-04 — 두 번 터짐)
`table-fixed` + `colgroup`으로 폭을 못 박은 칸에 `flex`로 컨트롤을 늘어놓으면, 합계가 칸을 넘는 순간
**넘친 부분이 옆 칸 위로 흘러가고 옆 칸의 불투명 배경(입력·카드)에 덮여 "잘린 라벨"처럼 보인다.**
`overflow:hidden`이 아니라 **덮임**이라 원인을 못 찾고 폰트·폭을 의심하게 된다.
- **규칙**: 고정 폭 칸 안의 가로 나열 컨테이너는 `flex flex-wrap`. 넘치면 아래로 접는다 —
  표 행 높이는 보통 **가장 키 큰 칸**(긴 textarea 등)이 정하므로 접히는 세로 여백은 대개 공짜다.
- **함께 움직여야 할 것끼리 묶어서 접는다**: 낱개로 두면 칸 폭이 1~2px 달라질 때 한 개만 내려가
  행마다 모양이 달라진다(예: `미제출`·`없음` 알약을 `<span class="flex gap-1">`로 한 덩어리).
- 실측(원스크린 표 과제 수행률, 130px 칸): 내용 172px → **42px가 교재명 칸을 침범**, 접은 뒤 23px 여유·2줄.
- 같은 사고 이력: 학생·반 칸(128px)에서 배지가 `shrink-0`이라 **이름만 줄어들어** "김지/연"으로 쪼개졌다
  (2026-07-30) → 이름을 `shrink-0 whitespace-nowrap`으로 잠그고 컨테이너를 `flex-wrap`으로.
- ⚠️ 긴 안내가 필요한 **한 줄 `<input>`의 placeholder는 줄바꿈이 없다** — 좁은 칸에선 칸 이름만 남기고
  예시는 `title`로 옮긴다(`textarea` placeholder는 여러 줄로 감기므로 그대로 둬도 된다).
> 한 줄 규칙: 고정 폭 칸의 가로 나열은 `flex-wrap`으로 접고, 같이 다녀야 할 것은 묶어서 접어라. 좁은 input의 긴 placeholder는 title로.

### 데이터 표 = **열 제목과 값은 같은 축** + **열 구분선은 `--line-faint`** (⚠️ 표 기본값, 2026-08-05 → 정렬은 2026-09-18 갱신)
원장 2026-08-05: *"행 제목 가운데 정렬. 그리고 열 구분할 수 있게 아주 미세한 세로선 — 거의 보일랑말랑 적당한 진하기."*
→ 2026-09-18 수업목록 캡처와 함께 *"행제목과 밑에 내용이 어긋난거 같은데 정렬해주고"* · *"다른 표도 이상한거 있음 전부 맞춰줘"*.
- 🔴 **열 제목(`<th>`)과 그 열의 값(`<td>`)은 같은 정렬이다.** 08-05의 "제목만 가운데 · 본문은 좌측"은 폐기 — 칸이 넓은 표에서
  제목과 값이 **서로 다른 자리**에 섰다(수업목록 '반 이름' 제목이 값보다 80px 넘게 오른쪽). 열마다 하나를 고른다:
  - **가운데(기본)** — 짧은 값: 이름·알약·날짜·시각·상태·개수(`3명`)·요일·코드·체크박스·작은 버튼.
  - **왼쪽** — 긴 글: 메모·설명·요약·사유·내용·감사로그 상세처럼 문장이거나 여러 줄로 감기는 값. **제목도 `text-left`**.
    **앞에 색 점·뒤에 표식이 붙어 길이가 들쭉날쭉한 값**(캘린더 태그 `● 02. 입학 상담`, 등록상담 이름 + `반 배정 완료`)도
    왼쪽 — 가운데로 모으면 점·이름 시작이 줄마다 달라져 오히려 어긋나 보인다(2026-09-18 실측으로 되돌린 두 곳).
  - **오른쪽** — 금액·자릿수를 견주는 숫자(청구액·수납액·단가·합계·잔액). **제목도 `text-right`**.
- ⚠️ **맨 `<th>`는 브라우저가 가운데로 세운다**(Chrome UA 기본 — 조상이 `text-*`를 명시하면 그 값을 물려받는다). 그래서
  `<th>`에 아무것도 안 적은 표는 "제목 가운데 · 값 왼쪽"이 저절로 된다 — 새 표는 **정렬을 명시**할 것.
- 가운데로 세우는 법: 행에 `[&>td]:text-center`(또는 칸마다 `text-center`). 칸 안의 **`flex` 묶음은 text-align을 안 따른다** →
  `justify-center`. 🔴 **행 변형(`[&>td]:text-center`)은 칸의 `text-left`를 이긴다**(`.x>td`가 클래스 하나보다 구체적이다 —
  예외가 에러 없이 무시된다). 예외 칸이 있는 행은 `<tr>`에 맨 `text-center`(칸이 물려받고 칸 클래스가 덮는다)를 쓰거나 예외도
  변형으로(`[&>td:nth-child(5)]:text-left`). 표가 `.stack-rows`/`.stack-table`(폰 카드)이면 그 묶음에 `phone:justify-start`(카드에선 globals.css가 왼쪽으로 되돌린다).
- 🔴 **넘친 열 머리는 가운데 정렬이 안 먹는다**(넘치면 왼쪽부터 선다) — 값이 걸린 머리(`구분: 특강 ⌄`)가 최소 창에서 제 칸에
  들어가는 폭을 실측해 `colgroup`을 정할 것(수업목록: 좁은 알약 열은 머리 여백만 `[&>th:nth-child(-n+2)]:px-1` — `!`로 덮으면
  레이어 안 important가 폰 카드의 `padding:0 !important`를 이긴다).
- ⚠️ **오른쪽에 고정(sticky) 열이 있는 넓은 표**는 그 옆 칸 제목을 오른쪽에 붙이면 고정 열에 **가려진다**(회차 확정
  `실납 청구액` → "실납 청"만 보였다). 넘치는 묶음 칸은 제목을 가운데 그대로 둘 것.
- 🔴 **이미 맞는 표는 건드리지 않는다**(원장 2026-09-18 *"이상한곳만 정렬하는거지 잘 정렬된것까지 이상하게 할 필요는 없음"*) —
  좁은 칸에서 값이 칸을 거의 채워 제목과 값의 시작·끝이 이미 겹치는 열은 어긋남이 아니다. 고칠지는 **눈(스크린샷)으로** 정한다.
- 예외 = **라벨|값 양식 칸**(견적서 학생 정보·지출결의서 기본/정산 정보·결재 도장)과 시간표·출석부 같은 격자(제목·칸이 이미
  같은 축)는 원래 모양 그대로. ⚠️ 종이 서식 **안의 항목 표**(머리 줄 + 값 열)는 같은 기준이다 — 견적서 과목·교재 표,
  지출결의서 항목 표, 환불 규정 표(원장 2026-09-18 *"견적서랑 지출결의서도 맞춰줘"*).
- **세로선은 가로선보다 한 단계 옅게** — 새 토큰 `--line-faint`(5%) / 유틸 `border-l-line-faint`.
  행 구분선(`--line` 9%)과 같은 농도로 주면 **세로선이 훨씬 세게 읽힌다**(행 높이만큼 길어서). 격자가 아니라
  "열이 있구나" 정도만 남기는 게 목적.
- **셀 상수마다 붙이지 말고 표 한 곳에서 건다**: `[&_tr>*:not(:first-child)]:border-l
  [&_tr>*:not(:first-child)]:border-l-line-faint`. 행 종류가 여럿이면(본문·참고행·묶음 첫 행) 한 군데를
  빠뜨리는 순간 그 행만 선이 끊긴다. 첫 칸은 제외 — 표 바깥 테두리와 겹쳐 이중선이 된다.
- ⚠️ **너비와 색을 같이** 지정할 것. 색을 빼면 Tailwind v4 기본 `border-color`(currentColor)가 먹어 진한 선이 된다.
  셀이 `border-line`(전면 색)을 이미 갖고 있어도 **side 유틸이 이긴다**(실측: `border-l-line-faint`가 적용됨).
> 한 줄 규칙: 열 제목과 값은 같은 축 — 짧은 값은 가운데, 긴 글은 왼쪽, 금액은 오른쪽(제목도 똑같이). 맨 `<th>`는 저절로 가운데라 정렬을 명시하라. 열 구분선은 `border-l-line-faint`를 **표 한 곳**에서 첫 칸 빼고 건다.

### 반응형 창 폭 — 넓은창 공간활용 + 좁은창 접힘 (⚠️ 새 페이지 기본값, 2026-06-19)
모든 (shell) 페이지는 크롬리스 iframe(플로팅 창)에서 렌더되고, 창은 **360px(MIN_W) ~ 최대화 시
전체폭(~2300px)** 까지 자유 리사이즈/스냅된다. **창=iframe이라 Tailwind 브레이크포인트
(sm 640 / md 768 / lg 1024 / xl 1280)가 창 폭에 그대로 반응** → 같은 창을 리사이즈하면 레이아웃이
라이브로 바뀐다(미디어쿼리·JS 불필요). 그래서:
- ⚠️ **고정 좁은 `mx-auto max-w-4xl` 중앙정렬은 안티패턴** — 창을 최대화하면 콘텐츠가 그 폭에 갇혀
  좌우 여백이 수백 px씩 비고, 그 안에서도 열이 안 늘어 단일 입력칸만 비대해진다(owner 학원설정이 주범이었음).
- **원칙: 넓은 창은 여백 대신 "열/콘텐츠"로 채우고, 좁은 창(sm 미만)은 단일 컬럼으로 접는다.** max-w를
  막연히 키워 단일 입력이 가로로 폭주하게 두지 말 것.

**pageType별 처방:**
- **설정(탭형 다카드)** = 좌측 세로탭 + 우측 본문 **마스터-디테일**: 바깥 `lg:grid lg:grid-cols-[200px_minmax(0,1fr)] lg:gap-8`,
  nav는 좁으면 상단 가로탭(`flex flex-wrap … lg:flex-col`), 섹션 카드는 `grid gap-4 xl:grid-cols-2`로 펼침.
  **레퍼런스: [owner-console.tsx](<src/app/(shell)/owner/_components/owner-console.tsx>)** (페이지 캡 `max-w-7xl`).
- **설정(비탭 다카드, 예 kiosk-settings)** = `grid gap-6 lg:grid-cols-2 lg:items-start` + `max-w-5xl`(헤더는 그리드 밖 full-width).
- **단일 입력만 있는 폼**(meetings/new, sheets 연결) = 오히려 **`max-w-xl~2xl`로 좁혀 가둔다**(열 늘릴 콘텐츠가
  없어 안 좁히면 한 줄 입력이 폭주). admin/cleanup처럼 짧은 카드 스택은 `grid md:grid-cols-2 xl:grid-cols-3`.
- **데이터 입력 폼**(학생/직원/반/상담) = 필드로 꽉 찬 중앙 `max-w-4xl`는 **OK**(희박한 낭비 아님 — 그대로 둠).
  더 채우려면 필드 grid를 `sm:grid-cols-2 xl:grid-cols-3` / `sm:grid-cols-3 xl:grid-cols-4`로(cap는 유지).
- **list / detail / dashboard** = full-width + `grid lg:grid-cols-[…]` 마스터-디테일(**이미 정석, 손대지 말 것**).
  넘치는 표는 막대스크롤만 두지 말고 **[`DragScrollArea`](src/components/ui/drag-scroll-area.tsx)** 로 감싼다
  (`<div className="… overflow-auto">표</div>` → `<DragScrollArea className="…(overflow-auto 뺀)">표</DragScrollArea>`).
- **student-screen / print / 단일 키패드** = 의도적 `mx-auto max-w-[680~768px]` 유지(읽기 흐름·단일 입력). 넓은창 여백 정당.

**좁은 창(360~480px) 체크리스트** (새 페이지 추가 시 필수):
- 모든 다열 grid가 sm 미만에서 `grid-cols-1`로 접히는가(기본 `grid-cols-1` 명시).
- 편집 헤더(타이틀 + 삭제/이동 버튼)는 `flex flex-wrap items-end justify-between gap-3`(안 그러면 360px서 한 줄에 낌).
- 버튼 그룹(상태칩 등)도 `flex-wrap`(출석 입력폼 6버튼 케이스).
- 가로 오버플로는 BREAKS가 아니라 `DragScrollArea`/`overflow-x`로 흡수(전역 스크롤바 하네스와 병행).

⚠️ **새 설정·폼 페이지를 만들 때 이 규약을 점검** — 특히 `mx-auto max-w-Nxl` 중앙정렬을 기본으로 박지 말 것.
같은 "큰창=펼침 / 작은창=접힘" 패러다임의 칸반 버전은 위 "다열 보드" 섹션 참고.

### 로컬 초안 자동저장 — 길게 입력하는 폼은 입력 중 유실 방지 (⚠️ 긴 폼 기본값, 2026-06-30)
"한참 입력하다 창을 닫거나 새로고침하면 통째로 날아가는" 긴 폼(등록상담·학생·직원·학생상담 등)은 **입력 중 로컬(IndexedDB)에
자동 보관**하고 다시 열면 복구한다. "실제 저장"(서버 커밋)은 기존 그대로 — 초안은 유실 방지/이어쓰기용일 뿐 **서버에 안 보낸다**.
- **인프라**: [`useFormDraft({ scope, formRef, enabled?, onRestore?, exclude?, ignoreForBanner? })`](src/components/forms/use-form-draft.ts)
  (입력 700ms 디바운스 → IDB 저장, 다시 열면 `draftSavedAt` 세팅) + [`<DraftBanner savedAt onRestore onDiscard />`](src/components/forms/draft-banner.tsx)(공용 복구 배너)
  + [`form-draft.ts`](src/lib/form-draft.ts)(`readFormValues`/`applyFormValues`/`hasMeaningfulValues` — **DOM 일괄 캡처/복원**). 녹음 IDB 복구와 같은 패턴, **별개 레이어**(둘 다 동작).
  + **상태 기반 변형** [`useStateDraft({ scope, snapshot, hasContent })`](src/components/forms/use-state-draft.ts) — 입력이 `<form>` DOM이 아니라 **React state(동적 배열)** 인 폼용(수강료 계산기). 직렬화 가능한 `snapshot`을 통째로 JSON으로 디바운스 저장, `restore()`가 파싱본을 돌려주면 호출부가 setState로 rehydrate.
- **적용 5단계**(레퍼런스 [consultation-full-form.tsx](<src/app/(shell)/enrollment/_components/consultation-full-form.tsx>)):
  ① `const formRef = useRef<HTMLFormElement>(null)` + `<form ref={formRef}>` (동시편집 가드가 이미 formRef를 쓰면 **재사용**).
  ② `const draft = useFormDraft({ scope: mode==="create" ? "x:new" : ` + "`x:${id}`" + ` })`. ③ 폼 첫 자식에 `<DraftBanner savedAt={draft.draftSavedAt} onRestore={draft.restore} onDiscard={draft.discard} />`.
  ④ **서버 저장 "성공 확정 후"에만 `draft.clear()`** — `state.ok && state.nonce` effect 안에서(B-2). ⚠️ **`<form onSubmit={()=>void draft.clear()}>`(제출 시점 무조건 clear) 금지** — 서버 검증
  실패해도(폼 화면에 남는데) 초안이 먼저 지워져 창 닫으면 복구 불가(2026-06-30 학생상담서 버그). ⚠️ **create 액션이 `redirect()`면 NEXT_REDIRECT throw로 nonce effect가 영영 안 돌아 'x:new' 초안이 안
  비워진다** → create 액션도 update처럼 **`return { ok:true, redirectTo, nonce: Date.now() }`**(redirect 금지)로 통일해 nonce effect가 create/edit 공통 발화하게 한다. 클라 onSubmit로 액션을 직접 await하는 폼(등록상담 create)은 **`catch`의 `if(/NEXT_REDIRECT/.test(msg)){ clearDraft(); return; }`** 분기에서 clear(네비는 프레임워크).
  ⑤ scope는 **폼마다 고유 접두**(등록상담 `consultation:*` ↔ 학생상담 `student-consultation:*` — 같으면 IDB 초안을 서로 덮어씀).
- **⚠️ 캡처 규칙**: DOM의 **name 가진** input/select/textarea/checkbox만 캡처/복원된다. 그래서 ―
  · **컨트롤드 React state**(과목점수 jsonb·반 색·SearchableSelect 등)는 자동복원 안 됨 → **hidden input(name)로 직렬화**돼 있어야 캡처되고, **`onRestore`로 setState rehydrate**(레퍼런스 subjectDetails 패턴). 신뢰 안 되면 `exclude`로 빼고 사용자 재입력(학생상담 studentId).
  · **비밀번호·서버 prop·봇 트랩**(직원 임시비번·공개접수 renderedAt/company/token)은 `exclude`로 **IDB에 안 남기기**(보안).
  · **기본값이 항상 채워지는 필드**(상담 일시 now·category·audience 등)는 `ignoreForBanner`로 빼서 **빈 폼 오탐 배너** 방지.
- **적용 현황(2026-06-30)**: ✅ 등록상담·학생(생성/수정)·직원·학생상담 + **수강료 계산기**(`useStateDraft` 스냅샷)·**반**(class-form: 스케줄 grid hidden input
  schedule_*_${i}를 onRestore에서 배열로 복원 → `key`로 ScheduleGrid remount + 과목/담임/색 setState)·**지출**(2026-07-01, expense-dialog — 하이브리드: DOM 필드 자동 캡처/복원 + 라인아이템·통화는 onRestore로 setState;
  빈 항목이면 hidden `lineItems`를 `""`로 정규화[액션 parse는 `""`·`"[]"` 동치=null]해 오탐 배너 방지, `ignoreForBanner`=분류/일자/합계/통화; 다이얼로그 조건부 마운트라 성공 시 clear+onClose 안전). ⏳ **SPECIAL 남음** = 학부모 QR 공개접수(uncontrolled DOM + 다중선택/false·null
  lossy state 혼합 → 하이브리드)·학원설정(제네릭 래퍼라 각 *-section이 직접 useFormDraft 또는 onRestoreDraft 콜백 필요) — 별도 패스. ⏭️ **skip** = 짧은 폼(시험 등록·회의 신규·성적 인라인·상담 녹음[녹음은 이미 복구]).

  `totalPages<=1`이면 자동 null. (서버 컴포넌트끼리 함수 prop 안전.)
  - **클라이언트 state 페이저**(href 아닌 onClick, 예: 등록상담 칸반 [column-cards](<src/app/(shell)/enrollment/_components/column-cards.tsx>))는
    `<Pagination>`을 직접 못 쓰니, 같은 모듈이 export하는 **`PAGER_STEP_BASE`/`PAGER_STEP_ENABLED`/`PAGER_STEP_DISABLED`/`PAGER_LABEL`**
    클래스 상수로 버튼·라벨을 만들어 **시각을 동일하게** 한다(새 페이저는 native 버튼 손깎기 말고 이 상수 사용).
  - ⚠️ **페이지 이동 시 위치 고정**: 마지막(짧은) 페이지나 페이지별 내용 높이 차로 목록이 줄면 페이저가 위로 튄다.
    **클라 state 페이저(버튼이 커서 밑에서 움직임)는 목록 영역을 고정 높이로**(column-cards `h-[56vh] overflow-y-auto`).
    서버 href 페이저는 페이지 전환=리로드라 버튼이 커서 밑에서 안 움직여 영향이 작다.
- **쿼리 헬퍼 2종** (feature `server/queries.ts`):
  - `getXPage(filters, page=1, pageSize=50): Promise<{ rows, total }>` — Supabase `.range(from,from+size-1)`
    + `.select(cols, { count: "exact" })`. **필터는 가능한 한 SQL로** (eq/gte/ilike/or). 조인 컬럼
    검색은 별도 id 해석 후 `.or("base.ilike.%q%,fk.in.(ids)")` (상담 학생명 검색 참고).
  - **Stat 카드용 경량 집계** — 행을 fetch하지 말고 `.select("*", { count:"exact", head:true })`로 count만
    (학생 `getEnrolledStatCounts`, 상담 `getStudentConsultationCounts`). 카드는 페이지가 아니라 **전체**
    기준이어야 하므로 페이지 rows에서 도출 금지.
  - 월 단위처럼 모집단이 이미 작으면(수납 ~400행/월) **한 번만 fetch 후 메모리에서 검색·슬라이스**해도
    됨(수납 `summarizeInvoices` + `filtered.slice`). 이중 fetch만 피하면 됨.
- **페이지 컴포넌트 표준 코드**:
  ```ts
  const PAGE_SIZE = 50;
  const page = Math.max(1, Number(sp.page) || 1);
  const [{ rows, total }, counts] = await Promise.all([ getXPage(filters, page, PAGE_SIZE), getXCounts() ]);
  const totalPages = Math.max(1, Math.ceil(total / PAGE_SIZE));
  const pageHref = (p) => { /* 현재 필터 보존 + p>1일 때만 page= 세팅 */ };
  // 빈 상태 판정은 rows.length이 아니라 total === 0
  // …목록… <Pagination page={page} totalPages={totalPages} hrefForPage={pageHref} />
  ```
- **page 리셋 규칙**: 필터 chip·검색·정렬·월이동 href(`buildHref`/`buildSortHref`)는 **page 파라미터를
  넣지 않는다** → 자동으로 1페이지로. `pageHref`만 `p>1`일 때 `page=`를 세팅. "결과 N건"은 `total`
  (페이지 rows.length 아님), 옆에 `{page}/{totalPages} 페이지` 표기.
- **PAGE_SIZE = 50** 고정(표·카드 공통). 변경 시 전 목록 동시 변경.
