# 발송 PC — 반 공지 기능 적용 안내 (2026-07-13)

## 무엇이 바뀌나
aywa 수업보고서 > **반 공지** 탭에서 원장/관리자가 반을 골라 공지를 쓰면, 이 PC의 발송 데몬이
각 학생의 ClassNote 알림장으로 **자동 게시**합니다(보고서 발송과 별개 큐, 같은 안전 스위치 공유).

## 적용 방법 (2분)
1. zip 안의 `scripts\_classnote\` 폴더 내용을 **같은 경로에 덮어쓰기** 하세요. 파일 4개:
   - `watch-classnote-queue.mjs` (데몬 — 공지 처리 호출 추가)
   - `classnote-notice-core.mjs` (신규 — 공지 게시 코어)
   - `classnote-admin-core.mjs` (신규 — ClassNote 로그인·API 공용 헬퍼)
   - `classnote-core.mjs` (최신본 — 킬스위치 포함, 이미 최신이면 동일 내용)
   - `process-classnote-notices.mjs` (신규 — 수동 1회 처리용, 평소 사용 안 함)
2. 발송 데몬을 재시작하세요: `발송PC-지정.bat`을 다시 실행하거나 PC를 재부팅.

## 확인 방법
- `D:\tmp\classnote\watch.log`에 데몬 재시작 후 `[notice]` 로그가 보이면 적용된 것입니다
  (공지가 없을 땐 아무 로그도 안 남는 게 정상 — 대기 건이 있을 때만 출력).
- aywa 반 공지 탭에서 "테스트 발송(학원이)" 후 1~2분 내 이력이 "발송 완료"로 바뀌면 정상.

## 안전장치 (보고서 발송과 동일)
- 실게시는 **데몬 --post 모드 + 학원설정 'ClassNote 실제 발송' ON** 둘 다 필요합니다.
  스위치가 꺼져 있으면 공지도 큐에 안 올라가고, 올라가 있던 것도 게시하지 않습니다.
- 학부모 미가입/보드 미배정 학생은 그 학생만 실패로 기록되고 나머지는 정상 발송됩니다
  (aywa 공지 이력에서 실패 사유 확인 가능).

## 롤백
문제가 생기면 `watch-classnote-queue.mjs`만 이전 버전으로 되돌리고 데몬 재시작
(공지 처리만 빠지고 보고서 발송은 그대로 동작).
