# 연동 PC 적용 안내 — 학부모 글 알림 + 발송 게이트 보강 (2026-07-15, **2차**)

> **이 zip은 워커 폴더(`scripts\_classnote`) 전체를 최신으로 맞춥니다.**
> 파일을 골라 넣지 마시고 **폴더째 덮어써 주세요** — 서로 물려 있어서 일부만 넣으면 워커가 뜨지 않습니다.
>
> ⚠️ **오늘 한 번 넣으셨어도 이걸 다시 넣어야 합니다.** 그 뒤에 발송 게이트 문제 4건을 고쳤습니다:
> - 로그인을 **보고서 2건마다 한 번**씩 하던 걸 **세션 유지**로 바꿈(반복 로그인은 절반이 실패해서, 대량
>   발송 때 "발송이 멈췄는데 화면은 정상"이 될 수 있었습니다)
> - 그런 상황에서 **영원히 재시도**하던 것을 멈추고, 사유를 화면에 남기도록
> - **발송 차단 기준을 바꿈**: "계정이 2개 이상"이 아니라 **"동명이인 매핑이 맞는지"**로
>   (계정이 여러 개인 건 대부분 같은 학생이 영어·수학 따로 가입한 것이라 막을 이유가 없었고,
>    정작 위험한 동명이인은 계정이 1개라 안 걸렸습니다)
>
> **⚠️ 워커 재시작이 반드시 필요합니다** — 파일만 바꾸면 이미 돌고 있는 프로그램은 옛 코드를 그대로 씁니다.

## 1. 무엇이 바뀌나

학부모가 ClassNote **수학 보드에 새 글**을 올리면, 그 학생의 **담당 수학 강사**에게 eywa 화면 우상단
**알림 벨**로 뜹니다. 강사가 ClassNote 앱을 안 열어도 "오늘 늦어요 / 아파서 쉬어요"를 바로 봅니다.
알림을 누르면 확인창이 뜨고, 확인하면 **ClassNote의 그 글로 바로** 이동합니다(새 탭).

- **읽기 전용입니다.** ClassNote에 글을 쓰거나 고치거나 지우지 않습니다. 학부모에게 나가는 것은 **아무것도 없습니다.**
- 확인 주기 = **1분**. (데몬은 15초마다 도는데, 피드 확인만 1분에 한 번 합니다.)
- 처음 켠 직후에는 **알림이 0건**입니다 — 과거 글이 한꺼번에 쏟아지지 않게 "지금부터"를 기준점으로 잡습니다.
  그 뒤에 올라오는 글부터 알림이 갑니다.
- **안 가는 경우도 있습니다(일부러)**: 동명이인이 있는 이름은 그 글이 누구 집 것인지 확신할 수 없어
  보류합니다(엉뚱한 선생님께 남의 집 얘기가 가는 것보다 낫습니다). 보류되면 로그에 이유가 남습니다.

## 1-b. 보고서 발송이 보류될 수 있습니다 — 동명이인 매핑 확인

**동명이인이 있는 이름**(eywa에 `박서준`과 `박서준C`가 같이 있는 경우 등)만 발송 전에 한 번 확인합니다.
학부모는 클래스노트에 가입할 때 **이름 뒤에 알파벳을 안 붙이기** 때문에, 보드 `(수학)박서준` 하나가
초6 박서준과 중3 박서준을 동시에 가리킬 수 있고, 반 초대가 엉뚱한 집에 갔으면 그대로 오발송이 됩니다.

그래서 그런 이름만 **원아 생년월일이 그 학생 학년과 맞는지** 대조하고, 안 맞으면 보류합니다
(`공유 보드` 배지 + 사유에 몇 년생인지 표시). 동명이인이 없는 이름은 **아무것도 확인하지 않고 그냥 나갑니다**
— 계정이 2개든 3개든(영어·수학 따로 가입, 학부모·학생 각자 가입) 상관없습니다.

**⚠️ 테스트 학생 '학원이'는 예외 등재가 필요합니다.** 테스트 계정이라 원아 생일이 실제와 달라 보류됩니다:

```
(수학)학원이
(영어)학원이
```

확인해서 같은 학생 것이 맞으면 **수업보고서 > 보고서 설정 > '공유 보드 발송 예외'** 에 보드명을 등재하세요.

## 2. 적용 방법

1. 워커를 멈춥니다: 바탕화면 **`발송PC-해제.bat`** 실행 (또는 작업 스케줄러에서 `eywa-classnote-worker` 종료)
2. zip을 풀어 **경로 그대로** `C:\eywa-sync-pc` 에 덮어씁니다
   (`scripts\_classnote\` 폴더 전체 — 파일 선별 금지).
3. 워커를 다시 켭니다: 바탕화면 **`발송PC-지정.bat`** 실행

> env(`.env.local`)에 **새로 추가할 값은 없습니다.** 기존 `DATABASE_URL` · `CLASSNOTE_UPLOAD_ID/PW` 그대로 씁니다.
> `.env.local`은 zip에 들어있지 않으니 **덮어써도 사라지지 않습니다.**

## 3. 적용됐는지 확인

로그 `D:\tmp\classnote\watch.log`(또는 `CLASSNOTE_OUT` 폴더)에 **`[feed]`** 로 시작하는 줄이 보이면 정상입니다.

```
[feed] 첫 실행 — 워터마크 1423955240로 초기화(과거 글은 알리지 않음)
[feed] 학부모 새 글 1건 감지 → 강사 알림 2건
```

아무 글도 안 올라오면 로그도 조용합니다(정상). 학부모 글은 **수학 기준 3주에 8건 정도**라 원래 드뭅니다.

수동으로 지금 확인해보려면 (변경 없이 점검만):
```
cd /d C:\eywa-sync-pc
node --env-file=.env.local scripts\_classnote\process-parent-posts.mjs
```

## 4. 동작 조건

- 워커가 **`--post` 모드**로 돌아야 합니다(현재 `run-classnote-worker.ps1`에 이미 그렇게 돼 있습니다).
- **연동 PC가 켜져 있어야** 알림이 갑니다(발송과 같은 조건). 꺼져 있던 동안의 글은 켜질 때 따라잡되,
  **3일이 지난 글은 건너뜁니다**(지난 "오늘 늦어요"는 의미가 없고, 밀린 알림이 쏟아지는 것도 막습니다).
- 발송 스위치(ClassNote 발송 ON/OFF)와 **무관하게** 동작합니다 — 이건 발송이 아니라 받아보는 기능이라서
  발송을 꺼둬도 학부모 글 알림은 옵니다.

## 5. 되돌리기

`watch-classnote-queue.mjs`를 이전 버전으로 되돌리고 워커를 재시작하면 알림이 멈춥니다.
(다른 기능 — 보고서 발송·반 공지·일일 프로비저닝 — 에는 영향이 없습니다.)

## 6. ⚠️ 선행 조건 (원장님 확인)

이 기능은 eywa DB에 **`classnote_feed_state` 테이블**(마이그레이션 0108a)이 있어야 동작합니다.
프로덕션에 적용되기 전에는 로그에 오류가 나고 알림은 안 갑니다(다른 기능에는 영향 없음).
