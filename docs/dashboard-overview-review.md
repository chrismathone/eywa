# 전체 현황 대시보드 적대적 리뷰

검수일: 2026-09-10. 대상: `/dashboard?view=one`, 기존 기본 대시보드는 유지.

## 발견 및 수정

| 검토 항목 | 수정 또는 확인 |
| --- | --- |
| 다른 세션 작업 손실 | origin/main 최신 신규생·좌석 변경을 fast-forward로 통합. 기존 dashboard stash는 적용·삭제하지 않음. |
| 최초 조회 실패를 0 또는 이전값으로 오인 | 영역별 성공·실패 상태를 분리. 정상값이 실제로 있을 때만 원래 확인 시각과 함께 유지. |
| 사용자가 바뀌거나 권한이 회수된 뒤 이전 수치 노출 | 학원·사용자·역할·강사 보기별 캐시 키, 재조회 시 권한 확인, 범위·날짜 변경 시 이전값 제거. |
| 출결 중복·교시 누락 | append-only 수정 이력을 공용 유효 기록 함수로 정리하되 다른 교시는 유지. 동일 결과로 도넛과 14일 막대 계산. |
| 부분 입력 반을 완료로 표시 | 예정학생 대비 실제 기록을 비교해 완료·입력 중·미기록 구분. |
| 출결 수치끼리 단위가 달라 보임 | 예정학생 기준 입력률과 학생·반·교시별 출결 칸을 명시. 출결은 칸, 청구서는 건, 학생은 명, 수업은 반. |
| 최근 출결이 미래 기록을 참조 | 오늘 이후 기록 제외. 조회 기간 내 기록 없는 날은 0%와 구분. |
| 날짜 미상 퇴원이 월별 증감을 왜곡 | 퇴원 관리의 시스템 정리 판정 재사용. 날짜 미상·수강 이력 없는 정리분은 추이 제외, 실제 수강 이력이 있는 행은 유지. |
| 수납 금액·반올림 오해 | 공용 청구·할인·수납 계산 재사용. 실제 미수가 남으면 100% 표시 방지. 청구월 기준 설명과 정확한 원 단위 제공. |
| 그래프 숫자·범례 불일치 | 0인 도넛 항목도 같은 색 매핑 유지. 음수 금액은 0 기준선 아래 표현. 금액 라벨 겹침 제거. |
| 최초 접속 시 차트 hydration 불일치 | SVG title의 여러 JSX 자식을 단일 문자열로 변경. 서버 HTML에 hydrateRoot를 연결해 복구 오류 없이 원래 차트 DOM을 유지하는 회귀 테스트 추가. |
| 신규생 과목별 시작일 차이 | 최신 main의 과목별 첫 수업·체크 규칙으로 판정. 선택 항목 제외, 확인 학생 중복 제거. |
| 명단이 없어서 조치하기 어려움 | 반복 결석 학생 이름, 신규생 체크별 확인 대상과 관련 원본 업무 링크 제공. |
| 일정 잡음·사라진 메뉴 이동 | 취소·예약 금지·운영팀 중요일정 필터, 대시보드 내 전체 일정 펼치기. 제거된 calendar 메뉴 링크 생성하지 않음. |
| 조회 행 수 제한 | 새 원천 목록은 안정 정렬과 페이지 조회 사용. 지출 공용 조회도 전체 페이지를 읽고 오류를 전파. |
| 원천 오류가 0으로 은폐 | 학생·수업·상담·지출 공용 조회에서 오류 확인 추가. 새 화면은 영역별로 격리. |
| 알림 폭주·연결 누락 | 1.2초 묶음 처리와 최대 5초 대기, 테이블별 구독 격리, 30초 폴링 및 복귀·재접속 조회. |
| DB publication 미설정 | 추가 전용 migration을 롤백 트랜잭션으로 먼저 검증한 뒤 적용, 25개 테이블 조회로 확인. 기존 RLS·데이터 변경 없음. |

## 검증

- 관련 테스트 42개 파일, 463개 테스트 통과: 대시보드, 신규생, 출결 유효 기록, 청구 계산, 지출 검색 및 새 화면·갱신 훅·차트 hydration.
- 새 화면의 원그래프 단위, 최초 실패 문구, 제거된 일정 링크 부재를 DOM 테스트로 확인.
- 갱신 훅 테스트: DB 이벤트 묶음, 권한별 구독, 이벤트 없는 30초 갱신, 부분 실패 시 값 보존, 구독 정리.
- 프로젝트 소스·테스트 타입 검사 통과. 기본 tsconfig가 포함하는 `.claude/worktrees` 복제본 때문에 전체 명령은 메모리 부족이 발생해, 동일 옵션에서 해당 복제본만 제외한 임시 설정으로 검사.
- 변경 파일 ESLint 검사 및 diff 공백 검사.
- 로그인된 실제 Chrome에서 운영 데이터, 자동 갱신 시각, 데스크톱·좁은 창 배치와 하단 운영 패널까지 확인. 기본 대시보드 정상 표시와 차트 수정 후 새로고침 시 개발 오류 표시가 사라진 것도 확인. 브라우저 검수 서버는 다른 세션의 3031을 보존하기 위해 3032 사용.

## 해석 범위

- 갱신 시각은 aywa 조회 완료 시각이다. 외부 서비스 원본이 즉시 동기화되었다는 뜻은 아니다.
- 여러 원천을 병렬 조회하므로 모든 표를 하나의 DB 트랜잭션 시각으로 보장하지 않는다.
- 학생 등록·퇴원 추이는 현재 학생 레코드의 처리일이다. 삭제·재등록의 모든 과거 이력을 복원하는 분석은 아니다.
- 영어·수학 시트는 해당 메뉴의 현재 사용자 조회 범위를 따른다. 없는 유지율·담당자·검증 상태를 만들어 표시하지 않는다.
- 운영 데이터에 시험용 출결·결제 행을 쓰지 않았다. 변경 알림 동작은 자동 테스트, publication 설정은 실제 DB 읽기, 조회 갱신은 실제 브라우저로 검증했다.
