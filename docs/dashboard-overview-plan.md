## 화면 구성

상단 5개 핵심 지표와 22개 분석 패널을 세 영역으로 배치한다. 큰 화면은 4열, 중간 화면은 3열·2열, 작은 화면은 1열로 흐른다. 등록·퇴원과 월별 수납 차트는 2열을 사용한다. 전체 현황을 먼저, 상세 분포와 업무를 이어 보여 준다.

| 영역 | 시각화 |
| --- | --- |
| 학원 운영 | 재원·출결·청구서 도넛, 신규생 단계 막대, 등록·퇴원 및 월별 수납 그룹 막대 |
| 학생·학습·상담 | 과목·학년·학교 막대, 등록 상담 전환, 14일 등원율 막대, 반복 결석 명단, 숙제·보고서, 학생 상담 |
| 수업·운영 | 신규생 체크 누적 막대와 확인 대상, 영어·수학 시트 입력률, 오늘 수업, 7일 일정, 직원 구성, 행정 건수, 지출 분류, 공지 |

흰 바탕·남색 중심으로 정렬과 구획을 통일한다. 정상은 녹색, 기한·주의는 황색, 결석·미수·기한 경과는 적색이다. 기존 Pretendard와 EyIcon/MenuGlyph를 사용하고 별도 아이콘·차트 라이브러리를 추가하지 않는다. 주요 라벨은 12–15px, 보조 기준 설명은 11px, 핵심 수치는 33px이다. 차트의 정확한 값은 범례 또는 펼칠 수 있는 표에 제공한다.

## 데이터 계약

- 학생 분포는 동일한 재원 명단 기준이다. 과목 간 중복 수강은 합산 학생 수와 구별한다.
- 등록·퇴원은 학생의 처리일(date 컬럼) 기준 최근 6개월이다. 당월은 오늘까지이며 미래 날짜와 날짜 미상 시스템 정리 퇴원을 제외한다.
- 출결은 수정 이력을 정리한 학생·반·날짜·교시별 칸이다. 등원율은 `(출석+지각)/유효 출결 칸`이다. 예정학생 기준 입력률은 별도로 설명한다.
- 수납은 취소 청구 제외, 기존 청구·할인·입금 계산을 재사용한다. 청구월별 수납과 입금일별 매출을 구별한다. 지출은 지출일 기준이며 서로 다른 통화를 합치지 않는다.
- 신규생은 기존 90일 목록과 과목별 기한·체크 정책을 재사용한다. 필수 확인 건수와 중복 제거한 학생 수를 구분한다.
- 서버에서 메뉴 권한·개인 권한 예외를 확인하고 기존 RLS·조회 범위를 사용한다. 클라이언트 캐시는 사용자·학원·역할·강사 보기별로 격리한다.
- 조회 실패를 0으로 바꾸지 않는다. 이전 정상값이 있으면 원래 확인 시각과 함께 유지하고, 권한·사용자·날짜 변경 시 이전 범위 데이터를 재사용하지 않는다.
- Realtime 알림은 재조회 신호로만 사용한다. 25개 원천 테이블 publication 설정과 30초 폴링을 병행한다. 외부 서비스 데이터는 해당 동기화가 eywa에 저장된 뒤 반영한다.

구체적인 발견 사항과 검증 범위는 [적대적 리뷰](dashboard-overview-review.md)에 기록한다. 개인 정보가 담긴 브라우저 캡처와 임시 검증 스크립트는 커밋하지 않는다.
