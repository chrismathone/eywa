## 결론 한 줄

aywa는 **"보습학원 운영 CRM"으로선 상당히 촘촘**하지만, 경쟁 제품들이 기본으로 얹는 **운영 주변부 기능 몇 개가 비어 있다.**
2026년 시장은 **운영 CRM층 ↔ 학습 특화층(문제은행·숙제·오답)**으로 분화 중이고 aywa는 의도적으로 운영층에 있다 —
따라서 "학습 콘텐츠/문제은행" 부재는 by-design이고, **진짜 아픈 건 운영층 안에서 놓친 6가지**(아래 A그룹)다.

**핵심 6대 미결 격차**: 증명서 자동 발급 · 출결 인증 하드웨어 폭 · 모바일 앱 체감 · 직원 근태·결재 · 상담 슬롯 예약·대기자 · 보강 스케줄링.
이 중 **증명서 발급**은 인프라 재사용으로 가성비 최고, **상담 예약·대기자**는 유일하게 차별화까지 되는 항목.

## A. 진짜 미결 격차 — 계획도, 의도적 제외도 아닌 순수 공백 (운영 임팩트 순)

> 이게 사실상 답이다. 결정 로그·계획 문서 어디에도 없어 착수 시 정치적 절차가 필요 없다.

### A1. 증명서 자동 발급 — 교육비 납입증명서·수강확인증 〔confirmed-missing〕
- **격차**: 원생/수강/납입 데이터에서 증명서를 자동 생성해 단체 발급하는 기능 전무.
- **검증**: `증명서/납입증명/수강확인/재원증명/납부확인` grep → **0건**(src 전체). 문서저장소(`academy_documents`)는 서식 보관·앱 작성 문서 중심.
- **왜 큼**: 연말정산(1월) 교육비 납입증명서 + 수시 수강확인증 = 매년 반복 데스크 대량 업무 + 교육청 지도점검 대응 문서.
  **A4 인쇄 인프라(`(print)` 라우트 + `usePrintWindow`)가 이미 있어 투입 대비 효과 최상.**
- **재사용 가능한 재료**: 학원설정 profile(학원명·대표자명·주소·로고)·billing account, 학생 데이터(재원 기간·학교·학년), 납입 내역(invoices).
- **전제 1개**: 완전한 납입증명서엔 **직인 이미지** 필요(현재 없음 — `sealUrl`은 Storage 버킷 필요, CLAUDE.md 'DB가 필요한데 없는 것'). 우회: 수강확인증은 로고 워드마크로 즉시 완결, 납입증명서는 사업자등록번호 jsonb 필드 추가(사소) + 직인은 "인쇄 후 날인" v1 → Storage 직인은 후속.
- **경쟁**: 에듀허브(수강확인증·연말정산 납입증명서 단체 자동 발급), 메이크에듀(교육청 점검 자료용).

### A2. 출결 인증 하드웨어 스펙트럼 — RF카드·QR·NFC·지문·안면인식 〔confirmed-missing〕
- **격차**: 키오스크 인증이 숫자 출석번호 단일 방식.
- **검증**: `src/lib/db/schema.ts:50` `attendance_access_method` enum = `["manual","kiosk"]` 두 값뿐, 인증수단 컬럼/확장점 없음. 키오스크 = 숫자패드(`kiosk/_components/keypad.tsx`, 출석번호 4~5자리). `kiosk_devices`는 태블릿 토큰 등록용이지 하드웨어 연동 아님. QR은 출결이 아니라 등록상담 공개접수 전용.
- **격차 크기(정확히)**: **셀프 체크인 키오스크 + 등하원 학부모 알림톡 자동발송(`checkin.ts`→Solapi)은 이미 가동** → 빠진 건 "인증 수단의 다양성(카드/생체)"뿐. 자체 시장비교 문서도 "웹 셀프체크+알림만 붙이면 따라잡기 쉬움"으로 평가.
- **경쟁**: 통통통(지문·RF·키패드·키오스크·출결앱 선택형), 에듀오케이(4종), BH소프트×토스플레이스 페이스패스(안면인식).

### A3. 관리자/강사용 모바일 앱 — 이동 중 출석·현황 조회 〔partially-exists〕
- **격차**: 전용 앱·PWA 없음(package.json에 react-native/expo/capacitor/next-pwa 없음, manifest·service worker 0건). 핵심 UX Stage Manager 플로팅 창은 데스크톱 전용(`layout.tsx:159` "데스크톱에서만 마운트").
- **이미 있는 것**: 반응형 모바일 셸(`mobile-top-nav.tsx`, 폰 브라우저로 대시보드·현황 조회 가능), 키오스크 체크인 태블릿 표면, 강사용 원스크린 미니셸.
- **격차 크기(정확히)**: "앱 자체 없음"은 맞지만 실제 아픈 지점은 **강사 폰 roll-call UX + 시간표·출석부 밀집 그리드의 모바일 체감 품질** 두 가지로 좁혀짐.
- **경쟁**: ACA2000 관리자앱(일일 인원·반별 출석·보강·진도·상담·결재), 학원조아·메이크에듀.

### A4. 직원 근태·업무일지·결재선 〔confirmed-missing〕
- **격차**: 직원 쪽은 휴가(`staff_leaves`)와 근무 "계획" 편집(`users.workSchedule` jsonb)까지만. 출퇴근 기록·업무일지 제출·다단계 결재 없음.
- **검증**: `근태/출근부/업무일지/출퇴근/timeclock/work_log` grep → 0건. `attendance_records`·`attendance_checkins`는 전부 학생용. staff_leaves는 approvedBy 1단계 승인만.
- **격차 크기**: 다강사 학원 인사·급여 근거와 직결. **단 급여 기능 자체가 비활성**(`payroll/config.ts` `PAYROLL_ENABLED=false`, 2026-07-07 결정) → 체감 크기는 급여 재활성 의지에 달림. 재사용 기반: 휴가 승인·지출결의서 다단계 결재 jsonb·키오스크 체크인 인프라.
- **경쟁**: ACA2000(출근부·업무일지·상위자 결재), 에듀오케이.

### A5. 온라인 상담예약·대기자(웨이팅) 관리 〔partially-exists — 차별화 기회〕
- **격차**: QR 공개접수는 단방향 폼 → 학부모 셀프 시간슬롯 예약·레벨테스트 예약·대기자 큐 없음.
- **검증**: `booking/reservation/appointment/slot/waitlist` 테이블 0건. `enrollment_consultations`의 일정 필드는 `consultation_date`(시각 없음)·`follow_up_date`뿐. `level_tests`는 결과 기록 전용(미래 예약 개념 없음). QR 폼에 날짜/시간 선택 필드 없음.
- **이미 있는 것**: 상담 상태 운용은 존재(`consultation_outcome` enum = pending/scheduled/consulted/ai_done/enrolled/declined/**no_show**), 등록상담 칸반 '대기·예약' 컬럼, 사전 인터뷰(QR 입학상담카드), 수동 예약 입력.
- **왜 유일한 차별화**: aywa 강점(등록상담 칸반 + AI 분석) 위에 **슬롯 캘린더·대기자 큐만 얹으면** 격차 해소를 넘어 차별화. "문의→레벨테스트 예약→대기자→등록 전환" 통합 퍼널은 시장 전체의 공백.
- **경계 주의**: 학부모가 직접 예약하는 표면은 **"학부모포털 영구 제외"** 경계에 닿음 → 착수 전 "학부모-facing 예약 화면 허용 여부" 결정 선행.
- **경쟁**: ACA2000 상담예약운용(시간당 무제한·사전 인터뷰·상태 필터).

### A6. 보강(보충수업) 스케줄링 — 결석→보강 배정→참석 확인 〔confirmed-missing〕
- **격차**: 출석 상태 enum에 `makeup` 값만, 결석 발생 시 보강을 잡고(일시·강사) 참석까지 추적하는 흐름 없음.
- **검증**: `attendance_status` enum `makeup` 값 존재하나 보강 일시·강사·원결석 연결 컬럼/`makeup_sessions` 테이블 없음. attendance는 상태 마킹·makeupCount 통계까지만.
- **격차 크기**: 출석부·시간표 강점의 자연 연장. **단 인재원 학칙 기본값이 "결석 별도 보강 없음"**(`owner/defaults.ts:62-63`) → 현 내부 운영 체감 작음, 보강 다빈도 학원 SaaS 확장 시 커짐.
- **경쟁**: ACA2000(보강 등록·참석 기록), 매쓰플랫·수학대왕(오답 클리닉=보충 시스템화).

## B. 의도적 단순화 — 문서엔 "안 함"이나 시장 트렌드상 재평가 여지

> 결정 로그/갭 문서에 "안 하기로" 적혀 있으나, 그 판단 이후 시장이 바뀐 항목. 뒤집으려면 명시적 재검토 필요.

- **B1. 숙제/과제 관리 루프** 〔partially-exists〕 — 출결·원스크린에 숙제 완료/미제출 "상태 체크"는 있으나(`attendance_records.homework_required/done`, `onescreen_daily_sessions.homework`, `lesson_reports.homework_score`), 과제를 1급 객체로 다루는 **배부→제출물→검사→피드백→미제출 팔로업** 루프 전무. `ijw-eywa-gap-2026-06-22.md:58`에 "메모·onescreen으로 대체"로 의도적 단순화됨. **재평가 근거**: 숙제 특화 SaaS(다했니)의 돌풍 + "운영·학습 경계 소멸" 트렌드.
- **B2. 학습 콘텐츠 축**(문제은행·오답클리닉·단어시험·AI 코스웨어) 〔planned-or-excluded〕 — 성적 "기록/차트"까지만, 학습 "실행" 루프 0(문제/문항/퀴즈/오답 테이블 0). `MARKET_COMPARISON_2026-06-18.md:79-83`에서 "보습 운영 타깃엔 필수 아님, 문제은행 진영과 정면충돌 회피"로 판정. **재평가 근거**: 문제은행 진영(매쓰플랫·수학대왕)의 운영 CRM 역침식 → Edutrix식 **제휴 연동**으로 대응할지가 전략 재평가 대상.
- **B3. OMR/자동채점·문항별 정답률** 〔confirmed-missing〕 — 성적은 수기 일괄입력(`batch-score-grid`)까지. `my-learning`의 "평균 정답률"은 성적에서 산출한 KPI 표시일 뿐 OMR·자동채점 아님. 학습 콘텐츠 축과 한 묶음. 경쟁: 에듀허브(스캐너 OMR·문항 정답률·성적표 자동생성).
- **B4. 전자서명 내장**(입회원서·개인정보 동의·환불규정 확인서) 〔confirmed-missing〕 — 동의는 체크박스까지만. "서명" 코드 히트는 전부 "인쇄 후 수기 서명"(`refund-request.ts` 결재란)·signed URL·랜딩페이지 섹션. 결정 로그 **"계약서 영구 제외"**와 연관. 경쟁: 모두싸인·하이클래스(가정통신문 전자서명 회신).
- **B5. 학생 리워드/게임화**(포인트·퀘스트·랭킹) 〔confirmed-missing〕 — 전무(배지/badge 히트는 전부 UI 배지). 단독 가치 낮음, 숙제/학습 기능 신설 시 함께 설계할 부속. 경쟁: 다했어요(쿠키 보상), 수학대왕(퀘스트·랭킹), 클래스카드(배틀).

## C. 의도적 영구 제외 — 경쟁 관점 격차지만 "12메뉴 정체성"으로 by-design

> 결정 로그에 박혀 있어 **재제안 대상 아님**. 참고용.

- **C1. 학부모 전용 앱/포털**(알림장·앨범·성적/출결 열람·읽음확인·1:1 채팅) — **조사상 기회비용 최대 항목.** 학부모 접점이 단방향 4종(QR 공개접수·등하원 알림·이탈방어 문자초안·인쇄 보고서)까지만, parent 역할·양방향 앱 없음. 최대 학부모앱 **아이엠클래스가 2026-02 종료**돼 대체 수요가 몰리는 시점이라, 이것만은 언젠가 명시적 재검토를 고려할 값어치 있음. (CLAUDE.md 결정 로그 "학부모포털 영구 제외".)
- **C2. 경영분석·매출분석 통계**(성장률·자동 결산) — 매출 부분은 제외 탭 + 수납 영역이라 이번 범위 밖. **단 상담/등록 전환율·순증감 분석은 이미 중간 깊이로 존재**(`enrollment/dashboard` 월별 상태분포·전환율 추세·상담사 실적, `consultations/stats` 전환율·사유 분포·월별 추세, `dashboard/metrics` 순증감).
- **C3. 캘린더/일정관리** — 영구 제외지만 회의록 3단계(기한→캘린더 등록)의 선행 의존성이라 `docs/meeting-to-workflow.md`에 그때 재검토 예고됨. 인접 조각(exams.examType='school' 학교시험일, operations.holidays)만 흩어져 있음.
- **C4. 셔틀버스 GPS 관제** — 설정·신청 플래그(`shuttleSchema`·`shuttle_bus_request`)만, 관제 코드 0줄. 원본 ijw 셔틀관리 탭조차 GPS 관제 아니었음 → 신규 개발 = 기사앱·실시간 인프라 별도 제품급.
- **C5. 신규생 유입/마케팅 채널**(학원 검색·리뷰 마켓플레이스 노출) — 제외 탭. QR→상담 퍼널은 강하나 그 "앞단"(문의 발생 채널)이 빔. 경쟁: 오늘학교(18만 학원 검색·리뷰).

## 우선순위 추천 (작성자 판단)

### 1순위 — 증명서 자동 발급 (A1)
세 가지가 동시에 맞아떨어짐: ① **순수 미결**이라 결정 로그를 안 건드림 ② **인프라 재사용**((print)+학원설정+학생/invoices 데이터)이라 신규 시스템 리스크 없음, 반응속도·품질 우선 원칙과 무충돌 ③ **인재원이 실제로 매년 겪는 반복 업무**(내부 단일테넌트 안정화 우선과 정합). 직인 버킷을 기다리지 않고 v1 출시 가능.

### 2순위 — 상담 예약·대기자 (A5)
유일하게 "격차 메우기"를 넘어 **차별화**가 되는 항목(aywa 칸반+AI 강점 위에 슬롯 캘린더·대기자만 얹음). 단 학부모-facing 예약 표면이 학부모포털 제외 경계에 닿아, 착수 전 결정 선행 필요 → 그래서 2순위.

### 지금은 미룰 것
- **출결 하드웨어·모바일 네이티브 앱**(A2/A3) — 하드웨어 생태계/앱 빌드로 공사 큼, 키오스크+알림·반응형 셸이 절반 커버 중.
- **직원 근태·결재**(A4) — 급여 비활성이라 명분 약함, 급여 재활성 시 세트로.
- **보강 스케줄링**(A6) — 인재원 학칙이 "보강 없음"이라 내부 체감 0, SaaS 확장 때.
