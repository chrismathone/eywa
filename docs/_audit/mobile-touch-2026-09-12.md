# 모바일 화면·터치 검수 — 2026-09-12

로그인된 관리자 계정으로 모바일 메뉴 23개와 하위 화면·상세 화면을 검수했다. 390×844를 기본으로 보고, 수정한 주요 화면은 320×568, 768×1024, 844×390에서도 확인했다. 개발 서버와 로컬 운영 빌드에서 수행한 검수이며 실제 서비스 데이터의 저장·발송·삭제는 실행하지 않았다.

| 그룹 | 확인한 화면 |
| --- | --- |

| 도움말·설정 | 도움말·아이콘, 학원 설정 기본 및 운영 체계·과목·수납·알림·상담·권한·메뉴·팝업·데이터·감사·시트 |

학생·반·상담의 넓은 데이터 표와 시간표는 기존 가로 스크롤 방식을 유지했다. 표의 필터가 잘릴 수 있어 바깥에 일괄적으로 `overflow: hidden`을 적용하지 않았다.

## 실제 터치로 확인한 동작

- 모바일 메뉴 열기·닫기·메뉴 선택 후 닫힘.
- 대시보드 상단 KPI 6개 팝업 열기·닫기.
- 새 원생·새 반 등록 화면 진입, 공개 접수 QR, 자산 등록·결석 통보 폼 열기.
- 수납 월 선택기와 강사 시트 필터 열기.
- 반 상세의 수강 날짜·등원요일 편집 열기·취소, 상담 목록 전환·셀 편집·취소.
- 월간 출석부 날짜 셀 터치 → 상세 팝오버 → 바깥 영역 터치로 닫기. 기록은 변경하지 않음.
- 소모품 행 터치 → 수정창 → 수량 입력 포커스 → 취소. 1·2페이지 왕복과 표시 건수 확인.
- 알림 보관함 전환, 사용자 메뉴에서 내 정보 이동.
- 교실 2D/3D 전환, 층 선택, 확대, 회전.
- 긴 자산 등록 팝업을 320×568과 390×400에서 검사. 화면 안에 유지되며 내부 스크롤과 취소 동작 정상.

검수 도구가 보낸 `pointerType: touch`, `isTrusted: true` 이벤트가 대상 컨트롤에 도달하는 것을 확인했다. 도구의 임베드 뷰포트 좌표 오차를 보정했으며, 앱의 클릭 핸들러를 직접 호출하는 방식으로 통과시키지 않았다.

## 검증과 한계

관련 회귀 테스트 24개 파일·307개 테스트, 전체 타입 검사, 변경 파일 ESLint를 통과했다. 운영 빌드도 검증했다. 최종 재검수한 출석부·수납·팝업 설정·대시보드·소모품·콜&상담의 4가지 화면 크기, 총 24개 조합에서 본문 가로 넘침과 요약 숫자 침범이 없었다. 운영 체계 설정도 같은 4가지 크기에서 확인했다.

화면 캡처·DOM 측정·터치 실행 결과는 로컬 `logs/mobile-audit/`에 보관했다. 이 자료에는 실제 업무 데이터가 포함될 수 있으므로 저장소에 포함하지 않는다.

물리적인 iPhone·Android, 모바일 운영체제 키보드·날짜 선택기·푸시 권한, 다른 권한 계정은 이번 브라우저 검수 범위에 포함되지 않았다. 저장·발송·삭제 및 출결 상태 변경 같은 실제 업무 쓰기는 수행하지 않았으며, 편집기를 여는 것만으로 저장되지 않는지는 회귀 테스트로 확인했다. 모든 업무 변경 흐름이 실기기에서 통과했다는 의미는 아니다.
