# 결정 로그 — 신규 콜&상담 여정(전화·방문·등록 기록) · 신규생 정착 관리 보정

2026-11-11 · aywa-next 인계 이식 + Claude·Codex 검토 합의(원장 승인 *"코덱스와 협의하고 진행"*).
화면 = 방문·등록 점검(`/enrollment/visits`) · 상담 상세의 '전화·방문·등록 기록' 칸 · 신규생 관리(`/newcomers`).
신규생 정착 관리의 본문 결정은 [`newcomer-live-restoration.md`](newcomer-live-restoration.md)(다른 세션이 main에 올린 운영판) — 여기는 그 위에 얹은 보정만 적는다.

## 콜&상담 여정

- **기록은 서버 전용 표**(`enrollment_journey_records` + 변경 이력 `enrollment_journey_revisions` · s2_0063 · 정책 0개). 읽기 = 상담을 사용자 권한(RLS)으로 먼저 읽고 그 상담에 걸린 기록만 남긴다 · 쓰기 = `save_enrollment_journey` 하나(기록 + 이력 한 거래 · version 비교 · `/api/enrollment/journey`). 추정 날짜를 만들지 않고 옛 상담 행을 고치지 않는다. 등록 확정 기록은 상담 상태·수납·반 배정을 바꾸지 않는다.
- 🔴 **기록이 걸린 상담은 지울 수 없다**(집계 제외가 아닌 기록 — s2_0064 BEFORE DELETE 트리거 + 앱 사전 확인). 확인 근거·변경 이력이 함께 사라지고 전환 집계가 소급해서 바뀌기 때문. 잘못 넣은 기록 = '집계 제외', 중복 상담 = 병합. 집계 제외 기록만 남은 상담은 지워진다. 사전 확인은 안내일 뿐이고 '확인 → 삭제' 사이에 들어온 기록은 트리거가 막는다(저장은 상담 행을 FOR SHARE로 잡는다). 삭제 순서 = 상담 행 먼저 → 녹음 파일(거절된 상담의 녹음만 사라지지 않게).
- 🔴 **병합 = 한 거래 · 서버 전용 함수**(`merge_enrollment_consultations_with_journey` — service_role만 실행): 상담 행 잠금(id 순) → 진 쪽 상담의 기록을 이긴 쪽으로 → 종전 병합 함수(`merge_enrollment_consultations` — 병합 규칙은 한 벌). 🔴 앱에서 기록을 따로 옮기지 말 것(옮긴 뒤 저장된 기록이 진 쪽과 함께 지워진다 — 옛 `merge-move.ts`를 되살리지 말 것). 🔴 화면 계정(authenticated)에 실행권을 주지 말 것 — 병합 권한(신규 콜&상담 쓰기 · 읽기 전용 보기 거절)은 앱 게이트 `requireMergeWrite`가 본다. 요청자는 그 거래 안에서만 `request.jwt.claim.sub`로 밝힌다(지점 판정 `auth_tenant_id()`와 활동 기록의 '누가'가 화면에서 병합하던 때와 같게). 옛 병합 함수를 직접 부르면 기록이 걸린 진 쪽 상담에서 삭제 차단으로 멈춘다(조용히 지워지지 않는다).
- **방문·등록 점검은 고른 연도만 읽는다** — 상담 본문·기록은 그 해(+ 끝나지 않은 후속 업무·결과 확인 전 예약 · 그 해 상담의 기록 전부 · 기록이 걸린 다른 해 상담), 🔴 **같은 사람 판정은 지점 전체 상담의 열쇠 칸 넷**(id·연결 원생·이름·보호자 연락처). 묶음이 다른 해 상담을 거쳐 이어지고 반대 증거도 다른 해에 있을 수 있어, 열쇠까지 연도로 줄이면 방문 대상 수·전환율이 달라진다(`summarizeJourney`의 `identity`). 그 해 상담은 연말까지 읽는다(오늘까지가 아니라 — 월별 '미확인'). 새 기록을 걸 상담 선택지 = 그 해 + 바로 앞 해 접수 상담(더 오래된 상담은 그 상담 상세에서). 기록 목록 = 그 해 기록 + **그 해 전부터 끝나지 않은 일**(후속 업무 미완료 · 결과 확인 전 예약) — 요약의 '결과 확인 전 예약'·'후속 기한 경과'가 세는 줄이 목록에도 보인다.
- **침산 70개월 검증 자료**(`historical-baseline.json` · 2021–2026)는 침산의 집계다 — 침산에만 내려준다(`isChinsanTenant` · 서버가 판정). 다른 지점엔 탭도 서지 않는다. 코드에 지점 id를 적지 않는다.
- 학생 통합 기록의 '전화·방문·등록 확인 기록' 칸 = 그 학생에게 이어진 상담의 기록(집계 제외 기록은 뺀다 · 신규 콜&상담 권한 — 권한이 없으면 '권한 없음'으로, 조회 실패와 섞지 않는다).
- 학원 비서 DB 지도(`assistant/catalog/tables-extra.ts`)에 새 표 6개의 설명이 있다 — 표를 더하면 그 파일에도 한 줄(가드 `catalog.test.ts`).
- 새 병합 함수가 아직 없는 DB에서는 병합이 '준비하는 중' 안내로 멈춘다 — 옛 병합 함수로 돌아가지 않는다(기록 보호가 깨진다).

## 신규생 정착 관리 — main판 위의 보정

- **'전체 완료 체크표' 쓰기 = `canWriteChecks`** — 정착 관리 자료(담당·피드백) 조회가 실패하면 `canManage`·`canReport`는 끄지만 종전 체크표는 잠그지 않는다.
- **'과목 기본 담당' 선택지 = 그 과목에 기본 담당이 있을 때만**(누구인지 이름과 함께). 기본 담당이 없는 과목엔 선택지를 내지 않는다(없는 기본값을 고르게 하지 않는다). 단 이미 기본 담당을 따르던 학생인데 그 기본 담당이 없어졌으면 '과목 기본 담당 따름 · 지금 기본 담당 없음'으로 보인다(그대로 저장해도 '미지정'으로 굳지 않게). 기본 담당 표(`student_onboarding_manager_defaults`)를 고치는 화면은 아직 없다 — 운영 DB의 행(수학·영어·EiE)은 직접 넣은 것이다.
- 완료 메모·연결 상담은 신규생 관리 화면에서만 읽는다(`loadNewcomers`/`loadCheckRows`의 `withDetails`) — 운영실 신호·매일 기록 경로에는 싣지 않는다. 후속 관리 대상 조회가 실패한 대체 경로에서도 메모는 읽는다(메모가 '없다'고 보이지 않게). 90일 창 밖 후속 관리 학생은 id 청크로 따로 읽는다(B3). 담당만(scoped) 권한의 학생 줄은 자기 과목만 접어서 다시 센다. 읽기 강사뷰가 지운 담당 범위도 담당만으로 본다(#154).
- 저장 오류는 이 기능이 던진 한글 사유만 화면에 낸다(조회 도우미의 영문 원문은 로그로).
- 🔴 **신규생 관리 기록이 있는 과목은 흡수·삭제하지 않는다** — 과목별 완료 체크(0256a) · 과목별 담당 배정 · 적응 피드백. 옮기는 규칙이 없다(배정은 DB가 과목 변경을 막고, 체크·피드백은 같은 학생·항목이 양쪽 과목에 있을 때의 규칙이 없다). 흡수 첫머리 · 사용 현황(삭제 창이 흡수 버튼 대신 까닭을 보인다) · 과목 행을 지우는 마지막 저장(`saveOwnerSection`)이 본다. 과목 기본 담당 행은 세지 않는다(설정값). ⚠️ 흡수가 여러 요청으로 나뉘어 있어, 흡수 도중 그 과목에 새 기록이 저장되면 마지막 저장이 거절하고 과목 행이 남는다(기록은 지워지지 않는다).
- 강사 기본 권한은 '없음' 그대로 — 열 때는 원장이 역할·권한에서 '담당만'으로. 코드는 강사를 늘 담당만으로 다룬다.

## 아직 없는 것

- 과목 기본 담당 설정 화면 · 흡수 때 신규생 기록을 옮기는 규칙 · 메이크에듀 수강 연결 자동화(인계본의 `sync-enrollment-links`) · 약속·인계 옮기기(`moveCareToMergeWinner`)를 병합과 같은 거래로 묶기.
- 옛 병합 함수(`merge_enrollment_consultations`)의 화면 계정 실행권 — 새 앱이 배포된 뒤 거둘 수 있다(지금 거두면 배포 전 앱의 병합이 멈춘다).
