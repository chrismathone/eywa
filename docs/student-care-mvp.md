# 학생 관리 요약 첫 구현

학생 상세에 **관리 요약** 탭을 추가해 흩어진 재원·수납·학습·상담 기록을 함께 확인한다. 확인한 변화에서 필요한 지원을 검토하고 기존 상담에 담당자와 다음 확인일을 기록한다. 학생별 등급표 개발안의 첫 구현이며 운영 배포나 운영 DB 변경은 하지 않았다.

## 사용 흐름

1. 학생 상세 → 관리 요약을 연다. 유지관리 보드에서 학생을 선택해도 이 탭으로 이동한다.
2. 지원 검토 등급의 근거와 자료 부족 항목을 확인한다. 각 항목의 **근거 보기**는 기존 상세 탭으로 연결된다.
3. **지원 상담 기록**으로 기존 상담 작성 화면을 연다. 상담 쓰기 권한이 있을 때만 제공한다.
4. 미완료 후속 상담의 **처리·결과 확인**에서 기존 상담을 연다.
5. **관련 업무 확인**에서 기존 `staff_tasks`의 상담 후속조치·결석 확인·진도 이상 업무를 함께 본다. 담당자·기한·처리 상태를 확인하고 기존 상세에서 이력과 원본을 연다. 종료된 업무도 **원본·처리 결과 보기**를 제공한다.

2026-10-20 `main`에 추가된 공통 할 일 기능(0377a~0380a)을 재사용했다. 같은 학생 업무를 새 표에 복제하거나 실제 상담을 하지 않았는데 상담 기록을 자동 생성하지 않는다. 숙제 수행률 하락은 이번 단계에서 자동 배정하지 않으며 지원 상담에서 원인·담당자·후속일을 기록한다. 처리 완료와 학습·출결 개선은 별개임을 화면에 표시한다.

업무 목록은 사용자가 열 때 읽는다. 진행 중은 기한 순, 종료 이력은 종료 시각 순으로 최대 30건을 표시하고 전체 건수는 DB의 정확한 집계를 사용한다. 여러 종류·100개 원본 단위로 나눠 조회해도 전체 앞 30건을 고른다. 새로 확인 버튼으로 조치 후 상태를 다시 읽는다.

이번 카드는 DB를 읽는 기능이다. 카드를 열어도 업무 생성, AI 호출, 슬랙·노션 발송을 실행하지 않는다. 상담 작성·업무 처리는 기존 화면과 서버 권한 검사를 따른다.

## 표시와 계산

| 항목 | 첫 구현 | 자료가 부족할 때 |
| --- | --- | --- |
| 재원 이력 | 수강 구간 합집합의 등록일수와 현재 연속 구간. 반 이동 경계와 과목 중복 제거 | 휴원 이력 미차감을 명시. 현재 휴원이면 연속 구간 보류. 실제 출석일수로 부르지 않음 |
| 누적 수강료 | 청구서의 기록된 납부액, 원본 항목별 수강료, 수강료 환불기록, 청구 월 범위 | 이관 전 자료 누락 가능성 표시. 항목 합계 충돌은 금액 보류. 활성 환불·환불 내역 미수집 시 순납부액 보류 |
| 숙제 | 과목별 최근 28일과 직전 28일 교사 평가 평균, 평가·미기록 건수 | 두 기간 모두 4건 이상일 때 변화 계산. 과목 미확인은 비교 보류. 실제 0%와 미기록 구분 |
| 출결 | 최근 28일의 최신 정정 기록에서 결석·지각 횟수 | 예정 수업 분모가 없어 출석률·연속 결석을 계산하지 않음 |
| 학습 수준 | 과목·검사 종류별 최근 진단 레벨과 날짜 | 척도가 다른 레벨을 합치거나 반 이름으로 추정하지 않음 |
| 성적 | 입학일 이후 과목별 첫 기록과 최근 기록. 과목·시험 이름·만점이 같은 경우 원점수 차이 | 시험 난도 미보정 표시. 첫 기록을 입학 진단으로 간주하지 않음. 다른 시험이면 직접 비교 불가 |
| 학부모 의견 | 열람 가능한 최근 학부모 상담 요약과 날짜 | 직접 만족도 점수는 미수집. 문구를 긍정·부정 점수로 변환하지 않음 |

수강료 분류는 기존 프로그램 비용 제외 규칙을 재사용하지만 급여 배분용 부분환불 제외 규칙은 적용하지 않는다. MakeEdu의 `paid` 값에 환불이 이미 반영됐는지 확정되지 않아 다시 차감하지 않는다. 환불이 없다고 명시되고 항목·합계가 확인된 자료에서만 순납부액을 제공한다. 누적 납부액을 LTV나 이익으로 표시하지 않는다.

## 지원 검토 규칙

첫 버전의 세 신호는 과목별 숙제 평균 20%p 이상 하락, 최근 28일 결석 기록 2회 이상, 미완료 후속 상담 기한 경과다. 결석 2회는 연속 결석을 뜻하지 않는다. 서로 다른 신호 영역이 2개 이상이면 **집중 관리**, 1개면 **관찰**이다. 같은 영역의 여러 과목·여러 상담은 한 영역으로 센다.

신호가 없고 숙제 비교·최근 출결·최근 90일 학부모 상담 근거가 충분하면 **안정**, 부족하면 **판단 보류**로 표시한다. 신호가 있어도 부족한 자료는 별도로 표시한다. 금액·LTV·낮은 절대 성적·상담 키워드는 등급에 넣지 않는다. 현재 퇴원 의사나 긴급 요청은 담당자가 확인하며 자동 긴급 판정은 하지 않는다. 이는 검증 전 시범 규칙이며 확률이나 퇴원 예측 모델이 아니다.

기존 유지관리 보드의 위험 점수·정렬 계산은 이번 변경에서 교체하지 않았다. 보드의 위험 등급과 새 카드의 지원 검토 등급은 기준이 다르다. 보드 전체를 새 근거와 규칙으로 이관하는 것은 다음 작업이다.

## 권한과 데이터 처리

- 로그인 세션과 기존 권한 체계를 사용한다. 학생 메뉴 권한, 학원 범위, 담당 학생 범위를 확인하고 범위 조회 실패 시 차단한다.
- 수납 권한이 없으면 청구서를 조회하지 않는다. 상담 권한이 없으면 상담을 조회하지 않으며, 담당자 제한이 있으면 다른 담당자의 상담을 제외한다. 학생 전체 열람 권한이 상담 제한을 풀지 않는다.
- 각 원본 조회에 학원·학생 조건과 정렬을 지정하고 1,000건을 넘겨도 페이지를 이어 읽는다. 서버 요청 안에서만 캐시하고 사용자 간 결과를 공유하지 않는다.
- 원본 SQL 오류·학생 개인정보를 로그로 남기지 않는다. 조회 실패, 권한 부족, 기록 없음, 실제 0을 구분한다. 상담 원문은 허용된 최근 학부모 상담의 짧은 요약만 카드에 표시한다.
- 학생 요약 집계는 기존 로그인 세션을 사용한다. 업무는 기존 서버 전용 `staff_tasks` 조회를 재사용하므로 서버의 기존 서비스 키를 사용하며 브라우저에는 전달하지 않는다. 학생 열람 범위와 업무 열람 범위를 모두 통과해야 한다. 업무 현황 권한이 없으면 본인에게 배정된 것만, 상담 원본은 상담 담당 범위를 적용한다.
- 업무 연결을 위해 새 표나 SQL을 추가하지 않았다. 기존 할 일 SQL이 없는 검토 환경에서는 업무 패널에 조회 실패를 표시하고 학생 카드 자체는 유지한다.
- PR 31의 미적용 시범 SQL에서 상담 권한 검사 오류를 수정했다. 공용 `auth_menu_access`에는 상담 기본값이 없어 별도 `management_agent_access`로 실제 상담 메뉴의 역할 기본값·마지막 유효 개인/역할 예외를 반영한다. 학생 역할의 일반 메뉴 부여는 차단하며 비활성·알 수 없는 사용자는 거부한다. 운영 DB 적용은 실행하지 않았다.

## 검증

- 2026-10-20 후속 연결: 관련 **30파일 240개** 기능 검사, 격리된 메모리 PostgreSQL의 권한·상태·알림 원자성 **71개** 통과. 운영 DB나 실제 학생 자료를 사용하지 않았다.
- 학생·업무 권한의 교집합, 다른 상담 담당자와 지점 제외, 원본 1,001건, 연결 담당자 1,001건, 최대 100개 ID 청크, 전체 건수와 앞 30건의 차이, 실패·빈 목록 구분, 응답 역전 취소, 공유 캐시 금지를 검사했다.
- 실제 React 화면을 가상 응답으로 구동해 관련 업무 열기 → 종료 이력 → 기존 상세 → 원본 링크 → 목록 복귀를 Chrome에서 확인했다. 1,440px·390px 화면에서 가로 넘침과 실행 오류가 없었다. 로그인·실제 DB 통합 시험을 대신하지 않는다.
- 변경 파일 ESLint 통과, Next.js webpack 컴파일·페이지 생성 완료. GitHub Actions는 계정 결제 실패/사용한도 사유로 작업을 시작하지 못했다(코드 검사 실행 전 중단). 로컬 검사와 구분한다.
- 신규 계산·권한·화면 검사 **36개**, 관련 기존 기능을 포함한 **19파일 190개 통과**. 실제 학생 대신 가상 기록을 사용했다.
- 사례: 과목 중복·반 이동·휴원 정보 부족·잘못된 날짜, 과목별 숙제·미기록, 출결 정정, 다른 시험 비교 금지, 부분환불 이중 차감 방지, 합계 충돌, 타 학원·미담당 접근 차단, 별도 수납·상담 권한, 1,000건 초과, 조회 실패와 창 안 이동.
- 후속 작업에서 개발용 예시의 `subjectKeys` 누락 3건을 수정했고 전체 TypeScript 검사를 통과했다.
- 실제 컴포넌트와 기존 스타일을 가상 데이터로 렌더링하고 Chrome의 1,440px·390px 화면을 확인했다. 모든 항목이 표시되고 가로 넘침이 없었다. 로그인한 운영 환경의 종단간 검증과 구분한다.
- Next.js webpack 빌드의 컴파일·페이지 생성을 확인했다. 저장소의 기존 설정이 빌드 시 타입 검사를 생략하므로 위 타입 검사 결과와 별도로 해석한다.
- 커밋 전 검토에서 상담 담당자 제한, 창 안 링크, 잘못된 날짜·공백 숫자, 학원별 과목 이름을 보완하고 해당 경계 사례를 재검증했다. 과목명은 기존 학원 설정을 읽으며 새 표시용 상수를 만들지 않는다.

## 다음 구현

1. 기존 유지관리 보드의 일괄 계산을 새 과목별 근거와 자료 충족도 규칙으로 맞춘다. 학생 수만큼 상세 조회를 반복하지 않고 일괄 읽기와 결과 대조로 검증한다.
2. 최신 공통 `staff_tasks`를 기준으로 숙제 하락 등 추가 신호의 담당·기한·재평가를 연결한다. PR 31의 별도 시범 사건과 공통 업무의 중복 생성·알림을 통합 정리한 뒤 활성화를 검토한다. 현재 시범 에이전트는 기본 꺼짐이며 이번 학생 카드 연결이 이를 켜지 않는다.
3. 직접 만족도 입력과 추적 시점, 비교 가능한 입학 평가, 휴원 이력, 수납·환불 원장 대조를 보강한다.
4. 권한별 검토 환경 대조 후 운영 적용 승인을 받아 관찰 모드로 시작한다. 외부 알림과 운영 배포는 별도 승인 범위다.
