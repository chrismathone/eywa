## R1: 출결 경로는 그대로, 승인 시 관측과 경고

Claude의 지적대로 행별 배타 사건 잠금은 여러 줄 출결에서 잠금 순서 역전과 기존 실패 격리 밖의 오류를 만들 수 있다. v3의 트리거 잠금 제안은 철회했다. 0349b의 관측 함수·트리거 정의는 변경하지 않는다. intake의 기존 사건 키 획득만 최신 결석 검증보다 앞선 별도 SQL 문장으로 옮긴다.

Claude가 허용한 두 대안 중 **승인 시 경고**를 선택했다. `0347a_makeup_command.sql`은 예외가 전체 트랜잭션을 롤백한다고 명시하며 실제로 예외를 잡지 않는다. 관측 직후 fail을 쓰면 신규 source_conflict도 사라지므로 관측과 경고를 성공 결과에 함께 커밋한다. 승인·분량 정책은 유지하며, 열린 확인 항목은 기존 assert_closable로 종결을 차단한다. 확인 항목이 해결됐다는 의미로 승인 성공을 표시하지 않는다.

현재 CommandForm은 일반 warnings를 표시하지 않는다. 승인 warnings 코드·확인 항목의 화면 매핑, 저장 후 toast와 replay 보존까지 P2에 포함했다. 접수·승인 모두 관련 case를 최초 잠금부터 id순으로 모아 잡는 설계 및 실제 병행 시험을 관문으로 뒀다. 긴 출결 트랜잭션이 접수·승인 커밋 모두를 가로지르는 한계는 숨기지 않는다.

## R2: 강사 화면 범위를 명단과 맞춤

DB는 로그인 계정의 범위를 판단하지만 대시보드 강사축은 effectiveTeacherId이므로 DB 범위를 그대로 보여주는 v3 문장을 철회했다. DB가 허용한 참여 중 **그 강사의 이번 주 담당 반의 참여 ∪ 그 강사가 실시하는 참여**만 표시한다. 관리자 뷰는 허용 전체, 담당 반0개 강사도 본인 실시 참여는 표시한다. 반 없는 참여는 관리자 또는 본인 실시 강사에게만 확인 필요로 표시한다.

겸직·다른 강사 뷰와 내 반 학생이 다른 강사/다른 반에서 받는 참여의 누출 방지를 수용 기준10에 넣었다. 기존 예약 주 기준과 새 RPC 오늘 기준의 차이는 유지·기록한다.
