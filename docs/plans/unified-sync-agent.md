# EYWA 통합 연동 앱 상세 설계

클래스노트·makeedu·영상 보관을 Windows 설치형 앱 하나로 설치하고 관리한다. 연동 PC에서 ZIP을 풀거나 스크립트를 실행하는 절차를 없애고, 웹의 `학원 설정 → 연동 → 연동 PC`에서 설치·지점 연결·상태·로그·업데이트를 관리한다.

상태: 2026-10-08 최초 작성한 **구현 기준 및 검증 계획**이다. 이후 구현한 1.0.0의 실제 동작·완료 범위·미실행 항목은 [운영 안내](../../apps/sync-agent/README.md)와 [수용 검증 보고서](../_audit/sync-agent-acceptance-2026-10-08.md)를 따른다. 아래 표에는 아직 제공하지 않는 확장 옵션도 있으므로 구현 완료 목록으로 해석하지 않는다. 운영 전환 전에는 기존 정상 경로를 유지한다.

## 확정된 사용자 요구사항

| 항목 | 기준 |
|---|---|
| 배포 | Windows 설치 EXE 하나. 클래스노트·makeedu별 설치 파일을 따로 관리하지 않는다. |
| 실행 | 통합 앱 하나가 연동별 기능을 관리한다. 연동별 오류와 무거운 작업은 내부적으로 격리한다. |
| 최초 연결 | 웹에서 받은 랜덤 12자리 지점 코드를 입력한다. 지점 ID·DB 주소를 사용자가 입력하지 않는다. |
| 설정 위치 | 웹의 연동 탭 안에 다운로드·코드·담당 PC·로그를 둔다. 현재 makeedu 탭의 담당 PC 카드를 이전한다. |
| 실행 허용 | 운영 측 허용, 지점의 기능 설정, PC의 일시 중지/선택 상태를 모두 따른다. |
| 앱 설정 | 로그인 시 자동 실행, 트레이 실행, 시작·중지, 연동 설정, 업데이트와 로그 옵션을 제공한다. |
| 업데이트 | 사용자 클릭 없이 새 정식 버전을 내려받고 검증한 후 유휴 시 적용한다. |
| 중복 차단 | PC 안의 중복 실행과 같은 지점을 맡는 여러 PC를 모두 막는다. |
| 웹 확인 | 지점에 귀속된 상태·로그·버전·업데이트 이력을 웹에서 확인한다. |
| 권한 | 설정 변경은 기존 연동 설정 권한을 사용한다. 화면을 숨기는 것 외에 서버에서도 검증한다. |
| 기능 동등성 | 기존 클래스노트·makeedu·Google Drive 영상 워커의 모든 운영 기능과 상태를 이관한다. [기능 대조표](./unified-sync-agent-parity.md)의 누락/미검증 항목이 있으면 기존 워커를 제거하지 않는다. |

코드 수명에 대한 선택은 아직 답변이 없으므로, 아래 설계는 **12자리 숫자·15분 유효·1회 사용**을 기본안으로 삼는다. 사용자가 지점별 고정 코드를 선택하면 이 항목을 다시 정한다. 코드는 최초 등록에만 사용하며 설치 후에는 기기 자격증명으로 연결을 유지한다.

## 사용자 화면과 동선

### 웹의 연동 PC 내부 탭

기존 `slack / makeedu / sheets / video` 내부 탭에 `agent`를 추가한다. 경로는 `/owner?tab=sheets&sub=agent`, 화면 이름은 `연동 PC`로 통일한다.

| 구역 | 내용과 동작 |
|---|---|
| 설치 | `Windows용 연동 앱 다운로드`, 정식 버전, 배포일, 지원 환경, 설치 안내 |
| 지점 코드 | `연결 코드 발급`, 12자리 표시·복사, 남은 유효시간, 재발급. 발급/조회에는 설정 변경 권한이 필요하다. |
| 담당 PC | 등록 기기 이름, 온라인 상태, 마지막 통신, 앱 버전, 시작 시각, 연결 해제·PC 교체 |
| 연동 상태 | 허용된 항목만 표시. 대기·처리 중·중지·연결 확인 필요·오류를 구분한다. |
| 최근 기록 | 연동/심각도/기간/작업 ID 필터. 마지막 성공과 마지막 오류를 따로 표시한다. |
| 업데이트 | 현재 버전, 다운로드/적용 상태, 미룬 사유, 실패·복귀 기록 |

makeedu 탭에는 수납 대조 안내, 자동 동기화 설정, `지금 동기화`, 실행 결과/이력을 유지한다. `동기화 담당 PC` 카드는 통합 탭으로 옮기고 짧은 `연동 PC 관리` 링크만 둔다. 앱의 공통 상태와 makeedu 업무 실행 이력을 섞지 않는다.

전체 기능이 꺼져도 이미 등록한 PC는 해제할 수 있어야 한다. 이 경우 공통 PC 관리만 제공하고 꺼진 연동 이름이나 내부 역할을 일반 화면에 나열하지 않는다. 등록 PC도 허용된 PC 연동도 없는 지점에는 설치를 권유하는 빈 기능을 노출하지 않는다.

다운로드 버튼은 실제 게시된 정식 설치 파일이 있을 때만 활성화한다. 개발 중인 파일이나 가짜 링크를 최신판으로 표시하지 않는다. 설치 파일에 계정 정보, `.env.local`, 개인 정보, 개발용 인증서/서명키를 포함하지 않는다.

### 앱 첫 실행

1. 중복 앱 실행을 검사한다. 이미 실행 중이면 기존 창을 연다.
2. 저장된 기기 자격증명이 있으면 서버에서 유효성을 확인한다. 없으면 코드 입력 화면을 표시한다.
3. 12자리 코드 입력은 공백·표시용 하이픈만 제거하고 숫자 12자리를 검증한다. 앞자리 0도 보존한다.
4. 서버가 코드를 확인해 지점과 설치 시도 번호를 연결한다. 코드를 소비하는 등록은 한 트랜잭션으로 수행한다.
5. 서버가 반환한 지점 이름을 화면에 명확히 표시한다. 다른 지점이면 작업 시작 전에 연결을 취소할 수 있다.
6. 기존 설치를 발견하면 전환 절차를 실행한다. 현재 작업을 마치고 기존 작업 스케줄러와 실제 자식 프로세스가 종료된 것을 확인한다.
7. 필요한 외부 계정과 권한을 점검한다. 각 계정은 이 지점의 설정만 사용한다.
8. 사용 가능한 연동과 기본 옵션을 보여주고 연결을 완료한다. 첫 연결만으로 학부모에게 시험 메시지를 발송하지 않는다.

코드가 틀림/만료/사용됨인 경우에는 공통 안내를 제공해 지점이나 코드 존재 여부를 열거할 수 없게 한다. 이미 등록된 PC가 있는 정상 관리자에게는 웹에서 해당 기기와 교체 절차를 보여준다. 코드와 자격증명은 명령행·로그·URL·클립보드 자동 기록에 남기지 않는다.

## 설정의 적용 범위

| 설정 | 기본안 | 저장 위치와 제한 |
|---|---|---|
| Windows 로그인 시 자동 실행 | 켜짐 | 해당 Windows 사용자 설정. 앱 한 개만 등록한다. |
| 시작 시 트레이로 실행 | 켜짐 | PC 설정. 재부팅 후 팝업이나 콘솔 창을 반복해서 열지 않는다. |
| 창 닫기 | 트레이 유지 | `앱 종료`와 구분한다. 종료 시에는 진행 작업 상태를 안내한다. |
| 연동 전체 일시 중지 | 해제 | 기간 지정 또는 직접 재개. 재부팅·업데이트가 중지를 해제하지 않는다. |
| 연동별 일시 중지 | 해제 | 서버가 허용한 연동을 더 제한할 수 있다. 금지된 연동을 켤 수 없다. |
| 클래스노트 실제 발송 | 기존 지점 설정 유지 | 기존 발송 안전 스위치와 시간창을 그대로 적용한다. 앱 중지와 별개다. |
| makeedu 정기 동기화 | 기존 지점 설정 유지 | 초기 시간은 기존 06:00/18:00 KST. 수동 요청과 정기 동기화는 구분한다. |
| makeedu 접속 점검 | 기존 08:30 KST | 실패 시 반복 로그인을 몰아 하지 않는다. |
| 자동 업데이트 | 켜짐 | 정식 채널만. 운영에서 긴급 중단할 수 있다. |
| 업데이트 시간 | 유휴 시 | 사용자가 적용 허용 시간을 지정할 수 있다. 진행 작업을 강제 종료하지 않는다. |
| PC 이름 | Windows 이름을 초기값으로 사용 | 표시용. 이름으로 기기를 인증하거나 중복을 판정하지 않는다. |
| 로컬 로그 | 기존 설정 보존 | 기존 클래스노트 기본은 30일·파일 회전 20MiB. 새 공통 진단 대기열은 최대 100MB로 제한하되, 기존 업무 이력을 업데이트 때 정리하지 않는다. |
| 웹 운영 로그 | 30일 | 서버 정책. 권한 변경·기기 교체 감사 기록은 기존 감사 보관 정책을 따른다. |
| 진단 상세 기록 | 기본 꺼짐 | 시간 제한 30분. 민감 정보 제거를 해제하는 옵션은 제공하지 않는다. |

연동 계정/자동 실행/적용 시간 등의 설정은 저장 전 검증한다. 기기 인증키, 서버 주소, 실행 파일 경로, 임의 SQL/명령어는 일반 설정으로 노출하지 않는다. 허용되지 않은 설정 키와 잘못된 값은 서버에서 거절한다.

실행 가능한 연동 = 서버 허용 ∩ 지점 모듈 사용 ∩ 연동별 업무 설정 ∩ 유효한 기기 등록 ∩ 실행 잠금 ∩ 지원 버전 ∩ PC의 실행 선택이다. 각 업무의 세부 발송 권한·시간창·학생 범위·중복 방지 규칙도 작업 직전에 계속 적용한다.

기존 `makeedu 자동 동기화 OFF`는 수동 실행까지 금지한다는 뜻이 아니다. `연동 전체 사용`, `정기 동기화`, `수동 동기화`의 의미를 구분한다. 클래스노트의 실제 발송 OFF도 읽음 확인/안전상 회수와 같은 기존 업무 규칙을 임의로 바꾸지 않는다.

서버 설정 변경은 버전 번호를 가지며 20초 이내 다음 조회에 반영하는 것을 목표로 한다. 긴급 중지·기기 해제는 새 작업 승인에서도 검사한다. 이미 외부 서비스에 접수된 요청을 소급해서 취소할 수 있다고 표시하지 않는다.

## 인증과 지점 격리

### 연결 코드

- 암호학적 난수로 숫자 12자리를 생성한다. 중복은 DB 고유 제약과 재생성으로 처리한다.
- 서버에는 코드 원문 대신 서버 비밀키 기반 검증값을 보관한다. 코드 원문은 발급 시 권한 있는 화면에만 전달한다.
- 지점당 미사용 활성 코드 하나만 허용한다. 재발급하면 이전 미사용 코드가 무효가 된다.
- 기본 유효시간은 서버 시각 기준 15분, 사용 횟수는 1회다. 화면의 초시계는 안내이며 서버가 최종 판정한다.
- 발급 시 현재 지점과 설정 권한을 서버에서 확인한다. 클라이언트가 전송한 tenant ID를 그대로 사용하지 않는다.
- 입력 실패는 IP·설치 시도·전체 트래픽을 기준으로 제한한다. 공격자가 틀린 코드를 던져 특정 지점을 영구 잠그는 방식은 피한다.
- 등록 응답이 유실되어 같은 설치가 재시도하면 새 PC를 만들지 않는다. 기기 소유 증명과 등록 시도 ID가 일치할 때만 결과를 복구한다.
- 원문을 저장하지 않으므로 다른 브라우저에서 기존 원문을 다시 읽는 방식은 제공하지 않는다. 필요한 경우 재발급한다.

### 설치 후 기기 인증

- 등록 후에는 코드 대신 기기 전용 자격증명을 사용한다. 코드를 재발급해도 기존 등록 기기가 자동으로 끊기지 않는다.
- 비밀은 Windows 사용자 보호 저장소에 저장하고 서버에는 검증값/공개키를 보관한다. 일반 JSON이나 레지스트리 평문에 넣지 않는다.
- 서버는 기기 등록에서 tenant를 도출한다. 다른 지점 ID를 추가한 요청으로 작업·설정·로그 범위를 바꿀 수 없다.
- 로그/상태 전송, 작업 승인, 설정 변경 권한을 구분한다. 기기 키 하나가 사용자 권한 관리나 임의 DB 접근 권한이 되지 않는다.
- PC를 해제하면 이후 작업 승인·설정·민감 데이터 접근을 차단한다. 폐기된 키를 새 코드 발급만으로 복원하지 않는다.
- 앱 설정 변경은 짧은 관리 세션으로 보호한다. 트레이에서 상태 보기와 설정 변경의 권한을 구분한다.
- 설치 파일에는 공용 DB 비밀번호와 Supabase 서비스 키가 들어가면 안 된다. 지점 코드를 입력한 앱에 이 비밀들을 내려보내서도 안 된다.

관리자 기본 권한과 기존 위임 체계를 유지한다. `integration_settings`의 실제 권한 판정을 재사용하고, 코드 발급·기기 교체·설정 변경·로그 조회에 각각 서버 검증을 둔다. 지점 변경, 퇴사, 권한 회수 후 기존 브라우저/앱 세션의 변경 요청도 거절한다.

## 중복 등록과 중복 실행 차단

설치 파일을 다른 PC로 복사하는 행위 자체를 서버가 막을 수는 없다. 제품이 보장할 대상은 **같은 지점을 맡는 유효한 등록과 실행이 한 개뿐인 상태**다.

| 경계 | 차단 방법 |
|---|---|
| 같은 Windows 세션에서 두 번 실행 | 운영체제 단일 실행 잠금. 두 번째 실행은 기존 창으로 전달한다. |
| 다른 사용자 세션/다른 설치 폴더 | PC 잠금과 서버 실행 잠금을 함께 검사한다. 잠금 접근 실패를 허용으로 처리하지 않는다. |
| 같은 지점 두 PC 등록 | 지점당 유효한 담당 기기 하나라는 DB 고유 제약. 동시 코드 소비도 한 건만 성공한다. |
| 같은 등록 자격증명 복제 | 설치 식별과 소유 증명을 확인하며, 서버의 실행 인스턴스 잠금은 하나만 발급한다. |
| 기기 이름 변경/동일한 이름 | UUID 등 불변 식별자를 사용한다. hostname은 표시 전용이다. |
| 옛 PC 재접속 | 기기 해제·교체 세대를 검사해 이전 키/실행 세대를 거절한다. |
| 작업 중 재부팅/크래시 | 진행 작업의 확인/복구를 마친 후 새 작업을 시작한다. 오래된 PID만으로 살아 있다고 보지 않는다. |
| 구버전 스크립트와 동시 실행 | 운영 전환 단계에서 구 스케줄러·자식 프로세스와 구 자격증명을 정리하고 검증한다. 새 앱 잠금만으로 구 워커가 막힌다고 가정하지 않는다. |

서버 실행 잠금은 DB 트랜잭션으로 획득한다. 기본안은 20초 갱신·90초 유효이며 서버 시각을 기준으로 한다. 발급마다 증가하는 실행 세대를 갖고 모든 작업 승인·완료에 포함한다. 만료된 프로세스가 늦게 결과를 제출해 새 프로세스 상태를 덮지 못하게 한다.

서버 연결을 잃거나 잠금 갱신이 확인되지 않으면 새 작업을 시작하지 않는다. 장시간 동기화나 영상 처리 중에도 공통 상태 갱신은 별도 실행 흐름에서 계속된다. `makeedu`의 동기식 자식 실행이 상태 갱신을 멈추게 하지 않는다.

### PC 교체

1. 웹에서 현재 PC, 진행 작업, 마지막 통신을 확인한다.
2. 교체 요청은 현재 PC의 신규 작업 수신을 중단시킨다.
3. 진행 작업을 마치고 종료 응답을 받은 뒤 기존 등록을 폐기한다.
4. PC가 고장 나 종료 응답이 없으면 잠금 만료와 진행 작업 대조를 거친다. 불확실한 발송은 확인 대상으로 남긴다.
5. 새 연결 코드를 발급해 새 PC를 등록한다.
6. 구 PC가 돌아오면 연결 해제 상태만 표시하고 작업을 받지 않는다.

기기 교체와 단순 코드 재발급을 다른 동작으로 제공한다. 새 PC의 코드 입력이 조용히 기존 PC를 빼앗지 않게 한다.

## 작업 처리와 결과 불확실성

통합 앱은 하나의 설치·수명·업데이트를 갖는다. 내부의 연동 실행은 격리해 한 연동의 브라우저 충돌·자식 프로세스 지연이 나머지 연동의 상태 갱신을 막지 않게 한다. 같은 외부 계정으로 수행하는 충돌 가능한 작업은 순서대로 처리한다.

기본 상태는 `대기 → 승인됨 → 처리 중 → 성공/실패/확인 필요`다. 전원 종료·네트워크 단절로 외부 부작용의 발생 여부를 판단할 수 없으면 `확인 필요`로 남긴다.

- 학부모 발송·수납 관련 쓰기처럼 중복이 문제가 되는 작업은 업무별 고유 요청 키를 갖는다.
- 외부 서비스가 멱등 키를 지원하면 같은 키로 재시도한다. 지원하지 않으면 외부 결과를 대조하고 확인되지 않은 상태에서 자동 재발송하지 않는다.
- HTTP 2xx, 프로세스 exit 0, 살아 있는 heartbeat를 업무 성공의 동일한 증거로 취급하지 않는다.
- 부분 성공은 성공한 수신자/단계를 보존한다. 실패한 한 항목 때문에 완료된 전체 배치를 재실행하지 않는다.
- DB 기록 실패가 외부 게시 성공을 무효로 만들지는 않는다. 복구 시 외부 결과를 먼저 대조한다.
- 재시도 간격은 지수 증가와 분산을 사용하고 횟수/시간 상한을 둔다. 인증 실패·CAPTCHA·금지/권한 오류는 반복 재시도를 멈춘다.
- 시스템 절전·종료·강제 종료 후 복구는 최초 설치와 별도 경로다. 놓친 정기 실행은 중복 없이 필요한 최신 작업 한 번으로 합친다.
- 예약 실행 키는 서버 기준 날짜/슬롯으로 생성한다. PC 시간 변경·시간대 변경·일광절약시간으로 같은 실행이 두 번 생기지 않게 한다.

외부 서비스와 DB 사이에는 하나의 원자적 트랜잭션이 없으므로 무조건적인 정확히 한 번 발송을 약속하지 않는다. 외부 결과 대조와 `확인 필요` 처리가 수용 기준이다.

## 자동 업데이트와 복구

### 배포 규칙

정식 채널에 게시된 검증 완료 릴리스만 자동 업데이트 대상이다. 개발 중 수정/ZIP 생성 자체는 자동 배포 신호가 아니다. 버전에는 앱·연동 모듈·내장 실행 환경·지원 API/설정 스키마·최소 서버 버전 정보를 포함한다.

업데이트 파일과 릴리스 정보의 출처를 서명으로 검증한다. 체크섬만 함께 내려받아 비교하는 방식은 출처 검증을 대신하지 못한다. HTTPS, 배포 서명, 예상 앱 ID, 아키텍처, 단조 증가 버전 및 서버 최소 지원 버전을 함께 확인한다. 정식 설치 EXE의 Windows 서명도 배포 요건으로 둔다.

배포 도구는 검증된 설치/업데이트 도구를 사용한다. Windows 자체 포함 배포와 기존 Node/브라우저 실행 환경을 패키지 안에서 관리하는 방식을 우선 검토한다. 구현 시 [Microsoft 배포 문서](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)와 [Velopack 통합 문서](https://docs.velopack.io/getting-started/csharp), [코드 서명 지침](https://docs.velopack.io/packaging/signing)을 기준으로 구체적인 버전과 서명/복구 동작을 검증한다. 도구를 설치했다는 사실만으로 자동 복귀가 구현된 것으로 보지 않는다.

### 적용 순서

1. 새 버전 정보를 조회하고 서버/OS/실행 환경 호환성을 확인한다.
2. 현재 서비스는 계속 실행하면서 별도 임시 위치에 다운로드한다.
3. 서명·전체 해시·압축 경로·파일 목록·디스크 여유·설정 스키마를 검사한다.
4. 새 작업 수신을 중지하고 클래스노트·makeedu·영상 작업이 모두 종료되는 것을 기다린다.
5. 제한 시간 안에 비워지지 않으면 적용을 연기하고 기존 작업을 유지한다. 업데이트 때문에 외부 작업을 강제 종료하지 않는다.
6. 원자적인 버전 전환 기록을 남기고 새 버전을 시작한다. 이전 정상 버전과 설정 복구 지점을 보존한다.
7. 새 버전이 기동·인증·설정·서버 연결·업무 모듈 준비 점검을 통과할 때까지 실제 새 작업 수신은 잠근다.
8. 검증 성공을 서버에 기록하고 작업을 재개한다.
9. 실패하면 이전 정상 버전으로 되돌린다. 실패 버전은 격리해 같은 업데이트를 계속 반복하지 않는다.

업데이트 중 전원 종료 시 영속적인 전환 단계 기록으로 이전 정상 버전 또는 검증할 새 버전을 하나만 선택한다. 설치 중 앱 종료, 백신 파일 잠금, 디스크 부족, 다운로드 중단은 현재 버전의 삭제 사유가 되지 않는다.

현재 `kickVideoWorker()`와 `kickAttachmentRepair()`는 주 폴링과 별개로 진행된다. 폴링 종료만으로 유휴라고 판정하지 않고 이력 수집·직접 제출 훑기·다운로드·압축·재개 업로드·첨부 복구와 자식 프로세스까지 추적한다. 진행 작업의 원본/재개 상태와 확정된 Drive 계정·폴더는 버전 전환으로 바꾸지 않는다.

기존 설정·기기 자격증명·업무 중지 상태·작업 기록은 실행 파일 디렉터리와 분리한다. 압축에는 해당 파일을 덮어쓸 수 있는 경로가 없어야 한다. 절대 경로, `..`, 링크, 중복 이름, 대소문자 충돌, 과도한 해제 크기를 거절한다.

자동 복귀는 코드와 호환 가능한 설정을 대상으로 한다. 이미 발송된 글이나 변경된 외부 데이터는 코드 복귀로 되돌려지지 않는다. 서버 스키마는 전환 기간에 전후 버전을 함께 지원하고, 되돌릴 수 없는 스키마 변경과 워커 자동 배포를 한 단계로 묶지 않는다.

네트워크 단절을 새 버전 코드 결함으로 단정해 버전을 오가게 하지 않는다. 준비 점검의 실패 종류를 구분하고, 서버 장애는 업데이트 확정을 보류하거나 기존 정상 버전을 유지하도록 한다. 보안상 사용 금지된 버전으로는 자동 복귀하지 않으며, 이때는 중지 상태와 해결 안내를 표시한다.

## 로그와 웹 운영 상태

앱은 인증된 기기 경로로만 상태와 구조화된 이벤트를 전송한다. 서버가 기기 등록으로 지점을 결정하며, 요청의 지점 ID나 PC 이름으로 로그 소유자를 정하지 않는다.

| 필드 | 내용 |
|---|---|
| 식별 | 서버 tenant, device ID, 실행 instance ID, 이벤트 UUID, 실행 세대 |
| 시각 | 서버 수신 시각, 앱 발생 시각, 순번. PC 시각은 표시 참고용이다. |
| 실행 | 연동 종류, 업무 요청 ID, 앱/모듈 버전, 시작/완료 상태, 소요시간 |
| 결과 | 성공·실패 건수, 허용된 오류 코드, 재시도 여부, 확인 필요 여부 |
| 업데이트 | 이전/목표 버전, 다운로드·검증·적용·복귀 단계와 사유 코드 |

이름·전화번호·상담 내용·비밀번호·토큰·연결 코드·DB 주소·서명된 파일 URL·영상 내용·쿠키를 웹 로그에 싣지 않는다. 기존 stdout을 통째로 업로드하지 않는다. 허용 목록 기반의 구조화된 필드를 보내고 앱과 서버 양쪽에서 검증한다. 원문 오류가 필요한 로컬 진단에도 비밀 제거와 용량 제한을 적용한다.

인터넷이 끊기면 로컬의 제한된 전송 대기열에 보관한다. 재연결 시 이벤트 UUID로 중복 없이 이어 보낸다. 서버가 저장 확인한 항목만 전송 대기열에서 제거한다. 대기열 한도에 도달하면 오래된 일반 정보를 요약/정리하고 유실 건수를 남긴다. 감사 로그와 업무 상태의 영속 저장을 일반 디버그 로그 회전으로 지우지 않는다.

서버는 요청 크기·이벤트 개수·필드 길이·발생률·보관량을 제한한다. 진단 로그는 HTML로 실행하지 않고 텍스트로 렌더링한다. 다운로드 파일도 수식 주입/제어문자를 처리한다. 다른 지점 로그 조회, 임의 정렬/필터로 범위 탈출, 등록 해제된 키의 업로드를 차단한다.

웹에는 온라인/업무 정상/최근 성공을 따로 표시한다. PC가 살아 있지만 외부 로그인이 풀린 경우를 정상으로 표시하지 않는다. 상태가 오래되면 `마지막 확인 …`을 표시하고 성공 상태를 영구 유지하지 않는다. 같은 오류 알림은 묶고 복구 이벤트를 남긴다.

## 서버 데이터와 API 경계

| 데이터 | 주요 제약 |
|---|---|
| 등록 코드 | tenant, 검증값, 발급자, 만료·소비 시각, 등록 시도. 원문 없음. |
| 기기 | tenant, 불변 ID, 자격증명 검증 정보, 표시 이름, 등록/해제 정보. 유효한 담당 PC는 지점당 한 대. |
| 실행 잠금 | tenant/device, instance, 실행 세대, 서버 기준 만료. DB에서 원자적 획득·갱신. |
| 설정 | tenant 정책/PC 설정 구분, 버전, 허용 키, 변경자·변경 시각. |
| 작업 | 업무 고유키, 승인 세대, 상태, 시도 횟수, 단계별 결과, 불확실 여부. |
| 이벤트 | 서버에서 부여한 tenant/device, 이벤트 고유키, 허용된 필드와 보관 정책. |
| 릴리스 | 서명 검증 가능한 설치 파일, 버전/채널, 지원 범위, 게시/중단 상태. |

기기 등록·기기 인증·설정 조회·상태 갱신·로그 제출·작업 승인/완료·업데이트 조회를 별도 API로 나눈다. 임의 SQL 실행이나 임의 URL/셸 명령 실행 API를 만들지 않는다. 새 API는 입력 크기를 파싱 전에 제한하고, 인증·지점 범위·권한·실행 세대·입력 스키마를 검증한다.

테이블은 기본 접근을 닫고, 기존 사용자 RLS/권한 체계와 기기 전용 서버 경로를 분리한다. 기기가 서버 권한 계정을 흉내 낼 수 없어야 한다. 기기 자격증명은 자기 지점에 허용된 업무에 필요한 최소 자료만 받을 수 있다. 설정 응답에 원문 비밀키를 포함하는 경우에는 필요한 외부 계정의 범위를 별도 검토하고 평문 로그/캐시를 금지한다.

## 기존 코드에서 확인한 전환 과제

| 근거 | 현재 동작 | 새 앱 전환 기준 |
|---|---|---|
| `scripts/_classnote/watch-classnote-queue.mjs` | `DATABASE_URL`로 직접 DB 접근. 폴링·발송·읽음·영상 처리 관리. | 서버에서 지점 범위를 제한하는 업무 API/데이터 접근 계층으로 분리한다. 공용 DB 비밀을 앱에 배포하지 않는다. |

| `scripts/_classnote/setup-classnote-pc.ps1` | 스케줄러와 node 프로세스를 따로 종료/검증한다. | 최초 전환에서만 구 설치를 정리한다. 새 앱은 소유한 프로세스 트리만 관리한다. |
| `scripts/_makeedu/setup-sync-pc.ps1` | 정기 동기화·요청 감시·접속 점검의 스케줄러 3개. | 같은 주기/의미를 통합 스케줄러로 옮기고 중복 예약 실행을 막는다. |

**가장 먼저 해결할 전환 조건은 기존 DB 직접 접속이다.** 새 EXE 앞에 코드 입력 화면만 추가하고 공용 DB 비밀번호를 넘기는 형태로 구현하면 지점 코드와 로그 격리가 실제 보안 경계가 되지 않는다. 기존 워커가 가진 범용 접속 권한을 폐기하는 계획과 모든 사용처 목록이 필요하다. 공용 비밀번호를 무작정 바꿔 다른 서버/워커를 중단시키지 않는다.

구버전은 새 실행 잠금을 모른다. 신·구 워커가 섞여 있는 동안에는 통합 잠금만으로 중복 차단을 보장하지 않는다. 전환 시 기존 스케줄러 비활성화, 부모/자식 프로세스 종료 확인, 구 인증 경로 정리, 새 기기의 단독 실행 확인을 완료해야 한다.

2026-10-08 기존 ClassNote 실행기의 보완은 별도 [검증 기록](../_audit/unified-sync-agent-dryrun-2026-10-08.md)을 따른다. 이 보완의 갱신/유효시간은 30초/180초이며, 위 통합 앱 기본안 20초/90초와 구분한다. Makeedu의 실행 잠금 배선, 기기별 API 인증, 모든 업무 완료의 실행 세대 검증까지 구현됐다는 뜻은 아니다. `20261008073000_worker_execution_leases.sql`을 먼저 적용해야 수정 실행기가 작업을 시작할 수 있다.

## 적대적 검증과 출시 기준

별도 [실패 상황 및 수용 기준](./unified-sync-agent-failure-matrix.md)에 명시한 시험을 수행한다. 표의 항목은 구현/테스트 계획이며 통과 기록이 아니다.

기존 기능의 기준선은 [기능 대조표](./unified-sync-agent-parity.md)와 `scripts/_sync-agent/dryrun.cjs`의 가상 회귀 결과로 기록한다. 기존 `--post` 없는 워커도 DB 선점/복구 등을 수행하므로 운영 DB에 실행해 무변경 검증이라고 부르지 않는다. 가상 회귀 통과와 새 EXE 구현/수용 시험 통과는 별개다.

출시 순서는 인증·DB 제약과 경쟁 실행 시험 → 기존 기능의 지점 제한 API 분리 → 통합 실행/설정 → 설치/업데이트/복구 → 웹 연결/로그 → 구 설치 전환으로 한다. 실제 발송 기능을 켜기 전 관찰 모드에서 기존 처리 대상·토글·예약 실행과 대조한다. 원격 테스트만으로 연동 PC의 makeedu 신뢰 IP 로그인과 재부팅 복구가 통과했다고 판단하지 않는다.

첫 정식 설치에는 다음 증거가 필요하다.

- 동시 등록·동시 실행·구 PC 재등장 시험에서 유효한 담당자/실행자가 한 개다.
- 등록 코드만으로 다른 지점 데이터나 공용 DB 접속 권한을 얻을 수 없다.
- 업데이트 실패·파일 잠금·전원 종료 뒤에도 기기 연결과 이전 정상 버전이 복구된다.
- 업데이트와 재시작으로 중복 발송/중복 동기화가 발생하지 않는다. 불확실한 작업은 확인 상태로 남는다.
- 기존 지점의 실제 발송 스위치, 예약 시간, 모듈 OFF와 계정 설정이 보존된다.
- 웹에 설치 파일/코드/PC/로그가 실제 연결되고 makeedu 담당 PC 표시는 한곳에만 존재한다.
- Windows 로그인 자동 실행·트레이 종료·일시 중지 지속·외부 계정 재연결을 실제 연동 PC에서 확인한다.
- 정식 릴리스 서명·호스팅·철회·복귀 절차와 구 자격증명 정리가 완료된다.

서버 기기 등록 기능 배포, EXE 배포, 기존 워커 제거는 구분된 전환 단계다. 마지막 단계가 검증되기 전에는 통합 앱으로 운영 전환이 끝났다고 표시하지 않는다.
