## 적대적 검토 후 수정

- 휴강·폐강·비활성 반·현재 교시 없음에서는 과거 정규 시간표를 더하지 않고 보강만 계산한다.
- 1,000개 이후 최신 출결과 교시 정정을 읽는다. 다음 페이지 실패를 결석으로 취급하지 않는다.
- 실제 강사·등록·설정·시간표를 확인하지 못하면 연결된 보강 효과를 시수 기록 전에 보류한다.
  일반 출결 저장, 연결되지 않은 기존 보강, 직접 입력 시수는 보존한다.
- 연결된 시수는 엄격히 읽은 현재 설정으로 계산한다. 일반형과 침산 기본값이 섞이지 않게 한다.
- 실제 실시자는 보완 요청도 자기검토할 수 없다. 다른 관리자의 보완 요청·재제출은 독립 검사했다.
- 접수 후 승인 화면의 갱신 정체를 재현했다. 상세 명령은 데이터만 응답하고 권한 범위 내 자료를 다시 읽는다.
  늦은 조회·화면 이동 격리, 중복 제출 잠금, 같은 요청 ID 재시도, 활성 필드 저장 기준, 다른 폼의 미저장 보호를 검사했다.
- 부분 실패를 성공으로 세던 반복 검사와 불완전 SQL/화면 근거·다른 자료를 허용하던 패키지 검사를 강화했다.
  절대·상위 경로, 잘못된 해시·검토자·종료 코드, 바뀐 문서, 누락된 검사 근거를 거절한다.

## 남은 한계와 운영 도입

상세 저장 뒤 다른 창에는 변경 신호를 보낸다. 대시보드·시간표의 일부 표시용 서버 캐시는 최대 60초 뒤 반영되고,
같은 창의 뒤로 가기는 이전 화면을 보여줄 수 있다. SQL의 현재 권한·개정 검사와 실제 저장 판단은 유지한다.
다른 화면의 페이지 트리를 포함한 저장 응답, 세션 쿠키 갱신 같은 프레임워크 경로의 위험까지 해결했다고 주장하지 않는다.

원문 81개와 추가 19개를 보존한다. execution-matrix.csv의 83개 번호별 SQL/DB 부분 근거와
9개 합성 화면 검사는 원문 100개 전체 기대의 운영 수락 완료가 아니다. 영어·자동 안내·학부모 예약·TTL 등
후속 기능의 원래 기대는 미실행이다. Impeccable의 이전 운영 화면 검사를 재실행한 것으로 세지 않는다.

P6는 운영자가 rollout.md에 따라 백업·스키마 확인·원본 해시 사전 점검·사람 검토·소수 반 파일럿을
진행하는 단계다. 주기 대사 함수는 준비되어 있으나 운영 스케줄 등록은 이번 검증 범위 밖이다.
실패했던 실행과 이전 175개 파일 스냅샷의 결과는 외부 점검 근거에 과거 기록으로 남긴다.
