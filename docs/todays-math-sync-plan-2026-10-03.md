# 에이와 오늘의수학 계정과 반 동기화 계획

작성일 2026-10-03. **Claude·Grok 검토 조건을 반영한 최종 계획이며 사용자가 구현을 승인했다.** 사용자의 “어” 및 “계속” 지시에 따라 구현·검증을 시작한다. 이 문서는 계정 자동 활성화, 이메일 기반 기존 계정 연결, 퇴사와 지점 연결 해제에 따른 정지, 반과 수강 관계 동기화, 자동 로그인을 함께 설계한다. 운영 활성화는 본문의 검증·매핑·단계 배포 조건을 따른다.

## 사용자가 승인할 결과

**후속 지시 반영:** 운영 주소 `aywa.co.kr` / `today.aywa.co.kr`, 최초 지점 `침산`(원본 이름 `인재원 침산`). 에이와 토글 ON 시 대상 지점까지 자동 생성한다. 공통 서버 연결 설정만 한 번 입력하며 지점마다 환경변수/대상 지점 ID를 추가하지 않는다. OFF는 계정 이용 정지와 기록 보존, 다시 ON은 같은 지점 재사용이다. 아래 수동 binding/미리보기 단계는 기존 지점을 명시적으로 연결하는 예외 절차로 남기며, 신규 자동 생성의 운영 절차는 `todays-math-sync-operations.md`가 우선한다. 기존 계정 확인·승인과 충돌 보류 정책은 유지한다.

에이와를 직원 재직 상태, 지점의 서비스 활성화, 수학 반과 담당·수강 관계의 원본으로 삼는다. 선생님은 에이와에 로그인한 상태에서 오늘의수학 바로가기를 눌러 자신의 계정과 담당 반으로 들어간다. 퇴사 또는 지점 연결 OFF 시 해당 연동 계정은 삭제 없이 정지되고, 기존 세션과 직접 로그인도 제한된다. 자료와 연결 이력은 보존한다.

외부 큐·별도 SSO 상품·상시 서버를 새로 도입하지 않는다. 기존 Next.js API, Supabase Postgres, Vercel Pro 예약 실행을 사용한다. Supabase의 기존 DB 웹훅 기능을 설정할 수는 있지만 별도 인프라 설치가 전제는 아니다. 정상 전파는 수초를 목표로 하며 실제 지연과 사용량은 검증 단계에서 측정한다.

| 사용 장면 | 최종 계획의 기본 동작 |
| --- | --- |
| 지점 ON, 신규 수학 선생님 | 대상 자격을 확인해 계정 생성·활성화, 바로가기 자동 로그인 |
| 기존 이메일·이름 일치 | 기존 계정 우선, 동일인 확인·승인 후 계정 ID를 유지해 지점 전환 |
| 이름 불일치 또는 다른 연결과 충돌 | 기존 계정 유지, 해당 선생님 연결 보류, 해결 후 승인 |
| 지점 OFF 또는 퇴사 | 연결된 신규·기존 계정 모두 삭제 없이 정지, 기존 세션·직접 로그인 차단 |
| 반 이동·대강·수강 변경 | 실제 적용 상태와 기간에 맞춰 접근 변경, 과거 자료와 작성자 보존 |
| 에이와 장애로 자격 확인 불가 | 마지막 확인의 최대 60초 이후 연동 선생님의 조회·인쇄·채점 등 보호 기능 제한. 정상 확인이 다시 되면 다음 요청에서 회복하며 비연동 계정은 영향 없음 |

사용자는 2026-10-03에 **동일인 후보로 매칭한 뒤 기존 계정 본인 확인 또는 운영자 승인 후 지점 전환**하는 정책을 선택했다. 보류 중인 기존 계정은 아직 연동 관리 대상이 아니므로 해당 후보가 있다는 이유만으로 그 기존 계정을 정지시키지 않는다. 이후 사용자의 “어” 및 “계속”으로 전체 구현 계획도 승인되었다.

### 추가 승인 범위: 원생 상세의 오늘의수학 탭

2026-10-03 사용자 추가 지시: 에이와 **원생 → 학생 클릭 → 학생 정보**에 `오늘의수학` 전용 탭을 추가한다. 학생 로그인 화면을 뜻하지 않는다. 지점의 오늘의수학 기능이 켜져 있을 때만 탭을 표시하며, 기존 담당 학생 열람 권한과 서버 검증을 그대로 적용한다. 오늘의수학 관리자 DB의 동일한 sourceStudentId/지점 연결을 조회하여 연결 상태, 수강 반, 배정·완료 시험 수, 최근 학습 시각을 보여준다. 연결 전·조회 장애·기록 없음은 구분한다. 문제별 풀이 기록이 에이와에 영속 저장되는 역방향 이벤트 연동은 사용자가 지정한 **추후 단계**로 남긴다.

동기화 범위는 계정 자격·연결, 지점, 수학 반, 담당 및 대강 기간, 학생·수강 상태, 기존 연동 진도이다. 급여·수납·상담·개인 연락처 전체, 오늘의수학에서 만든 시험 결과를 에이와에 역으로 쓰는 기능은 포함하지 않는다. 개인 문서와 공용 문제은행을 다른 계정으로 자동 이전하지 않는다.

후속 사용자 요청(2026-10-03): **오늘의수학에서 문제를 풀면 에이와에 기록이 남는 역방향 연동을 추후 구현한다.** 현재 계정·관계·SSO 구현 다음 단계로 기록한다. 지점·학생·반의 고정 매핑을 재사용하고 풀이 시도 ID를 멱등 키로 삼아 문제 풀이/제출/채점 완료·재채점·취소를 구분한다. 점수·정오답·완료 시각과 이력 표시 범위는 후속 계약에서 확정하며, 이번 단계가 시험 결과를 이미 전송한다고 표시하지 않는다.

기존 `syncScope.ts`의 두 반 제한은 과거 운영 결정이다. 새 계정·담당·명단 동기화의 대상 범위와 자동 출제·학습 작업 실행 허용 범위를 분리한다. 이번 계획은 자격을 갖춘 수학 선생님과 실제 담당 관계를 연결하되, 기존 두 반 밖에 자동 출제를 확대하는 승인을 포함하지 않는다. 초기 시험도 두 반과 격리 fixture에서 시작한다.

이 분리는 현재 없는 게이트를 구현하는 작업이다. `runAutoDraft.ts` 등 자동 초안·출제 작업에 반별 허용 목록과 지점 ON 검사를 **명단 확대 전에** 넣는다. 새로 들어온 반에 자동 초안이 생기지 않는지, OFF 중 자동 작업이 멈추는지 검증한다.

## 기본 정책

### 대상 계정과 역할

자동 발급 대상의 추천 기본값은 **해당 지점의 재직 중인 수학 담당 선생님과 수학 겸임 선생님**이다. 아직 반이 배정되지 않은 수학 선생님도 계정은 활성화하고 빈 반 목록을 보여준다. 학생·퇴사자·승인 대기 직원·영어만 담당하는 직원은 자동 발급하지 않는다. 메뉴가 보인다는 이유만으로 과학·사무 계정을 자동 발급하지 않는다.

과목 정보와 실제 수학 수업 담당이 서로 다르면 충돌로 표시해 담당자가 정보를 바로잡는다. 영어만 담당한 직원에게 새 입구를 열지 않는다. 원장·관리자 계정은 명시적인 역할 매핑으로 연결하고, 강사를 임의로 지점 관리자나 플랫폼 관리자 권한으로 승격하지 않는다. 에이와의 역할과 오늘의수학의 legacy `role`·`branchRole`을 이름이 비슷하다는 이유로 그대로 복사하지 않는다.

가르칠 수 있는 역할은 에이와 `src/lib/permissions.ts`의 `ASSIGNABLE_TEACHER_ROLES`를 재사용한다. 이 목록은 `teacher`, `manager`, `master`, `admin`이며, 역할 판정과 재직·과목 판정을 따로 적용한다. 관리자 겸임 수학 교사를 누락시키지 않되 자동 발급의 기본 `branchRole`은 teacher이다. 관리 권한 연결은 별도 명시 매핑이다.

### 이메일로 기존 계정 연결

이메일은 앞뒤 공백 제거와 소문자 변환 후 후보를 찾는 데 사용한다. Gmail 점·별칭 제거 같은 공급자별 추측은 하지 않는다. 한 번 연결되면 `(issuer, eywaUserId)`가 계정의 고정 식별자가 되고, 지점 매핑은 별도로 관리한다.

- 같은 이메일의 기존 계정: 이름도 비교해 동일인 후보를 만든다. 이름은 Unicode NFC, 앞뒤 공백·연속 공백만 정규화하며 별명·유사 발음은 자동 일치시키지 않는다. 사용자 선택에 따라 후보의 본인 확인 또는 양쪽 지점에 권한이 있는 운영자 승인 후 기존 계정 ID를 유지해 해당 지점으로 전환한다. 이메일·이름 일치만으로 확인 절차를 생략하지 않는다.
- 없는 이메일: 충돌을 다시 검사한 트랜잭션 안에서 연동 계정 생성·매핑·발급 출처를 함께 기록한다. 더미·공통 비밀번호를 발급하거나 에이와 비밀번호를 복사하지 않는다.
- 이메일은 같지만 이름이 다르거나 비어 있는 경우, 다른 에이와 ID에 이미 연결된 경우: **기존 계정에 우선권을 주고 해당 선생님의 연결·자동 로그인을 보류**한다. 중복 계정을 만들거나 기존 계정의 이메일·비밀번호를 바꾸지 않는다. 해결 근거와 운영자 승인이 있어야 다시 연결한다.
- 기존 승인 대기·정지·거절·삭제 계정, 관리자 등 보호 계정: 자동 덮어쓰기·역할 하향·정지 해제 없이 충돌 처리한다. 다른 지점의 정상 계정은 동일인 확인과 전환 승인을 거친 별도 지점 이동으로 처리한다.
- 이메일 변경: ID 연결은 유지하고 원본 프로필 이메일만 갱신한다. 오늘의수학 로그인 이메일은 별도 확인 절차 없이 덮어쓰지 않는다. 이메일 충돌로 다른 계정을 다시 찾아 연결하지 않는다.
- 계정 삭제 후 같은 이메일로 재입사: 새 에이와 UUID는 새 신원이다. 과거 계정을 자동 승계하지 않고 연결 확인을 다시 한다.

기존 `eywaUserId` 연결은 이중 검사를 거쳐 새 연결 원장으로 이관한다. 단순 본인 연결 해제로 연동 관리 대상에서 빠져 OFF·퇴사 정지를 우회하지 못하도록 **관리 대상 계정 기록과 SSO 연결 설정을 분리**한다.

오늘의수학 가입도 이메일 본인 확인을 강제하지 않는다. 누군가 먼저 만든 승인 대기 계정을 이메일·이름 일치만으로 승인하면 그 계정의 기존 비밀번호를 가진 사람이 새 권한을 얻을 수 있다. 기존 계정은 승인 상태·발급 출처·본인 확인을 함께 검사한다. 명단 수입용 가상 계정, 로그인이 없는 연락처도 자동 연결 대상에서 제외한다.

승인자는 오늘의수학 운영자이며, 이미 대응 지점에 속한 계정의 연결은 그 지점의 승인 권한을 가진 운영자도 처리할 수 있다. 에이와 한쪽 지점의 권한만으로 독립 계정이나 타 지점 계정을 가져올 수 없다. 운영자 승인은 기존 계정 소유자가 그 선생님이라는 확인 근거를 포함해야 하고, 이름·이메일 비교만 다시 하는 승인은 허용하지 않는다. 소유권 확인이 안 되는 선점 의심·승인 대기 계정은 거절·삭제·이메일 변경으로 자리를 비우지 않고 기존 계정 우선 원칙에 따라 보류한다. 침해 여부가 확인되어 인증 수단 복구가 필요한 경우는 별도의 계정 복구 절차로 처리하고, 복구 완료·기존 세션 무효화 후 연결한다. 정상 소유가 확인된 기존 계정의 비밀번호를 연결만으로 일괄 폐기하지 않는다.

계정 복구는 오늘의수학의 플랫폼 운영자가 소유 확인 근거를 기록한 뒤 기존 `api/admin/users/[id]/password` 재발급을 수행하는 절차를 사용한다. 이 경로는 옛 비밀번호를 폐기하고 `sessionVersion`을 증가시킨다. 새 인증 수단은 확인된 주인에게만 전달하며 침해 의심 외부 로그인 연결도 함께 점검한다. 현재 자동 이메일 확인·메일 발송은 없으므로 운영자가 인증 수단 소유 증명이나 연동 이전 승인·실사용 이력 등 독립 근거를 확보해야 한다. 이름·이메일 일치나 구두 확인만으로 복구하지 않는다. 승인 대기 계정의 정상 승인과 연결 승인은 별도 조건으로 검사한다. 비밀번호 없는 연동 전용 계정에는 이 비밀번호 재발급 경로를 차단해 인증 방식이 조용히 바뀌지 않게 한다.

원본 이메일과 오늘의수학 로그인 이메일의 불일치는 운영 확인 목록에 표시한다. 주소 선점이나 잘못 입력한 주소가 기존 계정을 점유하면 자동 발급은 해결 전까지 보류될 수 있다. 이 경우 기존 계정 우선 정책을 유지하며 자동으로 계정을 빼앗거나 중복 생성하지 않는다.

보류 건에는 충돌 사유, 양쪽 ID, 지점, 후보 버전, 해결 담당자, 승인 이력을 남긴다. 승인 순간 최신 원본과 계정을 다시 읽고, 그 사이 이메일·지점·연결 상태가 바뀌면 승인을 무효화해 재검토한다. 지점 전환은 구지점 관리 연결 종료·기존 세션 취소·현행 반 권한 제거를 먼저 확정하고 새 지점 연결을 연다. 기존 자료는 소유·지점별로 유지하며 일괄 이동하지 않는다. 구지점에 속한 유일 관리자 등의 운영 의무가 있으면 해소 전까지 보류한다.

연결 상태는 후보·보류·확정·종료로 관리하고 이용 가능/정지 사유는 별도 계산한다. 한 오늘의수학 계정에는 현재 유효한 관리 연결을 하나만 허용하되, 종료된 연결·승인 이력은 여러 건 보존할 수 있게 한다. 승인된 새 UUID 연결이나 지점 이동 때 연결 세대를 바꾼다. 뒤늦게 온 구지점·구연결 사건은 종료 이력과 세대를 검사해 새 연결의 정지·활성화 상태를 덮지 못하게 한다. 과거 정지 사유를 자동 삭제해 새 연결을 승인하지는 않는다.

### 정지와 재활성화

유효 이용 권한은 `지점 ON AND 재직 active AND 대상 과목/역할 AND 연결 확정 AND 원본 자격 유효 AND 로컬 승인·정지·삭제 검사 통과`로 계산한다. 사유는 `tenant_disabled`, `staff_inactive`, `subject_ineligible`, `source_removed`, `mapping_conflict`, `source_stale` 등으로 구분하고, 기존 수동 정지·삭제·거절 상태와 별도로 보관한다.

OFF는 그 지점에 연동된 신규·기존 선생님 계정 모두에 적용한다. 사용자 행을 삭제하지 않으며 관련 자료, 매핑, 과거 담당 기록을 보존한다. 실제 권한은 지점 차단 플래그로 즉시 닫고 개별 계정 상태 갱신을 진행해 대량 처리 중 빈틈을 줄인다. 수신 측의 모든 로그인 방식, 세션 확인, 페이지/API/서버 액션이 같은 판정을 사용한다.

다시 ON 해도 이 설정에 따른 정지 사유만 제거한다. 여전히 퇴사·부적격·수동 정지·거절·삭제 상태면 활성화하지 않는다. 복직 역시 모든 조건을 다시 평가한다. 연동의 계정 삭제 전파는 금지한다. 소스에서 삭제되거나 지점에서 제거된 계정은 정지한다.

신규 연동 계정에만 최소 권한과 발급 승인을 명시한다. 기존 계정의 `approvalStatus`, `suspendedAt`, `deletedAt`, 비밀번호를 upsert 기본값으로 덮어쓰지 않는다. 관리 기록과 삭제 흔적은 계정 삭제의 연쇄 삭제 대상에서 제외한다. 플랫폼 복구용 계정은 일반 교사 관리 계정으로 편입하지 않으며, 이미 겹쳐 있으면 별도 복구 계정과 교사 계정을 분리한 후 연결한다. 연동된 교사에게 OFF 예외를 주는 방식으로 해결하지 않는다.

보호 계정 분리에는 서로 다른 확인된 이메일을 사용한다. 기존 `User.email`에 가짜 내부 이메일을 넣거나 같은 이메일의 두 계정을 자동 생성하지 않는다. 이메일 재사용으로 기존 연동 계정이 주소를 점유한 경우도 자동 교체 없이 보류·확인 후 해소한다. 실제 연락 이메일과 고정 연동 ID는 원장에 따로 둔다. 플랫폼 관리 계정은 교사 관리 원장에 넣을 수 없고, 원장에 편입된 교사 계정에 플랫폼 관리 권한을 부여할 수도 없다.

오늘의수학 `src/app/api/admin/users/[id]/route.ts`의 정지 해제는 로컬 수동 정지만 해제한다. 연동 정지 사유·접근 취소 세대·원본 자격 만료를 지우거나 줄이는 권한을 주지 않는다. 마지막 활성 원장의 수동 정지 제한도 연동 회수의 예외가 아니다. 지점 차단은 이 관리 화면의 성공 여부와 무관하게 먼저 적용하고, 개별 프로필·승인·이메일 처리 실패로 되돌리지 않는다. 모든 로그인과 보호 요청은 합산된 유효 자격을 검사한다.

수동 정지의 원본 값은 `manualSuspendedAt` 등 별도 필드로 이관하고, 기존 정지 계정은 수동 정지로 보존한다. 기존 `suspendedAt`에는 수동·지속 연동 정지의 합산 결과를 호환용으로 반영한다. 두 사유가 모두 없을 때만 비우며 DB 제약/트리거와 공통 갱신 경로로 임의 해제를 막는다. 이는 잘못된 구형 배포에서도 이미 적용된 정지가 쉽게 풀리지 않게 하는 추가 보호다. 동적 자격 만료·반 권한·SSO 재사용까지 구형 코드가 보호한다고 보지는 않는다.

OFF→ON, 퇴사→복직이 빠르게 이어져도 과거 세션이 되살아나면 안 된다. 원본의 지점·직원별 **접근 취소 세대 번호**를 증가시키고, 수신 측 세션의 세대·`sessionVersion`을 비교한다. 최신 상태만 합쳐 처리하더라도 취소가 있었던 사실은 버리지 않는다.

### 지점과 반 및 학생 관계

에이와 지점과 오늘의수학 지점은 ID로 명시 연결한다. 지점 이름으로 추정하지 않는다. 한 계정의 지점 변경은 이전 지점 권한 취소를 먼저 확정한 뒤 새 지점 권한을 부여한다. 충돌한 매핑은 보류하며 다른 지점의 자료·개인 문서·관리자 권한을 함께 옮기지 않는다. 현재 원본이 표현하지 못하는 동일 계정의 동시 다지점 근무는 임의로 합치지 않고 명시적 충돌로 관리한다.

현재 `Class`에는 지점 ID가 없고 `ownerScope.ts`가 작성자 계정의 현재 `branchId`로 반·시험의 지점을 추론한다. 따라서 계정의 지점만 바꾸면 과거 반까지 새 지점 관리자에게 보일 수 있다. **지점 전환 전에 운영 데이터의 지점을 작성자의 현재 소속과 분리한다.** 반에는 명시적 지점/연동 binding을, 학생 수강·시험·진도에는 안정된 반·지점 문맥을 기록한다. 원본 소속이 불명확한 과거 자료는 보류해 확인하며, 개인 작업물은 기존 개인 소유로 남긴다. 원래 작성자라도 종료된 반 관계를 우회하지 못하게 운영 데이터의 `ownerUserId === viewer.id` 무조건 허용 경로를 제거한다. 이 이관과 구·신 지점 관리자 조회 회귀 검증 전에는 계정 지점 전환을 켜지 않는다.

오늘의수학에 `ClassMembership` 관계를 추가해 담임·유효 대강·허용된 수업 담당을 여러 명 표현한다. `Class.userId`를 바꿔 접근 권한과 자료 소유권을 한꺼번에 옮기지 않는다. 반에 속한 학생·시험·진도 API는 반 관계에 기반한 공통 권한으로 전환하고, 개인 문서·장바구니·문항 저작권은 기존 소유자를 유지한다. 담임 부재·퇴사로 반을 삭제하지 않고 관리자가 담당을 지정할 수 있는 상태로 보존한다.

`Class.userId`의 기존 필수 관계와 사용자 삭제 cascade도 이관 범위다. 보관 중인 연동 반의 소유자 계정은 임의 하드 삭제하지 못하게 하고, 관계를 안정된 보관 주체로 옮겨야 하는 경우 명시적인 이관으로 처리한다. 원본 제어 행·대기열 역시 지점·직원 삭제로 함께 지워지지 않게 한다.

반 관계가 있다는 이유만으로 모든 쓰기를 허용하지 않는다. 관계에 역할·기간·허용 작업을 두고 담임, 교시 담당, 대강을 구분한다. 대강의 기본값은 유효기간 동안 필요한 명단·수업 정보 조회이며, 학생 로그인 발급·반 관리·과거 진도 수정·담당 이전을 허용하지 않는다. 추가 수업 작업이 필요하면 P0의 작업별 권한표로 명시한다. 기존 `ownedRowsWhere` 전체에 대강을 넣는 일괄 권한 확대는 금지한다.

학생은 고정 `eywaStudentId`로 한 명을 유지하고 `StudentEnrollment` 관계로 복수 수학반 수강과 시작·종료·휴원 기간을 표현한다. 기존 `Student.classId`는 이관 중 주반 호환용으로만 유지한다. 학생을 여러 개 복제하거나 반 이동 때 시험·SRS 이력을 다시 만들지 않는다. 조회와 쓰기는 요청의 반과 학생 수강 관계를 모두 확인해 다른 반·지점 이력이 새지 않게 한다.

학생의 휴원·퇴원·반 이동은 수강 관계를 변경한다. 선생님 계정 정지와 학생 로그인 계정 정지는 동일 사건으로 취급하지 않는다. 학생 로그인 정책은 기존 운영 규칙을 유지하고, 유효한 반·지점의 학습 콘텐츠 접근 범위를 다시 검증한다.

담당 교체 후 이전 담임에게 남는 것은 본인의 개인 작업물과 작성자 이력이다. 종료된 담당 관계를 근거로 그 반의 학원 운영 데이터에 계속 접근하게 하지 않는다. 새 담당은 허용된 반의 기존 학업 이력을 볼 수 있지만 다른 반·지점 이력까지 열리지 않는다. 종강 반은 관리자의 기록 조회를 보존하고, 재개강 때는 기존 종료 사유와 원본의 실제 관계를 확인해 복구한다.

모든 컬럼 변경을 외부에 보내지 않는다. 위 계약에 영향을 주는 컬럼과 테이블을 명시한 목록을 만들고, 새 변경 경로와 새 테이블이 추가되면 목록과 검증을 함께 갱신하도록 CI에서 검사한다. 담당 판정은 에이와 기존 공통 함수와 효력일 규칙을 재사용하며 별도 복제 규칙을 만들지 않는다.

날짜 경계는 테이블 전체에 같은 비교식을 강요하지 않는다. 수강의 일반 종료일은 포함, `is_transferred` 이동 종료일은 제외이며 `src/features/enrollments/eligibility.ts`가 기준이다. 대강은 `delegation-window.ts`의 양끝 포함을 따른다. 운영 기간 종료는 `0274a_class_period_enrollment_end.sql`의 실제 교시 구간에서 도출하고, 기간 연장만으로 지난 기수 학생을 자동 복원하지 않는 기존 규칙을 유지한다. KST 자정 전후와 같은 날 시작·종료를 별도 fixture로 고정한다.

현재 명단 표시는 `isEnrollmentOnRosterOn`/`enrollmentPhaseOn`을 사용해 휴원 학생을 상태 표시와 함께 남긴다. 출결·현재 학습 수행 대상은 휴원을 제외하는 `isEnrollmentActiveOn`으로 따로 판정한다. 이 둘을 섞어 휴원을 퇴원·명단 누락으로 처리하지 않는다. 관계 스냅샷은 현재뿐 아니라 예정·종료 구간과 휴원 상태를 담고, 화면·학습 작업이 목적에 맞는 판정을 사용한다.

`pending_teacher_*`는 현재 수동 적용 예약이다. 날짜가 지났다는 이유로 수신 측이 먼저 담임을 교체하지 않는다. 시간표 스냅샷의 자동 적용은 별도 경로이며, 동기화는 실제 커밋된 `classes.teacher_id`와 유효 교시 관계를 따른다. 기존 자동 적용 cron의 오래된 50건 조회 한계는 P0에서 회귀 검증하고, 동기화가 원본에 아직 적용되지 않은 예약을 대신 실행하지 않는다. 퇴사 메모의 미래 날짜도 이미 비활성화된 계정을 연장하는 근거가 아니다.

source Auth 계정의 수동 로그인 차단·삭제도 자격 검사에 포함한다. `auth.users`를 일반 API로 노출하지 않고, 필요한 차단 상태만 서버 전용 제어 질의로 읽는다. 이 상태의 변경 포착 방법과 권한은 P0에서 확인하며, 이메일 확인 시각·최근 로그인 시각 등 불필요한 Auth 변화로 전체 동기화가 반복되지 않도록 한다.

## 전달과 적용 구조

1. **권한 변경과 필수 기록을 함께 커밋한다.** 접근에 영향을 주는 테이블·컬럼의 실제 변경만 지점 버전·접근 취소 세대와 내구성 있는 변경 대기열에 기록한다. OLD/NEW 지점과 삭제 식별자를 보존한다. 이 기록 실패는 해당 원본 저장 실패이며, 외부 전송 실패는 원본 업무를 롤백하지 않는다. 진도·표시 정보는 아래의 별도 규칙을 따른다.
2. **커밋 후 웹훅으로 알린다.** DB webhook/pg_net는 에이와 자신의 발신 경로를 깨우고, 서버가 상대방에게 서명해서 전송한다. 행 전체나 비밀번호·연락처를 보내지 않는다. 깨우기 실패 시 원본 대기열이 남고 예약 실행이 다시 보낸다.
3. **수신을 영속화한다.** 오늘의수학 API가 서명·시간·본문 크기·버전·지점 범위를 검사하고 고유 event ID로 inbox에 기록한다. 저장 전에 성공을 응답하지 않는다. 중복 event ID와 동일한 본문은 재성공, 같은 ID의 다른 본문은 충돌이다.
4. **지점별 작업자가 현재 상태를 읽는다.** 수신 이벤트의 오래된 payload를 그대로 적용하지 않고 인증된 제어 상태와 고정 스냅샷을 읽는다. 저장된 이벤트와 작업 lease가 있어 함수 종료 후에도 다시 처리할 수 있어야 한다. `after()`만 믿는 비영속 작업은 완료 조건이 아니다.
5. **한 지점 안에서 원자적으로 반영한다.** 계정 연결·관계·적용 버전·결과를 트랜잭션으로 커밋한다. 작업자 lease token을 검증해 만료된 작업자가 새 작업자의 결과를 덮지 못하게 한다. 대상별 오류는 충돌로 격리하고 정지·접근 회수는 뒤로 미루지 않는다.
6. **원본까지 적용 결과를 회신한다.** 수신 완료와 반영 완료를 구분한다. 타임아웃으로 결과가 불명확하면 event ID/작업 ID로 결과를 조회하고 멱등 재처리한다. 원본 상태는 대기·수신·적용·충돌·실패로 표시한다.
7. **누락을 대조한다.** 1분마다 실패 전달·중단된 작업·효력일을 확인하고, 5분마다 지점 버전·권한/명단 해시를 대조한다. 하루 한 번 전체 관계를 대조한다. OFF 지점과 삭제·변경 흔적도 대조 대상에 남겨 정지 알림이 막히지 않게 한다.

제어 상태 API는 지점 OFF 시에도 인증된 수신자에게 OFF와 취소 세대·버전을 돌려준다. 학생·진도 반출 API는 기존처럼 차단할 수 있으나 그 503을 빈 명단이나 영구 중단으로 해석하지 않는다. 새 지점별 연결은 기존 단일 `TODAYS_MATH_TENANT_ID`/소유자 전역 설정을 재사용하지 않는다.

제어 응답은 `200 + enabled:false`라는 확인된 OFF와 `5xx/timeout`이라는 확인 불가를 구분한다. 조회 오류까지 false로 접는 기존 `isFeatureOptedIn` 결과를 제어 계약으로 사용하지 않는다. 확인 불가는 기존 자격 유효기간을 연장하지 않으며, 만료 시 접근을 제한한다. 실제 운영 transport를 확인하고 `EYWA_DATABASE_URL` 직접 조회 등 제어 검사 우회 경로는 새 연동을 켜기 전에 차단한다.

필수 기록 대상은 지점 활성화/만료 설정, 직원의 재직·역할·과목·소속·삭제와 Auth 로그인 차단, 반 운영 상태·담임·교시 담당·유효기간, 위임 및 수강 관계이다. 진도와 표시 정보의 변경 알림은 별도 대기열로 다루며, 알림 기록 실패 때문에 수업보고서·이름·학교 저장을 막지 않는다. 그 내용은 완전한 스냅샷·해시 대조로 복구한다. 권한 이력 손실과 내용 갱신 누락을 같은 복구 방식으로 취급하지 않는다.

연결 설정이 없는 지점은 연동 잠금·대기열을 만들지 않는다. Auth 미러가 `public.users`에 같은 값을 다시 쓰는 경우에도 필수 컬럼이 실제 달라졌는지 `IS DISTINCT FROM` 조건으로 확인한다. 로그인 시각·비밀번호 재설정·화면 설정만 바뀐 사건은 권한 동기화를 일으키지 않는다. 필수 기록 오류는 기존 DB 오류 해석기에 전용 코드와 재시도 안내를 등록하며 일반 화면에 플랫폼 역할 이름을 노출하지 않는다.

### 스냅샷과 순서

스냅샷은 지점·유형별 개수, 고정된 source revision, 생성 시각, 유효 시점, 페이지 해시와 완료 표식을 갖는다. 데이터와 버전을 같은 DB 읽기 스냅샷에서 고정해 페이지 도중 원본이 바뀌어도 섞이지 않도록 한다. 초기안은 단일 SQL 스냅샷에서 연동 필드만 모아 불변 페이지로 저장하는 방식이며, 구현 시 부하와 크기를 검증한다.

권한 원본 revision과 내용 스냅샷 generation은 분리한다. 내용 스냅샷 generation은 지점별 export 작업자가 직렬화된 생성 트랜잭션에서 부여하고, 해당 읽기에 포함된 권한 revision을 함께 저장한다. 표시 정보 알림을 잃어 권한 revision이 그대로여도 해시 차이가 있으면 새 내용 스냅샷으로 수렴한다. 내용 generation 증가가 오래된 권한 revision을 새 권한으로 인정하는 근거는 아니다. 수신은 세대·권한 revision·내용 generation을 각각 검사한다.

모든 페이지의 개수·해시·지점·유형이 일치하고 완료 표식이 있어야 없는 관계를 종료할 수 있다. 0건도 명시적인 정상 0건만 인정한다. 페이지 실패·필터 변경·API 503·부분 목록은 삭제·퇴원 근거가 아니다. 실패한 이전 작업과 오래된 버전은 최신 적용 상태를 덮지 못한다.

버전은 단순 timestamp 비교로 만들지 않는다. 지점별 버전 행을 원본 변경 트랜잭션에서 잠그고 갱신해 커밋 순서를 정의한다. 지점 이동 때는 정렬된 순서로 두 지점을 잠가 교착을 줄인다. 역할 회수·OFF 등 접근 취소 세대는 최신 상태 병합 시에도 보존한다. 장기 장애 뒤에는 누적 이벤트를 모두 HTTP로 재생하기보다 최신 스냅샷으로 수렴하되 취소 세대를 반영한다.

트랜잭션 밖에서 발급한 단순 sequence는 커밋 순서가 아니다. 같은 지점의 권한 변경은 작은 제어 행의 잠금을 커밋까지 유지하는 방식으로 직렬화하고, 여러 행·지점의 잠금 순서와 재시도를 부하 시험한다. 권한 대기열 저장 실패를 무시하는 방안은 채택하지 않는다. 실패한 같은 DB에 dirty 표시를 남길 수 있다는 보장도 없고, OFF→ON 중간 사건이 사라지면 현재 상태 대조만으로 과거 세션 취소를 복원할 수 없기 때문이다. 이는 Slack 알림과 달리 권한 변경 기록을 필수 데이터로 취급하는 선택이며, 이 작은 기록의 오류는 원본 저장 실패로 사용자에게 알려 재시도하도록 한다. 외부 HTTP 실패와 표시 정보 기록은 이 트랜잭션 규칙에서 분리한다.

배포 전 스키마 검사와 운영 상태 검사에서 필수 트리거의 설치·활성화·계약 버전을 확인한다. 트리거 미설치/비활성화는 정상 동기화로 간주하지 않는다. 필수 기록 없는 변경이 발견되면 해당 지점의 신규 부여와 정지 해제를 보류하고 현재 접근을 보수적으로 제한한다. 주기 대조는 저장된 사건의 전달 실패·대상 데이터 차이·쓰기 없는 효력일을 수렴시킬 수 있지만, 기록되지 않은 과거 OFF→ON을 재구성한다고 주장하지 않는다. 복구는 제어 행 잠금 아래 새 보호 세대를 올려 기존 세션과 lease를 전부 무효화하고, 원본 스냅샷 검증과 재로그인 후 재개한다. 트리거를 끄는 수입·복원은 이 보호 절차를 거치는 점검 작업으로만 허용한다.

백업 복구로 원본 버전이 뒤로 가는 경우도 구분한다. 늦은 웹훅·오래된 스냅샷은 정상 중복으로 무시하지만, **새로 인증한 현재 제어 응답**이 수신자가 알고 있는 버전/취소 세대보다 작으면 재기준 필요 상태로 차단한다. 운영자가 source epoch를 새로 발급하고 양쪽 binding에 승인한 뒤 전체 대조·세션 취소를 거쳐 재개한다. 서로 다른 epoch의 숫자 크기만으로 자동 신뢰하지 않는다. 대상 DB 복구 역시 원본의 현재 epoch·세대를 다시 확인하기 전 신규 접근을 열지 않는다.

웹훅 봉투는 `schemaVersion`, `eventId`, `bindingId`, `tenantId`, `sourceRevision`, `occurredAt`, `entityType/id`, `changeKind`, `revocationGeneration`으로 제한한다. 역할·이메일·명단 전체는 인증된 source 상태 API에서 읽는다. target 조회·ACK API도 binding과 event ID에 묶어 다른 지점의 상태를 읽거나 성공 처리할 수 없게 한다.

제어 조회는 `enabled`, 계정의 자격 사유, 원본 시각·다음 효력일·취소 세대를 반환한다. 명단 export는 source ID, 최소 프로필, 역할/과목, 반과 기간 관계만 제공한다. 단일 사용자의 자격 확인에는 전체 지점 스냅샷을 매번 생성하지 않는다. protocol/schema 버전이 맞지 않는 요청은 보류하고 부분적으로 구형 규칙에 적용하지 않는다.

자격 응답에는 해당 사용자의 반 목록 revision과 반별 권한 revision을 포함한다. 담당/위임·명단이 바뀐 반의 revision이 대상보다 앞서면 그 범위만 보류하거나 원본의 현재 허용 작업을 확인한다. 무관한 반의 변경으로 지점 전체를 멈추지 않는다. 계정 취소 세대(OFF·퇴사·부적격·연결 변경)와 반 관계 revision은 분리한다. 학생 한 명의 반 이동이나 대강 종료만으로 선생님을 로그아웃시키지 않되, 해당 반의 오래된 권한 캐시는 즉시 무효화한다. 재직 확인이나 계정 lease 갱신이 낡은 반 접근을 연장하지 않는다.

정지 전파와 정보 갱신의 작업 우선순위를 분리한다. 퇴사 계정의 이메일 충돌이나 진도 한 행의 오류가 지점 OFF 및 기존 담당 권한 회수를 지연시키면 안 된다. DB 트리거 실패·잠금 대기는 관측하고, 일괄 수입 시 영향을 측정해 원본 업무의 잠금 시간을 수용 범위 안으로 유지한다.

### 인증과 정보 보호

웹훅·상태 조회·SSO 비밀키는 용도별로 분리하고 서버 전용 저장소에서 관리한다. 웹훅은 raw body에 대한 HMAC, timestamp, nonce/event ID, issuer/audience, 허용된 tenant/binding을 검증한다. 임의 callback URL은 받지 않고 상대 배포의 고정 HTTPS 주소만 호출한다. 키 교체는 key ID와 짧은 이전 키 유예를 지원한다.

새 대기열·연결 원장·로그는 일반 클라이언트가 직접 수정할 수 없도록 전용 스키마/권한을 설정하고, 노출 스키마의 테이블에는 RLS를 적용한다. 관리자 클라이언트 쿼리에도 지점 조건을 명시한다. DB 트리거의 search_path, 실행 역할과 함수 EXECUTE 권한을 점검한다. 비밀키·토큰·전체 직원 payload는 로그에 남기지 않는다.

## 자동 로그인과 접근 취소 지연

신규 연동 계정은 비밀번호 없이 이용 가능한 연동 전용 인증 방식으로 생성한다. SSO는 연결 원장과 현재 자격을 확인한 계정에만 이 방식의 로그인을 허용한다. 기존 비밀번호/OAuth 로그인 계정의 자격 검사는 그대로 유지한다. 기존 `passwordHash` 거절 조건을 모든 계정에 대해 단순 제거하지 않는다.

생성 시 `branchRole=teacher`, 관리자 여부 false, 승인 상태와 수업용 메뉴 권한을 명시해 기존 `role=director` 등의 스키마 기본값으로 권한이 커지지 않게 한다. `role` 값은 현재 화면 호환성을 검증한 최소 권한 매핑으로 고정한다. 복구 편의를 이유로 알 수 없는 비밀번호 해시를 채워 구형 SSO의 검사를 통과시키지 않는다.

자동 로그인은 수신 사이트에서 시작한 요청과 결합한다. ① 에이와 바로가기가 오늘의수학 시작 주소로 이동한다. ② 오늘의수학이 짧은 state와 PKCE 검증값을 자기 사이트의 보안 쿠키에 저장하고 에이와 인증 주소로 보낸다. ③ 에이와가 현재 사용자·지점·재직·연동 자격을 검사해 state와 PKCE challenge에 묶인 60초 이내의 일회용 코드를 발급한다. ④ 오늘의수학이 쿠키의 state를 확인하고 서버 간 교환으로 코드를 원자적으로 소비한다. ⑤ 서명된 신원·binding·취소 세대를 확인하고 같은 jti로 두 세션을 만들지 않도록 소비 기록을 남긴 뒤 로그인한다. 인증 교환이 실패하면 새 바로가기로 다시 시작하며 일회용 코드를 되살리지 않는다.

브라우저 URL에는 개인정보를 담은 서명 토큰 대신 짧은 불투명 코드만 넣는다. 코드도 query 로그에 남을 수 있으므로 가능한 접근 로그에서 숨기고, `no-store`·`no-referrer`·고정 redirect·짧은 만료·1회 소비·PKCE를 함께 적용한다. 인증 토큰과 쿠키 값을 앱 로그에 출력하지 않는다. 다른 계정이 이미 로그인해 있으면 전환할 신원을 확인받은 뒤 전환한다. 같은 신원의 정상 바로가기는 추가 비밀번호 없이 통과한다. 새 관리 binding에서 state/소비 검사가 없는 구형 SSO 경로로 우회하지 못하게 한다.

양쪽 SSO 비밀키의 정규화와 최소 길이를 일치시킨다(현재 발신 trim·32자, 수신 raw·16자의 차이 해소). 서버 간 신원 토큰은 프로토콜 버전, issuer/audience, 지점 binding, 고정 사용자 ID, jti와 취소 세대를 포함한다. 카나리 지점 allowlist는 필수이며 비어 있을 때 모든 지점을 받는 기본값을 새 경로에 사용하지 않는다. SSO 시계 오차 유예와 접근 자격 유효기간은 별도 규칙으로 두고, SSO의 30초 유예가 정지 상한에 더해지지 않게 한다.

첫 연결 확인이 필요한 기존 계정만 한 번 연결 화면을 거친다. 확인된 기존 계정과 자동 생성 계정은 이후 비밀번호 입력 없이 담당 반으로 이동한다. 관리 대상의 수동 unlink는 직접 로그인 권한을 새로 주지 않는다.

확인된 계정이란 원장에 신규 발급·기존 승인 계정의 현재 인증 수단 재확인·운영자 승인 중 하나가 기록된 계정이다. 이름·이메일 후보 일치는 그 기록이 아니다. 승인 대기 계정의 비밀번호를 안다는 이유만으로 해당 계정을 승인하거나 연결하지 않는다.

웹훅만으로 장애 중 즉시 차단을 보장하지 않는다. 수신 측은 연동 사용자 요청에서 **최대 60초의 원본 자격 확인 유효기간**을 적용하는 안을 추천한다. 유효기간은 원본이 확인한 시각에 고정하고 재수신·중복 이벤트·로컬 활동으로 연장하지 않는다. 효력 종료 시각이 더 빠르면 그 시각에 만료한다. 캐시 만료 후 원본 자격을 다시 확인할 수 없으면 연동 계정 접근을 잠시 차단한다. 이는 보안을 우선해 원본 장애 때 오늘의수학 접근도 제한하는 선택이다.

이 자격 갱신은 1분 cron에 맡기지 않는다. 보호 요청에서 만료된 계정의 작은 제어 상태를 서버 간 조회하고, 같은 계정의 동시 조회를 합친다. 정상 응답을 검증한 경우에만 새 유효기간을 설정한다. 만료 경계에서 갱신이 늦으면 확인되는 동안 요청을 기다리거나 재시도 안내하며, 만료된 자격을 임의 연장하지 않는다. 원본 시각과 요청 시작 기준의 유효기간 중 더 이른 값을 사용해 지연 응답·시계 오차로 창이 늘어나지 않게 한다. 이 경로의 부하·지연·장애와 60초 경계를 실제 배포에서 통과시키는 것이 P6의 필수 조건이다.

원본 질의에는 짧은 timeout과 실패 후 짧은 재요청 억제를 두어 장애 때 조회가 폭증하지 않게 한다. 재요청 억제는 만료 자격의 허용 유예가 아니다. P6에서 목표를 통과하지 못했다고 60초를 조용히 늘리지 않고, 설계를 수정하거나 가용성 정책 변경을 사용자에게 확인받는다. 급한 계정 차단은 오늘의수학 수동 정지로도 가능하다.

신규 로그인과 민감한 쓰기는 최신 자격 확인을 우선하고, 보호된 조회도 동일한 유효기간 한계를 적용한다. 계정 정지가 반영되면 다음 서버 요청부터 거절한다. 반 권한 회수는 저장 시점에도 검사해 이미 열린 화면에서 뒤늦게 제출한 쓰기를 막는다. 오프라인 브라우저에 이미 표시된 내용까지 회수할 수 있다고 주장하지 않는다.

| 원본 커밋 → 대상 계정/권한 반영 | 웹훅 깨우기가 동작하는 정상 운영 대표 부하에서 p95 5초 이내 목표; 실측 전 보장 아님 |
| OFF/퇴사 후 접근 차단 | 정상 웹훅은 위 목표, 전달 장애 시 마지막 원본 확인의 60초 유효기간 만료 후 거절; 시계 오차·이미 실행 중 요청 조건 별도 검증 |
| 변경된 반 목록의 열린 화면 표시 | 포커스 복귀·탐색·저장 시 재검증. 계속 열린 활성 화면의 15초 갱신은 선택적 변경 알림이 성립할 때의 UX 목표이며 서버 권한 차단과 별개 |
| 예약 효력일 | KST 정의 준수; 권한 종료는 요청 시각 판정, 백그라운드 상태 정리는 분 단위 |
| 일시 장애 복구 | 재시도 1분 이내 시작 목표; 전체 회복 시간은 backlog·데이터량에 따라 측정 |
| 누락 탐지 | 권한/명단 버전·해시 5분 대조, 하루 전체 대조; 오래된 권한 lease 연장 금지 |

중복·일괄 변경은 지점 단위로 합쳐 전송하고, 변경 없는 대조에서 전체 명단을 반복 전송하지 않는다. 재시도는 지수 증가·jitter·최대 대기와 수동 재실행을 갖춘다. 같은 지점의 독성 데이터 하나가 다른 지점이나 정지 사건을 막지 않게 한다. 이벤트/전달 원문 로그의 보존 기간과 접근 취소 세대·적용 버전의 장기 보존을 구분한다.

트리거의 `occurredAt`은 기록 시각이며 정확한 커밋 시각으로 부르지 않는다. 시험 장치가 원본 커밋 확인, 수신 저장, 대상 적용 커밋, 거절 응답을 각각 측정한다. 진도 대량 적용은 권한 처리와 별도 작업으로 분리해 기존 진도 전량 교체가 계정 정지를 밀어내지 않게 한다. 5분 대조는 작은 권한·명단 해시를 대상으로 하며, 변경 없는 진도 전체를 반복 계산하지 않는다.

별도 서비스 고정비는 없다. 기존 서비스의 호출·CPU·메모리·DB 저장·전송 사용량은 증가한다. 동기화 전용 분당 실행 작업 하나는 30일 기준 최대 43,200회 예약 호출이다. 하나의 동기화 작업이 발신 재시도·수신 미완료 재개·날짜 경계를 점검하되 기존 Slack 발송 경로와는 분리한다. 사용자별 매초 polling과 전체 명단을 매번 읽는 방식은 피한다. 실제 Pro 잔여 크레딧과 트래픽은 배포 전에 확인하며 무조건 추가 청구 0원을 보장하지 않는다.

공식 참고: [Supabase DB 웹훅](https://supabase.com/docs/guides/database/webhooks), [Supabase Cron](https://supabase.com/docs/guides/cron), [Vercel Cron 제한](https://vercel.com/docs/cron-jobs/usage-and-pricing), [Vercel Functions 과금](https://vercel.com/docs/functions/usage-and-pricing). 웹훅의 비동기 전송은 자동 재시도·전달 순서·정확히 한 번 적용을 대신 보장하지 않는다. 이 보장은 위 저장·적용 절차와 테스트로 만들어야 한다.

## 구현 단계와 완료 조건

| 단계 | 담당 범위 | 완료 조건 |
| --- | --- | --- |
| P0 계약과 현황 고정 | 양쪽 저장소 | 사용자 계획 승인, HEAD/스키마/기존 writer/매핑 후보 dry-run, 담당·날짜 규칙과 데이터 소유권 고정 |
| P1 계정과 제어 기반 | 오늘의수학 + 에이와 제어 API | 지점·계정 연결 원장, 연동 정지 사유·취소 세대, 자격 lease, 기존 수동 정지 보존 |
| P2 내구성 있는 변경 전달 | 에이와 + 오늘의수학 | 원본 트랜잭션 outbox, 서명 수신 inbox, 재시도·lease/fencing·ACK·상태 조회, OFF 시 제어 경로 동작 |
| P3 관계 모델과 접근 범위 | 오늘의수학 + 관계 export | 복수 교사·복수 수강, 날짜 기반 대강, 반·학생·시험·진도 API 권한 전수 전환, 개인 자료 보존 |
| P4 기존 연동 이관 | 양쪽 데이터 경로 | 지점별 source ID, 전체 삭제 쿼리 제거/격리, 자동 출제 허용 게이트 선행, 명단 확대, 단일 writer 전환, 과거 ID·자료 검산 |
| P5 자동 발급과 SSO | 양쪽 인증·계정 경로 | 확인된 기존 매핑과 신규 계정 자동 로그인, 코드·토큰 1회 소비, 보류 계정 확인·복구·승인, 직접 로그인/기존 세션/연결 해제 우회 방지 |
| P6 운영 확인 | 양쪽 운영 화면·검증 | 반영 상태·지연·충돌·마지막 성공·재시도 표시, 아래 전체 검증과 성능·장애 시험 통과 |
| P7 배포 | 양쪽 작업 세션 | additive schema→수신 준비→발신 관찰→dry-run→한 지점 canary→확대, rollback 시험 완료 |

오늘의수학 구현은 해당 저장소의 작업 세션에서 수행한다. 이번 에이와 계획 작업이 다른 세션의 변경을 덮어쓰지 않는다. 공통 계약은 한 파일/버전과 양쪽 fixture로 맞추고, 독립 구현을 병렬로 진행해도 통합 검증 전 완료로 보지 않는다.

P3의 권한 전환에는 `ownerScope.ts`·`ownership.ts`와 반/학생/진도/시험 API뿐 아니라 시험 인쇄·확정·기본 범위·일일 복습, 학생 계정 발급·비밀번호 변경, 지표·작업실 개요·예약 초안도 포함한다. 공통 함수를 호출하지 않고 직접 `userId`·`branchId`로 접근하는 경로를 함께 목록화한다. 학생 로그인·공유 링크 등 별도 공개 정책은 교사 세션과 섞지 않고 각자의 보호 경계를 검증한다. 영어 화면은 공통 권한 코드 변경의 회귀 대상이다.

반 접근 판정은 공통 함수로 모으고, 소유/지점 조건을 과도하게 넓히거나 좁히는 변이 시험과 역할별 허용·거절 시험을 함께 둔다. 반에 연결된 시험이어도 개인 예측 회차의 자료라면 개인 소유 경계를 유지한다. 예약 작업과 오래 걸리는 생성 작업도 실행/결과 저장 시 현재 지점·반 자격을 확인한다.

P1/P2의 정지·기존 세션 취소와 P3/P4의 관계 권한·구형 writer 차단을 검증하기 전에는 자동 발급을 운영에 켜지 않는다. 1차에 복수 담당·복수 수강을 생략한 채 단일 소유자에 덮어쓰는 축소안은 이번 요구를 충족하지 못한다. 단계는 작업 순서이며 필수 시나리오의 제외가 아니다.

## 배포와 되돌리기

기존 데이터는 삭제하지 않는 추가 스키마부터 배포한다. 수신 경로와 서명 검증을 먼저 배포하고, 발신을 관찰 모드로 켜 계정 생성·정지 전 적용 예정 차이를 확인한다. 기존 이메일 매핑과 지점 매핑을 승인한 뒤 한 지점만 실제 반영한다. 계정 OFF/ON·퇴사·반 이동·실패 재시도와 차단 지연이 통과해야 확대한다.

새 writer를 켜기 전 기존 `runSync`와 수동/예약 실행 경로를 지점 단위로 잠그고 구형 실행의 잔존도 차단한다. 과거 source ID·학생/반 ID와 자료 수를 대조하고, 소유자 전역 설정과 전역 진도 교체 로직을 제거하거나 구형 단일 지점으로 확실히 격리한다.

문제가 생기면 새 발급·관계 갱신을 중지하고 마지막 성공 버전을 보존한다. 롤백이 정지·접근 취소·자격 만료 검사를 우회하지 않아야 한다. OFF 상태에서 단순 비밀번호 로그인으로 폴백하지 않는다. 복구는 보관한 이벤트와 현재 원본을 다시 대조하며, 사용자 계정·학생·시험을 삭제해 초기화하지 않는다.

롤백 대상은 새 정지 원장·세션 세대·일회 표 소비·자격 만료를 이해하는 호환 배포로 한정한다. 기존 `suspendedAt`만 보는 옛 버전으로 무조건 되돌리지 않는다. 배포 이력에 호환 복구 버전을 먼저 확보하고 시험한다. 호환 버전이 없으면 새 발급/쓰기만 멈추고 보호 경로를 유지하는 복구 배포를 사용한다.
