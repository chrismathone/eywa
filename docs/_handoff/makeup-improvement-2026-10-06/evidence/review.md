# 보강관리 객관적 사용성·연동 검토 — 2026-10-06

현재 보강관리는 접수·승인·예약·실시 검토를 처리할 수 있다. 다만 강사가 간단히 등록하고 관리자가 모든 보강의 일정과 진행을 한눈에 파악하는 수준에는 미치지 못한다. 특히 완료 건이 대시보드 예정 집계에 남는 표시 오류를 실제 앱에서 재현했다.

| 강사 등록 | 가능하지만 기본 동선은 복잡함 | 학생·결석일·반·필수 메모 입력, 승인 대기, 별도 예약 선택 |

## 1. 우선 수정할 오류: 종결된 보강이 ‘보강예정 / 지남’에 남음

- 케이스 `a2d7840f-f295-4400-82c8-303f3e48c518`: `closed`, 잔량 0분, 종료 사유 `completed`.
- 실시 인정: `verified`.

그러나 관리자 대시보드의 ‘보강예정 4건’ 팝업에 이 학생이 `10/5 14:30`, **지남**으로 계속 표시됐다. 같은 건은 시간표 보강 탭에서 빠지고 전체 보강 목록에서는 **종결 / 업무 없음 / 0분**으로 표시됐다. 대시보드에서 아직 미이행인 건으로 오인할 수 있다.

## 2. 기존 예약과 새 보강 목록은 자동으로 합쳐지지 않음

**분류: 현재 수동 도입 범위의 제한. 자동 연동을 기대하는 운영에서는 누락 위험.**

기존 방식이 사용하는 `makeup_reservations`에 가상학생E의 예약을 로컬 합성 자료로 추가했다. 새 보강 케이스는 생성 전후 모두 4건이었고 해당 예약의 새 장부 매핑은 0건이었다.

- 대시보드에서는 E의 `10/13 14:30` 예약이 표시됐다.
- 새 보강 전체 목록에는 E가 없었다.
- ‘미연결 근거 → 기존 보강 약속’에서는 E가 나타나며 **기존 보강 예약 연결** 버튼이 제공됐다.

이 확인은 기존 등록 화면에서 버튼을 눌러 저장한 재현이 아니라, 그 저장 경로의 자료 형태를 만든 뒤 실제 조회 화면을 비교한 것이다. 기존 저장 소스도 [makeup-reservation-actions.ts](F:/eywa/src/features/attendance/server/makeup-reservation-actions.ts:233)에서 기존 예약 테이블에 기록하며 새 접수 명령을 호출하지 않는다. [candidate-action.tsx](F:/eywa/src/features/makeups/components/candidate-action.tsx:13)의 명시적 연결을 거쳐야 한다.

강사뷰의 ‘보강 학생 추가’ 역시 기존 수업 명단·출결을 등록하는 경로이고 새 보강 접수를 자동 생성하는 경로가 아니다. 이는 [makeup-register-actions.ts](F:/eywa/src/features/onescreen/server/makeup-register-actions.ts:37)에서 확인한 소스 판단이며, 이번에 해당 추가 버튼의 저장을 직접 재현한 것은 아니다.

수동 연결 자체는 기존 약속을 검토 없이 권리로 바꾸지 않는 도입 설계다. 따라서 결함으로 단정하지 않는다. 하지만 보강관리 운영을 켰다고 기존 모든 입력이 새 목록에 자동 통합되는 것은 아니다. 관리자 목록에 미연결 예약 건수와 연결 진입점을 더 분명하게 제공하고, 기존 등록 동선에서 새 접수·연결로 이어지는 안내를 주는 것이 필요하다.

## 3. 강사 등록: 직접 접수는 가능하지만 반복 선택이 많음

**분류: 사용성 개선. 접수 권한 차단으로 재현된 문제는 없음.**

일반 강사 계정으로 담당 반의 가상학생C를 접수했다. 실제 저장 후 승인 대기 상태가 되었고 업무 담당자는 그 강사로 자동 지정됐다. 관리자 승인 버튼은 강사 화면에 나타나지 않았다.

직접 접수 화면은 과목·사유·학생·결석일·반·메모의 6개 항목이다. 과목과 결석 사유는 기본값이 있지만 학생·날짜·반·메모는 사용자가 입력한다. 반은 학생과 날짜를 먼저 지정해야 선택할 수 있고, 유효 반이 하나여도 자동 선택되지 않는다. 메모도 필수다.

검색 선택기는 검색어 입력과 목록 선택을 함께 제공한다. 목록에 초점을 주면 자동 조회하므로 **검색 버튼을 매번 눌러야만 하는 것은 아니다**. 그래도 여러 필드에서 별도 선택을 반복한다.

접수 후에는 관리자 분량 승인과 별도 예약이 필요하다. 승인 후 예약 화면에서 실시 강사·강의실·연속 교시·실제 출결·보고서 반은 빈 선택 상태였고, 분량은 승인한 60분으로 자동 채워졌다. 실시 날짜는 오늘이 기본값이다.

장점도 있다. 기존 결석 후보 화면에는 학생·반·날짜·결석 근거를 이미 담아 접수하는 [간편 접수 경로](F:/eywa/src/features/makeups/components/candidate-action.tsx:17)가 있다. 이번에는 소스로 확인했으며 후보 접수 버튼을 추가 실행하지 않았다. 직접 접수만 보고 모든 등록이 6항목이라고 판단하면 과장이다. 다만 진입 명칭 ‘미연결 근거’는 강사가 쉬운 접수 경로로 인식하기 어렵다.

개선 방향: 학생·결석일·반을 알고 있는 출석부와 강사뷰에서 접수로 바로 연결하고, 유효 후보가 하나일 때 선택을 채워주며, 선택 가능한 본인 실시 강사도 기본 제안한다. 관리자 분량 승인과 독립 실시 검토는 유지한다. 새로운 입력 편의 때문에 검토 없이 시간·시수·청구가 확정되어서는 안 된다.

## 4. 관리자 목록: 업무 잔량 중심이며 수업 일정 중심은 아님

**분류: 사용성 개선.**

확인한 목록은 승인 대기·담당 미지정·예약 필요·기한 임박/경과·실시 기록 필요·검토 대기 등을 건수로 보여준다. 잔량, 예약 중 분량, 추가 예약 가능 분량과 다음 업무도 함께 제공한다. 미처리 처리에는 유용하다.

그러나 [목록의 열](F:/eywa/src/features/makeups/components/case-list.tsx:27)은 학생·원수업 / 진행 / 분량 / 다음 업무 / 담당·기한이고, 예약이 있더라도 ‘다음 예약 날짜’만 표시한다. 실시 강사·예약 시각·강의실은 목록에 없다. [필터](F:/eywa/src/features/makeups/components/list-toolbar.tsx:25)도 상태·다음 업무·과목·학생 이름이 중심이며, 오늘·이번 주·실시 강사·강의실을 고르는 필터가 없다.

또한 이 목록의 담당자는 **업무 담당자**다. 실제 예약에 강사26·강사29가 배정된 A/B도 업무 담당자가 비어 있어 ‘담당 미지정’으로 표시됐다. 이는 예약 강사가 사라진 오류가 아니라 두 담당 개념이 다른 결과다. 현재 목록에서는 그 차이를 한눈에 알기 어렵다.

개선 방향: 현재 업무 목록을 유지하면서 오늘·이번 주 일정 보기를 제공한다. 그 보기에는 학생·보강 날짜/시간·실시 강사·강의실·승인/예약/실시/검토 상태를 함께 표시하고, 업무 담당자와 실시 강사를 분리해 이름을 붙인다. 주요 요약은 승인 대기·예약 필요·검토 대기·기한 경과 등을 우선 제시할 수 있다.

증거: [관리자 목록](admin-list-1440.png), `observations.json`의 `admin_list`에 실제 열·선택 항목·행 텍스트가 저장되어 있다.

영어의 기존 보강 기능을 없앤다는 뜻은 아니다. 수학 시범운영의 새 장부를 영어에도 전부 지원한다고 볼 수 없다는 의미다. 또한 선행 구현 문서는 공용 완료 함수의 일부 무응답과 다른 12개 호출 경로가 관측 범위 밖이라고 명시한다. 모든 후속 실패를 현재 UI가 알려준다고 판단하지 않는다.

## 권장 순서

1. 완료·검토 중·예정의 조회 기준을 맞춰 대시보드 오류를 해결한다.
2. 기존 예약과 새 장부의 연결 누락을 목록에서 알 수 있게 한다.
3. 출석부·강사뷰의 기존 학생/결석 정보로 간편 접수하고 반복 선택을 줄인다.
4. 관리자에게 오늘·이번 주 보강 일정과 실시 강사·시각·강의실을 함께 제공한다.
5. 그 뒤 실제 강사와 관리자의 동일 과제를 관찰해 입력 시간과 누락 여부를 측정한다.

브라우저 화면 비교 최종 실행은 4개 확인 모두 성공했고 오류 배열은 비어 있다. 앞선 감사 스크립트의 로딩/정확 텍스트 선택 실패와 합성 fixture의 반·시수 검증 실패는 확인 도구와 사전 조건을 수정한 뒤 재실행했다. 이를 앱 결함 수에 포함하지 않았다. 이번 검토에서 재현된 정확성 결함은 위 완료 건 예정 집계다.
