# 사용자 시나리오와 완료 기준

2026-10-02 · 계획 단계의 기준이며 아래 시험은 아직 실행하지 않았다.

## 시나리오 A — 다음 달 영어 시간표 만들기

1. 시간표에서 `연습실`을 열어 기준일의 시간표를 복사하고 `11월 영어 A안`으로 저장한다.
2. 강사시간표에서 수업 블록을 다른 요일/교시/강사 열로 옮긴다. 수업 길이와 블록 내 상대 위치가 유지된다.
3. 통합시간표를 열면 같은 수업 배치가 즉시 보인다. 별도 반영 버튼으로 두 표를 동기화하지 않는다.
4. 통합시간표에서 학생 여러 명을 선택하여 다른 반으로 옮긴다. 강사시간표의 해당 반 명단/검사 결과에도 반영된다.
5. 수학과 겹치는 학생을 포함한 배치도 연습안에는 저장된다. 관련 두 수업과 겹치는 시간을 확인한다.
6. 스마트 도우미가 제시하는 대안을 비교한다. 선택한 안의 변경 미리보기를 보고 연습안에 적용한다.
7. Undo 한 번으로 도우미의 묶음 변경이 모두 복구된다. Redo로 같은 변경을 되살린다.
8. 새로고침하고 다시 열어도 서버 저장 완료된 연습안이 같다. 저장 실패분은 복구 가능한 상태로 명시된다.
9. `11월 영어 B안`으로 복제해서 별도 실험한다. A안/운영 시간표는 변하지 않는다.
10. 적용일을 지정하고 변경 내용을 검토한다. 운영 데이터가 바뀌었다면 달라진 항목부터 재검토한다.
11. 실제 반영 성공 이후에만 운영 시간표가 바뀐다. 중간 실패 시 일부 반/학생만 바뀌지 않는다.

## 시나리오 B — 구글 시트 작업 유지

- 관리 대상 영어 3개 탭을 갱신해도 다른 이름의 연습 탭 내용/병합/서식/메모/수식/탭 ID가 보존된다.
- 관리 대상 탭의 기존 ID도 유지한다. 추가 탭에서 관리 탭을 참조하는 수식이 `#REF!`로 바뀌지 않는다.
- 연습 탭을 만드는 것과 운영에 가져오는 것은 다르다. 가져오기는 명시한 탭과 적용일을 미리보기한 뒤 반영한다.
- 관리 탭 갱신으로 그 탭을 참조하는 연습 탭 수식의 **계산 결과**는 달라질 수 있다. 탭 보존과 값 동결을 혼동하지 않는다.
- 문서 전체 수정 시각만 보는 현재 자동 동기화의 편집 보호는 유지한다. 추가 탭 편집만으로 건너뛰는 문제는 탭 단위 변경 감지 설계가 검증된 뒤 개선한다.
- 구글 서비스 장애/권한 오류/크기 한도/중간 전송 실패에서도 전체 문서 교체로 폴백하지 않는다.

## 성능과 시험 환경

아래 값은 목표이며 실측 결과가 아니다. 개발용 데스크톱 성능으로 합격 처리하지 말고 실제 사용 PC 사양을 기록한다.

- 입력/선택 반응 p95 100ms 이내, 드래그 시작 p95 100ms 이내를 초기 목표로 검증한다.
- 충돌 결과는 편집 후 p95 200ms 이내 목표. 큰 연산은 Web Worker에서 수행하고 `검사 중`을 구분한다.
- 스마트 도우미는 첫 유효 후보 1초 목표, 전체 탐색은 별도 제한 시간/취소 제공. 목표 미달 시 사실을 기록하고 범위를 조정한다.
- 합성 규모는 소형/통상/확장(통상 5배)을 별도 고정한다. 학생·배치·셀 수와 p50/p95/최대 메모리를 결과에 남긴다.
- Windows Chrome/Edge + 한글 IME를 기본 실사용 축으로, macOS Safari/Chrome과 Firefox는 플랫폼별 단축키 및 클립보드 차이를 따로 시험한다.
- 모바일은 읽기/검토/간단 편집을 검증하되 PC 키보드 시험 통과를 모바일 완성으로 주장하지 않는다.
- iframe 작업창/확대 축소/여러 창/모달 포커스/스크린리더와 키보드 전용 흐름을 각각 시험한다.

## 완료 보고 규칙

계획 작성, 프로토타입 성공, 기능 구현, 실브라우저 검증, 운영 배포를 구분한다. 검증하지 않은 브라우저/단축키/수학 기능은 완료로 표시하지 않는다.
