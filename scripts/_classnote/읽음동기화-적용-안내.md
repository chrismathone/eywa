# ClassNote 학부모 읽음 동기화 — 연동 PC 적용 안내 (2026-07-18)

학부모가 **수업 보고서를 읽었는지**를 ClassNote에서 가져와 eywa에 기록하는 기능입니다.
이걸 켜면 나중에 "학부모가 아직 안 본 보고서" 알림을 만들 수 있습니다.

> **ClassNote에는 아무것도 쓰지 않습니다.** 피드를 읽기만 하고(GET), eywa 데이터베이스의
> 읽음 시각만 채웁니다. 학부모에게 나가는 것은 전혀 없습니다.

---

## 0. 무엇이 바뀌나

- 상주 워처(`watch-classnote-queue.mjs`)가 **30분마다** ClassNote 피드를 훑어
  "이 보고서를 학부모가 언제 읽었는지"를 eywa에 기록합니다.
- 기존 발송·학부모 글·댓글 기능은 **그대로**입니다. 실패해도 서로 독립입니다.

---

## 1. 이 패키지 풀기

이 zip을 연동 PC로 옮겨, **eywa 저장소 폴더**에서 **"여기에 압축 풀기"** 하세요.
`<저장소>\scripts\_classnote\` 안의 파일이 최신으로 덮어써집니다.

포함 파일:
- `classnote-read-core.mjs` ← **새 파일**(읽음 동기화 본체)
- `classnote-read-core.test.mjs` ← 새 파일(테스트, 실행엔 불필요하지만 같이 둡니다)
- `sync-classnote-reads.mjs` ← **새 파일**(수동 1회 실행·점검용)
- `classnote-feed-core.mjs` ← 수정본(읽음 조회용 창 함수 추가)
- `watch-classnote-queue.mjs` ← 수정본(30분마다 읽음 동기화 호출 추가)

---

## 2. 워처 재시작 (이게 전부입니다)

파일만 덮어쓰면 **다음 재시작부터** 자동으로 돕니다.

1. 작업 표시줄에서 워처 창(검은 콘솔)을 찾아 닫습니다.
2. `scripts\_classnote\발송PC-지정.bat` 을 **더블클릭**합니다(원래 등록 방식 그대로).
   - 또는 컴퓨터를 재부팅하면 작업 스케줄러가 알아서 다시 띄웁니다.

정상이면 워처 로그에 30분 안에 이런 줄이 뜹니다:

```
[읽음] 피드 2400건 · 학원발송 2308 (읽음 1733/미읽음 575, 링크없음 1444) → 갱신 후보 570
[읽음] edutrix 매칭 갱신 161건
```

> `링크없음`이 많은 건 **정상**입니다 — 강사가 ClassNote에 직접 쓴 알림장이나 학원 공지는
> 수업 보고서가 아니라서 매칭 대상이 아닙니다.

---

## 3. 지금 바로 한 번 돌려보고 싶다면 (선택)

저장소 폴더에서 명령 프롬프트를 열고:

```
node --env-file=.env.local scripts\_classnote\sync-classnote-reads.mjs
```

- 위 명령은 **아무것도 바꾸지 않고** 현황만 보여줍니다(점검 모드).
- 실제로 기록하려면 끝에 `--apply` 를 붙입니다.

---

## 4. 문제가 생기면

- 워처 로그에 `[읽음] 오류...` 가 보이면 → 다음 폴(30분 뒤)에 자동 재시도합니다. 계속되면 알려주세요.
- `⚠️ 후보 N건이 eywa 행과 매칭되지 않음` 이 뜨면 → eywa 쪽 야간 동기화(새벽 3시 30분)가
  아직 안 돈 것일 수 있습니다. 하루 지나도 그대로면 알려주세요.
- 이 기능을 잠시 끄고 싶으면 → `watch-classnote-queue.mjs` 에서 `pollReportReadsOnce` 로 시작하는
  줄(주석 `// 6)` 아래)을 지우고 워처를 재시작하면 됩니다. 나머지 기능엔 영향 없습니다.
