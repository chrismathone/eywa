# 실험실 퇴원보고서

2026-10-15 직접 상태 변경 권한 분리: `studentStatusManagerIds`는 기존 원생·퇴원관리의 직접 처리 자격이다. 보고서의 요청·작성·지정 승인·취소 및 서비스 전용 최종 적용·예약 cron은 이 명단을 추가 요구하지 않고 기존 메뉴·과목·참여자·동결 정보 검증을 유지한다. 보고서 승인으로 직접 상태 처리 권한이 생기지 않는다.

2026-10-13 사용자 요청. 원본: [퇴원보고서 양식](https://docs.google.com/spreadsheets/d/1ewKFvW2rL1eUGCcHDP2Y2tGJI03r7ZSCXiFH05XCPns/edit). 지정된 `월별 통계` 탭은 통계용이며 실제 양식은 `원본`·월별 퇴원 탭에 있다.

- 메뉴: 상담·재원 → 퇴원보고서(실험실). 카드와 메뉴 편집 보관함에 등록하고, 실험실 배정 메뉴에는 작은 플라스크를 표시한다. 실험실 사용을 켠 지점만 접근. 기본 역할 권한은 관리자·원장 전체, 강사 본인 배정 건. 다른 강사 보기·지점 보기는 읽기 전용이다.
- 관리자 요청 → 해당 수강 반의 담임별 보고서 한 건 작성 → 지정 관리자 전원 승인. 원장은 요청 시 선택 사항이며 미선택이면 관리자가 최종 승인한다. 원장을 선택한 경우에만 관리자 전원 승인 후 선택 원장 전원이 승인한다. 작성자·관리자·원장 명단은 서로 겹치지 않는다. 지정하지 않은 사람이 대신 승인할 수 없다(사용자 정정 2026-10-14).
- 작성 요청은 창 크기를 늘리지 않는 오버레이다. 학생은 검색 가능한 드롭다운 하나에서 고르고, 강사·관리자·원장은 복수 선택한다. 작성 강사는 실제 수강 반 담임만 후보이며 대상 수강의 담임 모두를 포함해야 한다. 관리자 목록과 기본 선택은 선택한 담임의 대상 수강 과목에 맞춘다. 여러 과목이면 해당 관리자들의 합집합이며, 강사가 다른 곳에서 가르치는 과목은 포함하지 않는다. 개인별 담당 범위가 있으면 그 범위를 우선한다. 강사를 바꾸면 범위 밖 관리자 선택을 제거하고 새 과목 관리자를 기본 선택하되, 여전히 유효한 직접 선택·해제는 유지한다. 담당 관리자가 없으면 요청을 막고 담당 과목 확인을 안내한다. 이승엽·박소선의 표시 역할은 관리자이며 원장 후보에는 나타나지 않는다. 관리자 후보에도 같은 과목 필터를 적용한다.
- 원본의 성명·학교·학년·반·수강기간·담임·종료일·출결·퇴원사유·상세사유·학생/학부모 상담·담임 의견·원비·미납을 반영. 상세사유는 제출 시 200자 이상. 상담하지 못했다면 사유를 기재한다. 임시 저장에는 제출 필수값을 강제하지 않는다.
- 제출 후 본문은 고정. 승인자가 반려하면 해당 강사가 수정·재제출하고 그 보고서의 모든 승인을 처음부터 받는다. 다른 강사의 이미 승인된 보고서는 유지한다. 학생당 진행 중인 요청 묶음은 하나이며 담임별로 보고서가 나뉜다. 모든 보고서의 모든 승인이 끝나야 수강을 한 번만 처리한다. 취소는 요청 묶음 전체에 적용한다.
- 요청자·지정 원장은 진행 중인 요청을 취소할 수 있다. 요청자와 지정 원장이 퇴직해 요청이 고착된 경우에는 현재 원장이 취소하고 다시 요청할 수 있다. 현재 원장이라도 다른 사람으로 지정된 승인 차례를 대신 승인할 수 없고, 처리 완료된 보고서를 취소할 수 없다.
- 전체 퇴원은 모든 현재·예정 수강 과목을 포함하고 학생 상태까지 바꾼다. 선택 과목이 모든 수강 과목이면 전체 퇴원으로 자동 결정하며, 일부이면 과목 수강종료로 결정한다. 같은 과목의 담임이 여럿이어도 보고서에는 각 담임의 반만 표시한다. 실제 처리는 요청한 전체 과목을 대상으로 하며, 수학 시트 내보내기도 전체 요청 대상 수강을 사용한다.
- 미래 종료일은 전체 승인 후 예약 상태다. 기존 매일 00:05 KST 작업이 처리일에 요청 묶음을 한 번만 적용한다. 요청 당시 학생·수강·담임 정보를 동결해 제출·각 승인·예약 처리 때 비교한다. 화면 조회와 학생 선택은 같은 수강 조회·변환을 사용한다. 정보가 달라지면 제출·승인을 거절하고 현재 정보로 다시 요청하도록 안내한다. 예약 처리에는 재검토 상태·참여자 알림을 남기며 실제 수강은 건드리지 않는다.
- 상태 변경·수강 종료·이력·웹 알림을 하나의 DB 트랜잭션으로 처리한다. 쓰기 RPC는 서비스 역할 전용이고 웹 액션이 메뉴·지점·보기 모드·과목 범위·행위자 권한을 확인한다. 보고서와 이력은 클라이언트에서 직접 읽거나 쓸 수 없다. 직접 API 주소 입력도 동일하게 보호한다.
- 기존 퇴원관리의 직접 처리 기능은 유지한다. 새 승인 기능은 실험실의 별도 흐름이며 기존 기능을 학원 전체에서 강제로 대체하지 않는다. 승인 완료된 수학 종료는 기존 퇴원 시트 내보내기를 사용한다.
- 준비 전 DB에서는 화면에 준비 안내를 표시하고 기존 퇴원 예약 작업은 계속 작동한다.
