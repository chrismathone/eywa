# 실험실 퇴원보고서

2026-10-13 사용자 요청. 원본: [퇴원보고서 양식](https://docs.google.com/spreadsheets/d/1ewKFvW2rL1eUGCcHDP2Y2tGJI03r7ZSCXiFH05XCPns/edit). 지정된 `월별 통계` 탭은 통계용이며 실제 양식은 `원본`·월별 퇴원 탭에 있다.

- 메뉴: 실험실 → 퇴원보고서. 실험실 사용을 켠 지점만 접근. 기본 역할 권한은 관리자·원장 전체, 강사 본인 배정 건. 다른 강사 보기·지점 보기는 읽기 전용이다.
- 관리자 요청 → 해당 수강의 담당 강사 작성 → 지정 관리자 승인 → 지정 원장 승인. 작성자와 두 승인자는 서로 다른 사람이다. 결재선 생략·전결·대결을 지원하지 않는다.
- 원본의 성명·학교·학년·반·수강기간·담임·종료일·출결·퇴원사유·상세사유·학생/학부모 상담·담임 의견·원비·미납을 반영. 상세사유는 제출 시 200자 이상. 상담하지 못했다면 사유를 기재한다. 임시 저장에는 제출 필수값을 강제하지 않는다.
- 제출 후 본문은 고정. 관리자가 반려하면 강사가 수정·재제출하고 두 승인을 처음부터 받는다. 진행 중인 보고서는 학생당 하나다. 취소한 뒤 대상·날짜·담당자를 변경해 다시 요청한다.
- 요청자·지정 원장은 진행 중인 요청을 취소할 수 있다. 요청자와 지정 원장이 퇴직해 요청이 고착된 경우에는 현재 원장이 취소하고 다시 요청할 수 있다. 현재 원장이라도 다른 사람으로 지정된 승인 차례를 대신 승인할 수 없고, 처리 완료된 보고서를 취소할 수 없다.
- 전체 퇴원은 모든 현재·예정 수강 과목을 포함하고 학생 상태까지 바꾼다. 과목 수강종료는 선택 과목의 모든 현재·예정 수강만 닫으며 다른 과목·재원 상태는 유지한다. 마지막 과목이라도 전체 퇴원이 목적이면 요청 구분을 전체 퇴원으로 지정한다.
- 미래 종료일은 승인 후 예약 상태다. 기존 매일 00:05 KST 작업이 처리일에 적용한다. 요청 당시 학생·수강·담임 정보를 동결해 최종 승인·예약 처리 때 비교한다. 정보가 달라지면 즉시 승인은 거절하고, 예약 처리에는 재검토 상태·참여자 알림을 남기며 실제 수강은 건드리지 않는다.
- 상태 변경·수강 종료·이력·웹 알림을 하나의 DB 트랜잭션으로 처리한다. 쓰기 RPC는 서비스 역할 전용이고 웹 액션이 메뉴·지점·보기 모드·과목 범위·행위자 권한을 확인한다. 보고서와 이력은 클라이언트에서 직접 읽거나 쓸 수 없다. 직접 API 주소 입력도 동일하게 보호한다.
- 기존 퇴원관리의 직접 처리 기능은 유지한다. 새 승인 기능은 실험실의 별도 흐름이며 기존 기능을 학원 전체에서 강제로 대체하지 않는다. 승인 완료된 수학 종료는 기존 퇴원 시트 내보내기를 사용한다.
- 준비 전 DB에서는 화면에 준비 안내를 표시하고 기존 퇴원 예약 작업은 계속 작동한다.

적용: `node --env-file=.env.local scripts/withdrawal-reports-db.mjs --apply`. 병행 작업의 질병·권고퇴원 사유 반영은 `--upgrade`. 회귀 검증은 `--test`이며 테스트 지점·학생·알림을 모두 롤백한다. 운영 학생에게 테스트 요청을 생성하지 않는다.
