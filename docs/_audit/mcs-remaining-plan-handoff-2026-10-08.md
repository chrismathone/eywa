# 수학 강사 시트 — 목표 클릭과 남은 계획 수정 handoff

기준 커밋: `a4e2bb19a93b25ba6f020612da500c0fe59c0ae9`. 사용자 요청은 목표를 눌러 남은 계획을 폭넓게 수정하는 기능이며, 날짜·단원·남은 진도 배분을 직접 수정하는 범위를 명시적으로 선택했다. 기존 검증 후 푸시·배포와 Supabase CLI SQL 적용 지시를 따른다.

## 구현 계획과 결과

1. 반 전체 표의 목표 점·최종 목표 라벨, 학생 집중 보기의 목표 점·목표 목록을 같은 편집창에 연결한다. 클릭한 학생과 목표 번호를 전달하고 해당 목표의 날짜 입력에 초점을 둔다. 편집 권한이 없는 화면에서는 기존 계획 조회 동작을 유지한다.
2. 편집창은 최신 목표·현재 진도·실제 수업 요일·휴강·학생 수강 기간을 서버에서 다시 조회한다. 과정·목표 단원·완료 예정일·구간별 블록 분량·교재를 수정하고 다음 목표 추가 및 미완료 목표 제거를 지원한다. 변경 후 수업일별 계획을 저장 전에 확인한다.
3. 적용일의 최신 확인 진도를 남은 계획의 시작 위치로 삼는다. 이미 지나고 도달한 목표는 보호한다. 이전 계획의 날짜별 단원 위치를 보존하고, 기한을 넘긴 미완료 목표도 다시 계획한다. 실제 수업보고서·진도·시간표·출결을 변경하지 않는다.
4. 수정 계획은 고정 월 4블록 규칙 대신 입력한 목표 날짜·구간별 분량과 실제 수업일에 따라 배분한다. 기존 자동 계획은 기존 학기·월 배분 규칙을 유지한다. 수정 계획을 다시 확장해도 이전 도착점과 배분을 유지한다.
5. 지점·반·학생·수업 유형·시작월·목표 버전을 명시하여 저장한다. 창을 연 뒤 목표·현재 진도·반 유형이 변경되면 저장을 거절한다. 최종 DB 갱신도 `updated_at` 조건으로 동시 수정에 대비한다. 감사 기록을 남기고 목록·집중 보기·진도맵을 갱신한다.
6. 계획 수정일을 가로지르는 월·주 구간은 새 시작 위치에서 계산하여 역순 구간을 방지한다. 과거 화면은 수정 전 계획임을 표시하며, 목표를 줄여도 이전 계획 위치와 실제 차이를 동일한 차시 눈금으로 보여준다. 복습 심화는 목표 기한 이후에 확인된 실제 기록도 편집 기준과 수정 후 화면에서 보존한다. 블록 분량이 작아도 장기 수정 목표의 마지막 정거장까지 표시한다.

## 저장 및 배포 순서

마이그레이션: `supabase/migrations/s1_season1.sql#0397a_mcs_remaining_plan_revision.sql`.

- 기존 목표 표에 nullable `plan_revision` JSONB를 추가한다. 수정 적용일·실제 진도 기준점·보호할 정거장 수·이전 계획의 단원 위치를 저장한다.
- 기존 자동 계획 제약을 보존하고, 수정 정보가 있는 계획에 날짜·분량 변경을 허용한다. 수정 정보의 형태·상한, 시작일·기간·분량 제한을 검증한다.
- 일반 로그인·비로그인의 직접 갱신 권한을 추가하지 않으며 RLS와 서비스 역할 권한을 유지한다. 앱 서버가 기존 반 편집 권한과 자료 범위를 재검증한다.
- SQL은 단일 DO 트랜잭션이며 Supabase CLI로 운영 앱과 DB 대상이 일치함을 확인한 뒤 적용한다. SQL을 먼저 적용하고 코드 배포를 진행한다. 운영 학생의 목표나 보고서를 검증 목적으로 저장하지 않는다.

버전이 없는 이전 방식의 목표는 새 표준 계획 등록 경로를 이용한다. 오래된 목표를 동시 수정 보호 없이 덮어쓰는 폴백은 추가하지 않았다. 실제 진도가 확인되지 않는 경우에는 시작 지점부터 배분한다고 명시하며, 실제 진행률을 임의로 만들지 않는다.
