# 학생별 재원 유지 관리 개발안

2026년 10월 20일 기준 개발 제안이다. 학생의 재원 이력, 누적 납부액, 학습 참여, 학습 수준, 성적 변화, 학부모 의견을 기존 학생 상세와 유지관리 화면에 모은다. 관리 등급은 필요한 지원의 시급성을 뜻한다. 담당자가 근거를 확인하고 조치한 뒤 실제 변화까지 에이와에서 확인하는 것이 목표다. 이 문서는 개발 사양이며 해당 기능이 운영에 적용됐다는 뜻은 아니다.

전체 개발 순서는 [경영 에이전트 개발 우선순위](management-agent-roadmap.md)를 따른다. 학생 지원 우선순위에는 누적 수강료나 예상 LTV를 넣지 않는다. 납부액은 권한 있는 경영자의 참고 정보이며, 학습 수준 자체가 낮다는 이유만으로 퇴원 위험 등급을 올리지 않는다.

2026년 10월 20일 첫 구현: 학생 상세의 관리 요약 탭과 기존 상담 연결을 개발했다. 이 문서의 전체 목표 중 읽기 집계와 근거 확인 단계이며, 직접 만족도 입력·자동 지원 사건·효과 추적은 후속 범위다. [구현 범위와 검증](student-care-mvp.md)을 참조한다.

현재 유지관리 계산은 최근 성적 두 건을 과목 구분 없이 비교하고, 상담·메모의 단어 포함 여부로 이탈 신호를 만든다. 재등록 전망의 28·58·82는 규칙에 따른 고정값이며 확률 모델이 아니다. 새 카드에서는 이 값을 퇴원·재등록 확률로 표시하지 않고, 비교 축과 맥락 확인을 먼저 보완한다.

현재 `isTuitionReceipt`는 급여 배분 목적의 분류이며 부분환불 거래를 제외한다. 누적 납부액에는 그대로 적용하지 않는다. 실제 수납·환불 원장을 대조하는 별도 집계를 만들고, 공통 분류를 재사용할 수 있는 범위만 추출한다.

## 관리 등급과 초기 운영 규칙

학생의 학업 성적 등급과 지원 우선순위를 별도로 표시한다. 초기에는 설명 가능한 규칙을 사용하고, 한 개의 100점 총점이나 퇴원 확률을 제시하지 않는다. 아래 시간과 기준은 학원 자료로 조정할 시범 운영안이다.

| 등급 | 근거 | 제안 업무 |
| --- | --- | --- |
| 긴급 지원 | 담당자가 확인한 현재 퇴원 의사·해결되지 않은 중대한 불만 등 | 담당 책임자가 당일 확인하고 연락·지원 계획과 다음 확인일을 남긴다. |
| 집중 관리 | 유효한 최근 기간에서 둘 이상의 독립 영역이 악화되거나, 조치 후에도 같은 문제가 지속 | 담당 강사가 2영업일 안에 학생·학부모와 원인을 확인하고 계획을 세운다. |
| 관찰 | 하나의 영역에서 의미 있는 변화가 발견됐으나 맥락 확인이 필요 | 다음 수업 또는 1주 이내에 확인한다. |
| 안정 | 기본 자료가 충족되고 현재 확인된 지원 신호가 없음 | 정기 피드백과 목표 점검을 유지한다. |
| 판단 보류 | 자료가 부족하거나 낡아 정상 여부를 판단할 수 없음 | 부족한 기록을 확인하는 업무를 만든다. 학생의 문제로 표현하지 않는다. |

자료 부족은 등급 옆에도 표시한다. 일부 자료가 없어도 확인된 긴급 신호는 유지하며 ‘판단 보류’로 덮어 숨기지 않는다. 등급 하향·상향 수정은 담당자가 사유와 확인일을 남기고, 원래 신호와 수정 이력을 보존한다.

시범 운영에서 먼저 검증할 후보 규칙:

- 숙제: 같은 과목·같은 평가 방식으로 최근 4주 평균이 직전 4주보다 20%p 이상 하락한 경우. 각 기간 평가 4건 이상일 때만 변화 신호로 사용한다. ‘20%p·4건’은 검증 전 설정값이다.
- 출결: 취소·휴원·기록 정정을 제외한 예정 수업에서 연속 2회 결석이면 이유 확인 대상으로 올린다. 확인된 질병·행사 등은 맥락으로 반영하며 자동 퇴원 판정에 쓰지 않는다.
- 성적: 같은 평가 척도의 이전·현재 기록을 비교한다. 학교 시험은 과목·학교·학년·시험 유형을 묶어 원점수를 제시하되, 난도가 달라 비교성이 불명확하면 하락 규칙을 적용하지 않는다. 비교 가능한 검사에만 교사가 정한 변화 기준을 사용한다.
- 만족도: 직접 응답의 개선 요청, 또는 사람이 확인한 현재 미해결 요청을 신호로 사용한다. ‘퇴원하지 않기로 했다’, 과거 인용, 이미 해결한 환불 등을 단어만으로 긴급 처리하지 않는다.
- 입학 초기: 첫 수업 후 2주·4주 시점의 적응 확인을 기본 지원 업무로 제안한다. 신규 학생의 자료 부족은 낮은 평가가 아니다.

같은 원인에서 나온 중복 신호를 독립 영역 두 개로 세지 않는다. 성적이 낮아도 꾸준히 성장하고 참여가 안정적인 학생은 그 이유만으로 높은 지원 등급을 받지 않는다.

## 학부모 의견 수집

초기 카드에는 기존 상담과 확인된 학부모 의견을 먼저 연결한다. 직접 만족도 입력은 이해하기 쉬운 동일 문항으로 제안한다: 수업 이해와 도움, 성장 체감, 피드백·소통 만족을 각각 1~5점으로 묻고, 개선 요청과 재원 계획은 별도 항목으로 둔다. 응답일·응답 경로·과목·질문 버전을 보존한다.

최초 확인 시점은 입학 후 4주와 정기 상담 시점으로 제안한다. 설문 발송은 기존 허용된 연락 수단과 수신 설정을 따른다. 이번 계획 작성은 실제 설문·문자 발송을 포함하지 않는다. 오래된 응답에는 경과 기간을 표시하고, 작은 응답 수를 전체 학부모의 만족도로 확대하지 않는다.

## 화면과 업무 흐름

1. **학생 상세의 관리 요약**: 재원기간·납부 이력, 과목별 숙제·출결·학습 수준·성장, 학부모 의견, 지원 등급과 이유를 한 화면에 모은다. 기존 성적·수강·수납 입력 화면으로 연결한다.
2. **기존 유지관리 명단**: 긴급성, 미처리 기한, 담당자, 학년·과목, 자료 부족 여부로 필터한다. 기본 정렬은 지원 시급성과 처리 기한이며 납부액 순으로 지원을 배정하지 않는다.
3. **근거 확인**: 신호가 나온 기간과 원본을 담당자가 확인한다. 과거 캘린더 일정은 동일인 확인과 취소·중복 제거 후 연결하고, 예약 건수를 상담 완료 횟수로 세지 않는다.
4. **에이와 업무 접수**: 상담, 학습량 조정, 반 적합성 점검, 학부모 설명 등 조치와 담당자·기한을 정한다. 기존 학습·출결 원본을 자동 수정하지 않는다.
5. **실행과 보고**: 담당자는 실제 조치, 확인된 원인, 합의 내용, 다음 점검일을 남긴다. 슬랙·노션에는 최소 알림과 로그인 필요한 에이와 링크만 보낸다.
6. **효과 확인**: 조치 후 2주에는 숙제·출결·요청 해결 여부를 재확인하고, 성적은 다음 비교 가능한 시험 때 확인한다. 30·60·90일 재원 여부는 관찰기간이 지난 학생만 집계한다.

하루마다 같은 학생에게 새 사건을 만들지 않는다. 같은 학생·원인·진행 중 사건은 갱신하고, 이미 확인한 근거는 반복 알림을 억제한다. 새로운 근거나 기한 경과가 있으면 다시 알린다. 담당자가 없으면 운영 관리자에게 배정 요청으로 남긴다.

| --- | --- | --- |
| 학생 카드 읽기 집계 | `src/features/student-care`에서 기존 서버 조회와 순수 계산 함수를 조합 | 원본과 합계가 맞고 누락·조회 실패를 구분하며 학생 상세·유지관리 명단이 같은 집계를 사용 |
| 비교와 근거 모델 | 영역, 기간, 출처, 관측 수, 갱신일, 비교 가능 여부, 규칙 버전 | 과목이 다른 시험·불명확한 레벨·미기록 숙제를 잘못 비교하지 않음 |
| 검토 이력 | `student_care_reviews` 후보: 학원·학생·검토자·근거 버전·판정·사유·다음 확인일 | 등급 정정과 변경 사유 추적, 동시 수정 충돌 방지 |
| 직접 만족도 | `student_parent_feedback` 후보: 문항 버전·학생·응답일·경로·응답·요청 | 기존 의견과 별도 출처 표시, 무응답 처리, 정정 이력 |
| 사건 출처 확장 | 상담 후속조치와 학생 관리 신호를 구분하는 출처 모델 | 기존 상담 사건·RLS·명령·알림 동작을 유지하면서 학생 관리 사건 생성 |
| 재평가 기록 | 기존 사건에 기준 지표·검증 시점·결과를 연결 | 연락 완료, 문제 해결, 재원 관찰 결과를 각각 조회 |

현재 `management_cases.consultation_id`는 필수이고 상담별 유일성이 있다. 학생 관리 사건을 붙이기 위해 가짜 상담을 생성하지 않는다. 상담 외 출처를 지원하도록 테이블 제약·RPC·RLS·알림을 함께 확장하고 기존 상담 사건의 유일성을 유지한다. 사건 출처 확장 전에는 카드에서 기존 학생 상담·후속조치 작성으로 연결하는 수동 경로만 사용한다.

초기 집계는 읽기 전용으로 만들고, 비교 이력에 필요한 최소 파생값만 추후 스냅샷으로 저장한다. 전체 원문을 복제하지 않는다. 스냅샷 보존·삭제는 원본 정책과 연결하며, 삭제되거나 접근 범위가 바뀐 학생의 캐시·파생 자료도 함께 정리한다.

## 권한과 개인정보

- 학원 범위와 담당 학생 범위를 서버·RLS·캐시 키에서 일관되게 확인한다. 운영 관리자에게도 해당 학원 범위만 제공한다.
- 누적 납부액과 세부 거래는 기존 수납 조회 권한을 따른다. 학생을 가르칠 권한만으로 금융 정보를 추가 공개하지 않는다.
- 교사는 담당 학생의 지원 근거와 필요한 조치에 접근한다. 의견 원문의 별도 권한과 비공개 상담 범위를 유지한다.
- 초기 AI 역할은 검증된 구조화 사실의 요약과 대응안 제안이다. AI가 등급 확정·학부모 발송·반 변경·퇴원 처리를 실행하지 않는다.
- 외부 알림에는 이름·학교·성적·납부액·연락처·상담 원문을 넣지 않는다. 학생 개인정보로 외부 검색을 하지 않는다. 실학생 자료는 샘플·테스트·PR에 넣지 않는다.

## 검증과 시범 운영

| 검증 항목 | 필수 가상 사례 |
| --- | --- |
| 재원기간 | 동시 두 과목, 중간 휴원, 재입학, 당일 이동, 미래 시작, 시작일 누락, 이관 전 이력 미확인 |
| 누적 수강료 | 중복 수납, 분할 납부, 취소, 부분·전액 환불, 교재 포함 결제, 형제간 잘못된 연결, 일부 기간 이관 |
| 숙제 | 실제 0%, 미기록, 옛 상태 문자열, 기간별 표본 부족, 과목별 서로 다른 추세, 취소·중복 보고서 |
| 학습 수준과 성적 | 영어·수학 최근 기록 혼재, 다른 난도, 학교·학년 변경, 서로 다른 레벨 척도, 입학 평가 누락 |
| 학부모 의견 | 긍정·부정, 부정어, 과거 인용, 해결된 불만, 무응답, 오래된 응답, 여러 보호자 의견 불일치 |
| 권한과 성능 | 다른 학원, 미담당 교사, 수납 권한 없음, 담당 변경, 삭제 원본, 1,000건 초과, 페이지 누락·조회 실패 |
| 사건과 알림 | 재실행 중복, 새 근거 재개, 담당 없음, 기한 변경, 결과 반려, 외부 전달 재시도, 민감 정보 미포함 |

1. 가상 자료로 계산·권한·상태 전이를 검증하고 기존 유지관리·수납·상담 회귀 검사를 통과한다.
2. 운영 적용 승인 후 일부 반에서 관찰 모드로 4주 검토한다. 새로운 외부 알림은 끄고 담당자가 오탐·누락·자료 오류를 기록한다. 4주는 기록 품질과 업무량 확인 기간이며 퇴원 감소 효과를 확정하는 기간이 아니다.
3. 대응 가능한 업무량과 데이터 품질을 확인한 뒤 활성 범위를 넓힌다. 규칙 버전과 변경일을 남기고 정기 재검토한다.
4. 판단 정확도는 경고 적중·누락·선행 일수·오탐률로, 운영 품질은 접수·조치·재확인 소요시간으로 측정한다. 학생별 중복 알림은 한 사건으로 센다.
5. 실제 퇴원은 학원 전체 퇴원과 일부 과목 종료를 구분한다. 졸업·이사·휴원·재입학도 별도 기록한다. 월별 전체 퇴원율과 개선 가능한 사유의 퇴원율을 함께 본다.
6. 30·60·90일 유지율은 동일 학년·입학 시기·과목·초기 위험 수준을 맞춘 집단과 비교한다. 관찰기간이 미완료인 학생을 유지 성공으로 세지 않는다. 단순 전후 차이를 프로그램의 인과 효과나 절감 매출로 확정하지 않는다.

예측 모델은 충분한 과거 결과와 시간 순서에 따른 검증이 확보된 후 별도 검토한다. 퇴원 결정 뒤 작성된 메모·환불 기록을 이전 시점의 예측 자료로 사용하는 정보 누출을 막는다. 과목·학년·신규/장기 재원별 오류 차이와 자료 누락도 확인한다.

## 개발 순서

1. **카드 MVP**: 모든 요청 영역의 현재 값·이력·출처를 한 화면에 제공하고, 비교 불가·미확인 상태를 명시한다. 기존 유지관리 계산의 과목 혼합·문구 오해·확률 오표시를 먼저 보완한다.
2. **지원 업무 연결**: 수동 검토부터 시작해 담당·기한·결과 확인을 붙인다. 사건 출처 확장을 검증한 뒤 확인된 신호의 자동 업무 생성을 연다.
3. **성장과 만족도 보강**: 과목별 평가 척도와 입학 기준점을 정리하고 직접 만족도 입력·시계열·정기 재평가를 추가한다. 기본 카드에 없던 값을 임의 추정해 채우지 않는다.
4. **효과 검증**: 30·60·90일 결과, 규칙별 정확도와 담당자 부담을 확인해 기준을 조정한다. 경영 보고에는 집계된 유지율·학습 변화와 처리 성과를 연결한다.

미국 IES의 학교 조기경보 체계 연구에서는 출결·과목 이수 관련 일부 지표가 개선됐지만 장기 중도탈락 개선까지 입증한 것은 아니다. 이 개발안은 ‘신호 확인 → 담당 지원 → 결과 점검’ 구조를 참고하며, 해당 연구의 임계값이나 효과 크기를 한국 학원 퇴원율에 그대로 적용하지 않는다.
