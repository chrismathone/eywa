# 상담 이력 확인과 후속조치 에이전트 — 첫 구현

기존 운영실 KPI·입학 상담·학생 상담·슬랙 전달 기능을 재사용한다. 처리와 결과의 원장은 에이와다. 슬랙과 노션에는 알림과 에이와 링크만 전달한다. 운영 배포와 운영 DB 변경은 별도 승인 대상이다.

## 이번 범위

- **입학 상담 전**: 신규 콜&상담 입력 화면에서 과거 캘린더 확인. 저장된 상담 상세에서는 자동 조회한다. 기존 `PriorConsultsHint`·같은 학생 상담 묶음은 그대로 유지한다.
- **과거 캘린더**: 현재 동기화의 과거 30일 창과 별개로, 공유된 입학 상담·신입생/시범수업 캘린더에서 2000년부터 조회일까지 이름 검색을 읽기 전용으로 실행한다. 기존 구글 일정과 `calendar_events`를 수정하지 않는다.
- **동일인 근거**: 기존 `same-person.ts`의 이름·휴대폰 정규화를 재사용한다. 학교·학년 변경으로 배제하지 않는다. 이름만 일치하는 것은 별도 확인 후보다. 이름·연락처 일치도 확정 병합이 아니다.
- **횟수 구분**: 일정 건수·오늘 이전 건수·서로 다른 날짜를 구분한다. 취소 제목과 구글 취소는 집계에서 제외하고 UID+회차 중복을 제거한다. 일정만으로 실제 상담 완료·등록 전환을 주장하지 않는다.
- **등록 근거**: 세션 권한으로 읽을 수 있는 에이와 학생 기록을 함께 확인한다. 읽기 실패·근거 미발견·등록 근거 발견을 구분한다. 과거 이관 누락이나 연락처 변경이 있으므로 미발견은 미등록 확정이 아니다.
- **학생 상담 후속조치**: 기존 `student_consultations.follow_up_date/follow_up_done/counselor_id`를 읽어 기한이 된 미완료 상담을 사건으로 만든다. 담당자 접수 → 처리 결과(완료·재연락·관리자 판단) → 관리자 근거 확인으로 종료한다.
- **감시와 피드백**: 원본 변경·담당자 변경·완료 취소를 다시 확인한다. 늦어진 건은 설정 간격으로 알린다. 관리자 운영실에 진행·결과 대기·원본 확인 필요와 최근 종료 결과를 표시한다. 원본이 삭제돼도 독립 처리 기록 주소에서 관리자가 검토할 수 있다.
- **AI 대응안**: 명시 버튼으로만 구조화 사실을 전달해 제안을 작성한다. 결과는 사건 버전에 맞춰 저장한다. AI가 배정·발송·학생 상태 변경·완료 판정을 수행하지 않는다.

## 설정과 적용 순서 — 아직 운영에 적용하지 않음

1. 검토 환경에서 `0377a_management_agent_tables.sql`부터 `0377e_management_agent_delivery.sql`까지 순서대로 적용한다. 기존 `auth_tenant_id`, `auth_menu_access`, `users`, `student_consultations`, `notifications`, `tenant_settings`가 필요하다. 롤백은 먼저 모드를 끄는 방식이며 처리 이력은 보존한다.
2. 학원 설정 → 알림 → 후속조치 관리를 **관찰**로 시작한다. 기본값은 **끔**이다. 관찰에서는 추가 외부 알림이 없고 기존 알림 경로를 유지한다.
3. 가상 상담으로 담당자 접수, 재연락일, 결과 제출, 원본 완료 체크, 관리자 확인, 재개를 검증한다. 쓰기 권한 없는 계정·다른 학원 계정으로 접근도 확인한다.
4. **운영 승인 후** 활성 모드로 전환한다. `/api/cron/management-agent`는 기존 `CRON_SECRET`으로 보호하며 매시간 15분에 실행하도록 등록했다. 상담 생성·수정·완료 토글에서는 해당 상담만 재확인한다.
5. 슬랙은 기존 계정 매핑·라이선스·알림 설정에서 `management_followup` 전달을 켠다. 기존 inbox/outbox·재시도·조용한 시간 정책을 따른다.
6. 노션 알림을 선택하면 `NOTION_TOKEN`, 정확한 `NOTION_TENANT_ID`, **별도 알림용** `NOTION_MANAGEMENT_DATABASE_ID`, HTTPS `NEXT_PUBLIC_APP_URL`을 설정한다. 기존 직원 업무 DB를 재사용하지 않는다. 노션 댓글·완료 체크를 에이와로 읽어오지 않는다.

캘린더는 기존 `GOOGLE_CALENDAR_SERVICE_ACCOUNT_KEY` 또는 `GOOGLE_SERVICE_ACCOUNT_KEY`를 사용한다. **`GOOGLE_CALENDAR_TENANT_ID`를 명시해야** 이력 조회가 열린다. `GOOGLE_CALENDAR_IDS`의 태그가 입학 상담·신입생·시범수업에 해당하는 캘린더를 사용하며, 다른 명칭이면 `GOOGLE_ENROLLMENT_HISTORY_CALENDAR_IDS`에 사용할 ID들을 줄바꿈 또는 세미콜론으로 지정한다. 기존 공유 목록에 없는 ID는 허용하지 않는다. 서비스 계정에는 해당 캘린더의 세부정보 읽기 권한만 필요하다. 개발 중 연결 도구로 읽은 캘린더 계정과 앱 서비스 계정은 다르므로 배포 전 앱 계정의 공유 권한 확인이 필요하다.

## 개인정보·실패 처리

- 구글 설명·메모·첨부·참석자는 요청하지 않는다. 제목에는 연락처가 있을 수 있어 서버에서만 매칭하고 화면에는 날짜·출처·일치 수준·검증한 원본 링크만 반환한다. 서버 캐시는 학원·이름·조회일·설정된 캘린더별로 5분이다. 매 요청 권한을 다시 확인한다.
- 원본 제목·메모·연락처·이름은 AI 대응안이나 외부 알림에 싣지 않는다. 테스트·PR에는 실학생 기록을 넣지 않는다.
- Google 페이지를 끝까지 읽되 캘린더별 10페이지·2,500건·20초 제한이나 요청 실패 시 **불완전 조회**를 표시한다(진행 중인 요청은 10초 안에 종료). 실패를 ‘이력 없음’으로 숨기지 않는다. 이름이 제목에 없거나 접근할 수 없는 캘린더는 확인하지 못한다.
- 사건·이벤트·알림 대기열에는 tenant_id와 RLS를 적용한다. 직접 상태 쓰기는 금지하고, 세션 RPC가 담당 범위·버전·원본·근거를 다시 확인한다. 이벤트와 내부 알림은 같은 트랜잭션에 기록된다.
- 노션 생성 응답이 유실되면 사건 UUID로 기존 알림을 찾아 갱신한다. 생성 여부가 불확실하고 찾을 수 없으면 자동으로 새 페이지를 다시 만들지 않고 전달 확인 필요로 남긴다. API 전송 성공은 담당자의 업무 접수가 아니다.

## 검증

앱 단위·화면 검증:

```sh
pnpm exec vitest run src/features/enrollment-history src/features/management-agent src/features/enrollment/same-person.test.ts src/features/owner/preset.test.ts src/lib/ai/key-groups.test.ts
```

독립 인메모리 PostgreSQL + pgTAP 검증(운영 DB·앱 환경 파일을 읽지 않음):

```sh
npm install --prefix tests/management-agent-db --ignore-scripts
node tests/management-agent-db/run.mjs
```

실제 신규 SQL을 실행해 학원 격리, 담당 범위, 직접 변경 거절, 중복 실행, 접수와 완료 구분, 낙관적 잠금, 원본 변경·삭제, 1,000건 초과 조회, 전달 claim 복구를 확인한다. 기존 인증 함수는 최소 계약으로 만든 가상 함수이므로 실제 Supabase 인증·슬랙 전달·노션 권한의 통합 검증을 대신하지 않는다.

## 후속 범위

- 전체 후속 순서는 [경영 에이전트 개발 우선순위](management-agent-roadmap.md)를 따른다. 다음 개발 1순위는 [학생별 재원 유지 관리 카드와 지원 업무](student-care-development-plan.md)다. 재원 이력·누적 순수납·숙제·학습 수준·성장·학부모 의견을 기존 화면에 연결하는 계획이며, 이번 첫 구현에 해당 기능이 포함됐다는 의미는 아니다.
- 이번 자동 사건 생성은 **학생 상담 후속조치**에 한정한다. 입학 상담에서 발견한 반복 문의는 상담 전 근거 안내와 기존 후속 연락일·내용·미등록 사유 기록으로 연결한다. 캘린더 후보를 자동으로 새 사건에 배정하거나 외부 알림으로 발송하지 않는다.
- 아침 상담 예정자 일괄 사전 보고, 동일인 확인 결과 보존·정정, 입학 상담 반복 문의의 정식 담당 업무 전환은 다음 단계다. 이번 화면을 검증한 뒤 기존 입학 상담 담당자와 기한을 활용한다.
- 미수납·출결 이상 등은 기존 탐지기를 재사용하는 후속 어댑터다. CSV 업로드·KPI 대시보드·별도 챗봇은 이 변경에 추가하지 않는다.

API 근거: [Google Calendar events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list) — 읽기 권한, q 검색, 페이지 토큰, 시간 범위.
