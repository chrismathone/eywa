  - **저장(SQL 0)**: `window_mode`(기존 행, 행 없음 = 켜짐) = "창 엔진을 쓰나" · 새 행 `window_keepalive`(`tenant_licenses.feature`는 자유 문자열, **기본 꺼짐 opt-in**) = "그 엔진을 한 화면씩 쓰나". `windows` = 앞 켜짐·뒤 없음/꺼짐 · `keepalive` = 앞 켜짐·뒤 **명시로 켬** · `single` = 앞 꺼짐(뒤 값 무시). 판정 단일 소스 [`shell-mode.ts`](src/lib/license/shell-mode.ts), 슈퍼관리자 카드는 두 행을 **항상 함께** 쓰는 셋 중 하나 고르기(`setTenantWindowMode` — 감사로그 `toggle_license` + `mode`, 라이선스 켜기·끄기 목록에는 안 넣는다). 마이그레이션이 없으니 앱이 SQL보다 먼저 배포돼도 안 죽는다([[#95]]).
  - **동작**: 같은 창 엔진(window-store·RouteWindow·창 신호)을 쓰되 **창 크롬 없이 화면 가득, 한 화면만 보이고** 다른 메뉴로 가면 이전 화면은 닫지 않고 **`visibility:hidden`으로 숨겨 둔다**(🔴 display:none 금지 — [[#131]]; iframe에 `visibility:visible`을 못박지 않는다 — 자식의 visible이 조상의 숨김을 이긴다). 돌아오면 스크롤·필터·탭·입력 중 내용이 그대로다. 영속 복원된 화면은 보일 때 처음 로드한다(최소화 = 미활성, B6). 규칙은 순수 함수 [`planKeepalive`](src/components/workspace/keepalive-rules.ts)가 정하고 스토어 `applyKeepalive`가 적용(멱등 — 스토어 변경마다·1분마다·시작 때). **상수 한 곳**: `KEEPALIVE_MAX=5`(보이는 것 포함 · 넘으면 가장 오래 안 쓴 숨은 화면부터) · `KEEPALIVE_EXPIRE_MS=2h`(숨은 화면의 마지막 사용 후 — 사용 = 보이게 됨·숨게 됨·화면 안 클릭·키·휠, 막 떠난 화면은 떠나는 순간이 마지막 사용이라 떠나자마자 만료·상한으로 사라지지 않는다, 영속본 `lastUsed`라 브라우저를 껐다 켜도 같은 기준, 복원 직후엔 보이던 화면도 같은 기준) · 10분 = 기존 `STALE_AFTER_MS`(숨었다 돌아올 때 소프트 새로고침 — 화면은 그대로, 데이터만; 가드가 두 값이 같음을 잠근다). 🔴 **입력 중(미저장)·작업 중(녹음) 화면은 상한·만료 어느 쪽으로도 말없이 안 버린다**(건너뛰므로 상한을 넘을 수 있다 — 숨은 화면엔 확인 창을 띄울 자리가 없다).
  - **방식이 바뀌면 초기화**: 레이아웃이 방식 + **판(epoch — 방식 행 둘의 `updated_at` 중 최신, 행이 없으면 `none`)**을 내려 주고, 캔버스가 `adoptOwner(owner, mode, epoch)`로 영속본과 비교한다(`needsModeReset` — 방식이 다르거나, 같아도 판이 다르면). 판까지 보는 이유 = 창 모드 → 단일 화면 → 창 모드로 **바꿨다 되돌린 사이** 접속하지 않은 사람의 옛 창이 살아나지 않게. 🔴 표식 없는 옛 영속본 = 창 모드이고 판은 안 본다(배포 날 창 모드 지점의 새로고침 복원이 안 깨진다). 🔴 라이선스 조회가 실패하면(판 = 모름) 방식을 채택하지 않는다(일시 장애 한 번에 모두의 유지 화면이 지워지지 않게 — 그 요청은 종전 fail-open대로 창 모드로 보인다). 🔴 **방식은 문서 하나 동안 고정**이다 — 셸 공급자(`ShellModeProvider`)가 처음 받은 방식·판을 끝까지 쓴다. 바탕이 다시 그려져(`router.refresh`·재검증) 새 값이 와도 따르지 않는다: 따르면 캔버스가 창 트리 ↔ 화면 트리를 갈아 끼워 iframe이 전부 다시 마운트되고 **입력·녹음이 말없이 끊겼다**(적대 리뷰). 창 엔진 여부(`WorkspaceEnabledProvider` — 창 모드를 끄면 false)도 같은 이유로 고정한다(도중에 꺼지면 캔버스가 사라져 열린 창이 파괴됐다 — 재리뷰). 바뀐 방식은 다음에 페이지를 열 때(새로고침·새 탭·다음 접속) 적용된다. 다른 계정이면 무엇이든 전부 닫는다. 이 효과는 캔버스가 늘 마운트라 **단일 화면·폰에서도** 돈다(어느 방향 전환이든 잡힌다). 슈퍼관리자 카드에도 "다음 접속 때 전부 닫힌다"를 적었다. 스토어 규칙(복제 금지·사용 도장)은 영속본의 방식이 아니라 **지금 그려진 방식**(런타임 `kaActive`)을 본다(조회 실패로 이 요청만 창 모드일 때 규칙이 섞이지 않게).
  - **주소·뒤로가기**: 주소창 = 보이는 화면([`use-keepalive-follow.ts`](src/components/workspace/use-keepalive-follow.ts)). 화면 전환 = `pushState`(기록 한 칸 → 뒤로가기가 이전 화면), 같은 화면 안 이동(드릴인) = `replaceState`. 반대로 주소가 바뀌면(뒤로·앞으로·직접 열기·새로고침·공유 링크) 그 화면을 연다(딥링크). **근거**: same-origin iframe 안 이동도 한 탭의 합동 세션 기록에 쌓인다 — 드릴인마다 주소창을 `replaceState`로 맞춰 두면 기록 칸마다 '주소창 주소 + 그 칸의 iframe 주소'가 한 쌍이라, 되감을 때 화면 전환 칸은 `popstate`로(→ 그 화면을 보이게), 드릴인 칸은 그 화면 iframe의 되감기로(→ 관찰자가 주소를 다시 맞춘다) 풀리고 보이는 화면과 주소가 어긋나지 않는다(숨은 화면만 조용히 되감기는 '죽은 뒤로 한 번'이 없다 — 숨은 화면의 기록 칸은 그 화면이 보일 때 쌓인 것이다). 스토어 → 주소는 **보이는 화면이 바뀐 때만** 쓰고, **주소에서 출발한 동기화**(뒤로·앞으로·직접 열기) 중에 생긴 변화는 `replaceState`로만 맞춘다(쌓으면 앞으로 가기 기록이 잘린다). 🔴 이미 연 화면을 다른 주소로 옮길 때 iframe `src` 속성을 바꾸지 않는다 — src 변경은 합동 세션 기록에 한 칸을 쌓아 뒤로를 두 번 눌러야 이전 화면으로 갔다. 이 방식에선 src를 처음 실은 주소로 고정하고 `location.replace`로 옮긴다(`RouteWindow` `pinnedHref`, 창 모드는 종전대로 src가 따라간다). Next는 외부 `pushState`를 가로채 라우터 주소만 맞추고 렌더된 트리는 그대로 둔다 — 그래서 사이드바 강조(포커스 창 기준)·`usePathname`이 보이는 화면을 따른다. 탭 제목도 보이는 화면 문서의 제목을 따르고(뒤로가기 목록의 이름) 첫 화면으로 오면 바탕 제목으로 되돌린다.
  - **바탕(<main>)**: 늘 첫 화면(운영실 또는 권한상 `/menu`)이어야 한다. 바탕이 **실제로 그리는 화면은 주소가 아니라 라우터 트리**(`useSelectedLayoutSegments`)로 안다 — 주소를 직접 열어 들어왔거나(딥링크: 서버가 그 화면을 바탕에 렌더) 바탕에서 `router.refresh()`·재검증 액션이 돌면(그때 주소 = 보이던 화면) 바탕이 그 화면이다. 첫 화면으로 돌아갈 때 바탕이 첫 화면이 아니면 주소만 바꾸지 않고 **그때 한 번 라우터로 첫 화면을 연다**(미리 옮기지 않는다 — 첫 화면을 안 볼 사람에게 운영실 렌더를 치르게 하지 않는다). 🔴 바탕이 첫 화면이 아닌 화면의 **사본**을 그리고 있으면 React `<Activity mode="hidden">`으로 **잠재운다**(`KeepaliveMainGate` — 효과·폴링·구독·리다이렉트 처리가 멈춤, 다시 깨우지 않는다 — 첫 화면으로 갈 때 라우터가 갈아 끼운다). 이 방식은 주소가 늘 화면이라 **모든 새로고침이 딥링크**다 — 안 그러면 그 사본이 덮인 채 폴링을 계속 돌렸다(적대 리뷰, B6). 🔴 **첫 화면(운영실)은 잠재우지 않는다** — `display:none`이면 셸 <main> 스크롤이 0으로 잘려 돌아온 운영실이 맨 위에 와 있었다(재리뷰). 레이아웃이 이 방식일 때만 감싼다. 생성폼 끝의 바탕 갱신(`RouteWindow` autoClose의 `router.refresh`)은 이 방식에서 하지 않는다(소스 목록 창은 reload). 폭이 좁아져 이 방식이 꺼지면 본문이 그 주소의 화면을 그리게 소프트 이동한다.
  - **주소 → 화면 찾기**: ① 이미 그 주소를 보여 주는 화면(메뉴 화면이 안에서 드릴인한 상세 포함 — iframe의 **실제 주소**로 비교, 창 id를 주소에서 다시 계산하면 `students`가 드릴인한 `/students/abc`를 못 알아보고 새 화면을 연다) ② 없으면 그 주소의 화면을 연다 — id는 메뉴·링크·알림·팰릿·창 모드 딥링크와 같은 `windowIdForHref`(상세는 메뉴 화면과 다른 화면 — 숨겨 둔 목록을 상세로 옮겨 필터·스크롤을 날리지 않는다). 같은 id 화면이 입력 중·작업 중이면 옮기지 않고 보이게만. 보이던 화면이 닫히면(생성폼 autoClose 등) **열기 전에 보이던 화면(없으면 첫 화면)**으로 돌아간다 — 창 엔진의 '순서상 마지막 창'은 숨은 옛 화면이다(`kaBack`).
  - **겉모습 = 단일 화면과 같게**: 화면 문서(iframe)는 `embed-main`이 아니라 단일 화면 셸 `<main>`과 **같은 클래스**(`KEEPALIVE_MAIN_CLASS`, 가드가 토큰을 대조) — 머리글이 창용 한 줄로 접히지 않고 데스크톱 한 줄 머리글이 선다. 문서를 **뷰포트 전체 폭**으로 깔고 사이드바(z-45)가 그 위를 덮으며, 사이드바 폭만큼 왼쪽 안쪽 여백은 문서가 부모 사이드바를 재서 만든다(`--keepalive-rail` — 첫 페인트 전 인라인 스크립트 + `KeepaliveFrameBridge`) — 그래서 폭 기준 반응형(`desk:`·compact-chrome·`phone:`)이 단일 화면과 똑같이 판정된다(사이드바를 뺀 폭으로 재면 노트북에서 모바일 배치로 접힌다). 화면 문서가 이 모양을 쓸지는 **부모가 이 문서에서 쓰는 방식**(쿠키 `eywa-shell-mode` — 셸 공급자가 적는다)을 따르고, 없을 때만 서버 판정이다(DB를 다시 읽으면 방식 전환·조회 실패 때 새 화면만 창 모양이 되어 사이드바 밑에 깔렸다). 쿠키는 브라우저 전체가 같이 쓰므로 판을 모르는 문서(조회 실패)·iframe 안에서 그려진 풀셸은 적지 않는다. body로 포털되는 **가운데 놓이는 고정 레이어**(공용 다이얼로그·가운데 정렬 덮개·`inset-0 m-auto` 상자·네이티브 모달 `<dialog>`·전폭 하단 바)는 globals.css `html[data-keepalive-frame]` 규칙이 사이드바 오른쪽 영역으로 비킨다(안 비키면 넓은 다이얼로그 왼쪽이 사이드바 밑에 깔린다). 창 최소 크기 안내는 안 낸다. 창 크롬이 없으니 인페이지 '← 뒤로'(`BackLink`)는 선다.
  - **화면 최대화**: 이 방식에서도 쓴다. 상태·계정 저장·사이드바 숨김은 부모 셸이 갖고, 화면(iframe)의 머리글 버튼은 postMessage(set/state/query — 같은 출처 + 등록된 iframe만)로 부모를 거친다(부모 쪽 = 무대가 그리는 `KeepaliveMaximizeSync`, 화면 쪽 = `KeepalivePageMaximize` — 첫 HTML은 서버가 읽은 계정값). 화면 문서의 첫 HTML용으로 화면을 열 때마다 `ui_prefs`를 한 번 읽는다.
