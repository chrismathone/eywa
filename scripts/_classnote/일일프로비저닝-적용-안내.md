# 발송 PC — 일일 프로비저닝 적용 안내 (2026-07-13, 반공지 zip 다음 버전)

## 무엇이 바뀌나
발송 데몬이 **매일 새벽 5시(KST) 이후 첫 폴에서 하루 1회** 자동으로:
1. **신규생 보드 생성** — 재원 + 발송 허용 과목(현재 수학) 수강인데 ClassNote에 보드가 없는 학생
   → `(수학)이름` 빈 반 자동 생성
2. **가입자 자동 배정** — 학부모가 가입까지 했는데 자기 보드가 비어있는 학생 → 자동 배정
   (배정 시 학부모 앱에 반 배정 알림이 갈 수 있음 — 정상 온보딩)

동명이인(같은 이름 재원생·같은 이름 원아)은 자동 처리하지 않고 로그에 "보류"로만 남깁니다(오발송 방지).
**학부모 초대(가입)만 데스크 몫**으로 남습니다.

## 적용 방법 (2분)
1. zip 안의 `scripts\_classnote\` 내용을 같은 경로에 **덮어쓰기** (반공지 zip을 이미 적용했어도 전부 덮어쓰면 됩니다):
   - `watch-classnote-queue.mjs` (데몬 — 일일 프로비저닝 호출 추가)
   - `classnote-provision-core.mjs` (신규 — 일일 프로비저닝 코어)
   - `classnote-admin-core.mjs` (갱신 — 반 생성 헬퍼 이동)
   - `provision-classnote-boards.mjs` / `assign-classnote-students.mjs` (갱신 — 수동 실행판, 평소 사용 안 함)
   - 나머지 파일은 반공지 zip과 동일
2. `발송PC-지정.bat` 재실행(또는 재부팅)으로 데몬 재시작.

## 확인 방법
재시작 직후(새벽 5시 이후라면) 첫 폴에서 오늘 치가 바로 1회 돌고, `D:\tmp\classnote\watch.log`에
`[provision] 일일 프로비저닝 완료 — 보드 생성 N · 배정 N` 로그가 남습니다.
지금은 보드·배정이 다 맞춰진 상태라 **0 · 0이 정상**입니다(신규생이 생기면 다음 날 숫자가 올라감).

## 조건 요약
- 데몬이 **--post(실게시) 모드**일 때만 동작(dry-run 데몬은 아무것도 안 만짐).
- 발송 스위치(ClassNote 실제 발송)와는 **무관** — 보드·배정은 발송이 아니라 준비 작업이라,
  스위치가 꺼진 기간에도 신규생 인프라가 미리 쌓입니다.
- 하루 1회 마커: `D:\tmp\classnote\provision-last-run.txt` (지우면 그날 다시 1회 실행 — 문제 없음, 멱등).

## 롤백
`watch-classnote-queue.mjs`만 이전 버전으로 되돌리고 데몬 재시작(프로비저닝만 빠지고 발송·공지는 그대로).
