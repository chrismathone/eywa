## SQL 적용

새 마이그레이션: `supabase/migrations/20261007171329_mcs_atomic_goal_reset.sql`.

- 함수는 `SECURITY INVOKER`, 빈 `search_path`, 일반 로그인·비로그인 역할 실행 권한 없음, `service_role`만 실행 가능하다.
- 두 목표 테이블 삭제를 한 호출의 트랜잭션으로 처리한다. 실제 오류를 삼키는 삭제 폴백은 없다.
- 운영 앱과 DB 연결 대상이 일치함을 확인한 뒤 Supabase CLI로 적용했다. 사용 중인 CLI의 다중 문장 prepared query 제한 때문에 동일 정의·권한을 단일 DO 트랜잭션으로 묶어 실행했다. 표준 마이그레이션 파일은 전체 BEGIN/COMMIT 형태로 보존한다.
- 운영 카탈로그에서 invoker·실행 권한·두 목표 테이블의 RLS 유지 여부를 확인했다. 운영 목표 초기화나 보고서 저장은 검증 중 실행하지 않았다.
- 배포할 코드의 초기화 액션은 이 함수가 필요하다. 이전 방식의 개별 삭제로 우회하지 않는다. 운영 함수가 먼저 적용돼 있으므로 코드 반영 순서에 필요한 조건을 갖췄다.
