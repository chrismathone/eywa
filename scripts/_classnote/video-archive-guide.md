# 클래스노트 숙제 영상 → Google Drive

기존 연동 PC의 `watch-classnote-queue.mjs --post`에 포함된 기능이다.
작업 스케줄러 `eywa-classnote-worker`, 로그인 세션, PC 임대, 재시작 절차를 그대로 사용한다.
웹 배포만으로 연동 PC의 코드가 바뀌지는 않는다. `scripts/_classnote` 전체 ZIP을 교체해야 한다.

## 지점별 저장 계정 (2026-10-04)

켜는 순서는 코드 확인 → SQL 한 묶음 → 워커 전체 교체 → 그 다음 계정이다. SQL을 코드보다 먼저 적용하지 않는다.

1. 계정 연결을 아는 웹 코드를 배포하고 확인한다. 구글 클라우드에 이미 있는 OAuth 클라이언트가 웹 애플리케이션이면 그것을 그대로 쓴다. 지금 있는 것이 데스크톱 앱이면 같은 프로젝트에 웹 애플리케이션 클라이언트를 하나 추가하고, 기존 데스크톱 클라이언트는 남겨 둔다. 웹 클라이언트는 모든 지점이 하나이고, 각 지점은 그 클라이언트로 자기 Google 계정에 로그인한다. Vercel에만 다음 세 값을 둔다.
   `HOMEWORK_VIDEO_GOOGLE_CLIENT_ID` · `HOMEWORK_VIDEO_GOOGLE_CLIENT_SECRET` · `HOMEWORK_VIDEO_GOOGLE_REDIRECT_URI`.
   `REDIRECT_URI`는 구글 콘솔에 등록한 고정 콜백 전체 주소다. 경로는 `/api/integrations/homework-video-drive/callback`이고, 운영은 `https://www.aywa.co.kr/api/integrations/homework-video-drive/callback`이다. 쿼리·해시·사용자 정보는 붙이지 않는다. 이 비밀은 발송 PC에 복사하지 않는다.
   예전 데스크톱 값 `GOOGLE_DRIVE_CLIENT_ID` · `GOOGLE_DRIVE_CLIENT_SECRET` · `GOOGLE_DRIVE_REFRESH_TOKEN`은 연결 번호가 없는 기존 계정 전용이다. 지점 계정의 Vercel 값으로 넣지 않는다.
2. 코드가 확인된 뒤에 `0338a_homework_video_drive_tenant_config.sql`, `0340a_homework_video_drive_accounts.sql`, `0341a_homework_video_drive_account_credentials.sql`, `0342a_homework_video_drive_account_routes.sql`을 **한 트랜잭션**으로 적용한다. 파일 안의 `begin`·`commit`을 바깥 트랜잭션으로 합치고, 마지막에 PostgREST 스키마를 갱신한다. `0338a`만 따로 적용하지 않는다. 이미 `0338a`만 있는 환경은 남은 세 파일을 한 트랜잭션으로 적용한다. 오늘의수학 `0339a`는 이 묶음과 별개다.
3. `scripts/_classnote` **전체 ZIP**을 덮어쓰고 `발송PC-지정.bat`을 실행한다. 계정 루트를 켜기 전에 이 워커가 온라인이어야 한다.
4. **학원 설정 → 연동 → 숙제영상 드라이브**에서 그 지점의 Google 계정과 빈 폴더를 지정한다. 새로 지정하는 폴더는 비어 있어야 하고,
   그 계정에 파일 추가 권한이 있어야 한다. 다른 지점과 동일하거나 상하위인 폴더는 지정할 수 없다. 공통 부모 아래의 형제 폴더는 가능하다.
5. 발송 큐 현황에서 새 워커가 연결됐는지 확인하고, `check-video-worker.mjs`로 지점 폴더와 계정이 맞는지 확인한다.
   `homeworkVideoTenantAccounts`가 없는 온라인 PC가 있으면 새 계정은 켜지지 않는다. 폴더만 바꿀 때도 폴더 지원이 없는 온라인 PC는 먼저 업데이트한다.

저장 위치는 지점별 DB 설정이 정본이다. 새 지점의 폴더를 PC 환경변수로 지정하지 않는다. 발송 PC에 새 클라이언트 비밀을 넣지 않는다.
계정 표가 생기기 전에는 기존 등록부에서 가져온 지점의 환경값이 설정 행이 없는 동안만 유지되며, 연결 해제 후 환경값으로 다시 켜지지 않는다.
계정 표가 있어도 연결 없는 기존 루트는, 그 루트가 이 지점 소유로 확인된 뒤에 발송 PC의 기존 인증을 쓴다. 발송 PC의 `GOOGLE_DRIVE_*` 세 키는 그 연결 없는 계정만 담당한다. 연결이 있는 계정만 서버의 짧은 접근 토큰을 받고, 그 조회가 실패해도 PC 인증으로 돌아가지 않는다.
기존 파일·영상 기록은 이동하거나 삭제하지 않는다. 바꾸기 전에 시작한 작업은 처음 찍힌 폴더와 계정에서 완료한다. 직접 제출 스캔은 그 계정의 루트만 본다.

PC가 서버에 토큰을 요청할 때 쓰는 `CLASSNOTE_INTERNAL_SECRET`은 발송 PC가 함께 알고, PC는 DB에도 직접 붙는다. 살아 있는 호스트 이름 확인은 지점·폴더·연결이 우연히 섞이지 않게 하는 장치다. 그 이름은 요청 본문에 있으므로 흉내 낼 수 있다. 서버는 호출한 쪽이 그 컴퓨터임을 증명하지 못한다. 시크릿과 DB 접근을 가진 PC에 대한 격리가 아니다. 그 지점 안에서는 지금 고른 계정이 아니어도, 이미 시작한 작업의 이전 연결까지 토큰을 받을 수 있다.
학생의 제출 주소는 모든 지점에서 `/v` 하나다. 사용 가능한 지점이 여러 곳이면 먼저 지점을 고르고, 한 곳이면 바로 학생 정보를 입력한다.
앱은 Drive 공유 권한을 바꾸지 않으며, 재생은 보는 사람의 Google 권한을 따른다.

## 이번 학원 설정

- 저장 위치: [학생동영상](https://drive.google.com/drive/folders/1r4PhTUJoCqLdlbdfGN8IhnGrokKK5DmK).
- 기존 `허주연T`, 시험용 `육소희 선생님` 폴더는 확정 ID로 DB에 연결했다. 같은 담임 폴더를 다시 만들지 않는다.
- 파일명: **에이와학생명_에이와반이름_에이와학교학년_클래스노트업로드날짜.mp4**.
  예: `류태경_LT4_칠성초3_2026-09-30.mp4`.
- 날짜는 원본 글·댓글 작성 시각의 한국 날짜다. 이전 영상도 복사한 오늘 날짜로 바꾸지 않는다.
- 로컬 임시 파일은 중단 후 재개를 위해 기관·영상 번호를 사용한다. Drive 표시 이름만 위 형식을 쓴다.

## 기존 연동 PC에 적용

1. 새 ZIP의 `scripts/_classnote` 폴더 전체를 기존 저장소에 덮어쓴다. 기존 `.env.local`은 유지한다.
2. 연동 PC에서 [Google Cloud CLI](https://cloud.google.com/sdk/docs/install)를 설치한다(이미 있으면 생략).
3. 기존 워커를 실행하는 Windows 사용자로 `scripts/_classnote/발송PC-영상연결.bat`을 더블클릭한다.
   Drive 최초 로그인 → 폴더 권한 확인 → 설정 저장 → 기존 워커 재시작 → 새 버전 적용 확인까지 진행한다.
   이미 Drive가 연결돼 있으면 로그인을 다시 요구하지 않는다. Google 로그인 화면이 나오면 해당 계정으로 동의한다.
4. 마지막에 **새 워커와 영상 저장 폴더 적용을 확인했습니다**가 나오면 완료다.
   기존 워커가 등록되지 않은 PC나 다른 Windows 사용자로는 시작하지 않는다.

직접 명령을 실행하려면 저장소 루트에서:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\_classnote\setup-video-drive.ps1 -Account chrismathone@gmail.com -FolderId 1r4PhTUJoCqLdlbdfGN8IhnGrokKK5DmK -RestartWorker
```

별도 예약 작업을 만들지 않고 기존 지정 스크립트를 재사용한다.
검사기는 DB의 새 `started_at`, 최근 심장박동, 영상 기능, 요청한 저장 폴더를 모두 확인한다.
로그에는 `[영상 이력]`, `[영상] Drive 저장 완료`가 기록된다.

설정 변경 없이 현재 적용 상태만 확인하려면:

```powershell
node --env-file=.env.local scripts/_classnote/check-video-worker.mjs
```

인증은 Google 공식 `gcloud auth login --enable-gdrive-access` 방식이다.
토큰 저장소를 직접 복사하거나 읽지 않고, 공식 CLI가 갱신한 토큰으로 업로드한다.
폴더 접근 확인에 성공한 경우에만 `.env.local`에 영상 설정을 추가하며 기존 파일을 백업한다.
설정: `CLASSNOTE_VIDEO_DRIVE_FOLDER_ID`, `GOOGLE_DRIVE_GCLOUD_ACCOUNT`, `GOOGLE_DRIVE_GCLOUD_PATH`.
다른 Windows 사용자/PC에서는 한 번 다시 로그인해야 한다.

서비스계정은 Workspace **공유 드라이브**만 지원한다(개인 Drive에서는 저장 한도가 0이라 올리지 못한다).
개인 Drive의 공유 폴더는 Workspace 공유 드라이브와 다르다.

### 연동 PC에 Google 로그인·CLI를 두지 않는 길 — OAuth 값 파일 (2026-09-30, 연결 없는 기존 계정)

이 절은 연결 번호가 없는 기존 계정만 다룬다. 우선순위 gcloud 계정 > 갱신 토큰 > 서비스계정은 그 PC 인증에만 적용된다. 연결 번호가 있는 지점 계정은 서버의 짧은 접근 토큰만 받고, 실패해도 이 PC 값으로 돌아가지 않는다. 아래 절차는 기존 계정을 위해 그대로 둔다.

올린 파일의 주인은 허락한 계정 그대로다(gcloud 방식과 결과가 같다). 로그인은 **다른 PC**에서 한 번만 한다.

1. 구글 클라우드 콘솔에서 한 번: Drive API 사용 → OAuth 동의 화면(대상 '외부', **게시 상태 '프로덕션'** — '테스트'면 7일 뒤 끊긴다)
   → 클라이언트 만들기(유형 **데스크톱 앱**) → JSON 다운로드.
2. 아무 PC의 저장소 루트에서(연동 PC가 아니어도 된다):

   ```powershell
   node scripts/_classnote/video-oauth-login.mjs --client=<client_secret_….json> --account=chrismathone@gmail.com
   ```

   브라우저에서 그 계정으로 허용 → 계정을 확인한 뒤 다운로드 폴더에 `aywa-video-oauth.txt`가 생긴다.
3. 그 파일을 연동 PC의 **다운로드 폴더**로 옮기고 `scripts/_classnote/발송PC-영상연결-OAuth.bat`을 더블클릭한다.
   인증 확인 → `.env.local` 백업·저장(gcloud 키는 지운다) → 값 파일 삭제 → 워커 재시작 → 지점 저장 폴더 적용 확인.
   저장 뒤 재시작·확인에서 멈췄으면 같은 bat을 다시 누른다(값 파일 없이 이어 간다).

설정: `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET`, `GOOGLE_DRIVE_REFRESH_TOKEN`.
우선순위는 gcloud 계정 > 갱신 토큰 > 서비스계정이다. 갱신은 `fetch`만 쓴다(연동 PC에 googleapis가 없어도 된다).

- 🔴 값 파일·클라이언트 JSON을 저장소나 `scripts/_classnote`에 두지 말 것 — 워커 zip은 그 폴더를 통째로 담는다
  (zip 빌드가 발견하면 멈추고, `.gitignore`도 두 이름을 막는다).
- 저장 폴더 변경은 학원 설정의 연동 화면에서 한다. 인증 파일에 들어 있는 옛 폴더 줄은 무시하고 기존 환경값도 덮어쓰지 않는다.
- 로그인 스크립트를 다시 돌려도 기존 연결은 그대로다. 스크립트는 허락을 자동으로 취소하지 않는다
  (취소는 그 계정의 허락 전체를 없애 연동 PC가 쓰던 토큰까지 죽인다 — 필요 없는 허락은 myaccount.google.com/permissions 에서 직접).
- 연결이 끊기면(허락 취소·만료) 워커 로그에 `[영상] Drive 인증 실패 — …`가 찍히고 영상 작업을 집지 않는다. 1~3을 다시 하면 된다.

## 수집·분류·중복 방지

- 학부모 글·댓글의 실제 `attached_video`를 수집한다. 본문이 비어도 포함하고, `[영상]` 글자만 있으면 제외한다.
- 기존 새 글·댓글 감지와 함께, 전체 이력을 날짜 제한 없이 조금씩 순회한다. 댓글도 100개 이후까지 페이지를 읽는다.
- 진행 상태는 DB에 저장한다. 중단 시 그 위치부터 재개하고 전체 순회 완료 후 7일 뒤 다시 순회해 오래된 글의 새 댓글도 회수한다(최근 글의 새 댓글은 댓글 감지가 따로 거둔다).
- 과거 이관은 **클래스노트에서 접근 가능한 과거 글·댓글 영상**이다. 기존 다른 Drive 폴더의 보관 영상은 이동하지 않는다.
- 학생은 기존 확정 ClassNote↔에이와 번호 연결을 사용한다. 학생명으로 추측하지 않는다.
- 에이와 반 연결 우선, 학생별 과목 보드는 해당 과목의 수강 이력으로 반을 정한다. 영상 작성일의 수강 기간을 사용한다.
- 반을 못 정해도 올린다(원장 2026-10-01 — 수집이 목적). 1인 보드 글은 JJ 반을 빼고 반을 정하고, 그래도 반이 여러 개이거나 없으면
  파일명의 반 자리를 `반미정`으로 둔다. 담임이 한 사람으로 정해지면 그 담임 폴더, 아니면 `담임 확인 필요` 폴더.
  에이와 학생 연결이 없으면 학생 자리를 `미연결 <ClassNote 보드 이름>`으로 두고 `담임 확인 필요` 폴더에 올린다.
- 담임 폴더는 담임 ID를 DB에서 한 번만 선점한다. 최초 저장한 폴더를 유지한다.
- 영상 큐는 기관+원본 영상 ID로 중복 제거한다. 같은 폴더의 같은 크기·MD5 파일은 같은 Drive 파일 ID를 사용한다.
- 생성 ID를 먼저 보존하고 전송을 재개한다. 업로드 후 Drive 파일의 부모·크기·MD5를 검증한다.
- 파일명이 같아도 서로 다른 영상은 별도 파일로 보관한다. 이름을 중복 판정 키로 쓰지 않는다.
- 실패는 15분 뒤 재시도한다. 기존 보고서 발송 루프는 다운로드·업로드를 기다리지 않는다.
- 로컬 원본은 500MB 상한이다. Drive 검증과 DB 저장 완료 뒤 워커의 임시 MP4(압축본 `*.aywa.*` 포함)를 정리한다. 실패한 작업은 재개를 위해 보존한다.
- 폴더를 공개하거나 담임에게 자동 공유하지 않는다. 기존 상위 폴더 권한을 따른다.

## 압축·Drive 용량 (2026-10-01)

원장 *"구글 드라이브 업로드 시에 압축해서 … 화질 같은 건 최대한 보존해서 압축"*. **앞으로 올라가는 영상만** 압축한다 —
이미 올라간 영상은 그대로 둔다(원장 *"311건은 냅둬 압축하지마"*, 재압축 도구 없음).

- 흐름: 내려받기 → (같은 폴더 중복이 아니면) 압축 → Drive. 압축본이 원본보다 **15% 이상** 작을 때만 압축본을 올리고, 아니면 원본.
  원본 영상 비트레이트가 이미 낮으면(픽셀·프레임당 0.08비트 미만 — ClassNote 1080p 약 4Mbps가 0.067) 인코딩하지 않고 원본(`kept-bitrate`).
  ffmpeg 없음·실패·시간 초과·검증 불일치(파일·영상 길이·크기·소리)는 전부 **원본을 올린다**(압축이 보관을 막지 않는다).
  판단(압축함·원본 유지·실패)은 영상 옆 `*.aywa.json`에 남겨 재시도 때 다시 인코딩하지 않는다.
- 설정(`video-compress.mjs` `COMPRESS_PROFILE`): H.264 High·8비트 4:2:0 · **CRF 22** · preset **medium** · 해상도 원본(긴 변 1920 초과만 1920으로)
  · 프레임 타이밍 그대로(가변 프레임 포함) · 세로 영상은 픽셀을 돌려 화면 방향 그대로 · 원본 AAC는 복사(그 외 AAC 128k) · faststart.
  HDR(HLG·PQ·돌비 비전)은 8비트로 옮기면 색이 바래 원본을 올린다.
- 근거(실측, ClassNote가 내려준 1080p 세로 15초 영상 1건 · 원본 4.1Mbps · VMAF는 원본 대비):

  | 설정 | 크기(원본 대비) | VMAF |
  |---|---|---|
  | CRF 21 medium | 1.75배 | 97.5 |
  | **CRF 22 medium** | **1.56배** | **96.9** |
  | CRF 23 medium | 1.38배 | 96.0 |
  | CRF 22 slow | 1.52배(medium보다 −2.5%) — 시간 1.8배 | 96.8 |
  | CRF 26 / 28 slow | 0.93배 / 0.72배 | 92.3 / 89.0 |

  CRF 21↔22의 화질 차이(0.6)는 눈으로 구분되는 폭(약 6)보다 훨씬 작고 크기는 12% 크다. 23은 95에 가까워 움직임·잡음이 많은 영상에서 여유가 없다 → 22.
  slow는 2.5% 줄이려고 시간이 1.8배라 발송 PC 부담만 커진다 → medium.
  🔑 **ClassNote가 이미 압축해서 내려주는 영상(약 4Mbps)은 화질을 지키는 설정으로는 더 줄지 않는다** — 위 표본은 오히려 커진다.
  그래서 이런 영상은 비트레이트만 보고 인코딩 없이 원본을 올린다(발송 PC 시간 절약).
  15% 넘게 줄이려면 CRF 26 이상(VMAF 92 이하)으로 화질을 깎아야 한다. 휴대폰 원본(1080p H.264 약 16Mbps · 4K 약 45Mbps)은 크게 준다.
- H.265는 쓰지 않는다: Drive 미리보기·브라우저 재생이 기기마다 갈린다(파이어폭스 미지원, 크롬은 하드웨어 지원 기기만, 옛 윈도는 유료 확장).
- 발송이 본업이라 ffmpeg는 **낮은 우선순위·CPU 절반**으로 돈다. 시간 상한 = 영상 길이×8+2분(10~60분), 넘으면 원본.
  워커(node)를 강제 종료하면 ffmpeg도 함께 끝난다(Windows에서 node가 자식을 '부모와 함께 종료'로 묶는다, 실측).
  작업 임대는 30초마다 갱신돼 10분 회수와 부딪히지 않는다. 그동안 다음 영상은 기다린다.
- 중복 판정은 **원본 지문**(원본 md5·크기) 그대로다 — DB `bytes`·`md5`도 원본. Drive 파일의 공개 `properties`에 `aywaSourceMd5/Bytes`(원본)와
  `aywaUploadMd5/Bytes`(올린 내용), `aywaCompressed`(`h264-crf22-medium-v1` 압축함 · `kept-bitrate` 이미 낮은 비트레이트 · `kept-savings` 절감 부족
  · `kept-hdr` HDR · 없음=판단 안 함)를 남긴다. 🔴 `appProperties`가 아니라 `properties`인 이유: 앱 속성은 OAuth 클라이언트마다 비공개라
  인증 방식을 바꾸면(gcloud↔OAuth) 안 보여 압축본이 "원본과 다름"으로 영구 실패한다. 값은 해시·크기·표식뿐이다.
  같은 원본의 압축본이 이미 있으면 다시 압축하지 않는다. 행의 `route.archive`에 Drive 크기·압축 여부가 남는다.
- **ffmpeg 설치(발송 PC 한 번)**: 워커를 돌리는 **같은 Windows 사용자**로 `scripts/_classnote/발송PC-영상압축-설치.bat` 더블클릭
  (winget `Gyan.FFmpeg`). 재시작 없이 10분 안에 잡힌다(winget 링크 폴더·설치 폴더를 직접 본다). 다른 위치면 `.env.local`에
  `CLASSNOTE_FFMPEG_PATH`(·`CLASSNOTE_FFPROBE_PATH`), 끄려면 `CLASSNOTE_VIDEO_COMPRESS=off`. zip에는 ffmpeg를 넣지 않는다.
- 🔴 **되돌릴 땐 옛 zip이 아니라 `CLASSNOTE_VIDEO_COMPRESS=off`**: 옛 워커는 압축본을 같은 영상으로 알아보지 못해(원본 md5와만 비교)
  이미 압축본이 올라간 영상의 재시도·중복이 영구 실패하고, 압축본으로 시작한 업로드 재개 기록과도 어긋난다.
- 라이선스: 이 ffmpeg 빌드는 GPLv3(libx264가 GPL)다. 별도 프로그램으로 실행만 하므로 aywa 코드에 GPL이 옮지 않고, 각 PC가 winget으로 직접
  받으니 우리가 바이너리를 배포하지 않는다. 다른 학원에 워커를 줄 때도 zip에 넣지 말고 같은 방식으로 각자 설치하게 할 것.
- **Drive 남은 공간 감시**(`video-drive-quota.mjs`): 계정마다 따로 본다. 연결 없는 기존 계정은 남은 공간이 **20GB** 아래면 새 영상 작업을 집지 않는다
  (`.env.local`의 `CLASSNOTE_VIDEO_DRIVE_MIN_FREE_GB`가 0보다 크면 그 값. 근거는 그 계정의 여유와 한 달 1~3GB 유입). 한도가 있는 새 계정은
  **1GB와 한도의 10% 중 작은 값**이 기본이다(15GB 계정은 1GB). `CLASSNOTE_VIDEO_DRIVE_ACCOUNT_MIN_FREE_GB`를 적으면 그 값을 줄이지 않고 그대로 쓴다.
  빈 값은 0이 아니다. 한도가 없는 계정은 이 검사로 멈추지 않는다. 멈춘 계정은 새 작업만 미루고, 이미 폴더가 찍힌 작업은 이어서 올린다.
  큐는 대기하고 공간이 생기면 자동 재개한다(로그 `[영상] ⚠ Drive 남은 공간 …`). 확인은 그 계정에 대기 영상이 있을 때 1시간마다, 문턱의 2배 아래면 5분마다.
  서비스계정(공유 드라이브)은 계정 용량이 아니라 보지 않는다. 앱 '발송 큐 현황'의 워커 줄에는 그 계정의 실제 문턱이 실린다.

### `/v`로 학생이 올린 영상의 사후 압축 (2026-10-16, 원장 *"학생이 업로드하면 바로 압축하고 전송"*)

학생 폰은 원본을 Drive에 바로 올린다(최대 2GB · 브라우저는 압축하지 않는다). 발송 PC(`--post`)가 **몇 분 안에** 그 파일을 받아 줄인다
(`video-link-compress.mjs` · 한 건 = `video-link-compress-job.mjs` · Drive 쪽 = `video-drive-replace.mjs`).
- **대상**: `student_homework_videos`의 `/v` 줄(`source='link'`) 중 업로드가 끝났고(`uploaded`) 저장 폴더가 찍힌 줄 — **새것부터**, 한 번에 한 건.
  지금까지 올라온 원본도 차례로 줄인다(밀린 영상). 할 일이 없으면 2분마다 본다. ClassNote 영상 작업이 도는 동안은 새로 시작하지 않는다.
  반대로 `/v` 압축이 도는 중에 ClassNote 영상이 오면 둘이 함께 돈다(발송을 늦추지 않으려고 — 그동안 인코딩 둘이 CPU를 반씩 쓴다).
- **처리**: Drive 파일을 범위 요청으로 나눠 받는다(요청 하나 120초 상한) → 원본 해시가 장부(`md5`)와 같은지 확인 → ClassNote 영상과 같은
  `prepareCompressedUpload`(CRF 22 · 15% 이상 줄 때만 · HDR·이미 낮은 비트레이트는 원본) → 줄였으면 **같은 파일 번호에 새 버전**(files.update
  media, 형식 `video/mp4` · 이름 끝 `.mp4`) → 해시·크기 확인 → **원본 해시의 옛 버전만** `revisions.delete`(못 지우면 Drive가 30일 뒤 정리).
  판단만 했으면(`kept-*`) 내용은 그대로 두고 표식만.
- 🔴 **DB `md5`·`bytes`는 원본 지문 그대로** — 같은 영상 판정(장부 지문·학생 탭 중복·직접 올린 사본)이 이 값을 본다. 결과는 `route.archive`
  (`state` = done · kept · skipped · retry · failed, `compression` · `driveBytes` · `sourceBytes` · `oldRevision` · `attempts` · `waits`).
  ⚠️ 담임이 Drive에서 **압축본**을 받아 폴더에 다시 올리면 그 해시는 원본 지문과 달라 같은 영상으로 잡히지 않는다(원본 사본은 잡힌다).
- 🔴 공개 `properties`에 원본 지문(`aywaSourceMd5/Bytes`)과 새 내용(`aywaUploadMd5/Bytes`)·`aywaCompressed`를 함께 적는다 — 판정 기록을 잃어도
  다시 받지 않고 이어 간다. `appProperties`(웹 앱의 업로드 확인 표식)는 보내지 않는다(그대로 남는다).
- **손대지 않는 것**: 올린 뒤 내용이 바뀐 파일 · 휴지통(반려) · 받고 줄이는 사이 바뀐 파일(덮어쓰기 직전에 다시 본다).
  담임이 폴더에 **직접 올린** 영상은 대상이 아니다(사람의 파일 — 읽기만 한다는 직접 제출 규칙 그대로).
- **고칠 수 있는 파일**: 저장 계정 소유(`ownedByMe`)이거나, **공유 드라이브** 파일이면 그 계정이 편집할 수 있을 때(`driveId` + `capabilities.canEdit` —
  공유 드라이브는 `ownedByMe`를 채우지 않는다). 아니면(발송 PC 인증 계정이 웹 저장 계정과 다름 등) 끝내지 않고 나중에 다시 본다.
  ⚠️ 교체 업로드가 도는 몇 분 사이 사람이 같은 파일에 새 버전을 올리면 압축본이 머리 버전이 된다(사람 버전은 옛 버전으로 남아 30일 뒤 사라진다 —
  `/v` 파일을 사람이 고쳐 올리는 길이 없어 받아들인 틈).
- **실패**: 내려받기·전송·인코딩 실패는 30분 · 2시간 · 6시간 · 24시간 뒤 다시, 다섯 번째에 그만둔다(원본 그대로). PC·설정 사정 — 인증 ·
  디스크(받을 크기 × 2 + 2GB 여유가 없음) · 폴더 확인 · 고칠 수 없는 파일 · **Drive 남은 공간이 원본의 85%보다 작음**(압축본의 최대 크기 · 새 버전은 옛 버전을 지우기 전에
  자리를 차지한다 — 그래서 받기 전에 본다 · 공유 드라이브 파일은 계정 개인 용량을 쓰지 않아 보지 않는다) · 교체가 공간·사용량 한도로 거절(403 사유·429) · 잠금 확인 실패 · 교체 뒤 해시가 아직 안 채워짐 —
  은 횟수를 세지 않고 1시간 · 2시간 · 4시간 … 하루까지 간격을 벌려 다시 본다(`waits` · 그만두지 않는다 · 고쳐지면 저절로 이어 간다).
- **잠금**: 30초마다 늘린다. 남이 가져간 게 확인되거나 잇달아 세 번 못 늘리면 잃은 것으로 보고(그 뒤 다시 늘리면 되돌린다), 긴 인코딩 뒤 교체 직전에 DB로
  한 번 더 확인한다. 잠금이 다른 실행으로 넘어갔으면 판정을 남기지 않는다(그쪽이 맡는다).
  판정을 DB에 못 남기면 두 번 더 해 보고, 그래도 안 되는 줄은 그 실행 동안 쉰다(세 번째부터 · 연동 앱을 다시 켜면 풀린다).
- **임시 파일**: 받는 원본·압축본은 `<영상 폴더>/<지점>/link/link-<줄 id>.*` — 매 주기 시작에 지난 실행이 남긴 `link-*`를 지우고, 한 건이 끝나면 그 줄의 것을 지운다.
- **연동 앱 종료·업데이트**: 돌던 인코딩·전송을 바로 끊고(시도로 세지 않는다) 다음 실행이 처음부터 한다 — 긴 인코딩(최대 60분)이 업데이트를 붙잡지 않게.
- **용량**: 압축이 끝나기 전까지 잠깐 원본 크기만큼 Drive를 쓰고, 교체 직후 옛 버전을 지워야 실제로 공간이 돌아온다. 발송 PC가 꺼져 있으면 켜진 뒤 처리.
- 적용 확인: 하트비트 `caps.homeworkVideoLinkCompress` · 로그 `[영상 압축·/v] 학생이 올린 영상 …MB → …MB · Drive 교체 완료`.

학생 상세의 **숙제 영상** 탭에서 과목별 목록과 Drive 뷰어를 제공한다.
영상 권한이 있는 Google 계정으로 로그인해야 재생할 수 있다.
학생 상세 권한 확인 후 지점·학생 범위의 메타데이터만 반환하며, 원본 주소·인증 정보는 브라우저에 전달하지 않는다.

- **링크 없이 올리는 길(2026-10-02, 0330a)**: 올리기 사이트 `https://www.aywa.co.kr/v` — 학생이 휴대폰 뒷 4자리(본인 또는 보호자 번호)와 **이름**을 넣고, 선생님이 낸 **영상 숙제**(원스크린 '영상 과제 있음' · 아직 안 낸 것 · 숙제일 + 7일까지)를 고르면 그 자리에서 제출 링크가 만들어진다(같은 반의 가장 늦은 안 낸 숙제 + 7일까지 — 2026-10-03 원장 "숙제날짜 기준 7일"). 숙제가 없으면 올릴 수 없고, 올린 영상은 고른 숙제에 묶인다(영상 제출 현황의 그 칸).
- 🔴 **2026-10-03 오후부터 학생마다 링크를 만들지 않는다**(원장 *"영상숙제 체크하더라도 /v 링크를 안내"* · *"학생영상 개별링크는 더이상 생성하지않고. 이미 생성된 링크들은 7일뒤 모두 제거하고. 이제는 클래스노트 업로드 혹은 /v 링크로만 업로드"*). 업로드는 ClassNote 또는 올리기 사이트(`/v`)뿐이고,
  영상 과제 있음인 수업보고서 글에는 `영상첨부 : https://www.aywa.co.kr/v` 한 줄이 붙는다(AywaSync 앱 업데이트 필요 — 옛 워커는 줄 없이 보낸다).
  이미 나간 링크는 만든 날 + 7일에 끝난다. 아래 두 길은 이력이다.

## 직접 올리는 법 (ClassNote에 못 올린 영상, 2026-10-01)

학부모가 ClassNote에 올리지 못한 영상은 선생님·관리자가 받아 **워커가 쓰는 담임 폴더에 그대로** 올린다.
연동 PC 워커가 10분마다 담임 폴더들을 **읽어**(옮기거나 이름을 바꾸지 않는다) 파일 이름으로 학생·반을 찾아 붙인다.
붙은 영상은 학생 상세 '숙제 영상' 탭에 **직접 제출**로 보이고, 반이 정해졌으면 영상 제출 장부에도 자동으로 센다.

- 폴더: [학생동영상](https://drive.google.com/drive/folders/1r4PhTUJoCqLdlbdfGN8IhnGrokKK5DmK) 안의 그 학생 담임 폴더(예 `이수진 선생님`) **바로 안**.
  하위 폴더는 보지 않는다. 담임을 모르면 `담임 확인 필요` 폴더. 폴더가 곧 담임이다(반의 현재 담임과 달라도 올린 폴더를 따른다).
  그 선생님 폴더가 아직 없으면(워커가 그 담임 영상을 아직 올린 적이 없다) `담임 확인 필요`에 올리기를 권한다 — 손으로 만든 폴더도
  읽기는 하지만 담임은 기록하지 않고, 워커가 나중에 같은 이름의 폴더를 따로 만든다(이름으로 폴더를 고르지 않는 설계).
- 파일 이름: 자동 업로드와 같은 **학생_반_학교학년_날짜.확장자**.
  예: `류태경_LT4_칠성초3_2026-09-30.mp4` · 반을 모르면 `류태경_반미정_칠성초3_2026-09-30.mp4`.
  - 학생 = 에이와 학생 이름 그대로(동명이인 접미사 포함). 학교학년 = 에이와 표기(`칠성초3`, 유아 `○○유치원 6세`, 없으면 `학교학년미등록`).
  - 반 = **지금 에이와에 보이는 반 이름**(그 날짜에 다닌 반이어야 한다). 날짜 = 학부모가 영상을 보낸 날(`2026-09-30`·`20260930`·`2026.09.30`).
  - 확장자는 mp4·mov·m4v 등 영상이면 된다. 앞뒤 공백·전각 밑줄(＿)·복사본 꼬리표 ` (1)`은 무시한다. 그 밖의 모양은 추측하지 않는다.
- 붙이는 규칙(추측 금지): 이름·학교학년이 같은 학생이 **한 명**일 때만(여럿이면 그 날짜 수강생 한 명으로만 좁힌다). 퇴원생은 그 날짜에
  학원생이었던 기록이 있을 때만. 접미사만 다른 학생(`김근우`·`김근우A`)이 함께 다니면 이름만으로 고르지 않고 반으로만 가른다.
  반 칸을 적었는데 그 날짜에 그 이름의 반을 다닌 기록이 없으면 반 없이 넣지 않는다(반 이동은 이동일부터 새 반, 휴원·종강 뒤는 아님).
- 못 붙인 파일은 수업보고서 → **영상숙제 확인** 위 안내(펼치면 파일 이름·사유)에 남는다. Drive에서 이름을 고치면
  10분 안에 다시 판정한다. 같은 학생의 같은 내용(MD5·크기)이 이미 반까지 정해져 보관돼 있으면(ClassNote 수집분 등) 따로 세지 않고
  안내에 '사본'으로 따로 센다(지워도 된다). 압축돼 내용이 달라진 사본(카톡으로 받은 영상 등)은 알아보지 못한다 — 같은 숙제를
  ClassNote로도 받았으면 직접 올린 쪽을 지울 것.
- 파일을 지우거나 다른 폴더로 옮기면 다음 훑기에서 그 기록도 빠진다(Drive가 진실). 워커가 올린 파일(ClassNote 수집분)은 건드리지 않는다.
- 2026-10-01 이전에 올린 옛 파일(`반 이름.mp4` 꼴, `허주연 선생님` 18개)은 양식을 못 읽으므로 조용히 넘긴다. 이름을 양식대로 고치면 읽는다.
- DB: `supabase/migrations/s1_season1.sql#0324a_homework_video_manual_drive.sql` 적용 전에는 이 훑기를 건너뛴다(워커 로그에 한 번 안내).

## 최근 영상 1건 시험

```powershell
node --env-file=.env.local scripts/_classnote/download-classnote-video.mjs --plan
node --env-file=.env.local scripts/_classnote/download-classnote-video.mjs --upload
```

기본 로컬 폴더는 `Downloads/aywa-classnote-videos`. `--out=경로`로 변경할 수 있다.
이미 받은 파일은 `--file=절대경로.mp4`로 지정한다(옆의 `.mp4.json` 기록 필요).
이 명령은 최근 글 최대 500개에서 1건을 찾는 진단용이며, 전체 이관은 상주 워커가 수행한다.
진단 명령을 연동 PC의 상주 워커와 동시에 별도 PC에서 실행하지 않는다(ClassNote 세션 충돌 방지).

## DB 준비

`supabase/migrations/s1_season1.sql#0315a_student_homework_videos.sql` 적용 필요(직접 업로드 영상은 `0324a`까지).
