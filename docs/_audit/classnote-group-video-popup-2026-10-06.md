# 수업보고서 클래스노트 묶음과 숙제 영상 팝업 검수

검수일: 2026-10-06. 최초 기준: `cdbda8635`. 최신 main의 설정 변경을 충돌 없이 반영한 최종 기준: `13c52fade`. 검수 담당: Codex.

## 결과와 동작

수업보고서의 클래스노트 관련 여섯 화면을 하나의 상위 탭으로 모았다. 하위 화면은 발송 큐, 반 구성, 반 공지, 직접 발송, 회수, 학부모 글·답글이다. 작성률·목록·보고서 설정·AI 멘트의 독립 권한은 유지한다.

학원 설정 → 기능 → 클래스노트의 기존 모듈 스위치 하나로 묶음을 숨긴다. 새 URL은 `?tab=classnote&section=<하위 화면>`이고 기존 `?tab=queue` 등의 링크도 유지한다. 모듈이 꺼졌거나 해당 권한이 없으면 허용된 화면만 선택한다. `section=report` 등으로 설정 권한을 우회하지 않는다. 학부모 글의 페이지 이동은 현재 필터와 `embed` 값을 보존한다.

영상 제출 현황의 재생 버튼은 현재 장부 위에서 팝업을 연다. 관리자와 강사의 장부가 같은 팝업과 기존 `HomeworkVideoPlayer`를 사용한다. 닫으면 iframe을 제거한다. 완료 체크·편집창·필터·현재 주소를 바꾸지 않는다. 업로드 대기 중이거나 유효한 재생 주소가 없으면 준비 중 안내를 표시한다.

## 적대적 리뷰

| 검토한 경로 | 판정과 근거 |
|---|---|
| 모듈 끔, 기존·신규 직접 URL | 공통 탭 판정으로 관련 화면과 업무 조회를 열지 않는다. 페이지 테스트와 실제 설정 저장 후 재접속으로 확인했다. |
| 모듈 끔, 오래 열린 화면의 서버 요청 | 반 연결·해제, 큐·반 구성 조회, 개별·단체 공지 조회·미리보기·발송, 대기/게시 공지 수정·삭제·회수, 보고서 회수의 누락된 모듈 검사를 보완했다. 업무 DB·감사 로그 진입 전 중단하는 테스트가 통과했다. |
| 기존 쓰기 권한, 읽기 전용, 답글 끔 | 조회 하위 화면 세 개만 열 수 있는 계정과 답글 끔의 표시·조회 제한을 확인했다. 기존 소유권·역할·발송 및 답글 모드 검사는 유지한다. |
| 다른 지점·반 영상 노출 | 서버 조회는 지점 조건을 유지하고, 내려보내는 영상도 표시되는 반×학생 범위로 제한한다. 팝업 선택은 영상 ID뿐 아니라 학생·반 ID도 일치해야 한다. |
| 잘못된 Drive ID·업로드 대기 | 기존 링크 검증 함수를 재사용한다. 업로드 완료와 검증된 ID를 만족한 경우에만 미리보기·썸네일을 전달한다. 원본 DB 필드와 외부 이동 링크는 전달하지 않는다. |
| 중첩 버튼·잘못된 완료 기록 | 체크 버튼과 재생 버튼은 형제 요소다. 재생 버튼의 클릭 전파를 막고, 재생 및 닫기에서 저장 호출이 없음을 확인했다. 재생 버튼은 24×24px이다. |
| 닫기·화면 너비·접근 권한 | 기존 Dialog의 초점·닫기 동작과 공통 재생기를 사용한다. 닫기 후 iframe 제거, 1440px 및 390px에서 화면 안에 표시되는 팝업을 확인했다. |

검토 범위에서 남은 차단 결함은 발견되지 않았다. 이번 코드에 대한 별도 Claude/Grok 검토를 실시했다는 의미는 아니다.

## 검증

- 최신 main 반영 후 관련 Vitest 16개 파일, 184개 테스트 통과. 서버 모듈 제한, 실제 페이지의 활성 조회, URL·권한 조합, 기존 공지 미리보기·발송, 영상 매칭·팝업·업로드 경로와 공통 탭·설정 화면의 연결을 포함한다.
- 변경한 TS/TSX 파일 ESLint 통과, 전체 `tsc --noEmit` 통과(8GB 힙), Next.js 16.2.6 프로덕션 webpack 빌드 통과.
- 실제 프로덕션 빌드와 로컬 PostgreSQL 17 / PostgREST 12 및 합성 인증·데이터로 브라우저 시나리오 8개 통과. 콘솔 오류 없음. 운영 DB·계정·실발송은 사용하지 않았다.
- 실제 학원 설정 화면에서 클래스노트 끄기·켜기를 저장하여 표시와 직접 주소 동작을 검증했다. 관리자와 담당 강사의 숙제 영상 화면 모두 같은 팝업을 확인했다.
- Drive 콘텐츠는 합성 미리보기 HTML로 대체했다. 실제 비공개 Google 영상 재생과 계정별 접근은 이 검수에서 실행하지 않았다. 기존 재생기의 썸네일 접근 검사·신규 업로드 처리·권한 안내는 그대로 사용한다.
- Happy DOM은 외부 iframe 로드를 비활성화한 테스트에서 `NotSupportedError` 로그를 남겼다. 네트워크 재생을 단위 테스트에서 수행하지 않는 설정에 따른 로그이며 테스트 판정에는 영향이 없다.
- 빌드와 동시 실행한 전체 소스 순회 테스트는 60초 제한을 초과했다. 빌드 후 다시 실행하여 184개가 모두 통과했다. 코드 판정 실패를 무시하지 않았다.
- 자동화 도구와 함께 연결한 브라우저의 캡처가 대기 제한에 걸려 기능 검사와 캡처를 분리했다. 최신 main에서 8개 동작 검사를 모두 다시 통과한 뒤 연결을 끊고 CLI로 강사 팝업의 1440px·390px 화면을 캡처·검토했다. 최초 수정 시 검토한 관리자 팝업·모듈 끔 화면도 증거로 보관한다. 날짜 필터를 처음 주소에 붙이는 기존 동작은 검수 주소에 기간을 명시하여 재생 동작과 구분했다.

최종 실행 로그는 `F:/eywa-review/classnote-video-20261006/`의 `tests-integrated.log`, `typecheck-integrated.log`, `lint.log`, `build-integrated.log`, `browser-integrated.log`에 보관했다. 빌드 체크아웃과 커밋 대상의 소스 4,820개 파일을 해시 비교하여 불일치가 없음을 확인했다(`source-match-integrated.json`).

## 운영 범위

SQL·스키마·환경변수·워커 변경은 없다. 발송 PC ZIP 교체는 필요 없다. 클래스노트 기능 끄기는 새 웹 조회·작업을 제한하며, 기존 큐를 삭제하거나 이미 접수된 워커 작업을 취소하지 않는다. 기존 회수 워커가 실제 발송 스위치와 독립적으로 동작하는 규칙도 유지한다. 영상 장부는 클래스노트 묶음과 별도의 기존 기능 설정을 따른다.

Vercel 배포는 사용자가 진행한다. 합성 지점의 설정은 검수 전 값으로 원복·확인했다. 검수용 브라우저와 이 작업이 시작한 로컬 서버만 종료했으며 3045·55449·55450·55451 포트가 닫힌 것을 확인했다. 기존 `supabase/.temp/` 파일과 다른 작업의 프로세스는 포함하지 않았다.
