# aywa 사용 설명서(PDF) 생성기

처음 접속한 원장님이 **PDF만 보고 학원을 세팅**할 수 있게, 탭(면)마다 1~3쪽 설명서를 만든다.
앱이 바뀔 때마다 **명령 한 번으로 스크린샷과 PDF를 다시 뽑는다** — 사람이 손으로 캡처하지 않는다.

```
pnpm manual:shots                    # 전체 촬영(검사 통과분만 PNG)
pnpm manual:build                    # 조립: 면별·메뉴별 PDF + 전체 한 권
pnpm manual:shots students           # 한 메뉴만
pnpm manual:build students/students  # 한 면만
```

(개발 서버가 떠 있어야 한다. 기본 주소 `http://localhost:3200`, 바꾸려면 `MANUAL_BASE`.)

## 파일

| 파일 | 역할 |
|---|---|
| `toc.json` | **목차 단일 소스.** 그룹(사이드바 묶음) → 메뉴 → 면. 순서가 곧 책 순서. |
| `pages/<메뉴>/<면>.json` | 면 하나의 내용(아래 스키마). |
| `pages/00-start.json` | 책 맨 앞 '처음 시작하기'. 단계 목록은 앱의 시작하기 카드(`src/features/onboarding/steps.ts`)에서 읽는다. |
| `scripts/_manual/*.mjs` | 촬영·조립·책 생성기. |
| `out/manual/` | 결과물(커밋하지 않는다). `<그룹>/<메뉴>/<면>.pdf` · 메뉴별 묶음 · 전체 한 권. |

## 면 파일 스키마

```jsonc
{
  "href": "/students",              // 여는 주소(창 안 화면)
  "open": "window",                 // window(기본, 바탕화면 위 창 안쪽을 찍음) | page(운영실처럼 창이 아닌 화면)
  "resolve": "firstClass",          // 상세 화면이면 주소의 :id를 채울 방법(생성기의 RESOLVERS)
  "prepare": [                      // 찍기 전에 화면을 설명할 상태로 만드는 조작(선택)
    { "click": { "text": "검색" } },
    { "fill": { "css": "input[placeholder=\"학생 이름\"]" }, "value": "김하늘" }, // 입력만 — 저장은 누르지 않는다
    { "wait": 500 }
  ],
  "maximize": true,                 // 표가 넓은 화면: 창을 최대화해 찍는다(선택)
  "viewport": { "width": 1320, "height": 1200 }, // 촬영 화면 크기를 직접 정할 때(선택)
  "shot": false,                    // 예시 데이터가 없어 그림 없이 글만 싣는 면(선택) — "noShotNote"에 그 사실을 적는다
  "minRows": 5,                     // 표 행 최소 개수(예시 데이터가 부족하면 촬영 중단). 폼 화면은 0. '기록이 없습니다' 한 줄은 행이 아니다
  "lead": "이 화면이 무엇을 하는 곳인지 두세 문장.",
  "callouts": [
    { "n": 1, "label": "새 원생", "target": { "help": "st-new" }, "body": "..." }
  ],
  "setup":   [{ "title": "…하세요", "body": "…" }],   // 처음 세팅할 때 할 일(순서대로). 없으면 []
  "faq":     [{ "q": "…요?", "a": "…" }],
  "related": ["수업목록(반 배정)", "…"]
}
```

### 번호 위치(`target`) — 셋 중 하나

- `{ "help": "st-new" }` — 화면의 `data-help` 표식(F1 도움말과 같은 표식). **가장 튼튼하다.**
- `{ "text": "새 원생" }` — 화면에 **글자 그대로** 보이는 버튼·열 이름. 첫 번째로 보이는 것을 잡는다.
- `{ "css": "table thead" }` — 영역 전체를 가리킬 때만.

촬영기는 번호 칸마다 **있는가 · 보이는가 · 화면 안에 다 들어왔는가 · 다른 것이 덮지 않았는가**를 검사하고,
하나라도 걸리면 스크린샷을 남기지 않고 멈춘다. 화면 글자가 바뀌어 `text`가 안 맞으면 여기서 드러난다.

## 촬영 규칙

- **데모 지점(slug=`demo`) 계정만** 쓴다. 다른 지점 계정이면 촬영기가 멈춘다(실제 원생 정보가 PDF에 찍히면 안 된다).
- 비밀번호를 쓰지 않는다 — 관리자 키로 일회용 로그인 세션을 만든다.
- 첫 접속 안내 팝업은 촬영 브라우저에서만 '봤음'으로 둔다. 개발 서버 전용 표시(Next 'N', 데이터 점검 도구)는 가린다.
- 반쯤 잘린 표 행은 빼고 자른다. 내용이 끝난 아래 빈 바탕도 자른다.
- 예시 데이터 표식(`[데모]`·`demo-history:v1`)·데모 계정 주소·데모 지점 이름은 **촬영 화면의 글자에서만** 바꾼다(데이터는 그대로).
- 번호 배지는 조립할 때 칸 **바깥** 빈자리(글자·다른 칸·다른 배지를 피해서)에 자동으로 놓는다.
- 촬영은 데이터를 바꾸지 않는다 — `prepare`는 누르기·입력만 하고 저장 버튼은 누르지 않는다.
- **통과한 스크린샷은 사람이 한 번 눈으로 본 뒤** PDF에 넣는다(`out/manual/_shots/` 에 PNG가 남는다).

## 말투 규칙 (codex 웹 검수로 정함 — 2026-09-23)

1. 화면의 기능과 결과는 **"~합니다"**, 원장님이 직접 할 일은 **"~하세요"**.
2. 버튼은 **"누르세요"**, 목록 선택은 **"고르세요"**, 파일을 받는 동작은 **"받으세요"**로 통일.
3. 기본 용어는 **'원생'**. 작은따옴표 **‘…’ 안의 글자는 실제 화면 버튼·메뉴 이름 그대로**(예: ‘학생 배정’) — 바꾸면 원장님이 버튼을 못 찾는다.
4. 재원·휴원·퇴원·반 배정 같은 현장 용어는 그대로 쓰고, '좁혀 보기'·'필터' 같은 추상어는 **화면에 보이는 결과**로 풀어 쓴다.
5. 한 문장에 한 가지 행동이나 결과. "여기·이것"만으로 대상을 가리키지 않는다.
6. 개발자 말 금지: 자연키·필터·파라미터·저장값·enum·API·캐시·동기화 요청 큐 등.
7. 세팅 순서의 제목은 할 일("…하세요"), 본문은 이유와 결과.

## 사실 규칙

- 설명서에 적는 동작은 **코드에서 확인한 것만**(버튼 이름·되는 일·안 되는 일·권한). 추측으로 쓰지 않는다.
- 역할별 차이(원장·관리자·강사)는 실제 권한 판정과 같게 적는다.
- 이 학원(침산)에만 있는 규칙·사람 이름·운영 사정은 적지 않는다 — 설명서는 **새 학원 원장** 기준이다.
- '무료'·요금·베타 약속은 적지 않는다.
