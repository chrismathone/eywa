# 발송 PC 워커 수정 적용 (2026-07-22) — 이미지 첨부 '개별 부착' 철회(방향 B) + 로그 정리(KST·스팸 제거)

## 왜 바꾸나 (두 가지)

### ① 이미지 첨부 = 개별 부착 철회, 보고서 스샷 하단에 크게(방향 B)
같은 날 오전 시도했던 "이미지 개별 부착"은 **철회**합니다. ClassNote가 여러 이미지를 **세로가 아니라 가로로 나열**해,
원장이 원한 세로 배치가 안 됐습니다(ClassNote 자체 제약). 대신 **이미지는 보고서 스크린샷 하단에 크게** 실어
**스샷 한 장으로 세로 완결**되게 바꿨습니다(`/r` 페이지가 이미 그렇게 렌더 — Vercel 자동 반영).

> ⚠️ **이 워커 재이관이 없으면 "이미지만 첨부된 보고서"가 발송 실패합니다.** 앱(route.ts)은 이미 이미지 URL을
> 안 주도록 배포됐는데, **구 워커는 여전히 개별 부착을 시도**해서 `첨부 목록 조회 실패 — 앱이 첨부 URL을 못 만듦`
> 으로 3회 재시도 후 `failed`가 됩니다(2026-07-22 학원이 테스트에서 실측). 재이관하면 해소됩니다.

### ② watch.log 정리 — 시간대(KST) + 스팸 제거
- **시간대**: 로그가 UTC(`…Z`)로 찍혀 실제 시각과 9시간 어긋나 보였습니다 → **KST `YYYY-MM-DD HH:MM:SS`** 로 변경.
- **스팸 제거**: `발송 허용 시간대 밖 — 대기`가 **15초마다** 밤새 수백 줄 쌓이던 것을 **상태 전이(밖↔안)에서 한 줄씩만**
  남기도록 변경. 읽음 동기화의 `이미 반영됨(정상)` 반복 줄도 제거(진짜 문제인 '토큰 미매칭'만 경고).

## 무엇이 바뀌었나

**앱(eywa) — 자동 반영(재이관 불필요)**: `report-attachments` 내부 API가 이미지 URL을 반환하지 않습니다(파일=비이미지만).
이미지는 `/r` 스샷 하단에 크게 실립니다. **Vercel 배포로 자동 반영** 완료.

**발송 워커 — zip 재이관 필요**:
- `classnote-core.mjs`: 이미지만 있는 리포트는 **내부 API 경로로 진입하지 않고**(개별 부착 안 함) 스샷 경로로 게시.
  비이미지 파일(PDF·엑셀·hwp 등) 첨부는 종전대로 네이티브 첨부.
- `watch-classnote-queue.mjs`: 로그 타임스탬프 **KST**.
- `classnote-read-core.mjs`·`classnote-core.mjs`: 반복 로그 스팸 제거.

> 자격증명·주소(`.env.local`)는 **그대로 두세요.** 코드만 교체하면 됩니다.

## 적용 방법 (약 2분)

1. 이 zip을 연동 PC(`학원동기화-PC`)의 **eywa 저장소 폴더**에서 **"여기에 압축 풀기"** → 기존 파일 덮어쓰기.
   > ⚠️ 반드시 **폴더 전체**를 풀어야 합니다(코어가 import하는 모듈이 빠지면 워커가 기동 못 함).
2. `발송PC-지정.bat` 더블클릭 → 워커가 새 코드로 **재시작 + dry-run 자가검사** 자동 실행.
3. "dry-run 파이프라인 검사" 통과하면 완료입니다.

## 적용 후 확인

**이미지를 첨부한 보고서**를 한 건 발송해 보세요(학원이 테스트 계정 등):

- ✅ **정상**: ClassNote 게시물에 **보고서 스크린샷 한 장**이 올라가고, 그 **하단에 교재 이미지가 크게** 세로로 붙어
  있습니다(개별 이미지·가로 나열 없음). 발송 로그에 `→ success`가 찍힙니다.
- ❌ 여전히 이미지가 **가로로 개별** 붙거나, 발송이 `첨부 목록 조회 실패`로 `failed`가 되면 → 워커가 **구 코드**로
  돌고 있는 것입니다(재이관·재시작 확인). 앱은 배포됐어도 워커는 물리 이관이라 따라오지 않습니다.
- watch.log을 열어 **시각이 KST**이고, `발송 허용 시간대 밖` 줄이 **매 폴 반복되지 않는지** 확인.
