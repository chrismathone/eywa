# 2026-10-22 학생 중심 온톨로지 · 원생 기여도

## 원장이 밝힌 최종 방향

모든 데이터를 학생에게 연결하고, 학생 → 반 → 강사 → 과목 → 학원 단위로 연결해 이해한다. 원생 기여도는 이 구조를 활용하는 첫 기능이다. 기여도 계산값을 학생의 원본 정보로 취급하지 않는다.

이 방향을 구현할 구조는 **대상·관계·시간이 있는 사실·원본 근거·해석 규칙**이다. 여러 반을 듣는 학생, 여러 과목을 맡는 강사, 공동 담당을 허용한다. 학생에서 학원으로 올라가는 순서는 조회와 집계의 관점이며, 단일 부모만 갖는 트리로 저장하지 않는다.

### 구현 원칙

1. 학생 식별은 지점의 실제 학생 ID를 기준으로 한다. 병합 표식을 따라 현재 학생을 찾되 원본이 기록된 학생 ID도 보존한다. 이름만으로 사람을 합치지 않는다. 끊어진 연결·순환은 확인이 필요하다.
2. 원본 기록은 기존 표가 소유한다. 공통 연결층은 원본의 종류와 ID, 발생일/청구월, 확인 시각, 연결 대상과 당시의 관계를 제공한다. 모든 원본을 하나의 거대한 표에 복제하지 않는다.
3. 수강·담당 관계에는 유효 기간이 있다. 지금 담당자를 과거 기록에 덮어쓰지 않는다. 과거 담당을 알 수 없으면 미확인으로 남긴다. 월 단위 자료에 임의의 정확한 발생일을 붙이지 않는다.
4. 같은 사실의 ID를 여러 관점에서 공유한다. 수학·영어 반에서 모두 본 학생을 학원 인원에서는 한 명으로 센다. 금액은 원래 청구 근거로 중복을 제거하며, 강사 귀속은 실제 담당 기간과 명시된 배분 규칙을 사용한다. **학생 점수를 더한 값이 곧 강사 점수나 과목 점수가 되는 것은 아니다.**
5. 사실, 규칙 판정, AI 해석을 구분한다. AI의 긍정 판정에는 원문 근거·판정 시각·모델 표시·취소 이력을 남긴다. 자료 없음·계산 전을 0으로 바꾸지 않는다.
6. 연결해 읽어도 기존 정보별 권한을 유지한다. 학생 열람 권한만으로 수납·직원 정보가 열리지 않는다. 상위 집계의 총점으로 금액 정보가 우회 노출되지 않게 한다.
7. 학원의 모든 사실이 학생에게서 발생하는 것은 아니다. 직원 근태·시설·지출 등은 해당 대상을 중심으로 직접 연결할 수 있다. 학생 자료의 합만으로 학원 전체를 표현한다고 가정하지 않는다.

공통 계약은 `src/features/students/ontology/`에 두었다. 학생 식별·사실·관계·중복 제거·병합 이력 해석을 구현하고, 상담·소개·수강·청구·출결·영상 제출·시험·긍정 신호를 원본 ID로 연결한다. `/student-contribution/ontology`에서 학생·반·강사·과목·학원 관점을 선택해 같은 사실의 집계를 본다. 학생의 월 상세에서 원본과 연결 근거를 확인한다.

이번 저장층은 월 집계 시 확인한 자료의 스냅샷이다. 마감한 달의 사실·관계를 보존하며, 원본의 최신 내용은 원본 화면에서 조회한다. 수업료는 청구 달, 활동은 발생 날짜를 유지한다. 월 합계에 여러 과목이 섞이면 각 과목에 금액을 복제하지 않으며, 반·강사에게 임의로 배분하지 않는다. 따라서 반·강사 합계를 다시 더해 학원 합계로 삼지 않는다.

학생 상담·메모·보호자 관계·교재·셔틀 등 나머지 기존 자료는 이 계약에 어댑터를 추가해 확장할 수 있다. 이 문서는 모든 기존 데이터의 통합 또는 그래프 데이터베이스 도입이 끝났다는 선언이 아니다. 기여도 원자료와 이를 활용하는 다섯 관점의 조회를 이번 범위로 구현했다.

### 10-13 결정 7의 변경 범위

**2026-10-13의 ‘글의 이름은 후보로만, 자동 확정 금지’는 지난 소개 백필에 한해 변경한다.** 원장 D3이 그 예외를 명시적으로 허용했다. 새로운 상담의 일반 연결 흐름은 기존처럼 직원이 후보를 선택한다.

백필 자동 연결은 이름 유일성(알파벳 동명이인·다른 메이크에듀 번호 충돌 방어), 상담일 재원, 소개 문맥, 본인·직원·복수 후보·기존 연결 충돌 없음의 네 가드와 명시된 학교·학년 일치 확인을 모두 통과해야 한다. 이름을 알 수 없는 소개는 연결 불가로 남긴다. 드라이런의 자동·확인·불가 건수와 자동 표본 20건을 먼저 보고하고, 승인 뒤 실행한다. 실행마다 감사 근거와 되돌리기 JSON을 남긴다. 같은 소개 연결을 읽는 직원 포트폴리오의 열린 달에도 영향을 줄 수 있다.

### 기본 배점과 원자료

- 소개 상담 5점, 소개 수업 시작 15점.
- 수업료 순액 10만 원당 1점, 과목·달 1점, 청구가 살아 있는 서로 다른 달 12개월마다 5점.

- 원장 전용 키 배정 요청(2026-10-22)을 반영해 `student_positive_signal`은 `STUDENT_ONTOLOGY` 키 그룹을 쓴다. 이후 원장이 Claude만 사용하고 모델·추론 강도 선택을 맡겼으므로 Claude `fast`/`low`로 시작한다(현 레지스트리 Haiku 5.5). 전용 키가 없으면 대기하며 다른 회사로 폴백하지 않는다. 기존 출결·학부모 만족도 키 그룹은 유지한다.
- 첫 적용은 침산 실험실 메뉴. 기본 목록은 재원생, 누적 총점순이며 최근 12개월 증가분으로도 정렬한다.

## 구현 순서와 운영 승인 경계

### 2026-10-27 출석·영상 인정 단위 변경

원장: “숙제로 인정된 영상 한개이상당 1점하자 (2개영상 숙제도 있으므로)”, “주간 출석을 모두 등원했다면 1점 배정하고.”

- 영상은 **정식 배정된 숙제 한 건에 실제 제출 영상이 하나 이상 연결되면 1점**. 같은 학생·반·숙제일의 여러 영상은 한 번만 인정한다. 미제출 숙제가 있어도 다른 숙제의 제출 실적은 인정한다. 실제 파일 없는 수동 체크, 숙제 없는 영상, 옮겨 남긴 숙제는 인정하지 않는다. 월말을 기다리지 않으며 숙제일의 달에 귀속한다.
- 개근은 **월요일~일요일 한 주의 예정된 정규 수업에 모두 출석하면 1점**. 학생별 모든 반·교시를 확인하고 같은 주는 한 번만 센다. 지각은 기존 `allowLate` 설정을 따른다. 대상 수업 0건, 출결 미입력, 보강 좌석·보강 상태만으로 인정하지 않는다. 한국 시간으로 일요일이 지난 뒤 집계하며, 월을 걸친 주는 일요일의 달에 귀속한다. 2026-01-01부터 자료를 확인하므로 2025년이 섞인 첫 주는 추정하지 않는다.
- 새 원수치 키는 `perfectWeeks`(주), `videoAssignments`(숙제 건). 이전 `perfectMonths`·`videoMonths`의 숫자를 새 단위로 읽거나 중복 가산하지 않는다. 기본 배점은 둘 다 활성화·1점이며 배점 설정에서 조정할 수 있다. 월말평가·긍정 신호는 기존 월 1회 기준을 유지한다.
- 과거 원본도 새 기준으로 다시 판정한다. D5에 따라 마감된 원본 JSON은 그대로 보존하고, 새 기준의 과거 실적은 열린 달 정정에 반영한다. 이전 월 기준 실적은 새 점수 계산에서 제외한다. 화면의 항목·단위·계산식·도움말과 영상 인정 내역도 동일 기준을 사용한다.
- 호환성: 새 키가 없는 과거 JSON은 새 단위를 0으로 읽는다. 새 저장 행은 기존 DB 가드를 위해 폐기한 두 키를 0으로 함께 저장한다. 설정 저장에서도 폐기한 배점을 비활성화한다. `0457a`는 새 두 원수치의 정수 검증만 추가하고, 기존 테이블·권한·마감 행을 변경하지 않는다.

읽기 전용 운영 자료 확인 → 순수 판정과 테스트 → 권한 배선 → 저장 구조 준비 → 소개 백필 드라이런 → 긍정 신호 밤 배치 → 월 집계·마감 → 목록·상세·배점 설정 → 시범 대조 순서로 진행한다. 공통 학생 연결 계약을 첫 두 단계에 포함한다.

**운영 DB 쓰기·마이그레이션 적용·소개 백필 실행·main 푸시는 별도 원장 승인 이후다.** 로컬 구현·테스트·읽기 전용 조회는 진행한다. 마이그레이션은 앱 배포보다 먼저 적용하고, 표가 없을 때도 화면은 계산 준비 상태를 표시한다.

구현 경로·시범 대조 결과·승인 후 순서는 [원생 기여도 적용 기록](../features/student-contribution.md)에 기록한다.

## 2026-10-23 학생 중심 읽기 확장

원장의 ‘골 프롬프트를 세우고 구현 진행’과 추가 참고 글을 반영한 로컬 구현이다. D1~D8이나 공개 범위의 새 결정은 아니다. Claude가 승인한 확장 계획의 현재 연결·원본 보호·고정 목적 요약을 [구현 기록](../features/student-ontology-expansion.md)에 정리했다.

- 현재 수강·역할별 담당·상담·메모·가족·두 보강 경로와 펼쳐 보는 학습·등원 기록은 기존 업무 원본을 읽는다. 월 기여도 payload를 새 도메인 원장으로 늘리지 않는다.
