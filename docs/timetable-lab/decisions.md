2026-10-02 · Claude/Grok 1차 보고서와 최종 교차 검토를 반영한 통합 결정. 계획 완료, 기능 구현 미착수.

## 최종 검토의 조건 반영

- **D07 이전 순서**: 연습실 delta 플래너는 검증된 순수 함수와 트랜잭션 부품을 먼저 활용한다. 기존 영어 시트 입력 경로를 공통 플래너로 옮기는 일은 P5 안정화 뒤 별도 전환 단계로 둔다. 그 전에는 기존 시트 파싱/종강/명단/확인 동작을 바꾸지 않는다. 전환 전후 Plan 골든 비교가 선행 조건이다.
- **D12 정보 부족의 범위**: 변경한 배치/배정 자체의 필수 식별·시간 정보가 없으면 실제 반영 불가다. 손대지 않은 외부 반의 기존 자료 공백은 `비교 불가`로 공개하며 이를 이유로 기존에 허용되던 모든 반영을 일괄 차단하지 않는다. 다만 관련 자료가 부족한 추천안을 `전부 충돌 없음`으로 인증하지 않는다. 미리보기는 검사한 축과 못한 축을 따로 보여준다.
- **D04 수식의 의미 경계**: 수식/서식 목표는 유지한다. 일정의 시각·담당·방·학생 연결은 명시적인 값이다. 수식 결과를 일정 값으로 쓰려면 `값으로 확정` 명령과 Undo를 거친다. 수식 자동 재계산은 그 자체로 배치/배정 revision 또는 충돌 결과를 바꾸지 않는다. 붙여넣기와 자동 수식 재계산의 외부 네트워크 호출은 0이어야 한다. 사용자가 링크를 명시적으로 여는 정상 브라우저 동작은 별도로 다룬다.
- **핵심 실험 순서**: Univer 명령 가로채기/내장 이력 처리를 먼저 확인하고, 실패하면 해당 연결안을 탈락시킨다. DOM 안도 동일한 전체 요구와 접근성/서식/수식 비용으로 평가한다. 미구현 키를 브라우저/앱의 엉뚱한 동작으로 넘기지 않는다.
- **남은 수식 이견**: Grok은 수식 결과를 명시적으로 일정 값으로 확정하는 경로에도 반대했다. Claude와 Codex는 자동 재계산과 사람이 확인하는 명령을 분리하는 조건으로 검증할 수 있다고 본다. 전원 동의라고 기록하지 않는다. 자동 운영 변경·수식 기반 충돌 확정·출결/금액 자동 쓰기는 허용하지 않으며, P0은 사용자 단축키 요구를 줄이지 않는 안전한 구현 가능성을 검증한다.

## P0에서 확정해야 하는 기술 항목

1. 에디터 포트: 명령 가로채기, 엔진 내장 이력 처리, 서식/수식/의미 명령의 단일 Undo. 합성 실험으로 판단한다.
2. 공식 단축키 전체의 플랫폼·문맥별 대응표. Grok의 N/X는 검토 제안이지 승인된 기능 제외 목록이 아니다.
3. 현재 숨김 월별 계획 데이터 유무와 분리등원 저장 형식은 개인정보 없는 건수 조회로 확인한다. 이번 계획 단계에서는 DB를 읽지 않았다.
4. 기존 검사기 간 차이표를 확정하고, 이미 정한 합반/자리/분리등원/권한 결정을 재질문하지 않는다. 새 정책 충돌이 남는 경우만 구체적으로 제시한다.
5. 실제 사용 PC의 기준과 합성 자료 크기. 성능 목표와 실측을 분리한다.
6. 임시 반/미확인 학생/교시 밖/부분 병합/외부 수식/불연속 붙여넣기의 의미와 오류 복구.

P0의 미확정 기술 선택은 막연한 후속 과제가 아니라 실험 입력·통과 조건이 있는 작업이다. 계획이 완료됐다는 것은 에디터 호환성이나 데이터 반영 검증이 끝났다는 뜻이 아니다.
