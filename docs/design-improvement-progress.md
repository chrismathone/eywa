## 추가 반영 · 기본 대시보드와 퇴원 페이지

2026-09-11 후속 지시로 `?view=one` 한정 제공을 끝내고 전체 현황을 기본 `/dashboard`로 승격했다. 모든 업무 창을 닫거나 최소화하면 대시보드가 보인다. 이전 `/menu`는 대시보드로 연결하며, 대시보드 권한이 없는 계정에만 업무 선택 안내를 남긴다. 기존 메뉴 격자와 창 뒤 메뉴 패널은 제거했다. 강사·학생의 전용 홈과 미저장 창 보호는 유지한다.

- 공지 관리는 `/dashboard/announcements`, 기존 일일 브리핑은 `/dashboard/briefing`으로 연결한다. 공지 읽기·관리 권한을 유지하고 변경 후 두 관리 화면과 전체 현황의 캐시를 갱신한다. 이전 브리핑 알림 링크도 새 경로로 연결한다.
- 퇴원 명단은 우측 사유 카드 높이를 관찰하여 표시 행 수를 정한다. 좁은 화면은 8행, 넓은 화면은 제목·페이지 바를 제외한 만큼만 표시한다. 마지막 페이지의 높이, 필터·embed·스크롤 위치를 유지한다. 일주일 이상 지난 날짜가 중복 표시되던 것도 정리했다.
- 워크스페이스·대시보드·퇴원·권한 등 23개 파일 226개 테스트 통과 후, 추가 권한·브리핑·복원 경계 회귀 검사를 통과했다. 변경 TypeScript 파일 32개 ESLint와 8GB TypeScript 검사 통과.
- 실제 Chrome에서 기본 화면, 기존 창 닫기, 직접 연 퇴원관리 창의 2페이지 이동 및 마지막 창 닫기 → `/dashboard` 전환을 확인했다. 카드 하단과 페이지 바 위치가 유지된다. 개발 검수는 3032에서 진행했고 다른 세션의 3031 서버는 유지했다.
- 적대적 리뷰에서 비동기 복원의 계정 채택 중 빈 상태를 잘못 감지하는 경쟁 조건, 대시보드 권한 거부의 순환 이동 위험, 하위 관리 화면 진입·갱신 누락, 작은 화면의 브리핑 링크 숨김을 점검하고 보완했다. 업무 데이터 변경이나 발송 없이 검증했다.

## 적용 결과 · 2026-09-11

- 업무 요약을 구분선이 있는 짧은 줄로 통일했다. 교재는 전체 신청·등록 대기·납부 대기·주문 대기·미납 합계·총 신청액을 분리했다. 단계별 수는 기존 전건 집계의 `needReg/needPay/needOrder`를 사용한다. 한 신청이 여러 대기 단계에 포함될 수 있다.
- 교재·지출·회의·상담·환불의 결과 수와 도구를 합쳤다. 화면 폭이 충분하면 한 줄, 부족하면 자연스럽게 감싼다. 교재의 이름·날짜·금액은 중간에서 줄을 나누지 않고 좁은 표에서 가로 탐색을 제공한다.
- 기간 이동의 중앙 라벨에서 월을 직접 고른다. 과거 달이 기본인 환불에서도 이번 달로 갈 수 있으며 필터·임베드 상태를 보존한다.
- 등록상담은 이름을 먼저 보장하고 학교·횟수 배지를 정돈했다. 상담 미리보기는 알려진 양식에서 실제 내용을 추출하며 저장 원문은 유지한다.
- 문서함의 폴더와 목록이 같은 범위로 집계된다. 직원 전용 문서는 제외하고 RLS를 유지한다. 조회 실패는 0 대신 미확인으로 표시한다.
- 시수 검증은 단가 누락·일부 집계·유효한 0원을 구분한다. 실측이 0회라도 확정 금액을 계산할 수 없으면 차액을 일치로 표시하지 않는다.
- MCS는 정규/특강 구분 안에서 반명과 진행률을 정렬했다. 보고서 큐는 핵심 상태·실패·재발송 기한을 유지하고 상세 누계와 로그 경로를 접었다.
- 이탈 방어의 중복 수치를 줄이고 월 수강료의 집계 대상을 명시했다. 퇴원 사유 비율은 사유 분석 모집단을 분모로 사용한다. 미기재와 운행 기록 부재를 실제 원인/운행 상태로 추정하지 않는다.
- 학생 등록은 기본 정보·보호자·등록 상태를 먼저 배치하고 부가 정보를 접었다. 26개 필드의 이름·값·타입·검증 속성을 AST로 대조해 동일함을 확인했다. 접힌 필드의 브라우저 검증 오류는 해당 영역을 펼친다.
- 계산기 입력/미리보기, 설정의 평일/주말 교시를 기본 업무 폭에서 나란히 표시했다. 교시명·시작·종료·삭제도 공간이 충분하면 한 행이다.
- 대시보드 `view=one`은 글자·두께·색을 공통 토큰에 맞췄고 중간 폭에서 차트와 범례가 읽히도록 배치를 보정했다. 기본 대시보드 선택과 데이터 갱신 경로는 유지한다.

## 검증과 리뷰

- 관련 Vitest **19개 파일, 398개 테스트 통과**. 상담 미리보기·문서 권한 범위/페이지 집계·금액 누락/0원·월 이동의 URL 보존·보고서 큐·공용 도구·대시보드·퇴원 분석과 다른 세션의 상담 감사로그 회귀를 포함한다.
- Next 타입 생성 후 `node --max-old-space-size=8192 node_modules/typescript/bin/tsc --noEmit` 통과. 기본 Node 메모리로 실행한 최초 검사는 메모리 부족이었고, 오래된 생성 타입도 재생성 후 해결했다.
- 변경 파일 ESLint와 `git diff --check`를 검사했다. 실제 브라우저에서 주요 업무 면과 폼을 다시 캡처하고 교재 980/1225/1440px 외곽 창, 설정 1225px 외곽 창에서 추가 검수했다. 최대화 상태에서는 요청한 창 크기가 적용되지 않는 캡처 도구 문제를 발견해 복원 후 재촬영했다.
- 적대적 리뷰에서 확정 금액 누락의 거짓 차액 0, 퇴원 사유의 잘못된 분모, 교재 표의 이름/단위 줄바꿈, 교시 삭제 버튼의 단독 줄, 대시보드 범례 줄바꿈과 빈 격자를 발견해 보완했다. 등록상담의 과거 개발 Issue 표시는 최종 방문에서 재현되지 않았다.
- 화면 자료는 실제 운영 정보를 포함하므로 `logs/design-audit`에 로컬로만 보관한다. 저장·발송·확정·삭제 등 실제 쓰기 동작은 실행하지 않았다. 전체 역할, 모든 상세/모달, 인쇄 지면의 E2E 완료를 의미하지 않는다.
- [36개 화면의 개선 전후 비교](../logs/design-audit/comparison.html). 사진 링크는 로컬 작업 공간에서만 유효하며 저장소에 업로드하지 않는다.
