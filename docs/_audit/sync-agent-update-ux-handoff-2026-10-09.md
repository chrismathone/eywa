# Windows 연동 앱 업데이트 점검 · 2026-10-09

## 문제와 근거

- 1.0.1 화면은 대기·다운로드·실패 상태에서도 동일하게 “다운로드가 끝나면 적용 방법을 선택할 수 있습니다”를 표시했다. 사용자는 약 3시간 다운로드 중인 것으로 이해했다.
- 09:49 사진은 최신 버전 확인 대기, 업데이트 조작은 관리 코드 잠금으로 비활성화되어 있었다. 서버 상태도 `update=idle`이었다.
- 관리 코드 입력 후 실제 이벤트: 09:52:10 KST `update_available(version=1.0.2)`, 09:53:05 `update_failed`, 09:53:12 하트비트 `update=error`. 해당 실패의 원인은 구버전이 오류 세부 정보를 버려 확정할 수 없다.
- 구버전의 “다운로드 중”은 ZIP 다운로드뿐 아니라 약 1만 개 파일의 검증·압축 해제까지 포함한다. 진행률이 없고 실패 이유도 웹에 남지 않았다.
- 사용자 지시: 업데이트는 관리 코드 없이 확인·적용할 수 있어야 한다.

## 구현

1. 1.0.3 / sequence 5 후보. 기존 게시 순번·파일은 변경하지 않는다.
2. PC 설정 잠금과 업데이트 조작을 분리한다. 확인·즉시 적용·예약·취소에는 관리 코드가 필요 없다. 연결 유효성, 웹 업데이트 허용, 작업 마무리, 버전별 선택과 만료·서명 검증은 유지한다. 계정·연동 옵션·이전 작업의 잠금은 유지한다.
3. 확인, 다운로드, ZIP 검증, 압축 해제·파일 검증, 준비 마무리를 표시한다. 수신 MB/전체 MB와 검증한 파일 수/전체 파일 수로 진행률을 제공한다. 완료까지 적용 버튼은 비활성화한다.
4. 아직 확인하지 않음, 최신 버전, 실패, 다운로드, 압축 해제 문구를 상태에 맞게 표시한다. 마지막 버전 확인 시각은 KST로 표시한다.
5. 파일 수신이 90초 멈추거나 전체 20분을 초과하면 다운로드를 중단하고 재시도할 수 있다. 이 시도의 임시 파일만 정리한다. 활성 설치·연결 정보·작업 기록은 삭제하지 않는다.
6. 실패는 고정 오류 코드로 분류해 앱·KST 로컬 로그와 웹 로그에 남긴다. 원시 오류·경로·학생 정보·비밀 값을 웹으로 보내지 않는다. 기존 클라이언트 이벤트와 호환되는 선택 필드만 추가한다.
7. 웹 로그 시각은 PC에서 사건이 발생한 시각을 우선 표시한다. 서버 수신이 늦어도 선택 날짜와 표시 시각이 일치한다.

## 검증과 현재 한계

- 네이티브 회귀 39개 통과. 스트림 진행량, 수신 정지 중단, ZIP·파일 무결성, 경로 공격 차단, 단계 전환, 실패 후 임시 파일 정리와 수동 재시도를 검증했다.
- 관련 웹/프로토콜 19개 검사, TypeScript, 변경 TS/TSX ESLint 통과.
- 실제 Electron UI 가상 서버 검사 통과: 진행률·단계·실패·최신 문구, 만료된 설정 잠금에서 확인·즉시 적용·예약·취소 가능, 계정·옵션 변경 거부, 웹 업데이트 OFF 거부, 작업 마무리·예약 취소·오래된 버전 선택 거부. 외부 업무나 실제 설치 적용은 실행하지 않았다.
- 기존 Electron 시험의 `evaluate` 인자 전달도 수정했다. Electron 모듈 인자 다음에 날짜 값을 받아 예약 시계가 실제로 진행되도록 했다.
- 실제 패키지 검수·서명 ZIP 전체 검수·게시 등록은 아래 릴리스 기록에 최종 결과를 추가한다. 현재 학원동기화-PC는 1.0.1이므로 설치 완료 검증을 대신했다고 표현하지 않는다.

## 발송 조건 조회 (쓰기·발송 없이)

09:44:50 KST 기준 사용자가 클래스노트 연동을 켠 변경이 반영되었다. 보고서 대기 13건 모두 기한·취소 조건에 해당하고 발송 스위치는 ON, 시간창은 08:30~22:30 KST다. ON 이후 발송 0건, 처리 중 0건. 프로세스 표시만으로 실발송 재개를 단정하지 않았다. 기존 1.0.1의 내부 실행 임대 확인 문제는 앞선 1.0.2에서 수정되었고 이번 후보에도 포함된다. 사용자가 켠 설정은 유지했다. 별도 발송 요청·회수·답글·공감·기기 등록·추가 동기화 요청을 실행하지 않았다.
