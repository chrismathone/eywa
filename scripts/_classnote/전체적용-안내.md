# 연동 PC 워커 — **전체 최신화** 안내 (2026-07-18)

> ⚠️ 먼저 넣으신 `eywa-읽음동기화-20260718.zip` **대신 이 zip을 쓰세요**(이걸 풀면 그 내용도 포함됩니다).

## 왜 전체를 새로 드리나

읽음 동기화만 담은 zip에는 5개 파일만 있었는데, 그 중 `watch-classnote-queue.mjs`(워처 본체)가
**zip에 없던 다른 파일의 함수**를 부릅니다. 연동 PC의 그 파일들이 7월 15일 이전 버전이면
워처가 시작하자마자 아래처럼 죽습니다:

```
SyntaxError: The requested module './classnote-core.mjs'
does not provide an export named 'closeClassnoteAdminSession'
```

7/15~7/18에 워커 쪽 변경이 여러 건 있었는데(학부모 새 글·댓글 알림, 반 공지, 파일 첨부, 읽음 동기화)
연동 PC에 전달됐는지 확실치 않아, **버전이 섞일 위험을 없애려고 전체를 담았습니다.**

---

## 1. 적용 (파일 풀고 워처 재시작 — 이게 전부)

1. 이 zip을 연동 PC의 **eywa 저장소 폴더**에서 **"여기에 압축 풀기"**.
   → `<저장소>\scripts\_classnote\` 안 파일이 전부 최신으로 덮어써집니다.
2. 작업 표시줄에서 워처 창(검은 콘솔)을 닫습니다.
3. `scripts\_classnote\발송PC-지정.bat` 을 **더블클릭**(원래 등록 방식 그대로).
   - 또는 컴퓨터를 재부팅하면 작업 스케줄러가 알아서 띄웁니다.

> `.env.local`은 zip에 없습니다(비밀값) — 기존 것을 그대로 쓰시면 됩니다. 새로 추가할 항목도 없습니다.

---

## 2. 정상 확인

워처 로그(검은 창)에 아래가 순서대로 보이면 정상입니다.

- 시작 직후: 오류 없이 폴링 시작
- 30분 안: `[읽음] 피드 …건 · 학원발송 …(읽음 …/미읽음 …) → 갱신 후보 …`
- 이어서: `[읽음] edutrix 매칭 갱신 N건`

바로 확인하고 싶으면 저장소 폴더에서 명령 프롬프트를 열고:

```
node --env-file=.env.local scripts\_classnote\sync-classnote-reads.mjs
```
(아무것도 바꾸지 않고 현황만 보여줍니다. 실제 반영은 끝에 `--apply` 추가.)

---

## 3. 문제가 생기면

- **워처가 바로 꺼진다 / 빨간 글씨** → 그 문구를 그대로 알려주세요(대개 위 SyntaxError 계열이며,
  이 zip을 제대로 풀면 해결됩니다).
- `[읽음] 오류…` → 다음 폴(30분 뒤)에 자동 재시도합니다. 계속되면 알려주세요.
- `⚠️ 후보 N건이 eywa 행과 매칭되지 않음` → eywa 야간 동기화(새벽 3:30) 전이라 그럴 수 있습니다.
  하루 지나도 같으면 알려주세요.

## 4. 포함된 것 (참고)

`scripts\_classnote\` 폴더의 워커 파일 **전체** — 발송 큐·반 공지·일일 프로비저닝·학부모 새 글/댓글 알림·
**읽음 동기화(신규)** · **폴러별 상태를 eywa 화면에 표시(신규)** + 배치 파일(`발송PC-*.bat`)·설치 스크립트(`*.ps1`).

> 폴러별 상태 표시: 적용하면 eywa의 "ClassNote 발송 큐" 카드에서 발송 PC 줄 아래에
> "발송 12:30 · 성공 2 · 읽음 12:30 · 매칭 3"처럼 각 기능이 마지막으로 언제 뭘 했는지 보입니다
> (오류는 붉게). 연동 PC 화면을 안 봐도 워커가 잘 도는지 eywa에서 확인됩니다.
