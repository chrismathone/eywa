# 수업 일정 기반 시계 지도 시안

2026-09-19 · 디자인 시안과 실제 화면 적용 기록. HTML 시안은 예시 데이터만 사용한다.

## 실제 코드 적용

사용자 승인 후 기존 디자인 유지안을 `src/features/math-progress-map`에 반영했다. `session-layout.ts`가 원래 월·주 각도 안에 실제 수업 날짜만 배치하며, 연간·연속·단계별 지도에서 비수업 요일을 생략한다. 일정이나 보고서에 있는 보강은 날짜순으로 포함하고 휴강은 제외한다. 월·분기·주차의 위치와 크기는 유지한다.

일간 완료는 연녹색, 주차 완료와 수업 눈금은 네이비, 월·분기는 아래 확정 팔레트를 적용했다. 연간·연속 지도 중앙은 MCS 공통 지표의 현재/전체 차시와 진도율을 사용하고, 기존 지도 ↔ MCS 바 ↔ 목록의 선택 및 URL 복원을 유지한다. 실제 컴포넌트로 월·목 두 칸, 수요일 보강 추가 시 세 칸, MCS 차시 중복 가산 없음, 데스크톱 1440px·모바일 390px 화면과 색상 값을 확인했다. 검증 화면은 로컬 `work/clock-validation/`에 있다.

아래 최초 A/B/C 제안과 검증 범위는 디자인 검토 당시의 기록이며, 실제 적용 기준은 기존 디자인 유지안이다.

추가 적용: 첫 등원일(`roadmap.enrolledOn`, MCS 학생 등록일) 이전은 연간·연속 지도의 월·주차를 흐리게 남기고 클릭·키보드·호버를 비활성화한다. 첫 등원 주는 등원일 이후의 수업만 배치하며, 날짜 선택기와 URL 복원에도 같은 기준을 쓴다. 첫 등원일을 모르면 임의의 시작일로 잠그지 않는다. 첫 등원 이전과 종강 이후에는 공휴일명·색상·수업 눈금·오늘 표식을 표시하지 않는다. 진도 합산은 바꾸지 않는다.

## 피드백 반영: 기존 디자인 유지안이 현재 권장안

추가 색상 지시: 사용자가 제공한 두 번째 시계 이미지의 일·주·월 팔레트를 그대로 사용한다. 주차 완료와 수업 눈금은 `#174481`, 일간 완료 배경은 `#cfe4d9` 및 글자 `#0d7743`, 중앙 진도 호는 `#0d7743`이다. 월 배경은 분기 순서대로 `#e3ebf9`, `#dfede7`, `#f7eadb`, `#f8f6fc`, 바깥 분기 호는 `#5f89da`, `#4a9972`, `#b38147`, `#917cd6`이다. 선택은 `#ffd25b`. 해당 이미지의 픽셀과 기존 토큰을 대조해 지정했으며, 새로운 일괄 네이비 팔레트를 만들지 않는다. 이 조정은 디자인 시안에 반영했다.

사용자는 기존 시계 디자인을 매우 선호하며 최초 A/B/C안의 변경 폭이 크다고 피드백했다. **현재 권장안은 `preserve.html`**이다. 아래 최초 세 시안은 이전 비교안으로 남긴다.

`preserve.html`은 원래의 링 반지름, 분기색, 월 위치, 주차 경계, 완료/진행/선택 색과 중앙 60%를 재현한다. **날짜 링은 실제 수업으로 압축하고, 안쪽 요일 부채꼴도 수업 있는 날만 남긴다.** 기존 날짜 링 배치와 수정안을 같은 데이터에서 토글한다. 실제 서비스 캡처와 동일하다고 주장하는 재현물은 아니다.

중요한 차이: 최초 A안은 월 전체를 실제 수업 수로 등분했지만, 수정안은 **기존 주차의 달력 각도 범위를 고정하고 각 주 내부만 그 주의 실제 수업 수로 등분**한다. 따라서 바깥 주차 칸과 수업 칸의 방사형 정렬이 유지된다. 수업 없는 주/달은 하나의 중립 구간으로 남긴다. 실제 날짜는 클릭 상세와 원래 요일 부채꼴에서 확인한다.

지도 상태색과 MCS 바 색은 각각 기존 의미를 유지한다. 완벽한 연동은 데이터와 선택을 공유하는 것으로 구현하며, 같은 색으로 일괄 변경하는 것을 전제로 삼지 않는다. 이전 문서의 색상 통일 및 링 축소 제안은 이 유지안에 적용하지 않는다.

실제 구현의 중심은 `WeekRing`의 눈금 배치와 그 눈금의 선택 표시다. `MonthRing`과 `YearRing`의 각도는 유지한다. `DayRing`은 월~일 고정 7칸 대신 실제 수업 날짜만 날짜순으로 표시한다. 월·목 수업이면 두 칸이고 토요일 보강이 등록되면 월·목·토 세 칸이 된다. 비수업 요일의 이름·회색 칸·예약 공간은 만들지 않는다. 실제 보강 일정과 기록이 있을 때만 날짜를 추가한다. 연속 지도에서도 기존 월·주 경계를 기준으로 같은 배치 규칙을 사용한다.

시안 하단의 `9/19 (토) 보강 추가 예시` 버튼은 로컬 예시 데이터에 복습 보강 1회를 넣어 요일 부채꼴·수업 링·목록이 같이 늘어나는 것을 보여준다. 진도 차시를 중복 가산하지 않으므로 전체는 21/35차시로 유지된다. 실제 수업 일정에는 저장하지 않는다.

`index.html`을 브라우저에서 열면 세 가지 시안을 전환하고, MCS 차시·월·수업을 클릭해 연동을 확인할 수 있다. 하단 진도 슬라이더는 예시 데이터의 현재 차시만 변경한다. 실제 학생 정보는 사용하지 않는다.

## 제안

| 시안 | 원형 배치 기준 | 장점 | 한계 / 용도 |
| --- | --- | --- | --- |
| **A. 수업 회차 시계 — 추천** | 월별 30° 구간 안에 실제 수업 회차만 균등 배치 | 월의 위치를 유지하면서 비수업일 간격 제거. 월·목 리듬은 오른쪽 수업 카드에서 확인 | 칸의 각도는 날짜 간격을 나타내지 않음. 연간·연속 지도에 적합 |
| B. MCS 차시 시계 | MCS의 교과 차시 순서 | 원형 눈금과 진도바가 1:1로 대응 | 시간 간격과 월별 위치는 표현하지 않음. 목표 중심 보조 보기 |
| C. 월별 요약 시계 | 12개의 월별 도달률 호 | 정보 밀도가 낮고 작은 화면에서도 읽기 쉬움 | 전체 회차 분포는 상세 목록에서 확인. 학부모 요약에 적합 |

A는 기존 분기·월·주·일의 다섯 동심원을 **월 → 실제 수업 → 전체 목표 진도**로 정리한다. 분기는 월 제목 보조 정보로, 주차는 선택 월의 수업 목록으로, 날짜는 수업 카드로 이동한다. 수업이 없는 화·수·금·토·일은 링의 칸을 차지하지 않는다. 휴강과 방학 이력은 보존한다.

단순히 비수업일의 색을 숨기는 것으로는 해결되지 않는다. 현재 `WeekRing`은 비수업일의 일부 눈금을 생략하지만 `dayAngles(date)`가 모든 달력 날짜에 각도를 배정하므로 실제 수업 사이의 공백은 남는다. 실제 수업으로 배치의 분모를 바꿔야 한다.

## 실제 연동 설계

1. 중앙의 전체 목표 진도, 현재/전체 차시, 기준일 계획, 남은 수업, 필요 진도는 `learningRailMetrics` 또는 `buildLearningMap(...).metrics`를 그대로 사용한다. 수업 완료 횟수로 차시 진도율을 다시 계산하지 않는다. 연도·월 탐색으로 이 값과 기준일이 달라지지 않는다.
2. 수업 회차는 기존 `learningClassDates`, `progress.days`, 실제 보고서 일자를 기준으로 구성한다. 월 8회나 연 96회를 고정하지 않는다. 일정 변경·등록 기간·휴강 규칙은 기존 계산을 따른다. 보강은 기존 데이터에 확인되는 수업 일자로만 추가한다.
3. 날짜별 수업은 `positions[]`를 통해 MCS 원장의 차시와 연결한다. 한 수업에 여러 차시, 같은 차시의 반복 복습, 차시와 매칭되지 않는 시험·복습 기록을 각각 보존한다. 반복 기록 때문에 전체 도달 차시를 가산하지 않는다.
4. 달력상의 표시 날짜는 현재 코드의 `calendarDate` 정책을 유지한다. 보고서 확인일을 우선하고, 미도달 차시는 계획일을 사용하며, 도달했지만 날짜를 모르는 차시는 임의의 계획일로 옮기지 않는다. 계획일과 실제 수업일은 상세에서 구별한다.
5. 회차를 선택하면 해당 회차의 명시적인 차시 집합을 MCS `LearningRails`의 `selectedPositions` 및 `selectedActualPositions`에 각각 전달한다. 계획과 실제 날짜가 다른 경우 각각의 집합을 구별한다. 바에서 차시를 선택하면 기존 `onSelectPosition`을 통해 같은 차시의 수업/상세를 연다.
6. 한 차시에 여러 수업 기록이 있으면 대표 수업은 기존 마지막 확인일 규칙을 따르고 관련 이력을 함께 표시한다. `grade:lesson`의 안정적인 식별자를 유지하며 회차 번호나 화면상 각도로 저장하지 않는다.
7. 월의 도달률은 그 월에 배치된 유일한 차시 집합으로 계산하고 `선택 월 도달`로 명시한다. 중앙 `MCS 전체 목표 진도`와 분모가 다르다. 날짜 미확정 차시는 별도 진입점에 보존하고 전체 분모에서는 누락시키지 않는다. 예시 시안은 모든 차시에 날짜가 있는 데이터이므로 미확정 진입점은 생략했다.
8. 연속 지도는 기존 선택 월 앞 5개월·뒤 6개월 범위를 유지한다. 데이터 없는 월은 일정 없음으로 표시한다. 월 슬라이더·목록 스크롤·URL 복원·뒤로 가기는 기존 공통 선택 상태와 연결한다. 샘플은 범위 전환과 월 이동만 구현했으며, URL 및 스크롤 연동은 실제 적용 항목이다.

연간 지도의 회차 각도는 월 시작각 + 해당 월 수업 순번 / 그 월 전체 수업 수 × 30°로 산정한다. 휴강 월은 하나의 중립 구간과 사유를 표시한다. 수업 일정 자체가 미확인인 경우 확정된 보고서 날짜만 표시하고 예정 회차는 만들지 않는다.

## 시각적 규칙

- **파랑 `#0000ff`**: MCS 현재 진도와 도달 차시. **빨강 `#ff0000`**: MCS 목표. **금색**: 탐색 중인 선택. **중립 회색**: 예정 수업. 복습은 도달색으로 완료를 오인하지 않게 작은 기호를 추가한다.
- 수업 칸은 출석 완료율을 나타내지 않는다. `도달`, `예정`, `부분 도달`은 연결된 교과 차시의 상태이며, 보고서/출석 상태는 별도로 표현한다.
- 현재 진도 점과 선택 월 호는 분리한다. 비수업일인 오늘은 필요할 때 날짜 눈금 바깥의 작은 마커로 표시하며, 가짜 수업 칸을 만들지 않는다. 샘플에는 고정 기준 수업으로 돌아가는 버튼이 있다.
- 적용 시 월 선택은 약 220ms의 짧은 이동, 선택한 수업·바·상세는 약 180ms의 동시 강조, 현재 진도 변경은 호의 길이 전환을 사용한다. 연간 화면의 월 위치를 클릭마다 회전시키지 않는다. 연속 범위 이동 때만 월 이동을 짧게 보간하고 12월→1월은 이어진 방향으로 움직인다.
- 이동 감소 설정에서는 애니메이션을 생략한다. 모바일은 지도 아래에 선택 월의 수업을 세로로 배치하고 개별 차시 선택은 더 넓은 상세 행으로 보완한다. 샘플의 매우 좁은 MCS 눈금은 실제 적용 시 확대/스크롤 hit area 개선 대상이다.

## 구현 접점

- `src/features/math-progress-map/components/week-ring.tsx`: 달력 일자 각도를 실제 회차 각도로 바꾸는 주된 접점.
- `src/features/math-progress-map/components/day-ring.tsx`: 고정 월~일 7칸 대신 선택한 수업 주의 회차 표시.
- `src/features/math-progress-map/components/timeline/circular-progress-clock.tsx`: 연간/연속 공통 시계 렌더링.
- `src/features/math-progress-map/components/linked-learning-map.tsx`: 이미 구현된 MCS 바와 지도 간 선택 연결 재사용.
- `src/features/math-progress-map/learning-map.ts`, `learning-dashboard.ts`: 교과 차시 원장과 일정 어댑터 유지.
- `src/features/math-sheets/lib/learning-axis.ts`: 진도 계산의 단일 기준 유지.

예시 시안은 HTML/CSS/SVG로 작성했다. 시안 단계에서는 실제 앱을 변경하지 않았고, 이후 승인받은 유지안을 React/Next.js 코드에 반영했다. Next.js 16.2.6 로컬 가이드에서 페이지 및 클라이언트 컴포넌트 규칙을 확인했다.

## 확인한 범위

1440px 데스크톱 및 390px 모바일에서 세 시안의 가로 넘침과 브라우저 오류를 확인했다. 차시 → 수업, 월 → 차시 집합, 수업 → 복수 차시 선택, 휴강 제외, 연속 지도의 연도 경계, 0%/100% 표시를 점검했다. 결과는 `qa-report.json`, 시안별 화면은 `*-desktop.png`, 모바일은 `session-mobile.png`에 있다.

실데이터 MCS 연결, 시간대/일정 예외의 회귀 검사, 저장 및 권한 테스트는 이번 디자인 시안의 검증 범위가 아니다. 실제 적용 시 위의 기존 원장과 선택 상태에 연결해 검증해야 한다.
