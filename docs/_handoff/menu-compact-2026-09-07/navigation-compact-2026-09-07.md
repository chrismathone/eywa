# 좌측 메뉴·내부 탭 컴팩트화 검토

기준: 2026-09-07, 로컬 HEAD `488964cf`, 사용자 첨부 사이드바 이미지.

**추천: 왼쪽은 업무군 8개 + 즐겨찾기 최대 4개, 업무군을 고르면 본문 메뉴 버튼으로 진입, 화면 내부는 업무 탭 한 줄 + 필요한 도구 메뉴.** 기능을 묶는 위치부터 바꾸고, 실제 화면 통합은 중복이 확인된 부분부터 진행한다.

후속 사용자 의견 반영: 왼쪽 구성은 유지하고 펼침 메뉴를 본문 버튼형 메뉴로 교체했다. 디자인은 흰색 바탕·얇은 테두리·네이비 아이콘으로 정리하고 기존 Aywa SVG 아이콘을 재사용한다. 버튼 높이는 데스크톱 약 108px, 3열을 기본으로 하며 좁은 화면은 2열이다. 즐겨찾기와 단일 목적지인 운영실·캘린더는 화면으로 바로 이동한다. 수납·학원 설정도 버튼형 입구를 제공하며, 각 화면에서 해당 업무군 메뉴로 돌아올 수 있다.

**최종 사용자 결정: “버튼형으로 갈꺼니까 그렇게 넘겨.” 버튼형 메뉴 진입은 확정된 구현 방향이다.** 아래 세 가지 대안 비교는 판단 배경이며, 플라이아웃으로 회귀하는 선택지를 다시 제안하라는 뜻이 아니다. 내부 탭별 세부 통합과 iframe·창모드 기본 동작은 별도로 검토한다.

이 문서는 로컬 코드의 메뉴 정의·렌더링·화면 전환·권한 조건을 조사한 설계안이다. 로그인한 운영 화면 전체를 클릭한 결과나 사용 빈도 분석은 아니다. 이미지에는 메뉴 23개가 보이며, 코드에는 권한 적용 전 노출 후보 24개가 있다. 차이는 조건부 메뉴인 선생님 원스크린이다. 아래 빈도 판단과 절감 목표는 설계 가설이다.

[클릭 가능한 비교 시안](./navigation-compact-preview.html) — 현재 구조 재현 / 추천 구조 전환, 업무군 열기, 메뉴·탭 선택, 전체 검색. 실제 학생·업무 데이터와 서버 연결은 없다.

## 1. 길어지는 원인

## 3. 세 가지 대안

| 안 | 상시 노출 | 장점 | 비용·한계 |
|---|---|---|---|
| A. 밀도만 조정 | 이미지의 23개 유지. 행 36→32px, 간격 4→2px, 제목 간격 축소 | 배치 학습 비용이 작고 빠르게 적용 가능 | 행 피치 40→34px로 약 15% 감소에 그침. 긴 목록 구조가 남음 |
| **B. 업무군 + 버튼형 메뉴 + 즐겨찾기 (추천)** | **업무군 8 + 즐겨찾기 최대 4 + 하단 지원 2 = 최대 14개 위치** | 왼쪽 길이와 위치가 일정. 자주 쓰는 화면은 한 번 클릭. 나머지는 업무군 선택 후 본문의 버튼으로 진입 | 즐겨찾기 밖 화면은 보통 2회 클릭. 각 업무군의 메뉴 화면과 돌아가기·전체 검색 필요 |
| C. 업무 영역별 전용 화면으로 통합 | 업무 영역 약 6개 + 영역별 보조 탐색 | 큰 구조를 가장 단순하게 보이게 할 수 있음 | 여러 창 동시 작업, 권한, 화면 상태, 조회 경계까지 바뀜. 초기 변경 범위가 큼 |

추천 B의 14개에는 즐겨찾기의 중복 진입점과 하단 설정·도움말까지 포함했다. 기존 23개 대비 상시 노출 위치는 약 39% 줄지만 **기능 수가 39% 줄어드는 것은 아니다**. 그룹 메뉴에는 모든 기존 목적지가 남는다. 즐겨찾기를 쓰지 않으면 10개 위치다.

메뉴 영역 높이는 23×40px + 그룹 제목·간격 약 130px인 현 구조에서, 12×34px + 두 묶음의 제목·간격 약 50px로 줄이는 것을 목표로 한다. 약 1,050→460px, 약 56% 감소라는 **설계 계산**이며 운영 화면 실측이 아니다. 하단 지원은 고정 영역에 별도로 들어간다. 전체 앱에서 최종 치수를 검증해야 한다.

```text
INJAEWON                    [접기]
[메뉴·화면 검색]

즐겨찾기                  [편집]
  시간표
  강사 시트
  출석부
  학생목록

전체 업무
  운영실
  캘린더
  수업                        ›    클릭하면 본문에 메뉴 버튼
  학생                        ›    버튼으로 기존 화면 진입
  상담·재원                   ›
  수납관리
  학원운영                    ›
  문서·결재                   ›

─────────────────────────────────
  설정                 도움말
  계정 · 알림 · 보기 전환
```

초기 즐겨찾기는 첨부 이미지와 업무 성격으로 가정한 예시다. 원장은 시간표·강사 시트, 사무실은 출석부·학생·수납, 상담사는 등록상담, 셔틀 담당자는 오늘 등하원을 고정할 수 있어야 한다. 자동으로 순서를 바꾸지 않고 본인이 정한 위치를 유지한다.

## 4. 내부 탭 정리안

### 학원 설정: 11개 가로 탭 → 5개 범주 + 선택한 설정 하나

| 새 범주 | 기존 항목 전부 |
|---|---|
| 학원 정보 | 프로필·브랜드 |
| 수업·운영 | 운영 체계, 과목 운영 |
| 청구·안내 | 수납·청구, 알림·약관, 상담 양식, 팝업 공지 |
| 계정·권한 | 역할·권한 |
| 시스템 | 데이터 정리, 감사로그, 연동 |

설정은 자주 오가는 업무 탭보다 찾아 들어가는 설정 목차에 가깝다. 넓은 창에서는 검색 가능한 설정 목차, 좁은 창에서는 현재 설정명 선택기를 사용한다. 5개 탭 아래 다시 4개 탭바를 쌓지 않는다. 기존 11개 URL을 유지하면서 선택한 페이지만 조회·렌더한다. 과목의 세션 기간은 계속 과목 운영 안에서 관리한다.

### 수납관리: 최대 8개 + 중첩 5개 → 기본 5개 + 도구·설정

| 새 위치 | 기존 항목 |
|---|---|
| 기본 탭 5개 | 수납, 교재, 지출, 환불 요청서, 강사 정산(master만; 그 외 4개) |
| `계산·정산 도구` 버튼 | 수강료 계산기, 회차 확정, 시수 검증, 저장된 청구서 |
| `단가·휴일` 설정 버튼 | 수강료 단가, 교재 단가표, 공휴일 |
| 교재 툴바 | 교재 목록을 기본 본문으로, 교재 단가표는 단일 설정 화면으로 가는 바로가기 |

계산기 안의 5개 탭바는 없애고 계산기 본문과 관련 링크로 정리한다. 교재 단가표 두 URL은 당분간 같은 단일 목적지로 이어지는 호환 진입점으로 유지한다. 회차 확정·시수 검증을 자주 쓰는 사람은 해당 화면 자체를 즐겨찾기할 수 있게 한다. 청구·정산 계산식이나 업무 순서를 이 작업에서 바꾸지 않는다.

### 수업보고서: 최대 8개 → 기본 4개 + 실행·설정

| 새 위치 | 기존 항목 |
|---|---|
| 기본 탭 | 작성률, 목록, 반 공지, 반 구성 |
| `직접 발송` 버튼 | 기존 compose 화면. 작성 상태를 보존하는 전용 화면으로 이동 |
| `관리` 메뉴 | 회수 화면. 별도 권한과 확인 동작 유지 |
| `설정` 메뉴 | 보고서 설정, AI 멘트 |

현재 회수 화면은 일괄 작업을 포함할 수 있으므로 목록 한 행의 버튼만으로 축소하지 않는다. 메뉴 이동과 실제 기능 축소를 분리한다.

### 학생 상세: 9개 → 5개 큰 영역

| 새 영역 | 기존 내용 |
|---|---|
| 개요 | 개요 |
| 수업·출결 | 수업, 출결 |
| 학습 | 성적, 진도 |
| 상담·기록 | 상담, 메모, 타임라인 |
| 수납 | 수납. 기존 billing 권한 보존 |

영역 안에는 짧은 섹션 목차 또는 현재 내용 선택기를 쓴다. 5개 탭 아래 3개 알약 탭을 또 쌓으면 효과가 작다. 과거 `?tab=grades`, `?tab=timeline` 링크는 새 큰 영역 안의 해당 내용을 바로 선택해야 한다. 숨긴 9개 본문을 모두 미리 조회하는 구현은 피한다.

### 전자결재: 7개 → 기본 4개 큐 + 상태 필터

기본 큐는 **전체 / 결재 대기 / 결재 예정 / 참조**. 기존 **진행 / 완료 / 반려·회수**는 전체 큐의 상태 필터로 옮긴다. ‘예정’은 순서상 아직 내 차례가 아닌 문서이므로 ‘대기’와 구분을 유지한다. 기존 쿼리는 새 큐·필터 조합으로 해석하며 각 큐의 조회 범위를 검증한다.

### 나머지는 적은 수의 선택지를 유지

- 캘린더 4개, 이탈 방어 4개, 재고 4개, 셔틀 4개, 직원 상세 최대 4개는 개수보다 높이·간격·선택 표시의 통일이 우선이다.
- 출석부는 월별 / 오늘 / 출결 모드의 공통 화면 전환을 먼저 갖춘다. 오늘 안의 좌석표 / 확인 필요 / 어제 출결은 목적이 달라 보존한다. 어제 출결의 날짜 범위 계산도 그대로 유지한다.
- 시간표의 과목과 보기 방식, 시트의 반과 기간은 서로 다른 선택 축이다. 메뉴 수를 줄이려 한 드롭다운에 섞지 않는다.
- 등록상담 작성 폼은 기본 정보 / 과목 상담 / 사전 체크리스트(있을 때)를 큰 구분으로 하고, 과목 상담 안에 과목 선택기를 둔다. 미저장 입력은 선택기를 바꿔도 남아야 한다.

## 5. 화면 밀도 기준

기존 흰색·네이비 학원색, Pretendard, 13px 메뉴 글자는 유지한다. 읽을 글자를 줄이는 대신 여백과 중복 탐색을 줄인다.

| 요소 | 현재 | 제안 |
|---|---|---|
| 왼쪽 메뉴 | 높이 36px + 간격 4px | 포인터 정밀 장치에서 높이 32px + 간격 2px |
| 내부 업무 탭 | FaceTabs 기본 약 42px, 별도 테두리 껍데기 | 바 높이 32~36px, 바닥선 또는 얕은 선택 배경, 1행 |
| 화면 선택지가 많은 경우 | 가로 스크롤에 의존 | 의미별 재분류 후 `도구`·`설정` 선택기. 현재 선택된 도구명은 항상 표시 |
| 왼쪽 하부탭 | 활성 메뉴 아래 인라인 확장 | 화면 안에서 전환. 모든 내부 목적지를 전체 검색에 포함 |
| 단축키 안내 | 여러 줄 상시 설명 | 도움말·검색에 통합, 하단은 작은 단일 진입점 |
| 모바일·터치 | 전용 상단 메뉴, 일부 셔틀 컨트롤 44px 규약 | 클릭 가능한 전체 메뉴 시트. 터치 대상은 44px 목표, 데스크톱 32px를 일괄 적용하지 않음 |

탭의 개수 목표는 보통 4~5개, 예외적으로 6개다. 의미가 다른 기능을 억지로 합쳐 숫자만 맞추지 않는다. 좁은 창에서는 현재 탭을 나타내는 선택기와 명시적인 ‘전체 보기’를 사용하고 가로 스크롤도 보조 수단으로 유지할 수 있다.

## 6. 구현 시 지켜야 할 연결

1. **메뉴 묶음은 권한이 아니다.** 그룹은 접근 가능한 자식이 하나라도 있으면 표시한다. 학생상담과 등록상담, 영어·수학 시트는 각자의 권한을 검사한다. ECS 권한이 없어도 MCS 권한이 있으면 수학으로 갈 수 있어야 한다.
2. **그룹과 창 식별자를 분리한다.** `navigationGroup`은 화면 분류에만 사용하고 기존 `menuKey`, `windowId`, 창 크기를 유지한다. 수업 그룹으로 묶었다고 시간표와 시트를 한 창으로 대체하지 않는다. Shift+클릭의 새 창 동작과 열림·포커스 표시도 유지한다.
3. **목적지 정의를 공유한다.** 목적지 ID·라벨·href·기존 권한·창 키·노출 표면을 한 곳에서 정의하고 사이드바, 화면 전환, 검색, 모바일이 파생해 사용한다. 표시용 정의만 클라이언트에서 공유하고 서버 권한 판정은 각 페이지에 남긴다.
4. **내부 탭을 왼쪽에서 없애기 전에 독립 진입점을 보완한다.** 출석부 공통 면 전환, 영어·수학 전환, 검색을 먼저 연결한다. 현재 ECS의 `/mcs` 링크는 빈 상태 안내에 있어 공통 전환기를 대신하지 못한다. 강사 내 메뉴에는 이미 MCS가 있으므로 이를 유지한다.
5. **셔틀 정의의 의존 방향에 주의한다.** 지금 `shuttleFaces()`는 `SUBTABS_BY_MENU.shuttle`에서 파생한다. 왼쪽을 정리한다고 그 데이터를 삭제하면 화면 안 탭도 없어진다. 목적지 정의와 사이드바 노출 정책을 먼저 분리한다.
6. **URL·기간·저장 상태를 보존한다.** `embed=1`, 탭·하위 탭, 날짜·주·월, 셔틀 시즌, 반·학생 선택, 스크롤과 미저장 입력을 유지한다. 공용 FaceTabs의 기존 `replace` 동작도 검토 대상이다.
7. **권한별 탭 차이를 정의에서 표현한다.** master 전용 강사 정산, 보고서 쓰기/설정, 학생 수납, 직원 활동 로그, EiE 전용 MP를 단순한 정적 배열로 노출하지 않는다.
8. **기존 숨김 정책을 보존한다.** 원스크린·수업 평가·전자결재는 사람별 노출이 다르다. 개발 시간표·구 급여·구 휴가 메뉴를 묶음 작업 중 다시 노출하지 않는다.
9. **이름을 바꾸면 페이지 제목도 바꾼다.** 사이드바 라벨과 iframe 제목은 함께 일치시킨다. 그룹명 추가는 기존 화면명 변경 없이 가능하다.

현재 Next.js 로컬 가이드 `node_modules/next/dist/docs/01-app/01-getting-started/04-linking-and-navigating.md`도 확인했다. 실제 변경에서는 기존 URL 기반 이동과 선택한 화면만 조회하는 경계를 유지하며, 그룹 하나에 모든 무거운 페이지를 미리 마운트하지 않는다.

## 7. 적용 순서와 검증 기준

**1차: 탐색 구조.** 공유 목적지 정의 → 내부 탭 검색·모바일 진입 보완 → 업무군·즐겨찾기·본문 메뉴 버튼 → 왼쪽 인라인 하부탭 제거. 목적지 URL과 실제 업무 화면은 기존 것을 사용한다. 실제 앱에서는 업무군 선택이 이미 열어 둔 창을 닫지 않도록 하고, 버튼으로 화면을 열거나 기존 창에 포커스한다. 메뉴로 돌아올 때도 작업 중인 창 상태는 유지해야 한다.

**2차: 중복이 큰 내부 화면.** 학원 설정 → 수납 → 수업보고서 → 학생 상세 → 전자결재 순으로 적용한다. 단가표 중복, 설정 탭과 실행 버튼 혼재, 학생 상세의 탐색 폭부터 줄인다.

**3차: 밀도.** 각 화면을 새 공용 탭·선택기로 이동하고 데스크톱/터치 크기를 분리한다. 기존 FaceTabs를 한 번에 전역 축소하기보다 사용처별 줄바꿈·포커스·iframe 폭을 확인한다.

검증할 실제 사용자 동선:

- 1366×768에서 기본 즐겨찾기·업무군·하단 지원까지 접근 가능하고, 그룹 선택으로 다른 메뉴의 세로 위치가 바뀌지 않는다.
- 시간표와 강사 시트를 동시에 열고 전환·Shift+새 창·포커스 표시가 유지된다.
- 영어 접근 없음 + 수학 접근 있음 계정에서도 데스크톱·모바일·검색으로 MCS 진입 가능하다.
- 원장 / 사무실 / 강사 / 상담 / 회계 / 읽기 전용 계정의 허용 목적지가 개편 전후 동일하다.
- 오래된 내부 탭 URL로 직접 열었을 때 같은 업무 내용과 기간이 선택된다.
- 설정·학생 상세 큰 영역 전환이 다른 모든 본문의 조회를 유발하지 않는다.
- 390px 모바일과 좁은 iframe에서 호버 없이 메뉴 버튼으로 탐색하고, 선택한 탭이 가려지지 않는다. 키보드로 업무군·메뉴 버튼·돌아가기에 접근 가능하고, 화면 전환 후 제목으로 포커스가 이동한다. 모바일 전체 메뉴는 Escape로 닫힌다.
- 화면별 미저장 입력과 기존 저장 확인 흐름을 보존한다.

실제 사용 빈도를 확보하면 즐겨찾기 기본값과 ‘계산·정산 도구’의 배치를 조정한다. 첫 배포의 성공 기준은 기능 삭제 수가 아니라 **왼쪽 스크롤 감소, 메뉴 위치 안정, 자주 쓰는 화면의 1회 진입, 모든 기존 목적지 접근 유지**다.
