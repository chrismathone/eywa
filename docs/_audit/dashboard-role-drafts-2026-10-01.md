## 3. 과목으로 안 좁혀지는 칸 (과목 관리자 시안에서 뺌)

스냅샷에 과목이 실려 있지 않아 후처리로 못 좁힌다. 켜려면 서버 조회에 과목 조건을 새로 붙여야 한다.

1. 재원생 구성 · 학년별 재원생 · 학교별 학생 — 학년·학교 집계가 과목 구분 없이 한 표(`students()`는 `TeacherScope` 인자를 받으므로 **과목 스코프로 바꿔 끼우면 서버에서 좁힐 수 있다** — 가장 값싼 길)
2. 출결 현황 · 최근 14일 등원율 — 학원 전체 합계 한 벌
3. 반복 결석 학생 — 학생 이름·횟수만
4. 등록·퇴원 추이 · 재원생 추이 — 월별 합계(`changes()`는 스코프 인자 있음, `enrolledTrend`는 강사 스코프면 null)
5. 신규생 단계별 관리 · 신규생 체크 진행
6. 콜&상담 전환 · 상담 진행 · 레벨테스트 및 첫수업 일정 — 일정은 제목 글자뿐
7. 학습·학부모 보고 · 학생 상담 — 합계 한 벌
8. KPI 신규문의 · 금일 등록 · 보강예정 — 명단에 과목이 없고 보강 예약은 반 이름만
9. 행정·자산 — 과목과 무관
10. 이번 달 수납 현황 — 청구서가 과목 구분 없이 합산(② 켜도 학원 전체 값)

좁혀진 칸(후처리): 재원생 수·프로그램 · 과목별 수강 · 수강 조합 · 현재 수업 현황 · 오늘첫수업 · 전일 결석 · 퇴원생(영어·수학만) · 강사 시트(과목마다 하나).
재원생 수는 `programs`(영어 = EiE + 인재원 영어, 수학 = 수학 프로그램)로 센다 — 영어는 두 트랙을 모두 듣는 학생이 있으면 겹쳐 세질 수 있다.

## 4. 원장이 정할 6가지 — 시안 위 체크박스(켜면 허용, 기본 전부 가림, 주소 `?t=1,4`)

| # | 체크 | 켰을 때 | 현재 운영실과의 관계 |
|---|---|---|---|
| ① | 데스크에게 미납 금액 | 데스크의 수납 칸이 **미수 잔액 금액**까지 | 현재 운영실엔 "미납 건별" 목록이 없다 — 건수 + 미수 잔액 합계뿐. 건별 금액은 수납관리 탭에만 있음 |
| ② | 과목 관리자에게 수납 금액 | 수납 현황 칸이 열림(**학원 전체 값** — 과목 분리 불가) | 과목별 청구는 새 집계 필요 |
| ③ | 과목 관리자에게 강사 시트 작성 현황 | 담당 과목 시트 카드 | 현재 운영실엔 **강사별 비교가 없다** — 과목별 한 줄(영어 주간·수학 월간). "강사별 작성률 비교"는 새 카드가 필요 |
| ④ | 과목 관리자에게 퇴원 명단(자기 과목만) | 퇴원생 KPI(영어·수학 과목 행만) | 카드엔 이름·학교학년·퇴원일·프로그램뿐 — **사유 원문은 카드에 없다**. 퇴원관리 메뉴 링크는 모든 비원장에게 막음 |
| ⑤ | 원장 외에도 전화번호 그대로 | 일정 제목의 전화번호를 가리지 않음 | 기본은 `010-****-5678`(뒤 4자리만) |
| ⑥ | 직원 구성 카드를 실장·데스크에게도 | 직원 구성 칸 | 지금은 개인 예외로 관리자 4명에게 열려 있음 |

⚠️ 지난 제안의 "AI 브리핑 원장 전용"은 **현재 운영실에 AI 브리핑 카드가 없어**(`daily-briefing-card.tsx` 소비처 0, `/dashboard/briefing`은 `/dashboard`로 redirect) 시안 대상이 아니다. 다시 들이면 원장 전용으로 시작할 것.

## 5. 실제로 적용하려면 바꿀 곳 (설계)

원칙: **메뉴 권한이 아니라 역할 묶음 기준 단일 함수**, 그리고 **서버가 스냅샷을 만들 때 건다**(#77 — 시안의 브라우저 걸러내기는 보는 사람이 원장이라 가능했던 것일 뿐, 실제엔 데이터가 클라이언트에 내려가면 이미 샌 것).

1. **묶음 판정 한 함수** — 예: `src/features/dashboard/role-bundle.ts`의 `dashboardBundleOf(user, matrix)` → `"owner" | "subject" | "manager" | "desk"`.
   - 슈퍼관리자·master = owner(슈퍼관리자는 역할이 admin일 수 있으니 표를 따로 묻는다 — 시안 `canOpenDraft`와 같은 두 줄. `staff.md` "새 제한 명단 자동 통과").
   - admin + `users.subjects` 있음 = subject, 없음 = desk, manager = manager. 그 밖(teacher·accountant·viewer)은 기존대로 메뉴 권한만.
   - 판정은 tenant-aware 헬퍼(`canAccess*`)와 같은 자리에서 — bare 역할 문자열 비교 금지(#58).
2. **영역(Area)별 정책표 한 곳** — `OVERVIEW_AREA_POLICY: Record<Area, { bundles: Bundle[]; scope?: "subject" }>`. `loadOverview()`의 `add(area, menus, load)`가 **메뉴 검사 옆에서 묶음도 검사**해, 못 보는 영역은 **조회 자체를 안 한다**(데이터가 안 만들어지고 DB 부하도 준다). 가드 테스트: `add()`로 등록된 모든 영역이 정책표에 있어야 한다(새 카드가 정책 없이 생기면 빌드 실패 — write-only-orphan의 역방향 방지).
   - 메뉴 권한과 **AND**(둘 다 통과). 원장이 개인 예외로 여는 칸(직원 구성 등)은 정책표 쪽에 "사용자별 허용" 한 곳을 두는 게 맞다(원장 결정, ⑥).
3. **필드 단위 가림은 서버 쪽 변형 함수** — 같은 모양을 유지한 채 값만 비운다.
   - 수납: `billing()`가 건수 변형(금액 0, 지금 달 하나)을 돌려주는 인자(`amounts: boolean`)를 받는다. 시안의 `trimBilling`·`billingAmounts` prop이 UI 쪽 모양(= `Overview`의 건수 변형)이다.
   - 일정 제목 전화번호: `calendar` 영역을 만드는 곳에서 `maskPhones`(`_lib/mask.ts`를 `src/features/…`로 옮김).
   - 공지: `getRecentAnnouncements(role)`에 **묶음에 맞는 SystemRole**을 넘긴다(시안은 원장 시점 4건 안에서 거르므로 실제와 건수가 다를 수 있다).
   - 행정·자산: `operations()`의 **"내 결재 대기"는 로그인한 사람의 결재함 건수**라 보는 사람 기준으로 다시 세야 한다(시안은 원장 개인 수치라 다른 역할엔 뺐다). 나머지 건수(회의록·공용 문서·운행 차량·자산)는 학원 단위다.
4. **과목 스코프** — `loadOverview`에 `subjectScope`(담당 과목 집합)를 하나 더 풀어, 이미 `TeacherScope`를 받는 `students()`·`changes()`·`firstClasses()`에 **과목 스코프(반 id + 그 반 재원생 id)**로 넘기고, 나머지(출결·결석·보강·시간표·퇴원)에는 과목 조건을 새로 붙인다. 3절의 "안 좁혀지는 칸" 중 1·4번은 이 한 번으로 풀린다. 담당 과목은 `users.subjects`.
5. **링크 메뉴(`allowed`)도 묶음 기준** — 카드의 ↗가 열 수 있는 메뉴를 묶음이 허용한 것으로 줄인다(시안이 `allowed`에서 `staff`·`owner`·`withdrawals`·(금액 안 열린) `billing`을 뺀 것과 같다). 실시간 구독 테이블(`overviewTables(allowed)`)은 이 줄임에 자동으로 따라온다.
6. **갱신 경로가 같은 함수를 지난다** — `refreshOverview()`는 이미 `loadOverview()`를 부르므로 위 1~5를 `loadOverview` 안에 넣으면 30초 갱신이 필터를 잃지 않는다(시안은 갱신도 `applyRoleView`를 거친다).
7. **화면 배치는 `OverviewLayout`을 묶음별로 선택** — 이번에 `overview.tsx`를 배치 값으로 받게 리팩터했으므로 묶음별 기본 배치(A/B/C 중 원장이 고른 안)를 `layout`으로 넘기기만 하면 된다. 시안의 `_lib/roles.ts`(`buildLayout`)를 `src/features/dashboard/` 아래로 옮겨 서버·화면이 같이 읽는다.
8. 마이그레이션 없음(DB 변경 없음 → #95 순서 문제 없음). 새 설정 필드를 학원 설정에 노출한다면 5단계(스키마·기본값·폼·소비처·검증)를 따를 것 — 6가지 토글을 영구 설정으로 만들 때만 해당.
9. 테스트: 묶음 × 영역 매트릭스 표 테스트(시안 `apply.test.ts`가 시안 버전의 전수 — 64개 토글 조합 × 3개 역할 × 3안에서 지출·6개월 수납·직원 영역 부재를 확인), 영역 등록 ↔ 정책표 가드, 슈퍼관리자 통과.

## 6. 시안 코드가 남기는 것 / 지우는 법

- 남는 것(실제 적용에도 쓴다): `src/features/dashboard/overview/layout.ts`(배치 타입) · `overview.tsx`의 `layout`·`billingAmounts` prop · `KpiStrip`의 `only`.
- 시안 전용: `src/app/(shell)/drafts/dashboard-roles/` 전체 — 확정되면 `_lib/*`를 features로 옮기고 이 폴더는 삭제(`route-key.ts`의 `drafts` 항목은 다른 시안이 없을 때 함께 정리).

## 7. 알려진 한계 / 남은 위험

- C안이 1,920×1,080 한 화면에 들어가는지는 **실브라우저로 못 쟀다**(이 환경에 로그인 계정이 없음). 카드 높이는 차트 내용에 따라 달라진다.
- 과목 관리자 시안은 좁혀지는 칸이 적어 **얇다** — 3절의 서버 스코프 확장이 있어야 실제 쓸 만해진다.
- 시안의 걸러내기는 브라우저에서 돈다 — 전체 스냅샷이 원장 화면에 내려와 있다(원장만 여는 화면이라 노출은 아님). 실제 적용 땐 이 구조를 쓰면 안 된다(5절 서두).
- 시안에서 차트 막대/꺾은선 토글을 누르면 원장 본인의 계정 설정(`ui_prefs.dashboard`)이 실제 운영실과 똑같이 저장된다(`Overview`가 그대로 쓰는 저장 경로).
- 공지는 원장 시점 4건에서 역할 대상만 거르므로 시안에선 4건보다 적게 보일 수 있다.
- 전화번호 가림은 정규식 한 벌이라 **모르는 표기는 가려지지 않은 채** 나간다(하이픈·점·슬래시·괄호·공백·en/em 대시·+82·0505는 처리. 붙어 쓴 두 번호·전각 숫자는 미처리). 시각 범위(1500-1600)·연도 범위는 일부러 안 가려서 둘 다 시각처럼 읽히는 번호(1544-1234)도 그대로다. 실제 적용 땐 일정 제목에 번호를 적지 않게 하는 쪽이 근본 해결이다.
- 시안의 카드 링크(↗)는 원장 권한으로 열려 **전 과목·전체 데이터 화면**이 열린다(예: 과목 관리자 시안의 재원생 ↗ → 원생목록 전 과목). 실제 적용 땐 목적지 화면의 권한·스코프도 같은 묶음 기준으로 맞춰야 한다.
- 영어 담당의 재원생 수는 과목 막대 합(학생 단위)이고, 수학은 수학 프로그램 수다 — 영어·수학 밖 과목(국어 등)은 퇴원 귀속·강사 시트가 없어 ③·④를 켜도 비어 있다.
