# 시간표 편집기 · 연습본 적용 구현 및 검증

## 사용자 확정 요구

- 개인별 메뉴 권한: 직원·역할·메뉴·권한·삭제 제목행과 열 정렬.
- 시간표 편집기는 본문 여백 없이 최대 가용 영역을 사용한다.
- 강사뷰 수업 블록은 실제 반 색상 사용. JJ·LAB 포함.
- 강사 열 순서 드래그 결과는 실제 강사별 시간표에도 반영. 개인 저장 순서·다른 과목 설정 보존.
- 반·강사 선택에는 검색 필터. 검색 중 기존 선택을 임의로 바꾸지 않는다.
- 학생 이동: 양쪽 반의 일반 명단 아래 별도 IN/OUT 그룹, 이름 뒤 IN/OUT, 가나다 정렬, 보라색. OUT은 배정 인원에 넣지 않는다.
- 명단 간격 축소, 학교·학년은 공용 표기 사용, 드래그 손잡이 아이콘 제거.
- 두 보기 모두 수업에 서식 있는 정보 팝업. 네이티브 title과 중복하지 않는다.
- 통합뷰 반 제목 드래그로 같은 행 또는 다른 행으로 위치 변경.
- 강사뷰↔통합뷰 전환 시 선택·상세 초기화, 보기별 도구 활성/비활성 구분.
- 통합뷰 학생 명단 접기 옆 교시 접기. 배치 확인은 수업 상세가 아닌 전체 검사 목록.
- *LAB도 추가·수정에서 설정.
- 최종 버튼 명칭은 **연습본 적용**. 실제 통합뷰·강사뷰 및 관련 운영 조회에 변경이 이어져야 한다.
- 적용 범위: **선택한 기준일부터 이후**. 적용 시각: **KST 00~23시 정시**, 분 선택 없음.

## 구현

화면 요구를 구현하고 `연습본 적용`을 새로 연결했다. 상단 적용 버튼에서 날짜와 KST 정시를 선택하고 변경 내용을 검사한 뒤 예약한다. 적용 내역에서 완료·실패·취소와 당시 연습본 불러오기를 지원한다. 변경이 없으면 예약하지 않는다.

실제 수업·자리·비수업 블록은 `class_schedules`·`teacher_schedule_blocks`를 적용일부터 새 버전으로 생성하고 이전 유효기간을 닫는다. 학생 이동은 원수강 종료와 새 수강을 같은 트랜잭션에서 처리한다. 기존 수강 식별자·급여 티어·보류 상태를 보존한다. 반·학생·강사 이름 수정은 관리 권한을 추가 검사한다. 새로운 강사 열은 계정 등록을 대신하지 않으며, 담임은 등록된 직원을 지정해야 한다.

불러온 시점의 교시·명단·담임 원본도 연습본에 보관한다. 사용자가 실제로 바꾼 필드만 운영 변경으로 계산하므로, 주초 수강 이력이나 예정 담임 표기가 현재 운영 정보에 덮어써지지 않는다. 시간만 바꾼 교시는 강사·강의실의 기존 FK 상속을 보존하며, 비수업 일정의 원래 강사 별칭도 보존한다. 담임만 바꾸면 화면의 교시 강사는 기존 강사로 명시해 유지한다. 원본 정보가 없는 예전 연습본은 운영 적용 전에 다시 불러와야 한다.

개인 반 배치·강사 순서·색·접기·크기·메모는 기존 `users.ui_prefs.timetable`에 부분 병합한다. 실제 통합뷰·강사뷰와 다음 불러오기가 같은 값을 읽는다. 기존 다른 과목/요일 그룹 순서는 보존하고, 강사 순서는 바꾼 열만 이동한다. 기존 글씨 크기와 편집기 크기를 함께 적용한다. 이동 명단의 IN/OUT은 연습본의 이동 전후 표시이며, 실제 수강은 기존 전입·종료 규약으로 저장한다. OUT을 재원/충돌 계산에 넣지 않는다.

정시 작업은 `/api/cron/apply-timetable-lab`에서 실행한다. 예약 시 운영 자료는 그대로다. 작업 실행 시 원본·지점·계정·권한을 다시 확인하고 직렬화 트랜잭션으로 반영한다. 출결·보고서·기존/새 보강 장부·교시 고정·자리 이동·인수인계·가져오기 예약이 연결된 변경은 사유를 알리고 차단한다. 다른 과목과 비수업 블록의 겹침 및 운영시간은 현재 DB와 학원설정으로 다시 계산한다. 클라이언트의 검사 자료를 신뢰하지 않는다.

적용 완료 후 열린 운영 시간표는 조회로 갱신한다. 편집 중인 연습본은 자동 덮어쓰지 않는다. 숨긴 창은 갱신 조회를 쉬게 한다.

같은 반/요일에서 교시마다 다른 학생 명단은 현재 수강 모델로 정확히 표현할 수 없으므로 적용 전에 차단한다. 전체 반 이동이나 등원 요일로 맞춰야 한다. 불러온 배치가 적용일에 이미 종료되었거나 이후 예약과 충돌하면 적용할 주를 다시 불러와야 한다. 스케줄러 지연으로 날짜가 넘어간 예약은 소급 적용하지 않고 실패 내역으로 남긴다. 정시 예약은 Vercel 스케줄러가 해당 시각 이후 실행하는 방식이다.

## 반영 경로 검증 계획

1. 서버가 적용일·정시·학원·권한·원본 변경 여부를 재검증한다. 다른 지점 자료·조작된 식별자는 거절한다.
2. 변경 검토 화면에서 수업 배치·반/강사 색상·순서·학생 이동·*LAB·표시 설정을 구분해 보여준다. 지원하지 못하는 표현은 조용히 버리지 않고 적용 전 차단한다.
3. 예약 시간 전에는 운영 테이블을 바꾸지 않는다. 정시에 실행하는 작업은 하나의 DB 트랜잭션으로 반영한다.
4. 배치와 수강은 기존 날짜 이력 규약을 지킨다. 출결·수업보고서·보강 연결과 충돌하는 수정은 보존 또는 적용 차단으로 처리한다.
5. 보기 설정은 부분 병합한다. 다른 과목·요일 그룹·다른 화면의 개인 설정을 보존한다.
6. 예약 성공/실패/취소 상태를 화면에서 확인 가능하게 한다. 중복 요청·동시 적용·재실행은 한 번만 반영한다.
7. 합성 자료 및 격리 DB에서 날짜 경계, KST 시간, 전체 롤백, 다른 지점, 권한 변경, 원본 변경을 검증한다. 운영 학생 자료를 시험 저장하지 않는다.
8. 변경 파일만 커밋·푸시한다. 공유 작업공간의 다른 진행 중 변경은 포함하지 않는다. 전체 타입 검사에서 발견한 이미 커밋된 `mcs-goal-revision.test.ts`의 `object | null` 선언은 실제 전달 가능한 `postgres.JSONValue`로만 수정한다. 실행 동작은 바뀌지 않는다.

## 배포 맥락

Vercel 앱/CLI의 연결 계정은 운영 팀 `bigshols-projects`에 접근하지 못한다. 프로젝트를 재연결하지 않고 기존 main Git 자동 배포 경로를 이용한다. GitHub의 실제 Production 배포 SHA와 성공 상태를 별도로 확인한다.

`20261008040000_timetable_lab_apply_jobs.sql`을 운영 프로젝트 `ylqviwxedsdikuslmwxf`에 Supabase CLI `db query`로 한 트랜잭션 적용했다. RLS 켜짐, 일반/비로그인 쓰기 금지, 서버 쓰기 허용, 본인 조회 정책, pending 중복 방지 인덱스를 확인했다. 적용 직후 예약 0건이며 운영 수업·수강 시험 변경은 하지 않았다. CLI 직접 SQL 적용이라 별도 마이그레이션 이력 등록은 하지 않았다.

## 검증 기록

관련 단위 검사 72파일/851건, 실제 PostgreSQL 트랜잭션 16건, 브라우저 동작 11건을 검증했다. 수정 TS/TSX 56파일의 ESLint도 통과했다. 브라우저는 1440/1188px에서 서식 팝업·선택 초기화·전체 겹침 목록·각각 접기·반 드래그·IN/OUT·학교/학년·검색 선택 보존·크기 저장/되돌리기를 확인했다. 격리 DB는 정시 전 유지, 수업/수강/개인 설정 동시 적용, 중간 오류 전체 롤백, 원본/계정/권한/지점 변경 거절, 취소/재예약, 동시 실행, RLS 쓰기 금지, 출결/보강/교시 고정 보호, 예약 멱등성, 다른 계정 조회/취소/연습본 조회 거절을 확인했다.

운영 원본 325개 배치를 읽기 전용 트랜잭션으로 대조했다. 교시 접기만 바꾼 계획의 수업·일정·반·학생·수강·강사 이름 변경은 전부 0건이었다. 실제 크기의 연습본이 서버 스키마·깊이·2MB 제한을 통과함도 확인했다. 이 검사는 운영 자료를 저장하거나 예약을 생성하지 않았다. 기존 겹침 90건은 새 변경으로 생긴 문제가 아니며 예약 검토 화면에서 확인 대상으로 제시한다.

적대적 검토에서 수업 선택 잔류로 전체 점검 버튼이 수업 상세를 여는 문제, CSS 초기화로 HTML 드래그 속성이 사라지는 문제, 빈 LAB 열의 자리 판정, 기존 FK 상속/별칭으로 변경 없는 수업을 다시 만드는 문제, 주초 수강·담임 이력을 운영 정보에 덮어쓸 가능성, 표시 설정 전체 덮어쓰기, 되돌리기/취소 후 요청 중복, 클라이언트 검사자료 변조, 적용 실패 후 연습본 복구 누락을 찾아 수정했다.

검증 자료는 `F:/eywa-review/timetable-*` 및 `F:/eywa-review/timetable-editor-20261008`에 있다. 이 폴더는 git worktree가 아닌 검증 복사본이며 운영 비밀 환경 파일을 넣지 않았다. 최종 webpack 프로덕션 빌드와 별도 전체 `tsc --noEmit --incremental false`, ESLint가 통과했다. 마지막 수정은 테스트 타입 선언만 바꾸며 실행 코드는 빌드 검증본과 동일하다. 빌드 산출물은 배포에 사용하지 않는다. 푸시 후 운영 배포는 GitHub Production의 해당 커밋 성공 여부와 인증된 운영 화면 조회로 별도 확인한다.
