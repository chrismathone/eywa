# 1.0.3 실제 PC 실행 후 점검 · 2026-10-09

## 설치·실행 확인

학원동기화-PC의 버전이 1.0.3으로 반영되었다. 10:31 KST 클래스노트 워커가 시작했고 10:32 하트비트는 최신이었다. 업데이트 상태는 `idle`, 두 모듈은 실행 중이었다. 이 초기 확인까지 기존 보고서 대기 13건 중 2건이 실제 자동 처리되었다. 이후 사용자가 허용한 학원이 테스트 작업은 아래에 별도로 기록한다. 일반 학생 대상 테스트 발송 요청은 넣지 않았다.

이때 다음 세 조회에서 오류가 확인되어 전체 정상이라고 보고하지 않았다.

| 경로 | 서버 기록 | 원인 |
| --- | --- | --- |
| 반 보드 대상 조회 | `3e7e5d2d…` / `unknown_operation` | SQL을 반환하는 동기 함수 호출이 일반 값으로 등록됨 |
| 자동 반 동기화 대조 | `d0bb7fc8…` / `unknown_operation` | 같은 SQL 함수의 import 호출도 일반 값으로 등록됨 |
| 첨부만 있는 글 재조회 | `63bb961c…` / SQLSTATE `42601` | NOT EXISTS 조건의 닫는 괄호 누락 |

## 수정 계획과 구현

- 카탈로그 생성기는 로컬/정적 import 함수 중 **직접 SQL 태그를 반환하는 동기 arrow 함수만** SQL 조각으로 판단한다. 각 매개변수에 그 함수의 정확한 템플릿 ID를 등록한다. async 함수나 일반 데이터 함수는 조각으로 허용하지 않는다.
- 첨부 조회의 괄호를 고친 새 템플릿을 등록한다. 게시된 1.0.3은 옛 ID를 보내므로, 서버 카탈로그에 해당 ID만 새 템플릿으로 연결한다. 양쪽의 모듈·매개변수 형태 확인을 유지하며 재귀·순환 연결은 깊이 제한으로 거부한다.
- SQL 문장을 PC에서 받거나 임의 SQL을 허용하는 방식으로 우회하지 않는다. 기존 query ID를 보존하고 지점 RLS·실행 임대 검증은 유지한다.
- 이 수정은 **웹 서버 배포로 현재 1.0.3에 적용**된다. 정식 sequence 5의 EXE·ZIP·명세·해시는 변경하지 않는다. 수정된 워커 원본은 이후 새 순번을 빌드할 때 포함한다.

## 검증

- 실제 `loadAywa`/`loadAutoSyncInputs`를 원격 DB 어댑터의 JSON 직렬화와 서버 컴파일러에 연결한 오프라인 재현 3개 통과. 다른 모듈·다른 SQL 조각·순환 호환 연결은 거부한다. 외부 요청 없음.
- 관련 회귀 105개, TypeScript, 컴파일러 ESLint 통과.
- 격리된 PostgreSQL 실제 제어/권한 시험 26개 통과. 운영 DB가 아닌 전용 fixture DB만 생성·삭제했다.
- 운영 DB **READ ONLY 트랜잭션**, 실제 `eywa_sync_agent` 역할, 같은 지점 컨텍스트로 워커가 직렬화한 네 조회를 실행했다. 대상 반 68, 학생 836, 자동 대조 결과 1, 첨부 재조회 후보 8. 다른 지점 학생 0. 출력은 건수뿐이며 저장·발송·알림 생성·AI 분류를 실행하지 않았다.
- 현재 워커의 SQL 태그 349개가 서버 카탈로그에 모두 존재한다. 단순 ID 존재 검사만으로 함수 조각의 형태까지 검증할 수 없었던 점을 실제 호출 재현으로 보완했다.

### 숙제영상 설정 이관 확인 필요

11:20~11:22 확인에서 실제 워커의 `videoArchive.enabled=false`, Drive 용량 검사 `checkedAt=null`, 완료된 당일 업로드 없음이었다. 지점의 `homework_video_drive_settings` 저장 행과 Google 계정 연결 행은 비어 있다. 운영 웹은 서버의 기존 폴더를 표시하지만 새 PC 워커가 그 설정을 사용한다고 보장하지 않는다. 기존 영상 보관 이력 431건과 대기 1건은 보존했다.

통합 앱의 기존 설정 가져오기는 `CLASSNOTE_VIDEO_DRIVE_FOLDER_ID`, Google 인증 설정 및 기존 상태 파일을 복사한다. 해당 값을 수동 계정 입력 폼에는 노출하지 않는다. 사용자는 가져오기 여부를 기억하지 못한다고 답했고, 실제 앱 캡처에서 실행 중 가져오기가 차단된 것을 확인했다. 비밀번호·토큰을 요구하지 않았다. 현재 앱에서도 로컬 옵션의 `이 PC에서 연동 일시 중지`를 체크하고 저장한 뒤 모듈 종료를 기다리면 웹에서 설정을 끄지 않고 가져올 수 있다. 설정 변경은 관리 코드 잠금을 유지한다.

이 확인 없이 다른 계정·폴더로 새 설정을 만들거나 임의로 영상 보관을 켜지 않았다. 현재 결과를 전체 외부 기능 정상으로 보고해서는 안 된다. 사용자의 **지금 구현하지 말라**는 지시에 따라 상단 바로 중지·재개 개선은 [1.0.4 계획](sync-agent-1.0.4-pause-handoff-2026-10-09.md)에만 기록했다.

### 원본 폴더 가져오기·재개 후 Google 확인

사용자가 기존 워커 원본 폴더에서 설정·기록 가져오기를 완료하고 다시 연동을 시작했다. 11:30:49 두 모듈이 재기동했고 11:33 확인에서 다음 결과를 얻었다.

- 실제 워커의 `videoArchive.enabled=true`로 바뀌었다. 저장 폴더는 해당 지점의 기존 등록 폴더와 일치한다.
- 기존 PC Google 인증 경로로 **11:31:19 Drive 용량 조회가 성공**했다. `quotaError=false`, `paused=false`, 실제 남은 공간 값이 반환됐다. 지점별 새 OAuth 연결 행은 만들지 않았으며 기존 인증·폴더를 이어 쓴다. 계정 비밀번호·토큰을 읽어 출력하지 않았다.
- 영상 1건이 11:31:20 다시 실패했다. 해당 영상의 고정 루트·계정 표식은 현재 폴더와 일치하고 다른 지점 소유가 아니다. 따라서 Google 설정 이관 미완료라고 단정하지 않는다. 현재 저장 오류는 원본·다운로드·폴더·업로드 단계를 구분하지 않는 일반 문구여서 **그 한 건의 원인은 미확정**이다. 11:36 읽기 전용 조회에서 원글은 **2025-11-18**, 큐 생성은 2026-10-01, `attempts=695`임을 확인했다. 이전부터 재시도가 누적된 작업이며, 일반 학생의 새 ClassNote 글을 만들어 재현하지 않았다. 저장된 원본 URL이 만료됐다거나 원글이 삭제됐다고 확인 없이 단정하지 않는다.
- Google 인증과 저장 폴더의 이관은 확인됐지만 이 실패 영상의 업로드 완료나 새 영상 전체 동작까지 성공으로 표현하지 않는다. 이전 보관 431건은 유지됐다.
