# 반 편집·여러 연습본·비교 (2026-10-02)

기존 강사뷰/통합뷰를 유지하며 반과 학생을 편집하고 이름을 붙여 여러 사본을 저장한다. 모든 편집은 같은 연습본과 Undo/Redo를 사용한다. 별도 워크트리 `chrismathone/timetable-lab`에서 구현했으며 운영 반·수강 등록을 변경하는 API는 추가하지 않았다.

## 편집 동작

- 반 이름은 해당 반의 모든 요일과 두 뷰에 함께 바뀐다. 식별자는 유지한다.
- 통합뷰에서 학생 이름을 다른 반으로 끌면 현재 반의 모든 배정에서 빼고 새 반 전체 수업에 넣는다. 다른 반·다른 과목의 배정은 보존한다. 사용자가 ‘도착 반 전체 수업’으로 범위를 확정했다. 키보드는 확인 패널의 ‘학생을 다른 반으로 옮기기’ 폼으로 같은 명령을 사용한다.
- 이동 학생은 운영 시간표의 전입 민트색 `#bbf7d0`/진초록 `#14512b`으로 표시한다. 원래 반을 툴팁에 남기고, 원래 반으로 돌아오거나 Undo하면 표시를 복구한다. 저장본에도 이동 출처를 보존한다.
- 합치기는 사용자가 고른 반의 시간표·색·이름을 유지하고 양쪽 명단을 중복 제거하여 전체 수업에 배정한다. 사라지는 반의 배치 수와 유지할 시간표를 실행 전에 보여준다.
- 나누기는 선택 학생과 기존 등원 요일을 새 반으로 옮긴다. 수업 배치·색·담임은 복사하고 새 배치에는 새 ID를 부여한다. 원본 운영 schedule ID를 새 반이 재사용하지 않는다. 사용자 그룹 순서에서 원래 반 옆에 배치한다. 초기 강사·방 겹침은 허용하며 표시한다.
- 수업 시작·종료와 40/50/60/80/90분 선택을 제공한다. 운영 교시의 연속된 시간 범위와 실제 가져온 수업의 예외 시간만 허용한다. 쉬는 구간을 건너거나 운영시간 밖으로 늘리는 것을 막는다. 회의 등 비수업 일정은 수업 운영시간을 넓히지 않는다. 이동·복사·추천도 같은 범위를 따른다. 비수업 일정 자체는 수업이 아니므로 끌어 옮길 때와 시간 폼 모두 운영시간 밖에 둘 수 있다(하루 안, 시작보다 늦은 종료만 확인). 처음에는 끌기만 풀려 있고 폼은 운영시간 밖 회의를 열자마자 경고와 함께 잠겼는데, 같은 규칙(`isAllowedTime`)으로 맞췄다.
- 반 이름·명단이 바뀐 뒤 예전 클립보드를 붙여넣으면 다시 복사하도록 안내한다. 변경 전 명단을 되살리는 것을 방지한다.

## 저장·비교

상단 ‘연습본 저장·불러오기·비교’ 또는 Ctrl/Cmd+S로 보관함을 연다. 저장할 때마다 이름 있는 새 사본을 생성하며 예전 저장본은 덮어쓰지 않는다. 목록은 현재 계정·지점만 조회하고, 시간표 전체 JSON 대신 요약 20개씩 읽는다. 세부 내용은 불러오기나 비교를 누를 때 읽는다. 저장 실패·잘못된 형식·오래된 화면의 불러오기는 현재 편집을 유지한다.

현재 편집안과 저장본, 또는 저장본 두 개를 강사뷰/통합뷰로 나란히 비교한다. 추가·삭제·시간·강사·강의실·이름·명단·색의 차이를 아래 목록에 표시한다. 비교용 두 Store는 읽기 전용이며 Undo나 Delete가 원래 편집을 바꾸지 않는다.

원격 DB 적용 및 실제 RLS 검증은 [저장 API 결과](draft-storage-results.md)에 기록했다. 브라우저 저장 테스트는 합성 응답으로 실행했다. 실제 사용자 로그인 세션의 전체 왕복을 검증했다고 주장하지 않는다.

## 성능

합성 1,200개 배치·4,800명 순수 알고리즘 실측:

| 작업 | 이전 | 변경 후 |
|---|---:|---:|
| 충돌 검사 | 78ms | 53ms |
| 추천 후보 탐색 | 4,137ms | 84ms |
| 편집 20회 이력 보관 | 945ms | 56ms |
| 같은 명단의 보관 객체 | 40벌 | 1벌 |

요일·자원별 색인으로 관련 수업만 비교한다. 추천은 최종 세 후보만 복사하고, 이력은 불변 상태에서 변경 경로만 보관한다. 순서·ID/이름 혼합·자습 자리 예외를 포함해 기존 알고리즘과 같은 결과인지 검증했다. 통합뷰는 반별 색인을 재사용하며 학생을 끄는 동안 이름표·놓을 반의 테두리만 갱신한다. 보관함·비교·검증 라이브러리는 필요할 때 로드한다. 이 수치는 전체 브라우저 렌더 시간이나 운영 자료 실측이 아니다.

## 검증과 남은 범위

아래는 마지막 수정(회의 시간 폼, 응답 지연 문구, 감사로그, 마이그레이션 개명)까지 넣은 뒤 다시 돌린 결과다.

- 실험 단위 테스트 42개(6파일) 통과. 새 기능과 기존 두 뷰의 브라우저 테스트 21개(`editing`·`library`·`native`·`views`) 통과. 반 합치기/나누기/학생 이동/시간 변경의 Undo, 지점 원본→저장→이동색 복원, 잘못된 저장본 보존, 비교 읽기 전용, 운영시간 밖 회의의 시간 변경을 확인했다.
- 브라우저 테스트 전체는 처음에 38개였고 두 번 돌려 36개·37개 통과였다. 실패한 것은 매번 달랐다(1차: Univer 이름 상자 2개, 2차: 페이지가 준비되기 전에 접근한 1개). 셋 다 이전 단계(P0 엔진 비교) 테스트였다. 원인은 준비 전에 입력이 들어가는 것이라, 이름 상자 입력은 준비될 때까지 다시 시도하고 `labProbe`는 생길 때까지 기다리게 고쳤다. 그 뒤 **전체 39개(Ctrl+S 테스트 1개 추가)가 세 번 연속 한 번에 통과했다.**
- 반 합치기·나누기 창이 열린 채 Ctrl+S를 누르면 보관함이 겹쳐 뜨던 것을 막았다. 열린 창을 먼저 닫으라고 알린다.
- 루트 `pnpm build` 통과(새 API 라우트 3개 포함).
- 저장 API·검증·조회 단위 테스트 30개(4파일), 원격 PostgreSQL pgTAP 33개 통과.
- 담당 과목 기본 선택 11개(2파일), 시간표 기능 폴더 전체 1,237개(103파일) 통과. 명시 URL 과목은 우선하며, 직원별 기본값이 달라도 링크는 선택한 과목을 유지한다.
- 루트 TypeScript(8GB, 메모리 부족 없이 종료 코드 0), 실험 TypeScript/프로덕션 빌드, 변경 파일 51개 ESLint 통과.- 루트 전체 테스트는 끝까지 돌렸다: 1,322파일 중 1,316 통과, 15,504개 중 15,496 통과. 그날 main의 새 커밋을 합친 뒤 다시 돌린 결과는 1,333파일 중 1,328 통과, 15,619개 중 15,612 통과다. 처음 실행의 실패 6파일·8개는 [인계·마무리 기록](CLAUDE-HANDOFF-2026-10-02.md)에 원인 커밋과 함께 적었다. 네 파일은 main에 이미 들어온 다른 작업이 원인인 고정 실패, 한 파일은 흔들리는 테스트이고, 마이그레이션 이름 가드 하나는 이 브랜치 파일도 걸려 있어 규약 이름으로 바꿨다(main의 파일 두 개 때문에 그 가드는 여전히 실패한다).
- 스크린샷으로 확인 패널·이동색·나란히 비교의 배치를 확인했고 비교 내부 카드가 세로로 쌓이던 CSS 선택자 범위를 수정했다(Codex 단계).
- 운영 화면 우측 도구줄의 ‘시간표 편집기’ 버튼은 이후 앱 통합 단계에 연결한다. 현재 편집기는 별도 로컬 실험 화면이다. 기본뷰·수학·전체 Sheets 단축키·출결까지 포함한 운영 반영은 다음 단계다.

자가 적대리뷰와 별도 코드 리뷰에서 과거 클립보드의 명단 복구, 드래그 중 변경, 이력 객체의 삭제 키, 비수업 일정의 운영시간 확장, 비교 CSS 누출, 개발 서버의 지연 의존성 재로딩을 점검하고 수정했다.
