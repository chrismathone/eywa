- **super_admin은 새로 만드는 어떤 제한 명단·게이트도 자동 통과한다** (원장 2026-08-13: *"superadmin은 앞으로 뭘 안해도 그냥 넣고봐. 명시"*). 권한 매트릭스(`perm-matrix`)가 이미 super_admin을 우회시키는 것과 같은 결이다 — **새 게이트를 만들 때 명단만 두고 super_admin을 빼먹지 말 것**(총괄이 자기 시스템에서 잠긴다). 판정은 [`isCurrentUserSuperAdmin()`](src/lib/auth/super-admin.ts)(요청 캐시, 경량). 선례 = [`canViewPayslipNow()`](src/features/payroll/server/payslip-gate.ts) — 하드 픽스 명단 **또는** super_admin.

- **super_admin 계정의 역할·재직 상태·삭제는 앱에서 못 바꾼다 — 운영자 스크립트 + 원장 명시 승인만** (원장 2026-09-30: *"이승엽 superadmin 으로 등급업. 겉으로는 관리자. 박소선과 동일."* → *"다음에 이런 일이 있어도 변경 안되게 강력 가드. 꼭 물어봐야하는걸로"*). 🔑 보호 대상 = **`super_admins` 명단에 있는 계정 전부**(이름을 코드에 적지 않는다 — 새 총괄은 자동 보호). 지금 둘(박소선·이승엽)은 실제 역할 master + 화면 표시 '관리자'(`displayRoleFor`). 🔴 **행위자가 누구든**(원장·다른 총괄 포함) 거절한다 — 비밀번호·이메일 보호선(`isProtectedSuperAdminTarget`, 총괄끼리는 허용)보다 강하다. 앱 문 = [`protected-accounts.ts`](src/lib/auth/protected-accounts.ts)(`refuseIfProtectedStaff` — 역할 변경·퇴사·인계 후 퇴사·삭제, 총괄 콘솔 역할·활성, 거절 시도는 감사로그 `staff_protected_refused`/`protected_account_refused`), 엑셀 직원 가져오기는 총괄 행을 원래 건너뛴다. DB 마지막 선 = 0309a 트리거(users·auth.users·super_admins, 값이 실제로 바뀔 때만 · 우회 `set local app.allow_protected_change = 'on'`). 🔴 **지점 화면 문구(거절 메시지·안내·감사로그 요약·DB 예외)에 '슈퍼관리자'·'총괄'을 쓰지 않는다** — '보호된 계정'이라고만(위장 결정 2026-07-02, 총괄 콘솔만 예외). ⚠️ 명단 조회 실패는 막되 '보호 계정'이 아니라 '잠시 뒤 다시'로(거짓 거절 기록 금지). DB는 명단·users 통째 비우기도 문장 트리거로 막는다. 🔴 AI 세션도 이 두 계정의 역할·상태·명단을 **조용히 바꾸지 말고 반드시 먼저 원장에게 물을 것**. 가드 = `protected-accounts.test.ts`.

- **전자결재 = 양식 중립 문서 껍데기 + 양식별 상세, 결재선은 순차** (원장 2026-08-14: *"전자결재 페이지를 만들자. 그중에 휴가를 먼저 사용하는 느낌으로"*, 0212a). 그룹웨어 표준 구성 그대로 — **기안 → 순차 결재선 → 결재대기·상신함·완료함**. 표는 `approval_documents`(문서번호·양식·상태·**current_step**) + `approval_steps`(결재란 한 칸) + 양식별 상세(`leave_forms`). 🔑 상세를 jsonb로 뭉치지 않은 이유 = 잔여 연차가 **일수 합산**이라 컬럼이어야 세고 거를 수 있다(B2). 새 양식(지출결의서 등)은 **상세 표 + 폼만** 더한다 — 문서 껍데기를 양식별로 복제하지 말 것. 결재 자격의 근거는 명단이 아니라 **동결된 결재선 + current_step**(내 차례일 때만), 회수는 아무도 결재하지 않았을 때만. 🔴 **파일럿 = 이승엽·김예원·엄소윤 + 테스터 계정**([`access.ts`](src/features/approvals/access.ts), `MENU_ACCESS.approvals` 기본값 전원 none — 엄소윤은 2026-09-18 원장 추가 지시) — 열 때는 명단을 늘리는 게 아니라 **기본값을 올린다**. ⚠️ 옛 `/leave` 전용 화면과 `leave_requests`·`leave_approvals`(0210a·0211a)는 **폐기**했다(0행) — 되살리지 말 것. **v2(0213a, 원장 "하이웍스 기준으로")**: 결재함 6종(대기·예정·진행·완료·반려·참조) + 기안 화면 **결재선 편집기**(순서 조정·서버 재검증 `line.ts`) + **자주 쓰는 결재선**(`approval_line_templates`, 개인 upsert) + **참조**(`approval_refs`, 열람만·종결 알림). **v3(0216a, 2026-08-18)**: 양식 = 휴가·품의·지출·**수입**(업무연락 폐기 — 재도입 금지) + **전결**(`final`, 즉시 종결·남은 칸 `skipped`) + **후결**(`deferred`→`post_approved` — 다음 사람이 넘기고 부재자는 사후 확인만, 사후 반려 없음) + **대결**(`acted_by`, v1 권한 = master). 지출·수입결의서는 /billing 장부와 **별개**(재무 집계에 안 닿음 — 통합은 추후 결정). 🔴 결재자·참조 후보 풀 = **활성 직원 전원**(원장 재지시 2026-08-14 *"테스트를 둘이 하는 거지, 결재자랑 이런 건 직원들 다 있어야지"* — 파일럿 명단은 **메뉴 노출만** 정한다). 그래서 결재 처리·회수·문서 열람 게이트는 **메뉴를 보지 않는다**(로그인 + 동결된 결재선/기안자 판정 + RLS) — 명단 밖 직원도 벨 알림 링크로 들어와 결재한다. 기안·템플릿만 메뉴 게이트(파일럿 2명). 기본 결재선은 없다(매번 지정 또는 자주 쓰는 결재선). 합의·수신·회람·임시저장은 범위 밖(필요 시 kind 확장).

- **연차 조정 = 법정 부여 위에 얹는 행 · 자리는 직원관리 · 권한은 명단 3인** (원장 2026-09-08: *"관리자랑 김예원이 직원들의 연차갯수를 조정해야하는데 해당 기능이 없음"* → *"여기서 관리자는 박소선 이승엽 김예원임"*, 0252a). 🔑 **자리 = `/staff/annual-leave`**(직원관리 머리 '연차 관리' 버튼) — 원장 2026-09-09 *"직원관리에 버튼 연동해주지 전자결재에 있는게 연차를 관리하는게 이상하자나"*(처음엔 전자결재 안에 뒀다가 옮겼다). **휴가 신청·결재는 전자결재, 연차 부여 일수는 직원 정보**라 자리가 갈린다(2026-08-25 *"휴가는 전자결재에서 관리"*와 충돌 아님 — 그쪽은 신청·결재). 🔴 **전자결재로 되돌리지 말 것.** 게이트는 [`canAdjustLeave`](src/features/leave/access.ts)(박소선·이승엽·김예원 + super_admin) — 셋 다 직원관리 접근이 이미 있어 **메뉴를 새로 열지 않는다**(직원관리를 보는 다른 데스크 직원에겐 버튼이 안 보인다). 이월·특별휴가·중도 정산처럼 **법이 아니라 사람이 정하는 몫**만 `leave_adjustments`(직원 × 연차 구간 × 가감 + 사유 + 기록자)에 담고, **부여 계산은 그대로**다(위 항목 — 입사일에서 도출). 🔴 **덮어쓰기가 아니라 행 누적** — 총 일수를 값 하나로 저장하면 왜 바뀌었는지가 사라지고 두 사람이 같은 사람을 동시에 고칠 때 뒤엣값이 앞엣값을 조용히 삼킨다. 화면은 *"총 18일로"*도 받지만 **저장은 언제나 차이 한 줄**이고, 구간·현재값은 **서버가 다시 계산**한다(오래된 화면이 남의 조정을 덮지 않게). 🔑 잔여 산식 단일 소스 = [`balance.ts`](src/features/leave/balance.ts)(잔여 = 법정 + 조정 − 사용 − 결재중) — 세 표면(내 연차 현황·기안 잔여 거절·관리자 표)이 같은 함수를 지난다. 문서 동결값 `granted_days`도 **조정 포함 총 부여**(법정분만 적으면 "부여 15일인데 18일째 사용"이 된다). 🔴 **자격 판정은 한 함수**를 화면·서버 액션이 함께 지난다([[#77]]) — 결재 파일럿 명단과 **일부러 분리**(테스터가 실직원 연차를 고치면 안 된다). 🔴 **이미 사용·결재중인 일수 아래로는 못 내린다**(내리면 잔여가 음수인데 화면은 0으로 가려 "다 썼다"처럼 보이고 승인된 휴가는 그대로 남는다) · 사유 필수 · 두 액션 모두 감사로그(`leave_adjust`·`leave_adjust_delete`). 🔴 **구간 귀속은 저장된 창의 '중앙 날짜'로**([`leaveRowMatchesPeriod`](src/features/leave/balance.ts)) — 시작일 일치로 보면 **입사일을 정정하는 순간** 구간 경계가 밀려 조정이 어느 구간에도 안 붙어 화면에서 사라지고(지울 수도 없다), 같은 이유로 `leave_forms`의 '사용'이 0으로 리셋돼 **이미 쓴 연차를 한 번 더** 쓸 수 있었다(0212a부터 있던 결함, 함께 수정). 🔴 **'창이 구간 시작일을 품는가'로 되돌리지 말 것** — 입사일을 앞으로 당겨 정정하면 그 줄이 **다음 해 구간에 유령으로 붙어** 내년 잔여를 깎는다(적대 리뷰가 반증). 중앙 날짜는 정정 방향을 안 가리고 구간이 안 겹쳐 **한 줄이 두 구간에 붙는 일이 원리적으로 불가능**하다. SQL은 겹침으로 넓게 받고 판정은 순수 함수 한 곳에서. ⚠️ 단 입사일을 **반년 이상 뒤로** 정정하면 그 줄이 다시 안 보인다(실측 +7~+11개월) — 종전은 어떤 정정에서도 그랬으니 폭이 좁아진 것이고 틀린 숫자를 만들지는 않는다. 더 줄이려면 구간 키를 근속 연차로 바꿔야 한다(별건). ⚠️ 조정은 **현재 구간**에만 넣는다(다음 구간 이월 예약은 없다 — 구간이 바뀐 뒤에 적는다). ⚠️ 관리자 표는 재직자만 세운다(퇴사 후 발견된 잘못된 조정은 화면에서 못 지운다). ⚠️ 삭제는 재직·입사일을 요구하지 않는다(퇴사자의 잘못 적은 행을 영영 못 지우면 막다른 길). ⚠️ 0252a는 `leave_forms.days`·`granted_days`를 `numeric(5,2)`로 넓힌다 — 옛 `numeric(4,1)`이 **반반차 0.25를 0.3으로 반올림**해 저장하고 있었다(0223a가 종류만 열고 정밀도를 안 넓힌 자리).

- **연차 부여 = 입사일에서 계산, 저장하지 않는다** (원장 2026-08-14). 법정 기준(1년 미만 월 1일·최대 11 / 1~2년차 15 / 3년차부터 2년마다 +1·최대 25)을 [`accrual.ts`](src/features/leave/accrual.ts) 순수함수가 도출한다 — 적립 행을 쌓으면 매달 배치가 필요하고 한 번 빠지면 그 사람만 조용히 틀린다. ⚠️ ~~이월·특별휴가 같은 수기 조정은 표현하지 못한다~~ → **✅ 해소(2026-09-08, 0252a)**: 조정 행(`leave_adjustments`)을 더해 **부여 = 법정 + 조정**으로 확장했다(아래 '연차 조정' 항목). 잔여 초과 기안은 **행이 만들어지기 전에 거절**(*"자동반려 필요없고 잔여없으면 신청 자체를 못하자나"* — 자동반려 상태·컬럼은 폐기, **재도입 제안 금지**). 차감 일수는 **일요일만 제외**(학원이 토요일을 운영한다 — 규칙은 `countLeaveDays` 한 곳). 🔴 옛 `staff_leaves`(직원관리 '휴가 관리', 0행)와 **일부러 분리** — 운영실 '오늘 할 일' 시그널이 거기 물려 있어 테스트 기안이 원장 화면에 뜨면 안 된다. 파일럿 종료 시 반드시 통합(절차는 0210a 주석).
