2026-10-22. 원장이 확정한 Claude 3차 최종 검토와 [D1~D8 결정](../decisions/student-ontology.md)을 구현한다. 이후 원장의 전체 집계 실행 요청에 따라 저장 구조와 최초 집계를 적용했다. 소개 백필·main 푸시·배포는 실행하지 않았다.

설정·월 원래 수치·긍정 신호의 세 표는 RLS를 켜고 정책을 두지 않는다. 브라우저 DB 역할로는 조회·변경할 수 없다. 서버 게이트는 새 메뉴와 수납 권한, 시범 지점, 실험실 동의를 확인한다. 설정·재집계·연결·판정 변경은 원장 권한과 쓰기 가능 여부를 다시 확인한다. 학생 원본 기록에는 기존 담당 범위도 적용한다.

월마다 원래 수치만 저장하고 총점은 조회 시 현재 배점을 적용한다. 마감 뒤 바뀐 청구·환불·소개·병합·판정은 이번 달 정정이다. 처음 집계가 중단되면 저장한 마감 행을 보존하고 이어서 복원한다. 동시에 두 작업이 집계하거나 집계 중 배점이 바뀌지 않도록 작업 토큰과 설정 버전을 검사한다. 이미 마감한 행은 SQL 트리거로 수정·삭제를 막는다.

병합은 원본 학생 ID와 마감 기록을 보존하고 살아남은 학생의 정정으로 반영한다. 과거 청구도 매 집계 때 연결된 원생번호만 청크·페이징으로 다시 읽어, 옛 청구 수정과 학생 연결 보완을 반영한다. 현재 휴원 표식을 지난 출결 전체에 소급하지 않는다. 정규 일정의 출결 입력이 모두 확인된 달만 개근으로 인정하며, 과거 휴원 구간은 별도 기록이 없다는 한계를 화면에 적는다.

## 화면 재설계와 온톨로지 참고 자료

원장 요청으로 Claude Haiku 5.5 / medium과 설계를 검토했다. 회의 기록은 `work/student-contribution-design-meeting.md`다. 전 탭에서 중앙 최대 폭 제한을 제거하고, 숫자·점수는 우측 정렬했다. 목록은 10·20·50명, 원본 기록은 10건, 긍정 신호는 8건, 소개 확인은 15건, 연결 학생은 15명, 연결 대상은 8개씩 나눈다. 정정은 원래 달의 묶음을 유지해 6개월씩 표시한다. 이 분할은 브라우저 표시 범위이며 DB 조회 자체를 서버 페이지 방식으로 바꾼 것은 아니다.

학생 상세는 누적 요약 → 현재 배점 기준 추이·항목별 계산식 → 월별 실적과 정정 → 원본 근거 순서다. 그래프는 만점이나 평가 등급을 만들지 않으며, 과거 시점에 확정된 점수가 아니라 현재 배점으로 다시 계산한 값임을 밝힌다. 배점 설정은 `/student-contribution/settings`에서도 같은 게이트로 열리며, 저장 전·후 전체 점수와 변화량을 표시한다. 인정 기준의 재판정 결과는 미리보기 범위에 포함하지 않는다.

다음 공식 자료를 확인해 객체 선택 → 연결 탐색 → 근거 확인 흐름에 반영했다.

- [Palantir Ontology 개요](https://www.palantir.com/docs/foundry/ontology/overview): 객체·속성·연결·행동 모델을 참고했다. 학생/반/강사/과목/학원을 관점으로 제공하고, 기존 권한을 지나는 원본·설정·검토 동작으로 이어진다.
- [Object Explorer 차트 탐색](https://www.palantir.com/docs/foundry/object-explorer/explore-charts): 그래프 선택으로 목록을 좁히는 방식을 기록 종류 필터에 적용했다.
- [W3C PROV-O](https://www.w3.org/TR/prov-o/): 출처 추적 개념을 참고해 발생 시점·확인 시점·원본/규칙/AI 판정·근거 링크를 구분했다. RDF/OWL 호환 저장소를 새로 도입한 것은 아니다.
- [Neo4j Bloom 공식 영상 안내](https://neo4j.com/videos/exploration-from-bloom-canvas-video-3-in-bloom-series/)와 [Palantir 공식 개요 영상](https://www.youtube.com/watch?v=YDAxITCNcko): 공식 게시 설명과 관련 문서를 확인했다. 영상 전체 재생이나 자막 전수 검토를 완료했다고 간주하지 않는다.

온톨로지 연결은 같은 원본 사실의 `related`에서 확인된 대상만 보여 준다. 학생 집합이 겹친다는 이유로 반·강사 관계를 새로 추론하지 않는다. 학원 전체는 원본 사실 ID로 중복 제거하고, 여러 과목의 금액을 임의 배분하지 않는다. 현재 범위는 기여도에 연결된 기록이며 학원의 모든 도메인이 연결됐다는 뜻은 아니다.

최종 화면 검토는 `work/student-contribution-ui-final-review.md`에 남겼다. Claude가 지적한 학원 자체 연결 0 표시, 소개 확인 용어, 배점 미리보기 설명을 반영했다. UI·페이지네이션·창 안 이동 10개와 관계 투영 2개 테스트, 변경 파일 린트, 의존성을 포함한 범위 타입 검사가 통과했다. 네 탭과 학생 상세를 브라우저에서 확인했고, 학생 목록 다음 페이지와 탭 전환도 실제로 동작했다. 900px 설정 화면에서 가로 넘침이 없음을 확인했다. 탭·상세·원본 링크는 기존 `EmbedLink`로 창 모드를 유지한다. 내장 브라우저의 한 탭에서 화면 갱신이 멈춘 현상은 새 미리보기 탭에서 해소됐으며 앱의 공통 창 구조는 변경하지 않았다.

## 탭 이동 성능 점검 (2026-10-22)

점검 범위는 기여도 목록·학생 기록 연결·지난 소개 확인·배점 설정, 학생 상세·월 이동이다. 운영 DB는 읽기 전용으로 조회했다. 집계·소개 연결·마이그레이션을 실행하지 않았다.

인증된 로컬 Next 개발 서버에서 같은 `embed=1` HTML 요청을 비교했다. 변경 전 두 번째 요청과 변경 후 준비 요청을 제외한 두 요청의 중앙값이다. 개발 서버·네트워크 편차가 있으며 운영 배포 속도를 뜻하지 않는다.

| 탭 | 변경 전 | 변경 후 | 확인한 병목과 조치 |
| --- | ---: | ---: | --- |
| 원생 기여도 | 1.97초 | 0.84초 | 학생별 수강 배열 반복 탐색을 인덱스로 교체, 작은 실적 합계를 재사용 |
| 학생 기록 연결 | 7.39초 | 1.32초 | 불필요한 전체 점수 RPC·학생 중복 조회 제거, 사실만 조회, 권한 범위별 요약 캐시 |
| 지난 소개 확인 | 1.95초 | 0.90초 | 학생 선택에 필요 없는 전체 점수 RPC 제거 |
| 배점 설정 | 1.46초 | 0.69초 | 학생별 실적 대신 합계·인원만 전달, HTML 응답 약 708KB → 116KB |

- 학생 상세는 모든 달의 수치·정정 요약을 읽고 선택한 달의 근거만 추가로 읽는다. 표본의 DB 응답은 355,029 → 64,928바이트(약 82% 감소)다. 월별 수치·정정 사유와 선택한 달의 사실이 기존 결과와 일치했다. 상세 준비 후 요청은 0.81~0.86초, 지난 달 전환은 0.86~1.83초였다. 작은 표본에서는 추가 왕복 때문에 DB 시간 자체가 일관되게 줄지는 않았다.
- 온톨로지 DB 응답은 월 전체 payload 9,727,811바이트에서 facts 투영 6,571,531바이트로 줄였다. 7,396개 사실·456개 관점의 결과는 793,950바이트로 캐시 한도 안이다. 원본 본문의 충돌 검사는 같은 ID가 재등장할 때만 수행해 관점별 반복 직렬화를 없앴다. 직접 계산은 변경 전 약 1.39초, 변경 후 표본 0.25~0.41초였다.
- 점수 RPC는 100명씩 병렬 조회를 유지한다. 781명을 하나의 RPC로 합친 실험은 약 6.06초로, 기존 병렬 조회 약 0.45초보다 느렸다. 원본 사실의 100명 분할 조회 실험은 DB 읽기가 0.56초에서 0.33초로 줄었으나 요청이 1개에서 9개로 늘어 채택하지 않았다.
- 각 하위 경로에 로딩 경계를 두고 클릭한 탭에 즉시 진행 상태를 표시한다. 실제 클릭에서 표시까지 5~14ms였고, 네 탭 모두 `embed=1`을 유지했다. 점수 SVG·표 페이지네이션·관점 선택은 클라이언트에서 동작하며 별도 AI 호출이 없다.

캐시 대상은 실적 합계와 권한 필터를 거친 관점별 요약뿐이다. 권한·학생 병합·대상 원생·담당 범위는 매 요청 확인한다. 학원·월·집계 버전과 현재 병합/대상/열람 범위를 캐시 키에 넣고 60초 재검증을 둔다. 수동 집계와 밤 배치는 부분 실패까지 포함해 `finally`에서 즉시 만료한다. 개인별 허용 예외·수납 권한·원본 열람 범위는 유지한다. 배점 설정은 캐시하지 않으므로 저장한 배점을 즉시 적용한다.

남은 비용은 처음 여는 달의 원본 읽기와 관점별 요약 생성이다. 캐시가 없던 2026-09 연결 화면은 4.36초, 두 번째는 1.47초였다. 학생 목록·소개 확인도 로컬 필터를 위해 전체 작은 목록을 전달한다. 새로운 DB 요약 표를 만들거나 모든 필터를 서버 페이지네이션으로 바꾸는 작업은 이번 변경에 포함하지 않았다.

변경 파일 린트, 영향 범위 타입 검사, 권한·캐시 분리·집계 후 만료·병합 학생의 월별 점수·원본 범위·중복 사실·배점 미리보기·페이지네이션 테스트를 확인했다. 측정 원본은 로컬 `work/contribution-perf-baseline.json`, `work/contribution-perf-after.json`, `work/contribution-route-after.json`에 있다. 2026-10-22 원장이 성능 개선분의 운영 배포를 승인했다.

배포 전 적대적 리뷰에서 요약 조회와 선택 월 근거 조회 사이에 집계가 갱신되면 수치와 근거의 저장본이 달라질 수 있음을 발견했다. 선택한 달은 두 번째 조회에서 수치·정정·상태·근거를 함께 읽도록 보완했고, 조회 중 수치가 바뀌는 사례와 병합 전 원생에게만 있는 달의 점수 중복 방지 테스트를 통과했다. 권한별 캐시 분리·부분 집계 실패 시 만료·현재 배점 재계산·창 안 이동을 재검토했으며 추가 배포 차단 사항은 없다.

## AI 키

학생 연결과 수치 집계는 AI 키 없이 동작한다. 학부모 글과 에이와에서 보낸 선생님 답글의 관찰된 긍정 신호 판정만 AI를 쓴다.

환경변수는 `ANTHROPIC_API_KEY_STUDENT_ONTOLOGY` 하나다. 원장은 로컬 입력과 Vercel 등록을 완료했다고 확인했다. 로컬에서는 값 노출 없이 등록 여부만 확인했다.

Claude `fast` 티어(현 레지스트리 Haiku 5.5), 추론 강도 `low`로 시작한다. 원장의 Claude만 사용 지시에 따라 `allowedProviders: ["anthropic"]`로 다른 회사 폴백을 차단한다. 전용 키가 없는 환경은 새 판정을 대기한다. 기존 기능의 기본 키·공통 폴백 동작은 유지한다. 사용량 키 이름은 `student_ontology`다. 키 값은 코드·문서·로그에 쓰지 않는다.

밤 배치에서 문구 후보를 먼저 거르고 AI를 호출한다. 저장된 판정은 원문이 바뀌어도 자동 재호출하지 않으며, 원문 변경은 계산 전으로 표시한다. 명시 재판정 요청만 다음 밤에 처리한다. 취소 기록은 재판정 뒤에도 보존한다. `ai_analysis` 라이선스가 없으면 새 판정을 실행하지 않는다.

한 번의 판정은 남은 AI 배치 예산과 45초 중 짧은 기한으로 실제 SDK 요청을 중단한다. 실패한 글은 판정 완료로 저장하지 않고 다음 밤의 대기 대상으로 남긴다. 지점 선택 모델이 있어도 Claude 제공자 제한을 벗어나지 않는다.

## 승인 후 적용 순서

1. 위 마이그레이션 두 개를 번호순으로 적용하고, 서버 전용 표·RLS·마감 트리거·집계 RPC를 확인한다. 앱 배포보다 먼저 적용한다.
2. 침산 실험실 동의와 원장 계정에서 목록·상세·설정의 두 권한을 확인한다. 다른 지점과 읽기 전용 보기는 설정·재집계가 차단되어야 한다.
3. 백필 드라이런을 다시 실행해 자동·확인·불가 건수와 자동 표본을 원장에게 보고한다. 승인된 보고서 지문, 원장 ID와 함께 적용 스크립트를 실행한다. 원본이 바뀌어 지문이 다르면 다시 검토한다.
4. 백필은 자동 통과 행만 연결한다. 기존 연결을 덮지 않고 연결별 감사로그와 `work/student-contribution-referral-rollback-*.json`을 남긴다. `prepared` 상태 파일은 커밋 여부를 감사로그와 대조한 뒤 판단한다. 확인 목록은 퇴원생 검색과 확인 근거 입력으로 수동 연결한다.
5. **현재 달 직원 포트폴리오도 같은 소개 연결을 읽으므로 점수가 바뀔 수 있다.** 백필 실행 전에 이 영향을 원장에게 알린다. 직원 포트폴리오 마감 달은 보존된다.
6. 첫 집계 후 수업료 월합·소개·활동·과거 마감·정정·운영/활동 비율을 표본 대조한다. 첫 집계가 부분 완료되면 다음 실행에서 이어간다. AI 판정과 일일 cron의 실제 실행·저장도 이 승인 단계에 속한다.
7. main 푸시와 배포는 원장이 승인한 범위에서만 진행한다.

## 재현 명령

환경변수 파일은 실행자가 정한다. 다음 읽기 전용 명령은 현재 기본 체크아웃의 파일을 사용했다.

```powershell
node --env-file=D:/eywa_refactoring/.env.local scripts/student-contribution/audit.mjs
node --env-file=D:/eywa_refactoring/.env.local --import tsx scripts/student-contribution/billing-preview.ts
node --env-file=D:/eywa_refactoring/.env.local --import tsx scripts/student-contribution/backfill-dry-run.ts
```

Vitest는 `src/features/student-contribution`, `src/features/students/ontology`, 공용 수업 시작 판정·성적 정규화·권한 메뉴·AI 키 그룹 및 제공자 제한의 영향 범위만 실행한다. 최초 영향 범위 26파일·174개, 이후 Claude 전용 연결과 정정 보완 6파일·98개, 요청 중단 전달 2파일·64개, 과거 담당 근거 조립 1파일·8개가 각각 통과했다(재검증 범위는 중복되므로 합산하지 않는다). 변경 파일 린트와 의존성을 포함한 범위 타입 검사도 통과했다.

SQL은 네트워크 DB를 쓰지 않고 PGlite 메모리 인스턴스에서 RLS·정책 0개·역할 차단·다른 지점 학생 차단·마감 보존·정정 합계·작업 토큰 등 19개 검증을 통과했다.

```powershell
npm install --prefix work/student-contribution-sql-check --no-save @electric-sql/pglite
node scripts/student-contribution/verify-sql.mjs
```

함께 실행한 Slack 카탈로그 검증에서 기존 분류 누락 4개(`todays_math_menus_update`, `math_textbook_assign`, `math_book_target`, `school_exam_periods`)가 확인됐다. 이번 기능의 감사 액션 6개는 별도 분류되어 있으며 외부 메시지 대상으로 내보내지 않는다. 기존 누락은 이 기능 변경에서 수정하지 않았다.
