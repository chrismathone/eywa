- v2와 v3를 단어 단위로 비교했다. 고쳐진 줄은 v3 기준 1·31·35·39·69·105·129·133·141·143·149행의 11곳이고 107행(P0 보완 항목)이 새로 생겼다. 나머지는 같다.

- 하지 않은 것: 함수 실행, 운영 데이터 조회.

## G1 코드 대조와 내 이전 보고서의 정정

39행의 서술은 코드와 맞다. `0267a` 14~38행에서 `confirmed_sessions`가 없으면 기준을 `attendance_units`로 보고, 그 기준이면 `session_units` 합을, 아니면 출석 날짜 수를 돌려준다. 이 함수를 정의한 마이그레이션은 0103a·0115a·0198a·0263a·0267a뿐이고 0267a가 마지막이다. `quantity_basis`를 다시 건드린 마이그레이션도 없다. "확정된 채 기준이 비어 있는 호환 행"이라는 표현은 DB 칸이 `not null default 'days'`라 실제로는 생기지 않지만, 앱이 빈 값을 days로 읽는 호환 처리(`class-billing.ts:207`)와 맞으므로 틀린 서술은 아니다.

내 1차 보고서와 v2 검토는 청구 회차를 "0263a의 출석 날짜 수"라고 적었다. 이는 0267a를 놓친 것이다. "분할 보강이면 2회 소비"와 "보충 지도는 그날 1회"는 days 기준으로 확정된 행에만 맞고, 미확정 행과 새 확정 행은 시수 합이다. Grok의 지적이 옳고 v3가 바로잡았다.

## 문장 사이 교차 검토

수정으로 새 모순이 생겼는지 아래를 따로 봤고 문제를 찾지 못했다.

1. 18행 "실제 출결/보고서 저장 때 모두 검사"와 97행 표의 "허용되지 않는 당일 결합 차단"은 그대로 남아 있다. 31행의 둘째 문장이 조건 없이 "정규 출결의 상태와 정규 시수 저장은 … 거절하거나 되돌리지 않는다"고 못박고 141행이 이를 차단 조건으로 두었으므로, 두 문장은 보강 효과를 막는다는 뜻으로만 읽힌다.
2. 31행 "보강값은 그날 출결 저장 때 한 번 기록된다"와 35행 "수기값이 없을 때만 기록한다"는 31행의 "기존 규칙대로"가 수기 예외를 포함하므로 맞물린다. 재반영 때 이미 값이 있는 칸은 35행에 따라 더하지 않고 검토 큐로 간다. 두 번 더해질 길이 없다.
3. 105행 충돌 (1)은 같은 날 정규+보강(조합 표 넷째 줄)과 맞는다. 보강 구간이 그 학생의 정규 수업 시간과 겹치면 거절이고, 앞뒤로 붙으면 허용이다.
4. 69행의 쓰기 허용 판정은 보충 지도 문단 안에 있다. 원결석이 있는 건은 종전처럼 예약 행이 게이트를 연다. 93행의 "native 어댑터 필수 구현"과도 맞는다. 구현은 하되 확정은 P0 결정 전까지 닫는다.
5. 129행과 §6의 켜짐 / 정리 중 / 꺼짐 설명이 일치한다.

인접 산출물도 계획의 서술과 같다. `수용테스트_단계매핑.csv`는 81행 전부 미실행이고, `추가수용테스트.csv`는 19행 전부 미실행이다. 추가 기준 MU-X16~X19가 C1·C2·C3·G2를, MU-X11이 G1을 다룬다.

## 비차단 메모 (P0에서 처리)

승인 조건이 아니다.

- 수납 확인 항목을 언제 만드는지가 없다. 39행은 무엇을 보여 줄지만 정한다. 기준별로 조건이 다르다(days면 실시 날짜 수가 원수업과 다를 때, attendance_units면 실시 시수 합이 다를 때, 공통으로 청구월이 달라질 때). P0 산출물에 생성 조건을 적는다.
- 35행의 수기 시수 차이 항목은 31행의 "시수 확인 필요" 항목과 달리 종결을 막지 않는다. 둘 다 급여가 걸린 대사 항목이므로 같은 규칙으로 맞추기를 권한다.
- 보충 지도의 운영 결정이 파일럿 전에 나오지 않으면 예약 확정이 닫힌 채로 출시된다. 그 경우 `수용테스트_단계매핑.csv`의 MU-065와 `추가수용테스트.csv`의 MU-X06은 "확정 거절 회귀"로 다시 분류해야 한다. 지금은 둘 다 파일럿 필수로 적혀 있다.
- 31행의 종결 금지는 한 참여에 케이스가 여럿일 때 그 참여에 배분된 케이스 전부에 적용된다고 명령 정의에 적는다.
