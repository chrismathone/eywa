# 2026-10-26 학부모 설명회와 학생 기여도

## 확정된 운영 원칙

원장 지시로 신청 또는 참석을 학생에게 연결한다. 취소되지 않은 신청은 참석으로 간주하며, 확인된 직접 형제에게도 각 학생의 기여로 인정한다. 같은 학생·같은 행사는 한 번이다. 과거 청구 이력이 없다는 이유만으로 참석을 제외하지 않는다. 2025·2026 연간일정의 명단은 고등수학관 행사를 포함해 인재원 침산 자료로 확인됐다.

이름의 A/B 구분, 전체 휴대폰, 보호자, 학교·학년의 기준 시점, 지점, 원본 위치와 취소 충돌을 대조한다. 전화번호만으로 보호자 이름이 없는 다른 학생까지 형제로 확장하지 않는다. 수동 형제 연결은 직접 연결만 사용한다. 연쇄 확장과 모호한 가구 합치기는 보류한다. 다른 시트에 기록된 과거 행사의 X도 해당 행사와 교차 확인한다. 불참·X의 의미가 확정되지 않으면 취소로 단정하거나 자동 인정하지 않는다.

## 구현한 저장·계산 방식

- 행사, 신청, 불변 원문 버전, 학생별 인정, 가져오기 실행을 분리한다. 최초 가져오기는 승인한 지문과 새 Drive·DB 대조 결과가 같을 때만 가능하다. 운영 DB 반영 전 준비 도구는 읽기 전용이다.
- `parentSeminarEvents`는 운영 기여 지표다. **1회당 1점은 제안이며 아직 원장 확정 배점이 아니다. 기본값은 비활성이다.** 승인이 기록된 명단이 있어야 화면에서 새로 켤 수 있다. 끄기는 항상 허용한다.
- 월마다 원수치를 저장하고 현재 배점으로 계산한다. 이미 마감한 달은 고치지 않는다. 과거 참석 추가·취소는 다음 정상 집계의 열린 달에 정정한다. 모든 인정 집합을 다시 계산하므로 재실행으로 건수가 늘지 않는다.
- 옛 설정과 월 원수치는 새 키가 없을 때만 0으로 읽는다. 기존 키가 누락되거나 값이 잘못되면 오류를 유지한다. 새 마이그레이션은 옛 마감 행을 다시 쓰지 않는다.
- 한 SQL 스냅샷으로 원본과 인정의 같은 시점을 읽는다. 학생 상세는 해당 학생·월, 연결 화면은 해당 월만 읽는다. 조회 실패는 표시 경로에서 격리하고 저장된 점수를 유지한다. 집계 경로에서는 실패시 중단해 허위 차감을 막는다.
- 보류 명단 수를 자료 범위에 표시한다. 일부 명단을 가져왔다는 사실을 전체 확인 완료로 바꾸지 않는다. 학생 개인 화면에 미확정 후보를 노출하지 않는다.
- 행사·출처·가족 식별자는 서버 비밀값으로 만든 HMAC이다. Drive 파일 ID와 연락처를 일반 화면으로 보내지 않는다. 가족 구분 키도 학생 화면에서는 제거한다. 원문 링크는 기존 쓰기 권한을 거쳐 요청할 때만 제공한다. 병합 전 출처 학생 ID는 보존한다.
- 실제 행사 수, 행사별 가족 수, 형제까지 포함한 학생별 인정 수를 구별한다. 학부모 행사에 임의로 과목·반·강사를 붙이지 않는다.

## 이번 반영의 범위와 남은 승인

앱 연결, 최초 가져오기·배치 되돌리기 도구, 드라이런·학생별 영향 보고를 준비했다. 보류 자료의 확인 목록은 원장용 로컬 보고서다. 앱에서 원문을 편집·확정하는 관리 화면, 두 번째 가져오기와 변경·삭제 대조 도구는 이번 최초 반영 범위에 포함하지 않는다. 기존 실행 이력이 있으면 첫 가져오기 도구는 덮어쓰지 않는다. 되돌린 뒤 다시 가져오기도 별도 대조 절차가 필요하다.

2026-10-26 최신 Drive 27개 시트를 다시 읽은 후보는 행사 13개, 학생 30명, 학생별 34건, 행사별 가족 29건이다. 1점/회 가정의 추가 영향은 누적·최근 12개월·이번 달 각각 34점이며 마감 수치는 유지된다. 검토 전의 44건 후보와 중간 32건 후보는 실행 승인 대상으로 쓰지 않는다. 다른 시트의 8월 참석 X와 보호자 정보가 부족한 전화번호 연결 등은 보류하고, 취소가 아닌 전화 확인 표시의 오분류를 바로잡았다. 실행 직전 데이터가 바뀌면 숫자와 지문을 다시 산출한다.

재검토 보완: 같은 날 서로 다른 회차를 저장하고, 이름만 있는 취소 기록도 접미사를 보존해 대조한다. 형식적인 보호자 명칭으로 가족을 확장하지 않는다. 원본을 다시 읽은 시각과 식별 키의 지문을 남긴다. 해당 학원 범위의 미확정 명단은 723행이며 자동 처리 중이라는 표현을 쓰지 않는다. 학생·월을 좁혀도 전체 자료 시작일을 유지하고, 조회 실패 결과는 캐시에 저장하지 않는다.

운영 마이그레이션·가져오기·배점 활성화·재집계는 아직 하지 않았다. 원장이 배점과 드라이런 범위를 승인한 뒤 순서대로 진행한다. 이 기능은 AI 판정이나 학생 요약 생성을 새로 실행하지 않는다.

검토: Claude Opus 5.5 xhigh. 운영 절차는 [실행 안내](../runbooks/student-parent-events.md), 앞선 설계는 [구현 계획](../plans/student-parent-event-contribution.md)을 따른다.

최종 수정 검토에서 실행을 막는 코드 결함이 없음을 확인했다. 관련 Vitest, 변경 파일과 의존성을 포함한 TypeScript·ESLint, 메모리 PostgreSQL의 스키마 33개·실제 가져오기/되돌리기 19개 검사를 통과했다. 이는 운영 데이터 반영 완료를 뜻하지 않는다.

배포 후 실제 배점 화면에서 기존 합계 캐시가 DB 호환 정규화를 건너뛰는 오류를 발견했다. 캐시 버전을 바꾸고 읽은 직후에도 옛 원수치를 정규화한다. 캐시 적중·비변형·기존 항목 오류 거절을 재현 테스트로 잠갔다. 운영 DB 쓰기로 우회하지 않는다.
