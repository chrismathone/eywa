## 이미 확정된 원장 결정

1. 관련 「2025 연간일정」·「인재원 연간일정 2026」의 설명회는 고등수학관 행사를 포함해 인재원 침산 자료다. 다른 지점 자료까지 확장하지 않는다.
2. 신청과 참석을 모두 학생에게 배정하며 **취소되지 않았으면 참석으로 인정**한다. 원본 상태는 보존하고 인정 결과를 별도로 둔다.
3. 형제의 학부모가 참여했어도 해당 학생의 학부모 참여이므로 형제 학생에게도 기여 실적으로 인정한다.
4. 이름·전화번호 등 여러 근거를 대조해 오배정을 막고, 어떤 방법으로도 확정하지 못한 건만 원장 확인 목록으로 남긴다.
5. 상한 없는 누적 실적, 현재 배점으로 과거 실적 재평가, 마감 월 원수치 보존과 이후 정정, 기본 열람 권한과 개인 권한 예외는 기존 정책을 유지한다.

## 조사 범위와 활성화 전 결정

- 원장의 요청대로 Drive에서 찾을 수 있는 설명회 신청·참석 자료 전체를 조사한다. 두 연간일정 파일은 지점이 확정된 우선 대상이다. 그 외 자료는 명시된 지점·행사·원본 근거를 확인해 침산 자료만 연결하며, 다른 지점은 제외하고 지점 미상은 보류한다. 조사 범위를 두 파일로 축소하지 않는다.
- 간담회 등 행사 이름이 설명회와 다른 경우도 행사 목록에 표시해 실제 성격을 확인한다. 안내문·특강 계획만으로 참석 실적을 만들지 않는다.
- 분류·배점은 **운영 기여 / 설명회 1회당 1점 / 상한 없음**을 제안한다. 아직 확정되지 않은 새 배점이므로 자료와 드라이런을 준비한 뒤 활성화 전에 확인한다. 월 최대 1회 제한은 도입하지 않는다.
- 행사 당시 청구·재원 여부는 조사 결과에 구분해 보고한다. 청구 이력이 없다는 이유로 확인된 학부모 참석을 임의로 제외하지 않는다. 등록 전·퇴원 후 사례는 표본과 함께 보여 주고, 별도 제한을 요청받지 않으면 확인된 학생·가족의 참석 이력을 유지하는 안으로 제시한다.
- 이번 범위는 지난 자료 가져오기와 기여도 연결이다. 앞으로의 신규 행사 입력·Drive 자동 동기화는 별도 작업이다.

## 데이터와 연결 단위

- **행사**: 지점·실제 행사일·행사명·회차로 식별한다. 신청서 작성일을 행사일로 쓰지 않는다. 날짜/회차가 불명확하면 보류한다. 같은 행사 명단을 여러 시트에서 가져와도 하나의 행사로 묶는다.
- **원본 신청 행**: Drive 파일 ID, 시트 ID, 원본 상태, 읽은 시각, 내용 해시, 원문 위치를 남긴다. 행 번호는 위치로만 사용한다. 행사·신청자 근거의 안전한 식별 해시와 내용 해시로 동일성을 확인하며, 같은 이름만으로 원본을 합치지 않는다. 행 이동·수정·삭제는 변경 이력으로 보존하고 충돌 시 재검토한다. 이름/전화는 권한 있는 서버에서만 대조하고 작업 로그·보고서에는 마스킹한다.
- **학부모 참석 인정**: 행사와 확인된 보호자/가족 관계를 잇는다. 실제 참석 확인과 ‘취소 없음에 따른 참석 간주’를 구별해 근거를 남긴다.
- **학생별 실적**: `(지점, 행사, 정규 학생 ID)`당 1건. 같은 행사 신청서 중복, 부모 두 명의 신청, 형제 각각의 신청이 있어도 한 학생에게는 한 번만 인정한다. 형제끼리는 각각 1건씩 인정하며 학원 전체 행사 참석 가족 수와 학생 기여 실적 수를 따로 표시한다.
- 학생 병합은 정규 학생 ID로 재연결하고 행사별 중복을 다시 제거한다. 재실행해도 같은 행이 늘지 않도록 유일 제약과 upsert 기준을 둔다.
- 행사 / 원본 신청 및 변경 이력 / 학생별 인정 / 가져오기 실행을 분리한다. 온톨로지 사실 ID는 `parent_event:<행사>:<정규 학생>`으로 두고 가족 참석 키를 별도로 둔다. 형제에게 같은 사실 ID를 재사용하지 않는다.
- 가족 키는 검증된 해당 행사의 가구 단위다. 서로 다른 부모 번호를 가진 같은 가구는 확인된 보호자·학생 관계로 합친다. 단순 번호 개수나 형제 관계의 전이적 연결 덩어리를 가족 수로 쓰지 않는다.

## 자동 연결 가드

다음 조건을 모두 충족한 경우만 자동 확정한다. 근거 강도가 약하면 점수를 넣지 않고 확인 목록으로 보낸다.

1. **자료 범위**: 확정된 지점의 설명회 신청/참석 자료인지 확인한다. 안내문·선물 배부·다른 지점 명단을 자동 참석 자료로 쓰지 않는다.
2. **학생 신원**: 이름의 알파벳 동명이인 표시를 보존한다. 원본에 접미사가 있으면 일치해야 하며, 접미사가 없을 때는 전체 전화와 추가 근거로 후보가 한 명으로 좁혀져야 한다. 이름만 같은 학생을 합치지 않는다. 학교·학년은 당시 날짜와 예비 학년을 고려해 대조한다. 빈 칸과 모순을 구별하고, 기준일을 모르면 임의로 현재 학년을 소급하지 않는다.
3. **연락처·보호자**: 기존 `phoneKeyOf`로 정규화한 전체 휴대폰과 학생/보호자 관계를 대조한다. 끝 4자리, 비슷한 이름, 담임 추정만으로 확정하지 않는다. 학원 공용 번호·자리 채움 번호·중복/재사용 번호·다른 가족과 충돌하는 번호는 자동 연결에서 제외한다. 한 칸에 번호가 여럿이면 각각 대조해 같은 검증된 가구로 모이는지 확인한다.
4. **충돌 확인**: 같은 원본이 다른 학생·가족·행사로도 해석되거나 취소 상태가 충돌하면 보류한다. 재원 상태는 신원 확인 근거이지 과거 참석 자체를 지우는 조건으로 쓰지 않는다.
5. **형제 확장**: 프로필의 기존 `siblingBasis`·`resolveSiblingIds` 판정을 재사용한다. 수동 '형제 아님' 지정과 같은 학생 중복 제외를 우선한다. 직접 확인된 학생의 직접 형제까지만 확장하고, 이름만 같고 전화 근거가 없는 관계나 행사 시점과 충돌하는 관계는 확인 목록으로 남긴다. A→B→C로 연쇄 확장하지 않는다.
6. **학생 이름 없는 학부모 행**: 전체 휴대폰이 지점의 한 검증된 가구에만 연결되고, 적힌 보호자 이름이 일치하며, 수동 형제 해제·다른 가구 충돌이 없어야 한다. 학생 이름 생략을 이유로 무조건 버리지 않되 번호 하나만으로 불확실한 가족 관계를 새로 만들지 않는다. 이 경로는 드라이런의 별도 분류와 표본으로 검토한다.

취소는 행사·보호자 신청 단위로 적용한다. 한 형제의 행이 취소돼도 다른 유효한 가족 신청이 남아 있으면 가족 참석 근거는 유지한다. '부재·전화기 off'는 취소로 보지 않는다. 원본의 '불참·X'는 어떤 열의 어떤 의미인지 확인해 신청 취소와 단순 참석 확인을 구별한다. 이를 일괄 취소로 바꾸거나 일괄 인정하지 않고, 뜻이 모호하면 해당 원본만 확인 목록에 둔다. '취소했다가 재신청' 같은 자유 메모는 취소 단어 포함 여부만으로 판단하지 않는다.

## 기여도 배선

- 제안 지표: `parentSeminarEvents` / **학부모 설명회 참석**. 운영 기여로 분류하고 **행사당 1점**을 초안으로 제안한다. 분류·배점은 아직 확정되지 않았으므로 활성화 전에 원장 결정이 필요하다.
- 월별 실적은 행사일 기준 인정 건수. 마감된 월을 덮어쓰지 않고, 기존 정정 계산 경로로 지난 행사 연결·취소·병합에 따른 증감을 반영한다. 재실행 시 현재 인정 실적과 이미 반영된 실적을 비교해 같은 정정을 반복하지 않는다.
- 마감된 과거 실적의 최초 반영은 현재 열린 달의 정정으로 들어간다. 따라서 이번 달 추이와 최근 12개월 증감이 달라진다. 드라이런에 이 효과를 따로 보고하며 원래 행사일과 반영 월을 함께 보여 준다.
- config/버전·기본값·검증, Raws/Metric·계산, 수집/월별 집계/정정, 설정 미리보기, 목록·상세·추이·계산식, 근거 유형과 원본 링크, 학생→반→강사→과목→학원 관점, 문서/테스트까지 함께 배선한다.
- 옛 설정 JSON은 업그레이드 함수로 새 지표의 기본값을 채운다. 활성화 결정 전에는 `enabled:false`다. 옛 원수치 JSON은 **이번에 추가하는 키만** 0으로 정규화하고 기존 키의 누락·잘못된 수치는 계속 오류로 처리한다. 원수치·정정·합계·상세 등 모든 읽기 경로에 동일 정규화를 적용한다.
- 합계 RPC는 키를 동적으로 합산하므로 본문 변경이 필요 없다. 마감 트리거에는 새 키가 **있으면 정수인지** 검사하는 조건만 추가한다. 옛 마감 행을 수정하거나 새 키를 필수로 만들어 구버전 앱의 쓰기를 막지 않는다.
- 운영/참여 분류를 `slice(0, 5)`로 나누는 세 지점은 지표별 그룹 정의 하나를 읽도록 바꾼다. 2026년부터 도는 활동 루프에 2025년 설명회를 끼워 넣지 않고 별도 순수 모듈에서 사실을 만든다.
- 병합 ID 적용 → 학생·행사 중복 제거 → 월별 합산 순서를 지킨다. 매 집계 때 인정 사실 전체로 다시 계산해 기존 정정 공식을 사용하며, 별도의 '점수 반영됨' 장부나 증분 가산을 만들지 않는다.
- 확정된 배점 변경은 과거 실적 전체에 적용한다. 집계는 기존 일일 기여도 작업에서 **DB에 가져온 자료만** 읽는다. Drive 읽기는 명시한 가져오기 작업에서만 수행한다. AI 요약·AI 신원 매칭은 실행하지 않는다.
- 학생·보호자·형제 수동 지정은 페이지 제한을 빠짐없이 읽어 한 번에 수집하고 기존 순수 함수를 메모리에서 사용한다. 학생마다 DB를 재조회하지 않는다.
- 반·강사·과목 연결을 행사 자료만으로 추측하지 않는다. 행사 당시 확인된 관계만 근거로 연결하고, 학원 관점에서는 동일 원본 행사를 중복 참석자로 세지 않는다.
- 아직 열리지 않은 행사는 예정 자료로만 보이며 행사일(KST)이 지난 뒤 인정한다. 원본에서 사라진 행은 자동 삭제하지 않고 확인 목록에 남긴다. 취소·연결 해제·형제 해제는 마감 보존 원칙에 따라 음수 정정한다.

## 권한·근거 표시

- 가져오기·확인 목록·수동 연결/취소는 기존 기여도 쓰기 권한을 적용하고 서버 전용 표로 보호한다. 개인 열람 예외를 원문 연락처 접근 권한으로 확대하지 않는다.
- 월 payload에는 행사명·날짜·인정 방식만 담고 보호자 이름·전화 원문을 넣지 않는다. 매칭 근거에는 일치/충돌 결과를 기록한다. 형제 이름도 해당 학생 열람 범위 안에서만 표시한다.
- 원본 행 링크는 원문 열람 권한자에게만 제공한다. 그 외에는 행사·자료 위치 설명만 표시한다. 미확정 행은 학원 단위 확인 목록에 두고 후보 학생 화면에 노출하지 않는다.
- 아직 가져오지 않았거나 표가 없는 상태는 '자료 확인 전'으로 구별한다. 확인 전을 0건 참석으로 표시하지 않는다. 데이터 읽기 정규화의 0과 자료 범위의 확인 여부는 별도로 관리한다.
- 가져오기·연결·취소·되돌리기에 감사로그를 남기고 기존 기여도 로그와 같은 분류를 사용한다. 외부 메시지는 발송하지 않는다.

## 실행 순서와 승인 자료

1. 읽기 전용으로 Drive 계정·대상 파일/시트·원본 상태와 DB 신원/가족 관계를 다시 조사한다. 최종 정책으로 새 드라이런을 만든다.
2. 순수 판정 함수부터 테스트: 동명이인 A/B, 전체/부분 전화, 가구 충돌, 학생 이름 없는 행, 신청/취소/재신청, 형제 직접/간접 연결, 학생 병합, 시트 정렬·행 삽입, 행사 회차/날짜 모호함, 재실행·취소 정정, 미래 행사. 옛 설정/원수치 읽기, 형제 사실 ID, 개인정보 payload·권한도 검증한다.
3. 원장에게 **고유 행사 수 / 직접 연결 학생 / 형제 확장 학생 / 학생별 인정 건수 / 중복 제거 / 취소 / 보류 사유별 건수**를 보고한다. 행사 목록, 지점 확인 범위, 행사일 재원 상태, 학생 이름 없는 가구 연결, 불참/X 해석, 최근 12개월 증감 변화를 구분한다. 직접 연결·형제·취소·충돌·큰 점수 변화 표본은 원본 위치와 근거를 함께 제시한다. 원문 개인정보가 담긴 전체 로그를 저장소에 커밋하지 않는다.
4. 코드와 읽기 호환성·권한을 Claude에게 적대적으로 검토받고 수정한다. 새 마이그레이션 번호는 최신 main에서 확인한다. 이전 작업트리의 0447a·0448a 번호는 main과 충돌하므로 재사용하지 않는다.
5. 원장이 배점·드라이런 범위를 확인한 뒤 호환 가능한 마이그레이션 → 비활성 상태의 앱 → 지문이 일치하는 승인 자료 백필 순으로 적용한다. 드라이런 이후 바뀐 행은 재검토한다. 마이그레이션·구버전 앱 사이에도 기존 집계가 계속 동작해야 한다.
6. 실제 저장 결과를 드라이런과 대조한 뒤 승인된 배점을 활성화하고 기존 기여도 집계를 한 번 실행한다. 학생별/행사별/가족별 합계, 취소 후 차감, 중복 방지, 형제 인정, 권한과 상세 근거를 확인한다.
7. 실패 시 신규 지표를 끄고 해당 import 실행의 연결을 감사로그와 함께 취소 상태로 되돌린다. 원본·마감 기록을 삭제하지 않는다. 복구 스크립트는 적용 SQL과 별도 파일로 둔다.

## 완료 기준

- 모든 자동 연결에는 신원·연락처·가족/취소·원본 위치의 검증 근거가 있다.
- 원장에게 보고한 드라이런과 저장 결과가 일치하고, 재실행·병합·중복 파일로 점수가 늘지 않는다.
- 신청·참석 간주·형제 확장·취소가 학생 상세의 근거에서 구별된다.
- 학원 전체의 실제 행사/가족 수와 형제까지 확장된 학생별 기여 실적을 혼동하지 않는다.
- 미확정 건과 아직 반영되지 않은 범위를 숨기지 않고 확인 목록에서 처리할 수 있다.
- 옛 설정·마감 원수치로 목록·상세·cron이 멈추지 않고, 형제 사실이 함께 있어도 다섯 관점 조회가 실패하지 않는다.
- 분류·배점 활성화 전에는 새 지표가 점수를 바꾸지 않는다.
