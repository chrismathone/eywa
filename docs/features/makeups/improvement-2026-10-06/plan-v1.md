## 변경 범위와 유지 조건

이번 작업은 수학 시범 기능에 한정한다. 영어 기존 보강·출결은 유지하며 새 영어 장부 운영, 자동 권리 발급/인정, 자동 소멸/환불/청구, 학부모 자동 발송, 셀프예약은 추가하지 않는다. 기존 직접 보강 학생 추가와 즉시 출결 쓰기를 새 승인 관문으로 차단하지 않는다.

서버/DB가 지점·역할·학생/반 범위·기능 모드·원사건 동일성을 계속 판단한다. URL와 클라이언트 기본값은 편의용이며 권한 근거가 아니다. 일반 지점 UI에는 내부 플랫폼 역할 이름을 노출하지 않는다.

운영 모드 on: 신규 접수·예약·연결 가능. draining: 기존 업무 조회·정리만, 접수·예약·변경·연결은 현재 계약대로 금지. off: 기존 예약 기능만 유지, 새 RPC 호출/쓰기와 접수 링크 없음. 켜짐/꺼짐을 자동 변경하지 않는다.

## P0 — 참여의 실제 진행 상태와 예정 집계 통일

### 조회 계약

새 migration으로 `makeup_list_participants`에 기존 필드를 유지하며 `session_state`, `classroom_id`, 현재 non-reversed `fulfillment_state`, 실제 실시 분량, 가장 최근 인정 반전 존재 여부, 조회용 진행 상태를 추가한다. 이미 SQL이 반환하나 TypeScript가 버리는 session/room 필드도 명시적으로 파싱한다.

진행 상태 계산은 공통 도우미와 조회 계약 한 곳에서 정의한다. 화면별 임의 추론, 날짜만으로 자동 완료/노쇼, 케이스 하나의 종결만으로 참여 전체 완료는 금지한다. 참여 한 건이 여러 케이스에 배분될 수 있다.

| 실제 근거 | 조회용 분류 | 보강예정 집계 | 관리자 확인 위치 |
| --- | --- | --- | --- |
| 참여 취소 또는 회차 cancelled/rescheduled | 취소·변경됨 | 제외 | 일정 이력 |
| 현재 실시 기록 verified | 검토 완료 | 제외 | 일정의 완료/케이스 종결 이력 |
| 참여 no_show | 미참석 | 제외 | 미처리 케이스 재예약/일정 이력 |
| 현재 실시 기록 submitted | 검토 대기 | 제외 | 검토 대기 업무/일정 |
| 참여 present/partial, 또는 draft/returned에 실제 분량·실시 근거 있음 | 실시 기록/보완 필요 | 제외 | 실시 기록·보완 업무/일정 |
| 인정 반전 후 재검토 전 | 재검토 필요 | 과거 수업을 예약으로 되살리지 않음 | 해당 케이스의 기존 정정 경로 |
| 실제 실시 근거 없이 confirmed 예약, 오늘 이후 | 예약 | 포함 | 예정 일정 |
| 같은 예약, 오늘 이전 | 지난 예약·기록 확인 필요 | 포함 | 예정 팝업·실시 기록 필요 |
| 서로 모순되는 상태 또는 신규 조회 필드 부재 | 확인 필요 | 완료로 추정해 숨기지 않음 | 조회 오류/확인 안내 |

`finished` 회차만으로 개별 학생이 인정됐다고 보지 않는다. partial 인정은 해당 참여를 완료 처리하되 남은 의무는 케이스 업무 목록에 남긴다. 단순 보고서 첨부/초안 존재만으로 실제 실시했다고 추정하지 않는다. 현재 함수의 page/cursor/total/truncated와 권한 범위는 보존한다.

### 소비처와 중복 제거

- `src/features/dashboard/server/makeup-upcoming.ts`: 신규 상태 기준 적용, 카드 수=팝업 행. 기존 오늘~1개월/과거60일 창 유지. popup 자동 이행 안내는 기존 예약과 새 검토 절차를 정확히 구분한다.
- `src/features/attendance/server/makeup-reservation-queries.ts`의 `getStudentUpcomingReservations`: 오늘 완료 건/검토 대기 건이 예정으로 표시되지 않도록 같은 분류 사용.
- 시간표는 기존 native 예약의 legacy 반영을 유지한다. 완성된 legacy 예약은 done이므로 미래 예약 조회에서 제외된다. 변경/취소/부분 인정/인정 반전도 비교 검증한다.
- 명단·출석부·보고서·영상숙제의 `loadNativeParticipants`는 완료 참여를 삭제/필터하지 않는다. 과거 수업은 해당 명단과 보고서 이력에 남아야 한다. 예정 조회에서만 공통 분류를 사용한다.
- 기존 예약/native 이중 표시 제거는 `legacy_maps` 및 예약 ID의 실제 연결 관계로 한다. 같은 학생·반·날짜·시각이라는 문자열만으로 다른 원결석 건을 임의 병합하지 않는다. 화면에 내보낼 케이스 링크도 행위자 범위 안의 것만 사용한다.

기존 스키마/새 스키마 혼합 배포를 위해 신규 필드 부재를 감지한다. 구버전에서 완료를 안전하게 판정할 수 없는 native 예정은 ‘확인 필요’로 드러내고 0건/정상 완료로 위장하지 않는다. DB 먼저 추가 적용 후 앱 배포 순서이며, 읽기 필드 추가만으로 기존 writer/장부를 변경하지 않는다.

## P1 — 기존 예약의 미연결을 한눈에 표시

- 보강관리 상단에 ‘기존 예약 연결 필요 N건’ 요약과 해당 후보 목록 링크를 제공한다. N은 같은 지점/역할 범위/수학 시범 대상의 `makeup_candidates(kind=legacy)` 전체 count를 사용한다. 페이지 첫30행 길이로 총수를 세지 않는다.
- q/과목 조건 적용 여부를 문구와 필터에 맞춰 명시한다. 케이스 상태/업무 필터를 기존 예약 count에 섞지 않는다. 조회 실패는 0건이 아니라 재시도 안내, 최근 성공 값은 오래된 값임을 표시한다.
- 연결은 기존 `link_legacy` 명령만 사용한다. 스냅샷/충돌 검토·멱등성·기존 약속 보존과 승인 대기를 유지하며 전체 자동이관/자동승인은 하지 않는다.
- 기존 예약 저장 성공 UI에 ‘보강관리 기록에 연결’ 진입을 제공한다. 성공한 예약 ID를 사용하고 등록을 취소하거나 재저장하지 않는다. 모드/권한/대상 과목상 불가하면 해당 링크를 표시하지 않는다.
- ‘미연결 근거’ 진입은 ‘결석 접수·기존 예약 연결’로 용도를 명확히 한다. 내부 데이터 이름은 변경하지 않는다.

## P2 — 출석부·강사뷰에서 간편 접수 및 유효 기본값

### 진입과 저장

- 출석부에서 현재 결석/인정결석 학생 행에 ‘보강 접수’를 제공한다. 강사뷰에서는 선택 학생의 결석 내역에서 동일 진입을 제공한다. 오늘 학생을 골랐다는 이유로 오늘을 원결석일로 만들어 접수하지 않는다.
- 새 접수 페이지는 전달한 student/class/date/attendance ID를 서버에서 재조회·검증하여 채운다. 현재 출결 정정 후의 유효 결석 여부, 같은 원사건의 기존 케이스/예약, 수강 기간·역할 범위를 확인한다. 유효 후보가 아니면 저장하지 않고 이유와 기존 건 링크를 제공한다.
- 실제 결석 근거가 있으면 기존 `source_kind=attendance` intake 사용. 학생·반·날짜·과목을 확인하고 한 번 저장하면 승인 대기. 관리자의 목표 분량 승인과 실제 실시 후 독립 인정은 분리한다.
- 전달값이 없거나 예정 결석/휴강이면 기존 수동 접수를 유지한다. 일반 결석 접수의 메모는 선택으로 바꾼다(현재 SQL intake는 메모 필수 아님). 예정 결석·휴강·추가 지도 등 정책 설명이 필요한 사유는 기존 메모 요건 유지. 승인·정정·취소·인정 등 사유 필수 명령은 완화하지 않는다.
- 동일 원사건의 연속 클릭/출석부와 강사뷰 동시 접수는 기존 occurrence lock+aliases에 의해 한 케이스를 사용하고 기존 건 안내로 연결한다.
- 출석부/강사뷰에서 저장 후 원래 창·선택 학생·반·날짜로 복귀할 수 있게 안전한 내부 return 경로를 유지한다. 외부 URL, `//`, 허용하지 않은 경로를 거절하고 embed를 보존한다.

### 기본값

- 학생·날짜·과목으로 조회한 **전체 유효 후보가 정확히 하나일 때만** 원수업 반과 실제 출결 반을 채운다. 조회 1쪽에 하나뿐인 것과 총1건을 혼동하지 않는다.
- 원반은 원수업일의 수강 기간, 출결 반은 실제 실시일의 수강 기간으로 각각 판단한다. 날짜/과목/학생 변경 시 관련 선택을 지우고 재검증하며 느린 옛 응답이 새 선택을 덮지 않는다.
- 실시 강사는 로그인 강사가 같은 지점의 재직 직원이며 해당 예약에서 선택 가능한 경우에만 기본 제안한다. 관리자/데스크의 로그인 계정을 실시 강사로 넣지 않는다. 변경 가능하고 서버가 다시 검증한다.
- 강의실·교시·합류 반은 자원 충돌과 수업 맥락 때문에 자동 추정하지 않는다. 기존 분량 기본값은 유지한다. ‘반 없이’, 합침/분리 또는 같은 날 다른 강사 귀속을 자동 선택하지 않는다.
- 기존 ‘보강 학생 추가’는 당일 명단·출결 작업으로 계속 동작한다. 선택한 과거 결석의 새 장부 접수/연결은 별도 명시 동작이며, 당일 출결 저장과 원자적 성공으로 위장하지 않는다. 기존 명단 작업을 취소/되돌리지 않고 접수 실패/미연결을 알린다.

## P3 — 관리자 오늘·이번 주 일정 보기

- `/makeups`에 ‘미처리 업무 / 보강 일정’ 보기를 추가한다. 기존 업무 목록은 유지한다. 일정 기본은 오늘, ‘이번 주’·명시 날짜 범위 제공. 날짜 기준은 KST, 이번 주 월~일.
- 일정은 실제 참여 1건당 1행이다. 한 회차 여러 학생은 학생별 행, 한 학생 여러 원수업 배분은 한 행의 여러 연결로 표현한다. 분배 수만큼 일정 건수를 늘리지 않는다.
- 학생 / 보강 날짜·시작~끝 / 실시 강사 / 강의실 / 수업 반 / 진행 상태 / 관련 보강 건을 표시한다. 업무 담당자와 실시 강사는 구분한다. 상세에서 각각 변경/검토를 수행한다.
- 필터: 날짜 범위, 실시 강사, 강의실, 과목, 학생 이름, 진행 상태. 목록·요약·pagination은 같은 조건에 대한 DB 집합을 사용한다. 날짜 범위 상한31일, 기본 today. URL에 조건을 보존하고 상세 복귀에서도 유지한다.
- 새 참여와 미연결 기존 예약을 함께 표시한다. 기존 예약에는 ‘기존 예약·연결 필요’를 표시하고 실시 강사/강의실은 없는 정보로 표시한다. 예약 생성자를 실제 강사로 대체하지 않는다. 기존 자료를 자동 case로 바꾸지 않는다.
- 신규 조회 `makeup_schedule`(가칭) RPC에서 count/filter/order/page를 DB로 수행한다. 서버 페이지와 read-types에 계약을 추가한다. 지점 권한 및 participant/case 범위를 적용하고, 직원/강의실 이름도 같은 범위의 자료만 반환한다. 권한 확대나 service-role 우회는 금지한다.
- 필터에 맞는 일정에 대한 상태별 수와 연결 필요 수를 제공하되 겹친 업무 flag의 합계를 총건수로 쓰지 않는다. 기존 업무 flag는 중복 가능한 의미를 유지한다.
- 권한상 일반 강사도 일정 보기를 쓰면 자기 허용 범위만 보이고, 담당 반 없는 배정 강사도 본인 배정 참여를 볼 수 있어야 한다. 케이스 원결석 반이 범위 밖이면 무권한 링크/정보는 노출하지 않는다.
- 390px은 정보 누락 없는 세로 카드, 1440px은 표. 상태는 문구+색상으로 전달하고 이름 있는 조작 요소, 키보드/초점, 가려짐 없는 팝오버를 유지한다.

## 필수 수용 기준

1. 감사의 D 완료 건: 대시보드/학생 예정 0행, 일정 이력에는 검토 완료, 케이스 종결·잔량0, 명단·보고서 보존.
2. 아직 검토 안 된 실제 실시: 예정 아님, 관리자 검토/기록 업무에서 발견 가능. 날짜 경과만으로 완료·노쇼 아님.
3. 부분 인정: 실시한 참여는 예정 아님, 잔여 의무는 재예약 가능. 인정 반전은 재검토로 보이고 시수·급여·청구 불변.
4. 취소/변경/미참석/근거 삭제/시수 불일치: 해당 상태가 정확하고 확인 업무가 숨지 않음.
5. legacy 예약 생성 → 연결 필요 +1, 수동 연결 후 −1, native/legacy 동시 목록은1행. 완료/취소 이력도 중복 없음.
6. 조회 실패·잘림·schema/mode off: 0건 성공으로 위장하지 않음. role/tenant/조회필터별 실제 count 일치.
7. 출석부와 강사뷰의 유효 결석은 재입력 없이 접수. 정정된 출결·다른 지점/담당 밖·잘못된 날짜/반 URL은 거절. 동시/반복 접수는 기존 case1개.
8. 기본값: 총1후보만 자동 선택, 여러 반/후보30건이상·날짜변경·역순응답·학생변경에 잘못된 값 없음. 관리자는 본인 자동 강사 아님.
9. 0개 담당 반의 배정 강사/타 반 담임의 배정 강사가 명단·출결·보고서를 정상 저장, 기존 S13 회귀 유지. 기존 수학/영어 당일 보강 학생 추가도 유지.
10. 일정: 오늘/월~일/월경계/실시강사≠업무담당/강의실변경/분배N:M/범위밖case/30행 넘는 자료의 행·count·필터·pagination 일치.
11. 새 SQL의 기존 함수 및 신규 함수 권한·search_path·지점 범위, 393개 실제 앱 스키마 체인 확인. 관련 타입·lint·production build·실질 회귀 검사와 390/1440px 브라우저 확인.
12. 실제 강사/관리자의 입력 시간·누락률은 사용자 연구 전에는 성과로 주장하지 않는다. UI 클릭 수는 실제 경로를 측정해 기록하고 목표는 유효 결석 문맥에서 확인+저장으로 접수 완료다.

## 적용·리뷰 경계

이번 요청에서는 계획과 Claude 합의만 완료한다. 운영 DB 적용·구현·push·Vercel 배포는 하지 않는다. 후속 구현 시 사용자 기존 승인 범위를 확인하되, DB 새 조회 계약은 기존 이력 없는 환경 전체 db push를 피하고 대상·기존 정의 대조·백업·단일 트랜잭션·권한/불변 검사로 적용한다. Vercel은 사용자 담당이다.

Claude는 이 초안과 실제 소스를 대조해 CHANGES_REQUIRED/APPROVE를 제출한다. Codex는 이견별 수용·정정 이유를 기록하고 수정안의 SHA256을 다시 확인받는다. 기존 기능의 앞선 승인은 이번 계획 승인으로 재사용하지 않는다.
