# 구글 입학 상담 방문 기록

신규 콜&상담의 **방문 기록**에서 `/enrollment/visitors`를 연다. 선택한 연도와 전년을 월별로 조회하여 예약 수요의 계절성을 비교한다. 사용자가 지정한 조사 범위는 **입학 상담 캘린더만**이다. 신입생/시범수업과 운영팀 중요일정은 제외한다.

## 집계와 사용

- `구글 기록 조회`를 누르면 24개월(2000년은 12개월)을 순서대로 읽으며 월별 결과를 표시한다. 연도 변경·중지는 이전 요청 결과의 화면 반영을 중단한다. 이미 전송한 읽기 요청은 끝날 수 있다.
- 제목의 상담·테스트·입테·입학테스트를 공백 정규화 후 분류한다. 레테도 테스트로 본다. 한 일정에 여러 단어가 있으면 입학테스트/입테 → 테스트 → 상담 순으로 한 건이다.
- 구글 **예약 시작일, 한국 시간** 기준이다. 최초 문의일·예약 생성일·실제 방문자 수·고유 학생 수·신규 등록 수가 아니다. 반복 방문·동명이인은 이름만으로 합치지 않는다.
- 취소와 확인 대기는 집계 예약에서 제외한다. 전화·온라인·재원생/학부모 상담, 내부 테스트·평가, 일정 변경, 서로 다른 사본 정보는 확인 대기다. 일반 테스트의 입학 목적까지 확정하는 분류는 아니다.
- 같은 iCalUID의 단일 예약 사본은 합친다. 반복 일정은 원래 회차 시각까지 같아야 합친다. 조회한 서로 다른 달에 같은 회차 사본이 있으면 양쪽을 확인 대기로 남긴다. 새 ID/UID로 다시 만든 변경 예약은 동일 여부를 알 수 없다.
- 전년 대비는 양쪽 월 조회 완료, 같은 조사 범위, 지난달까지일 때만 표시한다. 전년 0건의 증가율은 계산하지 않는다. 연중 최다 월은 과거 연도 12개월이 모두 조회된 경우만 표시한다.
- 월별 행을 누르면 해당 달의 목록과 취소·확인 대기·분류별 필터, 구글 원본 링크를 확인한다. 원본 수정 후 **다시 조회**하면 해당 지점·월 캐시를 갱신한다.

## 연결과 권한

기존 Calendar API 읽기 전용 서비스 계정을 재사용한다. `GOOGLE_CALENDAR_TENANT_ID`와 로그인한 지점이 정확히 일치해야 한다. 대상은 기존 `GOOGLE_CALENDAR_IDS` 중 공백 제거 태그에 `입학상담`이 포함된 캘린더다. `GOOGLE_VISITOR_HISTORY_CALENDAR_IDS`는 그 안에서 더 좁히는 선택 설정이며 다른 캘린더를 추가하는 우회 수단이 아니다.

전체 신규 콜&상담 열람 권한(full/readonly), 활성화된 calendar 모듈을 매 서버 액션에서 검사한다. scoped/none과 다른 강사로 보는 화면은 허용하지 않는다. 클라이언트가 지점·캘린더 ID를 지정할 수 없다.

설명·장소·참석자·연락처 필드는 요청하지 않는다. 제목의 전화번호·이메일은 마스킹한다. 오류에 API 요청·개인정보·자격증명을 싣지 않는다. 외부 AI 호출·상담 생성·구글 일정 변경·알림 발송은 없다.

## 완전성과 보관

기존 일반 캘린더 동기화는 과거 30일 범위여서 계절성 자료로 사용하지 않는다. 이 화면은 Google API에서 월 전체를 페이지 끝까지 읽는다. 빈 페이지도 다음 토큰이 있으면 계속한다. 캘린더별 12페이지/약 16초 후 다음 페이지가 남거나 요청이 실패하면 일부 조회로 표시하고 월 합계·비교를 보류한다. HTTP 요청 하나는 8초 제한이다.

선택한 캘린더를 끝까지 읽어도 원본 누락·비공개 제목·삭제된 과거 기록을 복원할 수는 없다. 제목·날짜가 없는 삭제 흔적 등은 확인 불가 건수로 별도 표시한다. **현재 구글 원본의 조회 화면이며 변경 불가능한 장기 보관 장부가 아니다.** 원본을 고치거나 지우면 이후 조회 결과도 달라진다. 외부 전송 없는 지점·월·설정별 Next 캐시(5분)만 쓰며 새 운영 DB 테이블은 없다.

Google API의 시간 범위·삭제·빈 페이지 정의: [Events list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list).

## 검증과 반영

합성 데이터로 분류, 월 경계, 취소, 반복 회차·사본, 페이지 절단·실패, 지점 격리, 권한, 연도 변경 중 응답 경합을 검사한다. 실제 표본은 제목 패턴 확인에만 사용하며 개인정보를 테스트 자료에 넣지 않는다. 로컬에는 운영 연결 환경변수가 없어 로그인한 운영 AYWA 화면의 종단 검증은 반영 승인 후 필요하다.

GitHub Actions는 사용하지 않는다. 로컬 테스트·lint·타입 검사·빌드와 데스크톱/모바일 화면 검증 후 검토용 PR로 제공한다. 운영 배포, 운영 DB 변경, 실제 외부 알림은 실행하지 않는다.
