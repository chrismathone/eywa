# MCS 적용 — 2026-09-17

- 반 화면: 1번 시안의 학생별 진도 레일.
- 학생 이름/행 클릭: 학생 집중 보기. 학생 선택을 주소에 보존해 새로고침·뒤로가기를 지원한다.
- 진도 단위: 블록. 실제 위치·상태는 모두 파랑, 목표는 옅은 파랑이다.
- 전체 목표: 반 전체 또는 학생별로 과정, 시작·완료 블록, 시작·완료일, 교재를 저장한다.
- 목표 배분: 시간표 유효 기간, 휴강일, 수강·반이동·퇴원 기간과 분리 등원 요일을 반영한다. 같은 날 여러 교시는 한 수업일로 계산한다.
- 실제 진도: 기존 수업보고서에서 읽는다. 시험/자유 입력은 직전 확인된 위치를 유지하며 상세에서 기록일을 표시한다. 기록이 없으면 진행률을 추정하지 않는다.
- 목표는 과정 하나 안의 시작~완료 범위다. 월·주·일 목표는 누적 블록 수이며, 블록은 같은 분량으로 배분한다. 1블록 이내 차이는 계획대로로 판정한다.

## 저장

`supabase/migrations/0269b_math_learning_goals.sql`을 연결 DB에 적용했다. 기존 월 목표와 수업 기록은 보존한다. 새 표는 서버 전용이며 테넌트·반 접근 게이트를 통과해야 저장할 수 있다. 샘플 목표는 저장하지 않았다.

작업 브랜치는 `feat/mcs-learning-goals`. 사용자 승인 후 최신 `main`과 통합해 배포한다. 아래는 배포 전 검증 결과다.

## 검증

- MCS 및 감사로그 관련 테스트: 319개 통과. 새 배분 계산 14개와 저장 경계 6개 포함.
- 수정한 파일 ESLint 통과.
- 앱·테스트 TypeScript 검사 통과 (`logs/mcs-qa/tsconfig.json`). 기본 `npm run typecheck`는 `work/`에 있던 별도 작업 복사본의 기존 오류를 포함하므로 검증에서 해당 복사본과 개발 서버 생성 파일을 제외했다.
- `npm run build` 통과. `/mcs/[classId]/month` 프로덕션 빌드 포함.
- 실제 앱: 인증된 테스트 반에서 목록 → 학생 집중 보기 → 목표 설정 창 확인. 모바일 가로 넘침·브라우저 오류 없음. 실제 학생의 목표는 변경하지 않았다.
- 컴포넌트 화면: 1440·1024·390px, 빠름/느림 동일 파랑, 검색·상태 필터, 키보드 진입, 상세 주소 새로고침, 저장 실패 시 입력 유지 확인.
- DB 삽입/upsert 검증은 롤백 트랜잭션으로 수행. RLS 및 서버 전용 쓰기 권한 확인.

화면과 브라우저 검증 결과는 `logs/mcs-qa/`에 있다. 초기 Turbopack 개발 서버에서만 404가 발생해 Webpack 개발 서버로 실동작을 확인했으며, Turbopack 프로덕션 빌드는 정상 통과했다.
