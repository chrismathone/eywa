## 유지 조건

수학 시범 범위를 유지한다. 영어 기존 보강·출결, 현재 같은 강사의 정규+보강 처리, 다른 날짜 분할·N:M 원결석 배분·독립 실시 검토를 보존한다. 자동 권리 발급·자동 인정·기한 소멸·환불/청구·학부모 자동 안내·셀프예약은 추가하지 않는다.

분량 승인, 관리자 자신의 실시 기록에 대한 자기 검토 거절, 수기 시수 확인, 시수·급여·청구 산식은 바꾸지 않는다. 기존 즉시 보강 학생 추가/출결 저장을 새 승인 조건 때문에 막거나 되돌리지 않는다.

DB가 지점·역할·학생/반/참여 범위·원사건·기능 모드를 판단한다. URL나 기본 선택값으로 권한을 부여하지 않는다. 새 공개 조회의 EXECUTE는 인증 사용자에게만 주고 비공개 도우미는 클라이언트 실행 권한을 회수한다. 일반 지점 UI에는 내부 플랫폼 역할 이름을 노출하지 않는다.

| 모드 | 이번 기능의 동작 |
| --- | --- |
| on | 허용 범위의 조회·접수·예약·기존 예약 연결 |
| draining | 기존 조회·실시·검토·정리. 접수/예약/변경/연결 진입과 명령은 기존대로 금지 |
| off | 기존 예약·출결 경로 유지. 새 장부 RPC·쓰기·접수/연결 진입 없음 |

설정 자체는 자동으로 변경하지 않는다. 메뉴 읽기/쓰기와 개별 명령 권한은 서로 구분한다.

## P0. 진행 상태와 예정 집계 수정

### 조회와 호환 계약

`makeup_list_participants`의 기존 행·정렬·범위·cursor/page/total/truncated를 보존한다. `session_state`, `classroom_id`, `planned_minutes`, `actual_minutes`, `period_ids`는 이미 SQL에 있으므로 필요한 TypeScript 선택 필드만 추가한다.

`with_progress: true`를 요청한 **대시보드 예정·학생 예정·보강 일정** 호출에만 다음을 추가 계산한다.

- 최상위 `progress_contract: 1`, DB의 KST `today`.
- 현재 살아 있는 실시 기록(state≠reversed)의 상태·실시 분량과 검토된 인정 분 합.
- `makeup_recognitions.kind='reverse'`에 근거한 인정 반전 여부. 실시 기록 reversed만으로 판정하지 않는다(노쇼 정정도 reversed를 만든다).
- 살아 있는 imported 연결과 연결된 기존 예약의 reserved/done 상태.
- 공통 `participant_progress` 결과와 별도의 확인 필요 플래그.

공용 기본 파서는 추가값이 없거나 낯설어도 기존 참여 줄을 거절하지 않는다. 출결 저장 문, 이행 훅, 명단·보고서·영상숙제·시수 마스터는 with_progress를 요청하지 않으며 동작/조회 비용을 유지한다. 새 진행 판정은 원문 상태를 사용하고 낯선 값을 ‘미기록 unknown’으로 접지 않는다.

신규 진행 호출이 최상위 표식을 못 받으면 해당 신규 참여 상태를 ‘확인 필요’로 표시하고 확정 예정 수에 섞지 않는다. 누락을 0건이나 완료 성공으로 숨기지 않는다. 일정 RPC가 없으면 일정 영역에만 ‘DB 설정 적용 후 사용’ 안내를 내고 기존 업무 목록은 유지한다. 권한상 sharedRead 생략/off인 기존 소비처는 현재 legacy 경로를 유지한다. 실제 조회/형식 오류와 기능 생략은 구분한다.

### 공통 상태 판정

SQL 도우미 하나를 진행 참여 조회와 일정 RPC가 공유한다. TypeScript는 상태 문구를 표시할 뿐 재판정하지 않는다. 다음 순서로 처음 맞는 상태를 택한다. 명시된 불일치/낯선 상태는 먼저 확인 필요로 분리한다.

| 순서 | 근거 | 표시 | 확정 보강예정 |
| --- | --- | --- | --- |
| 1 | 진행 표식 부재, 낯선 값, 뒤 조건에 맞지 않는 모순 | 확인 필요 | 별도 표시 |
| 2 | 참여 cancelled | 취소·변경됨 | 제외 |
| 3 | 참여 no_show | 미참석 | 제외 |
| 4 | present/partial + 현재 verified | 검토 완료(인정0분도 명시) | 제외 |
| 5 | present/partial + submitted | 검토 대기 | 제외 |
| 6 | present/partial + draft/returned | 실시 기록·보완 필요 | 제외 |
| 7 | present/partial + 현재 기록 없음 + 반전 인정 행 있음 | 인정 정정됨·실시 기록 다시 필요 | 제외 |
| 8 | unknown + 살아 있는 imported 연결 + 기존 예약 done | 기존 완료 근거 확인 | 제외 |
| 9 | unknown + confirmed + 보강일≥today | 예약 | 포함 |
| 10 | unknown + confirmed + 보강일<today | 지난 예약·기록 확인 필요 | 포함 |

회차 cancelled/rescheduled인데 참여가 살아 있거나 finished인데 unknown이면 모순이다. verified와 이후 열린 대사 항목은 모순으로 섞지 않고 ‘검토 완료+확인 필요’로 각각 표시한다. 날짜만으로 완료/노쇼를 만들지 않는다. 케이스 하나의 종결만으로 참여 전체를 완료라 추정하지 않는다.

부분/0분 인정 후 남은 의무는 기존 케이스 목록에 남는다. 인정 반전 후 다음 업무는 새 업무 종류를 만들지 않고 기존 ‘실시 기록 → 제출 → 다른 관리자 검토’다. 케이스 목록 SQL은 바꾸지 않되 진행의 기록/검토 집합이 기존 record_missing/review_pending와 대응하는지 실제 SQL로 검증한다. imported done 확인은 기존 legacy_done_review를 사용한다.

### 소비처·중복·범위

- 대시보드: 기존 오늘~한 달/과거60일 창을 유지하고 카드 수=팝업 확정 예정 행 수로 맞춘다. 확인 필요는 보조 수와 행으로 분리한다. 미연결 legacy의 출결 자동 이행과 새 보강의 독립 검토 안내를 구분한다.
- 학생 예정: 오늘 검토 완료·검토 대기·실시 기록된 native를 예정에서 제외하고 같은 공통 판정을 사용한다. 확인 필요 건은 경고 없이 조용히 버리지 않는다.
- **모든 허용 참여·연결을 먼저 읽어 mapped legacy 행을 대체한 다음 예정 조건을 적용한다.** 살아 있는 연결은 legacy 자체 행을 만들지 않는다. native와 연결 안 된 같은 날 legacy 약속은 별도 두 행이며 문자열 동일성으로 합치지 않는다.
- reserved→done 및 취소/변경의 legacy 삭제는 기존 명령과 같은 트랜잭션에서 이뤄진다. projection_jobs는 출결 효과용이므로 ‘예약 반영 지연’이 있다는 전제로 새 비동기 작업을 만들지 않는다. 모순 자료에서도 중복 우선 규칙은 지킨다.
- 대시보드의 native는 DB의 participant 범위를 따르고 legacy 반 집합으로 다시 잘라 버리지 않는다. 담당 반0개인 배정 강사도 본인 참여를 보고, 출결 반 없는 참여는 ‘출결 반 확인 필요’로 표시한다. DB가 허용한 참여의 반 이름·강사·방 정보는 같은 조회 범위에서 제공해 클래스 명단 접근을 확대하지 않는다.
- 기존 legacy 대시보드 범위는 이번 주 반 집합을 유지한다. native/새 일정은 DB의 오늘 담당/본인 배정 범위다. 주 중 담당 변경 시 집합이 다를 수 있음을 검증 기록에 명시한다. 대시보드는 전 과목·한 달, 신규 일정은 수학·선택 기간이므로 무조건 같은 총수를 주장하지 않는다.
- 시간표는 기존 legacy 반영을 유지한다. 원수업일=보강일 또는 출결 반을 나중에 지정한 native처럼 투영이 없는 참여는 기존 시간표 보강 탭에 없다는 한계를 유지하며 새 일정에서 보여준다. 새 시간표 projection을 추가하는 작업은 이번 범위에 넣지 않는다.
- 완료 참여는 명단·출석부·보고서·영상숙제 이력에서 제거하지 않는다. 예정 분류를 공용 명단 전체 필터로 적용하지 않는다.

## P1. 기존 예약 연결을 쉽게 발견

후보 읽기에 legacy status와 보강일 조건 및 기능별 권한 힌트를 추가한다. 기본 조회 호환을 유지한다. DB의 실제 전체 count를 사용하며 첫 페이지 행 수로 총수를 만들지 않는다.

| 분류 | 기준 | 상단 표시 |
| --- | --- | --- |
| 앞으로의 미연결 예약 | reserved, 날짜≥today | 연결 필요 N의 일부 |
| 지난 미연결 예약 | reserved, 날짜<today | 연결 필요 N의 일부, 자동 완료/노쇼 금지 |
| 이행된 기존 이력 | done | 별도 M건. 연결은 선택이며 완료 근거 확인 업무가 생김 |

legacy status는 reserved/done뿐이다. 취소는 행 삭제이고 native 취소 이력과 혼동하지 않는다. 상단은 수학·허용 반 범위의 예약임을 명시한다. q/과목 조건과 동일한 후보 집합을 쓰며 케이스 업무/상태 조건을 섞지 않는다. 조회 실패는 0건으로 표시하지 않는다.

`permissions.link_legacy`는 DB의 wide+mode on 조건이다. 일반 강사 intake 권한과 다르다. 권한이 없으면 새·기존 후보 화면과 예약 성공 화면 모두 연결 버튼/링크를 숨기고 ‘관리자가 연결합니다’를 보여준다. 단순 canWriteTenant나 현재 permissions.ts의 별도 분류로 작업 버튼을 판단하지 않는다.

‘미연결 근거’ 진입 문구를 ‘결석 접수·기존 예약 연결’로 명확히 한다. 연결 가능한 직원에게 기존 예약 저장 뒤 성공한 예약 ID의 연결 진입을 제공한다. 기존 예약은 재저장/취소하지 않는다. 원결석에 기존 예약이 있으면 강사 접수 끝 상태는 ‘기존 보강 예약이 있습니다. 관리자가 연결합니다’다.

연결은 기존 link_legacy만 사용한다. 스냅샷·충돌·멱등성·승인 대기·기존 약속 보존을 유지하고 자동 이관/승인은 하지 않는다.

## P2. 강사의 간편 접수와 검증된 기본값

### 문맥과 진입

출석부의 결석/인정결석 학생 행과 강사뷰의 과거 결석 선택에서 공용 접수 진입을 제공한다. 출석부 학생 행 및 현재 공용 MakeupAddFlow/MakeupConfirmDialog, 강사뷰 보강 추가의 결석 선택 문맥을 구현 시 함께 연결한다. 원생 이름 선택만으로 오늘을 원결석일로 만들지 않는다.

접수는 학생·원반·원수업일·유효 출결 ID를 서버에서 재조회해 채운 확인 화면을 거친다. 유효한 실제 결석은 source_kind=attendance로 한 번 저장하면 승인 대기다. 이미 접수된 동일 원사건은 기존 case로 이동한다. 기존 예약이 있으면 P1의 안내/관리 연결로 보낸다. 관리자 분량 승인과 실시 후 독립 검토는 유지한다.

창 방식은 기존 OpenWindowButton의 autoClose 접수 창을 사용하고 원래 창을 남긴다. 단일 화면 복귀 값은 raw URL이 아니라 출처 enum(attendance/onescreen)과 검증된 반 UUID·날짜·학생 UUID 등만 받는다. 목적지는 서버가 허용 경로로 만든다. 유효하지 않은 값은 버리고 보강 상세로 이동한다. 현재 back은 필터 문자열이므로 목적지 URL로 재사용하지 않는다.

withEmbed/EmbedLink를 유지하고 저장 성공 시 publishMutation을 사용한다. 강사 미니셸의 /makeups/new 허용을 구현 P2 시작 전에 확인하고 필요한 경우 그 경로만 추가한다. 새 문구는 화면 한국어/English를 지원하며 새 영어 장부를 켠다는 의미는 아니다. Next의 searchParams Promise 규약과 신뢰되지 않은 router URL 금지를 따른다.

### 저장 시 결석 검증과 메모

- 새 migration에서 cmd_intake의 attendance 근거 거절 조건만 강화한다. 선택 행은 칸의 최신 유효 결석/인정결석이어야 하고 같은 날 같은 반에 유효한 출석·지각·조퇴·보강 행이 없어야 한다. 후보 조회와 같은 SQL 도우미를 공유한다. 최신 정정 이후 stale ID를 직접 보내도 거절한다.
- 원반/날짜가 있는 접수(수동 포함)는 생성/근거 연결 후 같은 트랜잭션에서 observe_attendance_cell을 호출한다. 이미 출석인 날의 수동 예정 결석/휴강 접수는 거절 대신 source_conflict를 남긴다. 기존 권리·분량이나 정규 출결을 임의 변경하지 않는다.
- 정정과 접수 동시 실행은 다음 순서를 직렬화한다: 기존 occ:학생:원반:날짜 키를 **최신 결석 검증 전에** intake에서 획득하고, 출결 AFTER 관측 트리거도 INSERT/UPDATE/DELETE의 관련 원사건 키를 기존 relevance 조기 종료 전에 획득한다. 이동이면 old/new 키를 정렬한다. intake는 출결 행을 FOR UPDATE로 잠그거나 수정하지 않는다. 행 잠금→사건 잠금의 역순 교착을 추가하지 않도록 잠금 그래프와 실제 병행 시험을 출시 관문으로 둔다.
- 출결 정정이 먼저 확정되면 stale attendance 접수 거절. 접수가 먼저 확정되면 이후 정정 관측이 source_conflict/근거 삭제 확인을 남긴다. 출결 트리거의 기존 실패 격리·실패 작업 기록을 보존하며 정규 출결 저장을 보강 오류로 거절/되돌리지 않는다. 잠금/관측 실패와 실제 원사건/근거 삭제 모두 동일한 검증 대상이다. 기존 already-created case를 자동 취소/소멸하지 않는다.
- **메모 선택은 실제 attendance 근거의 결석 사유에만 적용한다.** 수동 결석·예정 결석·휴강·추가 지도는 메모 필수다. 서버 액션 missingKeys(intake)와 화면에서 강제한다. SQL 자체는 기존 메모 선택 정책을 유지한다. 승인·취소·정정·인정 명령의 사유 필수 규칙은 유지한다.
- 동일 결석의 반복/동시 접수는 기존 occurrence lock+source aliases로 case 한 건만 사용한다. 요청 멱등성과 저장 결과를 받지 못한 같은 요청의 재확인을 유지한다.

### 기본값

검색어 없이 학생·날짜·과목으로 조회한 전체 후보 total=1일 때만 반을 채운다. 페이지1에 하나뿐인 것과 전체1건을 혼동하지 않는다. 원반은 원수업일, 출결 반은 실제 실시일의 수강 기간을 사용한다. 학생/날짜/과목 변경 시 무효 선택을 지우고 재조회하며 느린 옛 응답이 새 선택을 덮지 않게 한다.

실시 강사는 로그인한 일반 강사가 서버의 허용 직원 후보에 있을 때만 제안한다. 관리자/데스크 자신을 자동 실시 강사로 넣지 않는다. 강의실·교시·합류 반·합침/분리·반 없이 선택은 자동 추정하지 않는다. 기존 승인 분량 기본값을 유지한다.

기존 당일 ‘보강 학생 추가’는 명단/출결 작업으로 계속 동작한다. 접수 액션은 별도다. 기존 저장 성공과 이후 접수/연결 실패를 하나의 성공으로 위장하거나 기존 출결을 되돌리지 않는다.

## P3. 관리자 ‘수학 보강 일정’ 보기

/makeups에 ‘미처리 업무 / 수학 보강 일정’을 제공한다. 업무 목록은 유지한다. 일정 기본은 오늘, 이번 주(월~일)와 직접 날짜 범위(max31일)를 제공한다. 오늘은 DB KST다.

새 makeup_schedule RPC에서 같은 허용 집합을 합치고 filter/count/order/pagination한다. 새 참여는 1인 참여당1행이며 복수 원결석 배분 수로 행 수를 늘리지 않는다. 미연결 기존 예약도 같이 보이고 ‘기존 예약·연결 필요’ 또는 ‘기존 이행’으로 구분한다. 실제 연결 ID로 중복을 제거한 뒤 상태·필터·페이지를 적용한다.

표시: 학생, 보강 날짜/시작~끝, 실시 강사, 강의실, 출결 반/합류 반, 예정 분/실제 분/인정 분, 진행 상태, 관련 case. 업무 담당자는 case별로 표시하고 한 참여에 여러 case면 허용 범위의 담당자를 모두 표시한다. 실제 실시 강사와 혼동하지 않는다. 여러 case의 인정 분도 행위자에게 허용된 배분만 표시한다.

필터: 날짜 범위·실시 강사·강의실·과목(수학 시범)·학생 이름·진행 상태·이력 포함. 취소/변경 줄은 기본 제외하고 이력 포함에서만 보인다. 필터·요약·행·pagination은 같은 DB 집합이다. 중복 가능한 업무 flag의 합계를 총일정 수로 쓰지 않는다. 조건 변경은 page1, 상세 복귀에도 조건을 유지한다.

미연결 legacy **및 연결된 imported 회차**에도 실시 강사/강의실이 없을 수 있다. ‘미지정’으로 표시하고 특정 강사/방 필터에서는 제외한다. ‘미지정’ 필터와 ‘해당 정보 미지정 N건’ 보조 수로 찾을 수 있게 한다. 보조 수는 같은 기간/학생/과목 조건에서 해당 강사/방 조건만 풀어 센 값이며 현재 총일정 수에 더하지 않는다. 예약 생성자/원반 담임으로 실제 강사나 방을 채우지 않는다.

새 일정 범위는 DB의 오늘 담당/본인 배정 계약을 사용한다. legacy도 학생·반을 같은 지점으로 재조인하고 같은 과목/담당 범위를 적용한다. 직원/방 이름·case 링크의 허용 범위를 지킨다. service-role로 범위를 우회하지 않는다. 담당 반0개의 본인 배정은 보여야 한다.

기간 밖 지난 예약/기록 누락은 기존 업무 목록의 ‘실시 기록 필요’에서 찾는다. 날짜 제한으로 처리 업무가 사라졌다고 표현하지 않는다. 수학·선택 기간 일정과 전 과목·한 달 대시보드의 총수를 무조건 맞추지 않는다. 동일 범위·기간·과목으로 정규화한 예정 집합과 카드/팝업, 일정 요약/행만 서로 대조한다.

390px은 정보가 빠지지 않는 카드, 넓은 화면은 표. 문구+색상, 이름 있는 조작 요소, 키보드·초점, 잘리지 않는 팝오버, 원래 창의 미저장 편집 보호를 유지한다.

## 적용과 되돌리기

번호는 구현/병합 시 다음 빈 번호로 정하고 테스트 migration 실행 순서·참조를 함께 갱신한다. 진행 계산용 비공개 도우미는 lateral/집계로 살아 있는 실시 기록을 한 번 읽도록 구성하고, 새 파일 끝에서 비공개 EXECUTE를 회수하고 PostgREST schema reload를 알린다.

권장 적용은 DB 추가 계약→앱이며 순서를 안전성 전제로 삼지 않는다. 변경될 0348c/0348e/0346a와 원결석 관측 함수의 **현재 적용된 최종 정의**를 백업한다. 옛 파일 재실행만으로 최신 다른 수정까지 잃는 되돌리기를 하지 않는다. 신규 정의의 정확한 undo SQL을 준비한다. 앞 파일을 재실행했으면 추가 migration도 재실행해야 함을 머리에 명시한다.

운영 이력표가 없는 기존 환경에는 전체 db push를 하지 않는다. 후속 SQL 적용은 Supabase CLI의 파일 단위 실행을 단일 트랜잭션으로 묶고, 대상/기존 정의 일치·백업·변경 함수와 무관 함수 불변·권한을 대조한다. on/off나 업무 자료를 이 적용으로 바꾸지 않는다. Vercel 배포는 사용자 담당이다.
