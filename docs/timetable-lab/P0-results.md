# P0 첫 실행 결과

2026-10-02 · **첫 비교 프로토타입 구현·검증 완료, P0 전체 통과와 엔진 선정은 미완료**.

## 실제로 만든 것

[`experiments/timetable-lab-p0`](../../experiments/timetable-lab-p0/README.md)에 별도 React/Vite 앱을 만들었다. 운영 Next 앱의 라우트/패키지/DB를 연결하지 않았다. 루트 TypeScript 검사에서 실험을 제외하고 ESLint는 실험의 생성물만 제외한다.

같은 합성 영어 자료를 자체 DOM 격자와 Univer에서 편집한다. 강사 배치 값, 통합표 표시, 학생 배정, 서식 변경, 추천 적용은 하나의 상태와 Undo/Redo 이력을 사용한다. Univer workbook의 별도 이력은 쌓이지 않는다. 셀 안의 미확정 텍스트 편집 버퍼는 엔진의 기본 편집 동작을 유지한다.

학생·강사·강의실 겹침을 보여 주며, 영어와 겹치는 가상 수학 수업도 검사한다. 가능한 시간 후보는 수업 길이·강사·방을 유지하고 최종 상태를 검사한다. 변경 후 오래된 후보는 적용할 수 없다. 실제 자료에 대한 충돌 판정이나 추천 정확도를 검증한 것은 아니다.

| Playwright 정상 동작 | 16 통과 | DOM/Univer 입력·복사·Undo, 학생 배정 연동, 추천 만료, 원본 보존, 화면 재마운트·서식 격리 |
| 보정 전 실패 재현 | 1건 예상대로 실패 | raw Univer의 Ctrl+Home; 전체 호환 성공으로 세지 않음 |
| TypeScript + Vite build | 통과 | 독립 실험 앱; 큰 엔진 청크 경고는 남음 |
| ESLint | 통과 | 실험 소스·시험·설정 파일 |
| 브라우저 직접 점검 | DOM/Univer 로드 확인 | 별도 agent-browser 세션, 페이지 오류 없음, 합성 화면 확인 |

Playwright는 예상 실패까지 포함해 `17 passed`로 요약한다. 여기서는 **16개 정상 성공 + 1개 결함 재현**으로 분리했다. API 호출로 연결만 검증한 시험과 신뢰된 실제 키 입력 시험도 코드의 제목에서 구분했다.

한글 시험은 Chromium CDP 조합 신호와 `insertText`를 이용했다. 실제 Windows IME의 한/영 전환, 조합 중 Esc/방향키/Shift까지 검증했다고 주장하지 않는다. Google Sheets/Excel을 열어 왕복 복사한 시험도 아직 없다.

빌드 산출물에서 지연 로드되는 Univer 주요 JS 청크는 약 6,451 kB, gzip 1,685 kB이고 CSS는 120.19 kB, gzip 17.53 kB다. 초기 앱 JS는 약 208 kB, gzip 67 kB다. 문서 편집기의 큰 비용이 확인되었으므로 엔진 채택 전 실제 로드 지연/메모리/편집 지연을 측정한다. 이 빌드 크기는 목표 시간 달성의 증거가 아니다.

## 발견해 고친 결함

1. **표 밖 잘라내기 붙여넣기 시 유실**: F10에 2칸을 붙이면 원본이 지워지고 표 밖 값이 도메인에 담기지 않았다. 엔진 clipboard hook에서 실제 붙여넣기 범위를 검사해 변경 전에 거절한다. 실제 Ctrl+X/V 회귀 시험에서 문서 전체가 유지되는 것을 확인했다.
2. **수식 복사가 확정 시간 변경**: 내부 복사된 수식 셀의 이전 값까지 목적지에 복사될 수 있었다. 수식을 붙인 목적지는 기존 확정값을 유지한다. 수식 결과의 값만 붙여넣기는 검증 전임을 표시하며 원본을 유지한다.
3. **지운 메모의 부활**: DOM Delete가 rich-text 내용을 남겨 엔진 전환 후 다시 표시될 수 있었다. 텍스트와 수식, rich text를 함께 지우되 서식은 보존하고 재마운트/Undo 시험을 추가했다.
4. **추천 적용 시 서식 손실**: 시각 셀을 통째로 교체하던 부분을 수정해 서식을 보존한다. 이전 rich text만 새 시각과 불일치하므로 제거한다.
5. **값만 붙여넣기의 서식 덮어쓰기**: DOM Ctrl+Shift+V가 목적지 서식을 유지하도록 수정했다. 수식 결과와 cut 조합은 아직 지원 완료로 처리하지 않는다.
6. **Ctrl+Home 의미 차이**: 엔진의 기본 키 처리는 PC Google Sheets 기대값 A1 이동과 달랐다. 격자에 포커스가 있고 셀 편집 중이 아닐 때만 보정한다. raw 실패와 보정 성공을 함께 유지한다.
7. **이력 표시 불일치**: native workbook 이력을 비웠더라도 메뉴 상태가 native 스택을 참조하면 비활성화될 수 있었다. 상태도 공통 이력을 참조하도록 연결했다.
8. **전역 CSS의 엔진 간섭**: 프로토타입의 header 스타일이 Univer 도구줄과 수식 입력줄을 축소했다. 앱 스타일 범위를 격리한 뒤 전체 너비와 도구줄 표시를 확인했다.

이름 상자의 오동작으로 보였던 경우는 테스트 locator가 글꼴 입력란을 선택한 것이 원인이었다. `[data-u-comp="defined-name"] input`으로 고친 뒤 raw/보정 양쪽에서 정상 동작을 확인했다. 엔진 결함으로 기록하지 않는다.

## 엔진 선택 판단과 남은 통과 조건

두 후보 모두 **아직 미선정**이다. Univer는 넓은 편집 기능과 앱 이력을 연결할 가능성을 보였지만 큰 번들, 구조 편집의 의미/이력, 전체 키 호환이 남았다. 자체 DOM은 연결을 통제하기 쉽지만 전체 스프레드시트 기능을 직접 구현해야 하는 부담을 확인했다.

| 계획 항목 | 이번 증거 | 남은 작업 |
|---|---|---|
| K01~K02 | 셀 2×3 복사, cut 실패 원본 보존 | 수업 블록/학생 ID 이동·복제 의미, 여러 학생 cut |
| K03~K04 | 여러 줄·빈 값 TSV, 내부 서식 일부 | 실제 Google Sheets/Excel 왕복, 병합/서식/외부 HTML |
| K05~K06 | 입력/선택 문맥 일부, 조합 신호 | 물리 IME, 셀 내부 Undo 전체, 모든 조합키 |
| K07~K09 | 독립 최상위 localhost 화면 | 기존 앱 창/iframe, 다중 창 키 격리, 권한 거절 |
| V01~V04 | 간단한 합성 학생·강사·방 겹침 | 날짜 이력, 분리등원 재매핑, LAB/JJ, 기존 검사기 비교 |
| 수식·서식·구조 | 자동 수식의 의미 보존, 서식 저장 | 결과 명시 확정, 상대 참조, 행열/시트 구조 명령, 그룹 이력 |
| 기존 자료 | 소스 경로 조사 | 개인정보 없는 집계, 숨은 월별 계획 자료/권한 확인 |
| 성능 | 빌드 크기 | 실제 규모·지연·메모리 측정 |

이 표가 해소되기 전 P1 영속 저장/운영 반영으로 넘어가지 않는다. 수업 3개가 고정 행에 연결된 지금의 비교 표를 최종 강사별 시간표라고 부르지 않는다. 전체 단축키 요구의 분모를 줄이지 않는다.

다음 P0 작업은 기존 창 환경의 입력 경계, 안정 ID를 보존하는 수업 블록 명령, 기존 검사기 22개 합성 fixture 비교다. 구글 추가 탭 보존 S는 계속 독립 작업이며 이번 프로토타입에 포함되지 않았다. JEV도 아직 연결하지 않았고 결정적 추천이 먼저다.

## 커밋 전 리뷰

Codex가 이번 코드·설정·문서를 원본 유실, 이중 이력, 오래된 후보 적용, 수식의 의미 변경, 서식/메모 손실, 운영 앱 유입, 완료 과장 관점에서 검토했다. 위 결함을 수리한 뒤 회귀 시험을 통과했다. 루트 앱의 패키지와 lockfile을 바꾸지 않았으며 실험 파일만 별도 설치/검사한다. 현재 한계는 이 문서와 화면에 공개했다. 원본 조사 보고서는 역사적 기준점을 보존한다.
