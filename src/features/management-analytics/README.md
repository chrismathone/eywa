# MakeEdu 경영분석 MVP

수납관리 → **경영분석** (`/billing?tab=analytics`). 표준 CSV 세 파일을 검증해
재원생·신규생·퇴원·순수납·상담전환과 월별 추이를 계산한다. 가상 샘플 불러오기와
샘플 CSV 다운로드가 있다. 집계 요약은 검증한 숫자로 작성하며 외부 AI 호출은 없다.

## 기존 시스템과 연결

- Next.js 16.2.6 / React 19 / TypeScript / Tailwind 4 / 기존 PageHeader·BigStat·UI 사용.
- `src/app/(shell)/billing/page.tsx`는 기존 수납 탭과 함께 새 서버 컴포넌트를 연다.
- `src/app/api/management-analytics/route.ts`의 POST만 집계한다. 기존 수납·학생 DB를 수정하지 않는다.
- 인증은 Supabase 세션을 검증하는 `getCurrentUser`, 권한은 `canAccessTenant`를 재사용한다.
  지점 `master` 또는 `admin`이며 유효한 수납 메뉴 권한이 있어야 한다. 위임받은 다른 역할은
  제외하고 강사뷰의 유효 역할을 적용한다. 타 지점 읽기 뷰(`tenantView`)도 차단한다.
  화면과 API가 같은 `server/access.ts`를 사용하며 API는 본문을 읽기 전에 권한을 검사한다.
- DB는 Supabase Postgres / Drizzle (`src/lib/db/schema.ts`), 기존 테이블은 tenant_id / RLS 구조다.
  이번 기능은 테이블·마이그레이션·Storage 객체를 만들지 않는다. 기존 `students.makeedu_id`는
  원생고유번호 연결의 참고점이며 현재 학생 스냅샷만으로 과거 재입원을 복원하지 않는다.
- 기존 `scripts/_makeedu` 임포터는 운영 자료를 쓰는 별도 경로다. 이 기능에서 호출하지 않는다.
- CI는 `.github/workflows/ci.yml`, 배포는 Vercel(`vercel.json`, 서울 리전)이다.
  main은 운영 배포와 연결되므로 이 MVP는 작업 브랜치 / Draft PR에서 검토한다.
  운영 병합·배포·DB 작업은 별도 승인 대상이다.

## 실제 내보내기 확인 (2026-10-19)

사용자가 로그인한 MakeEdu에서 목록 조회와 Excel 내보내기만 수행했다. 확인한 파일은
XLSX이고 이 MVP 입력은 CSV이므로 필요한 열을 준비한 뒤 CSV UTF-8로 저장한다.
원본 학생·연락처·수납 행은 코드, 테스트, 문서에 복사하지 않았다.

| 확인 화면 / 파일 | 확인한 관련 헤더 | 적용과 남은 조건 |
| --- | --- | --- |
| 원생목록 (`/member/student/list.do`) | 원생고유번호, 입학일, 퇴원일, 재원여부, 휴원여부 등 | 앞의 세 열만 자동 매핑. 현재 재원생 내보내기로 헤더를 확인했으므로 전체 과거 이력 확보를 증명하지는 않는다. |
| 수납통합내역 (`/pay/payUnionList.do`) | 이름, 수납건수, 청구액, 할인액, 적립금사용, 실제낸금액, 미납금액, 환불금액 등 | 확인한 파일에는 학생·거래 식별자와 개별 거래일이 없다. 표준 거래 CSV로 직접 사용할 수 없다. |
| 수납상세내역 (`/pay/reportDetailList.do`) | 이름, 생성월, 구분, 수납명, 수납여부, 실제낸금액, 수단, 청구일, 수납일 등 | 확인한 파일에는 학생·거래 식별자가 없다. `구분`은 수업/기타수납이므로 payment/refund로 자동 연결하지 않는다. |
| 상담 목록 (`/counsel/counselList.do`) | 화면의 상담일, 원생전환 등을 확인 | 내보내기를 시도했으나 파일 다운로드를 확인하지 못했다. XLSX 헤더·고유 상담/학생 식별자는 **미확인**이다. |

수납상세내역의 날짜 기준 메뉴에 `납부일(환불제외)`, `납부일(환불포함)`, `환불일`,
`납부+환불일(환불 원거래금액도 매출에 합산)`, `납부+환불일(기간내 금액만 합산)`이 있다.
순수납 대조 시 마지막 기준과 전체 학생(휴·퇴원 포함)을 사용하고 실제 납부·환불 발생일을
개별 거래로 정리해야 한다. 해당 필터로 만든 파일의 세부 환불 행 형식은 아직 검증하지 않았다.

**실자료 적용 전 필요한 사양**: 학생과 잠재 상담자를 잇는 영속 식별자, 고유 거래 식별자,
고유 상담 식별자, 실제 수납·환불 발생일과 금액, 최초 입원 및 재입원/퇴원의 전체 이력.
개발팀 또는 MakeEdu 측에서 원본과 대조한 자료를 제공해야 한다. 이름·전화번호로 추정
연결하거나 행 순서를 식별자로 만들지 않는다. 단순 열 매핑으로 없는 정보를 복원할 수 없다.

## 표준 CSV 계약

| 파일 | 필수 열 | 한 행의 의미 |
| --- | --- | --- |
| enrollments.csv | student_id, started_on, ended_on | 학생의 학원 재원 기간. 퇴원 전이면 ended_on은 빈칸, 재입원은 새 행. |
| payments.csv | transaction_id, student_id, paid_on, amount, kind | 실제 수납 또는 환불 한 건. 같은 거래를 중복 내보내도 ID는 유지. |
| consultations.csv | consultation_id, student_id, consulted_on | 상담 한 건. 과거 첫 상담을 판정할 수 있는 전체 상담 이력. |

- 학생 식별자는 세 파일에서 같아야 한다. 미입원 상담자도 변하지 않는 코드를 사용하고,
  나중에 입원해도 같은 코드로 연결한다. 기존 학생 상담도 넣을 수 있으며 계산에서 제외한다.
- 코드: 영문·숫자로 시작, 영문·숫자·밑줄·하이픈 1~80자. 앞자리 0을 보존한다.
  이 형식 검사는 개인정보 탐지기가 아니므로 이름·전화번호·계좌를 코드로 넣지 않는다.
- 날짜: `YYYY-MM-DD`, `YYYY/M/D`, `YYYY.M.D` (한국 날짜, 1900~2100년).
  데이터 기준일은 오늘 이하이고 모든 날짜는 기준일 이하. 조회 시작 ≤ 종료 ≤ 기준일.
- 금액: 1~1,000,000,000원의 양수 정수, 천 단위 쉼표 허용.
  `kind`는 `payment`/`refund` 또는 `수납`/`환불`. 환불도 양수이고 집계에서 뺀다.
  청구·미납·할인은 거래로 넣지 않는다. 무효 거래는 제외하고 실제 반환은 환불 거래로 표현한다.
- BOM, CRLF, 인용부호, 인용된 쉼표·줄바꿈, UTF-8 / EUC-KR 지원.
- 파일당 512KiB, 10,000개 데이터 행, 50열, 셀당 2,048자. 요청 전체 2MiB.
  초과분을 잘라 집계하지 않는다. 조회 기간은 최대 24개 달이다.
- 헤더만 있는 파일은 거래/상담 0건을 표현한다. 동일 정규화 행은 중복 제외하며,
  같은 식별자의 다른 내용·재원 기간 겹침·입퇴원 이력에 없는 수납 학생은 전체 분석을 중단한다.
- 오류는 자료 종류·레코드 순서·필드·고정 설명만 최대 50건 표시한다.
  행 번호는 빈 줄을 제외한 CSV 레코드 기준이며 인용 셀 내 줄바꿈의 실제 줄 번호와 다르다.

## 계산 기준

| KPI | 계산 |
| --- | --- |
| 재원생 | 종료일까지 입원했고 퇴원일이 없거나 종료일보다 늦은 고유 학생 수. 퇴원 당일부터 미재원. |
| 신규생 | 전체 입퇴원 이력의 **최초** 입원일이 기간 내인 학생 수. 재입원 제외. |
| 퇴원 | 기간 내 퇴원일이 있는 고유 학생 수. 같은 기간 재입원해도 퇴원 집계에는 남는다. |
| 순수납 | 기간 내 거래일 기준 실제 수납 합계 − 환불 합계. 음수 허용. |
| 상담전환 | 전체 이력의 첫 상담일이 기간 내인 미입원 학생 중 조회 종료일까지 최초 입원한 비율. 같은 날 상담·입원 포함. 분모 0은 계산 불가. |

월별은 선택 기간과 겹치는 날짜만 계산하고 그 달의 종료일을 전환 마감으로 사용한다.
따라서 전체 기간 전환율은 월별 비율의 합/평균과 다르다. 재입원이 있으므로 신규−퇴원은
재원 증감과 다를 수 있다. 반별 수강 이력, 휴원, 부서 이동을 학원 입퇴원과 혼동하지 않는다.
휴원은 별도 KPI로 모델링하지 않으므로 휴원 처리 정책은 원본 이력 정리 단계에서 확정한다.

## 개인정보와 저장 범위

- 브라우저가 매핑한 최소 열만 canonical CSV로 다시 만든 뒤 전송한다. 파일명도 고정값으로
  바꾼다. 미매핑 열(이름·연락처·상담 본문 등)은 네트워크 요청에서 제외한다.
- 인증된 서버는 같은 origin / 전용 헤더 / 요청 지점과 현재 지점 일치를 검사한다.
  원본 스트림을 크기 제한한 뒤 multipart를 읽어 Content-Length 없는 요청도 제한한다.
- 서버는 요청 메모리에서만 검증/계산한다. 원본·식별자·오류 내용 로그, DB/Storage 저장,
  LLM 전송, 결과 캐시, localStorage 저장이 없다. 응답은 집계값만, `private, no-store`다.
- 브라우저 파일은 선택 상태에만 유지한다. 자료 비우기·화면 닫기로 해제하며, 처리 중 비우면
  요청을 중단하고 늦은 응답을 폐기한다. 조건 변경 시 이전 결과도 제거한다.
- 원본에 지점 정보가 없으므로 형식이 정상인 타 지점 자료/누락 행을 자동 판별할 수 없다.
  업로더의 동일 지점·전체 이력 확인을 필수로 받으며 결과에도 이 한계를 표시한다.

## 샘플 검증과 출시 전 확인

`sample.ts`는 완전한 가상 코드 S001~S006만 사용한다. 2026-09-01~09-30 결과:
재원 4명, 신규 2명, 퇴원 1명, 수납 1,150,000원, 환불 100,000원,
순수납 **1,050,000원**, 첫 상담 3명 중 2명 전환 (**66.7%**), 동일 수납 중복 1행 제외.

```sh
pnpm exec vitest run src/features/management-analytics src/app/api/management-analytics
pnpm typecheck
pnpm lint
pnpm test:coverage
pnpm build
```

계산(날짜 경계·재입원·월별·분모 0·음수), CSV 검증, 1,000행 초과 처리, 업로드 용량,
비로그인/권한/타 지점/교차 출처, 개인정보 응답 제외, 파일 전처리, 샘플과 실제 파일 혼용,
조건 변경·취소·늦은 응답을 테스트한다. 계산 모듈에는 80% coverage 게이트를 추가했다.

실자료 출시 전: 위 식별자/이력 계약 확정 → 승인된 비식별 자료와 MakeEdu 기간별 수치 대조 →
별도 검증 환경에서 관리자·일반 직원·강사뷰·지점 전환 확인 → 기존 CI 실패 해소 → 운영 승인.
실제 AYWA 로그인 세션으로 전체 화면을 검증한 것은 아니며 현재 검증은 가상 자료와 권한 테스트다.
