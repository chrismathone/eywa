## 적용 전

1. 변경본의 독립 적대적 리뷰와 로컬 검증 결과를 확인한다. 운영 DB 백업·복구 절차를 준비한다.
2. 기존 DB가 기준 커밋의 alpha migration까지 적용된 상태인지 운영자가 점검한다. 특히 0267a 청구 소비 기준,
   0118a 강사별 일별 세션 키, 출결의 `session_units`·`taught_by`, 보고서 `unit_key`를 확인한다.
3. 시즌1 합본(`supabase/migrations/s1_season1.sql`)의 `0343a_makeup_*`부터 `0349*_makeup_*` 구역까지 순서대로 적용한다.
   migration 개별 순서를 바꾸거나 일부만 적용한 채 켜지 않는다. DB 변경본과 앱 변경본을 함께 준비한다.
4. 적용 실패는 원인을 확인하고 같은 migration을 재실행한다. 원본 예약·출결·보고서를 삭제하는 롤백은 하지 않는다.
5. 앱 변경을 배포한다. 기본 운영 상태는 **꺼짐**이다. 권한 예외만으로 꺼진 기능을 열 수 없다.

## 소수 수학 반 파일럿

1. 학원 설정 → 보강관리에서 운영을 켠다. 첫 출시 대상은 수학이며 영어·자동 권리 발급·새 자동 안내는 열지 않는다.
2. 강의실 정원과 교시 설정을 확인한다. 분량·자격·기한은 운영자가 개별 승인한다. 제안된 120/180분을 자동 정책으로 쓰지 않는다.
3. 미연결 결석과 기존 보강 약속을 조회한다. ‘도입 사전 점검’은 쓰기 0건으로 A~E 근거 등급·중복 후보·원본 해시를 출력한다.
   조회만으로 권리나 시수가 늘어나지 않아야 한다. 분류는 자동 자격·실시 인정이 아니다.
4. 기존 자료는 원본 해시·배치 번호로 분류하고 사람이 연결 대상을 확인한다.
   - reserved 약속: 일정을 보존한 승인 대기 건. 기존 점유보다 적은 분량을 승인하지 않는다.
   - done 약속: 특정 출결·보고서를 확인할 검토 후보. 자동 인정하지 않는다.
   - 메모·취소·모호한 날짜·같은 날 복수 약속: 일정·이력을 보존하고 검토한다.
   - 비활성 반·휴원·퇴원 학생: 미처리 건과 인계 대사를 보존한다.
5. 확인한 기존 약속을 ‘기존 약속 연결’로 연결한다. 원본 변경은 해시 충돌로 재검토한다.
6. 접수 → 분량 승인 → 예약 → 출결·보고서 → 참여 근거 → 제출 → 별도 검토자의 인정까지 확인한다.
7. 잔량·점유·예약 가능량과 출결 시수·담당 강사를 대사한다. 인정·예약이 출결 시수를 쓰는지 확인하지 말고,
   실제 출결 저장만 시수를 기록하는지 확인한다. 수기값은 유지하고 차이를 검토한다.
8. 같은 날 정규+보강은 시간표 담당과 모든 현재 유효 출결의 실제 담당이 보강 담당과 같아야 한다.
   대강 시 시간표의 해당 날짜 담당도 먼저 맞춘다. 혼합·미확인 담당과 다른 직원이 찍은 자리 출결은 보강 효과를 보류한다.
9. 같은 배치를 다시 연결해 케이스·배정·인정·시수가 늘어나지 않는지 확인한다.

## 대사·장애 복구

- ‘대사·복구’에서 연결되지 않은 항목까지 확인한다. 대사와 반영 작업은 각자 페이지와 전체 건수를 가진다.
- ‘현재 기록 다시 대사’는 차이를 탐지한다. 돈·출결·인정량을 자동 보정하지 않는다.
- 출결·시수 반영 실패는 실제 기록을 정정한 뒤 다시 확인한다. 사유만으로 완료 상태를 강제할 수 없다.
- 수기 시수 차이는 현재 값을 다시 확인하여 일치시키거나, 권한 있는 운영자가 차이를 명시적으로 승인한다.
- 일부 참여·불참의 선반영 시수는 자동 차감하지 않는다. 출석부에서 권한 있는 정정을 저장한다.
- 원출결 정정, 담당 퇴사·반 종강·휴원·퇴원은 업무를 삭제하는 사유가 아니다. 인계·재검토 큐에서 처리한다.
- 주기 대사용 `makeup_reconcile_tenants()`는 탐지 전용이다. 실제 운영 스케줄 등록은 별도 도입 작업으로 진행한다.

## 신규 접수 중단

1. 운영을 **정리 중**으로 바꾼다. 새 접수·예약·일정 변경·기존 약속 신규 연결이 중단된다.
2. 기존 참여·기록·검토·대사·인계를 처리한다. 실패 반영 작업을 빈 목록이나 완료로 취급하지 않는다.
3. 열린 보강·미처리 대사·미처리 반영 작업이 모두 없는 상태에서 **꺼짐**으로 바꾼다.
4. 연결된 옛 예약의 직접 수정·삭제 보호는 꺼짐 뒤에도 유지된다. 연결 표를 삭제해 우회하지 않는다.

## 로컬 합성 검증

`tests/makeup-db/run.mjs`는 명시적으로 격리한 로컬 `makeup_*` DB만 사용한다.
`tests/makeup-browser`는 `127.0.0.1:3045/55444/55445/55446`의 합성 DB·Auth·REST만 사용한다.
브라우저의 로그인 전송은 로컬 모형이다. 새 화면의 Next 서버 액션·명령 SQL·권한 검사·수량 원장은 실제 구현을 실행한다.
기존 출결·보고서 UI의 전체 운영 검증 또는 운영 인증 서버 검증을 대신하지 않는다.
가상 출결·보고서를 전제 자료로 넣은 브라우저 시나리오와 실제 기존 저장 함수 테스트를 구분해 기록한다.
환경 파일을 복사하거나 운영 키를 사용하지 않는다. `pnpm test:rls`를 임의 환경에서 실행하지 않는다.

## 후속 기능

영어 교시·수업 묶음, 동일 학생·과목·날짜의 복수 보강, 추가 지도 예약의 청구/급여 기준,
자동 안내·학부모 예약·TTL·휴강 일괄 생성은 이번 파일럿에서 비활성이다.
원문 수용 기준은 보존하며 이번 변경의 통과로 기록하지 않는다.
