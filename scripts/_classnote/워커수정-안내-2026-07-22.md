# 발송 PC 워커 수정 적용 (2026-07-22) — 교재 등 '이미지 첨부'를 ClassNote에 개별 이미지로도 부착

## 왜 바꾸나

원장 제보(김경민 7/21 보고서): 교재 이미지(`공통수학1개념원리.png`)를 첨부했는데 **ClassNote 게시물엔 개별 이미지로 안 보이고, 보고서 스크린샷 안에만** 들어갔습니다.

조사 결과 **eywa·발송은 정상**(DB 1건·성공·에러 0)이었고, 이건 **설계상 의도**였습니다 — 지금까지 이미지 첨부는 "어차피 /r 스샷에 나오니 중복 방지"로 개별 부착에서 빠졌습니다(비이미지 파일만 네이티브 첨부). 원장 결정으로 **이미지도 개별 이미지로 부착**하도록 바꿉니다(스샷 안 + 개별 원본 둘 다 → 학부모가 교재를 크게·개별로 확인).

---

## 무엇이 바뀌었나 (2곳)

**① eywa 앱 — 자동 반영(재이관 불필요)**: `report-attachments` 내부 API가 이제 이미지 첨부의 signed URL도 `images` 필드로 반환합니다. **Vercel 배포로 자동 반영**되며, **구 워커는 이 필드를 안 읽어 무해**합니다(재이관 전까지 종전과 동일 = 이미지는 스샷에만).

**② 발송 워커 — zip 재이관 필요**: `classnote-core.mjs`
- 이미지 첨부만 있는 리포트도 내부 API 경로로 게시(종전엔 비이미지 파일이 있어야만 진입).
- 이미지를 kage(`media-attachment-add-input`)로 업로드해 **스샷과 함께 `attached_images`에 개별 부착**.
- ⚠️ 이미지는 스샷에 이미 실려 있어 **best-effort**입니다 — 개별 부착이 실패해도 발송을 막지 않습니다(스샷엔 그대로 나옴). 반면 비이미지 파일(PDF 등)은 스샷에 없으므로 전건 실패 시 종전대로 발송 실패(재시도).

> 자격증명·주소(`.env.local`)는 **그대로 두세요.** 코드만 교체하면 됩니다.

---

## 적용 방법 (약 2분)

1. 이 zip을 연동 PC(`학원동기화-PC`)의 **eywa 저장소 폴더**(`C:\eywa-sync-pc`)에서
   **"여기에 압축 풀기"** → 기존 파일 덮어쓰기.
   > ⚠️ 반드시 **폴더 전체**를 풀어야 합니다(코어가 import하는 모듈이 빠지면 워커가 기동 못 함).
2. `발송PC-지정.bat` 더블클릭 → 워커가 새 코드로 **재시작 + dry-run 자가검사** 자동 실행.
3. "dry-run 파이프라인 검사" 통과하면 완료입니다.

## 적용 후 확인

**이미지를 첨부한 보고서**를 한 건 발송해 보세요(이수진 선생님 김경민 건 등):

- ✅ **정상**: ClassNote 게시물에 보고서 스크린샷 + **교재 이미지가 개별 이미지로 따로** 올라갑니다.
  발송 로그에 `이미지 N/N 개별 부착`이 찍힙니다.
- ❌ 여전히 스샷 안에만 있으면 → 워커가 **구 코드**로 돌고 있는 것입니다(재이관·재시작 확인).
  (앱은 배포됐어도 워커는 물리 이관이라 따라오지 않습니다 — 과거 "21분 차이로 구 워커" 전례.)

> ⚠️ 이미지가 여러 장일 때 ClassNote가 다중 이미지를 받는지는 첫 실발송으로 확정됩니다.
> 만약 첫 장만 붙거나 거부되면 알려주세요(폴백 조정).
