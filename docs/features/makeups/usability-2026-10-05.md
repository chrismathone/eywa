# 보강관리 사용성 감사 후속 검증

## 근거와 협의

사용자가 제공한 `AYWA_보강관리_사용성감사_2026-10-05.docx`와 재현 ZIP을 대조했다.
ZIP의 체크섬 대상 59개 파일을 확인했고, 소스 근거 54개는 줄바꿈을 정규화하면 참조 커밋과 일치했다.
감사 자체는 정적 소스 검토이며 운영 계정의 저장 동선이나 SQL 재현 결과로 취급하지 않았다.

Codex가 제안하고 실제 Orca Claude가 계획을 검토했다. Claude의 보완 조건 5개를 반영한 계획에 합의했다.
Claude가 서버·SQL을 구현하고 Codex가 화면을 구현한 뒤, 별도 Claude가 적대적 리뷰를 진행했다.
이번 협의에 Grok은 참여하지 않았다. 구현 및 검증 근거는 `F:/eywa-review/makeup-usability-review-20261005/`에 보존한다.

R01은 실시 인정과 **해당 출결 작업**의 연결 상태를 별도로 표시한다. 다른 효과 작업의 실패가 출결 실패로 보이지 않게 회귀 검증한다.
R03은 거절이 종결임을 명시하고 동일 결석 재접수의 기존 건 안내를 유지한다. 재개 기능은 추가하지 않았다.
R04는 학생·원수업 날짜에 맞는 원반 목록을 제공한다. 예약의 출결 반은 날짜 변경 시 다시 확인한다.
R06은 390px 실측에서 다음 업무·기한이 잘려 아래 768px에서는 같은 표 데이터를 한 건 단위로 배치한다.
R07은 두 앵커 저장 경로의 후속 반영 대기·확인 실패를 저장 결과와 함께 알리고 대사·복구 링크를 제공한다.
안내는 프레임 여부로 embed를 유지하고, 일괄 처리의 약한 대기 안내가 확인 실패 안내를 덮지 않는다.

## 검증 경계

- 로컬 합성 PostgreSQL: 30개 시나리오와 동시성 3개, 총 989개 검사 통과. 신규 5개 시나리오는 이전 정의에서 실패함을 Claude가 확인했다.
- 실제 앱 체인: 합성 플랫폼 위에서 기존 파일 402개 중 393개 적용, 플랫폼 관련 9개는 적용 한계로 기록. 보강 SQL 49개 적용·재실행과 시나리오 통과. 운영 플랫폼 전체를 검증했다는 의미는 아니다.
- 브라우저: 실제 Next 서버 액션·PostgREST·보강 SQL, 로컬 인증·가상 학생을 사용한다. 운영 자료를 만들거나 발송하지 않았다.
- 실제 앱 스키마의 강사뷰: 담당 반 0개/다른 담당 반이 있는 강사 두 경우 모두 배정 학생만 표시되고, 실제 보고서 저장으로 앵커 출결 및 `taught_by` 귀속을 확인했다. 상세 복귀에서 embed도 유지했다.
- 접수→승인→예약→참여→다른 검토자의 인정, 정정 후 재제출·재인정, 강의실만 변경, 출결 반 복구, 목록 복귀, 종결 후 대사, 실제 워크스페이스 이동·새로고침을 확인했다.
- 목록 360/390/768/1280px 및 CSS 200% 확대를 확인했다. 이는 OS·모든 브라우저 확대 조합을 검증한 결과가 아니다.
- 관련 검사 33개 파일·212개 통과, 타입 검사 및 변경 파일 lint 통과. 환경 파일이 없는 별도 소스 스냅샷의 최종 production 빌드도 통과했다.

## 적용과 유지한 경계

신규 SQL은 `0350a`–`0350f`다. 기존 migration을 수정하지 않았다.
운영은 migration 이력표가 없는 기존 환경이므로 전체 `db push`를 사용하지 않는다.
대상 프로젝트와 교체할 함수 6개의 소스 일치를 확인하고, 정의 백업과 되돌리기 SQL을 보존한다.
Supabase CLI로 여섯 파일을 한 DO 트랜잭션에 적용한다. 기존 정의가 달라졌으면 중단하고, 새 정의 및 나머지 함수가 변하지 않았는지 검사한다.
업무 자료·운영 모드·출결·보고서·청구 테이블을 이 SQL로 쓰지 않는다.

R02의 자동 대사 스케줄러는 추가하지 않았다. 저장소에 없고 운영 DB에 cron 스키마가 없지만 외부 스케줄러의 부재까지 단정하지 않는다.
검토·반전·종결 산식, 독립 검토, 출결 직접 저장 권한, 시수·청구 계산은 변경하지 않았다.
현재 휴원 학생이나 비활성화된 반의 앵커에 관한 기존 보고서 저장 제한은 유지한다. 명단에 있어도 기존 저장 관문이 거절할 수 있다.
R07은 두 앵커 경로만 다룬다. 공용 완료 함수의 일부 무응답과 나머지 12개 호출 경로는 기존 범위로 남아 있어 모든 후속 반영 실패를 관측한다고 주장하지 않는다.
Vercel 배포는 사용자 담당이다.
