# 통합 연동 앱 실제 워커 점검 / handoff — 2026-10-09

## 요청과 범위

- 기존 워커 PC에 설치한 EXE의 모든 역할을 점검한다. 메이크에듀 동기화는 허용된다.
- 일반 학생·학부모 발송, 답글, 공감, 회수 등 외부 변경을 시험하지 않는다. `학원이`는 실제 ClassNote 시험이 허용된 예외다.
- 일반 대상 작업 방지를 위해 웹의 통합 앱 ClassNote 실행만 잠시 OFF로 바꿨다. 전역 앱 실행과 메이크에듀는 유지했다. 원래 ClassNote 값은 ON이다. 검수 완료와 운영 재개는 구분한다.
- 앱으로 전환한 지점에서 `기존 동기화 PC` 표시를 숨긴다. 창의 File/Edit/View/Window 메뉴도 제거한다.

## 확인된 결함과 수정

1. 기존 PUBLIC RLS 정책이 `auth_tenant_id()`를 호출하지만 새 비상속 DB 역할에 실행 권한이 없어 SQLSTATE 42501로 큐 조회가 실패했다. 정책 의존성 조사에서 `auth_system_role()`도 누락됐다. 마이그레이션 `0406a_sync_agent_policy_function_grants.sql`은 이 두 함수만 허용한다. RLS 우회, 역할 상속, 다른 지점 접근 권한은 추가하지 않는다.
2. postgres.js에서 RETURNING 없는 명령의 `columns`는 null이다. 게이트웨이 직렬화의 `.map` 예외가 성공한 쓰기도 트랜잭션 롤백시켰다. 빈 배열로 직렬화하고 기존 SQLSTATE 제한과 실행 임대 검증을 유지한다.
3. EXE 브로커의 `remaining_ms`와 기존 ClassNote 어댑터의 `remainingMs`가 달라 임대를 얻지 못했다. 브로커 응답을 실제 소비자 계약에 맞춘다. 이는 새 EXE 1.0.2 업데이트가 필요하다.
4. 컴파일러가 이미 JSON으로 인코딩한 문자열을 `::jsonb`에 바로 바인딩해 postgres.js가 다시 인코딩했다. 실제 PostgreSQL fixture에서 객체 대신 JSON 문자열이 저장되는 것을 재현했다. `::text::jsonb`를 통해 한 번만 해석하도록 바꾸고 실제 gateway의 heartbeat·완료 쓰기, 빈 배열과 JSON 객체 저장까지 검사한다.
5. 작업 루프의 오류는 기존 PC 로컬 로그에만 남아 웹에서 원인을 구분하기 어려웠다. 알려진 쿼리의 실패에 한해 코드·쿼리 해시만 구조화 기록으로 저장한다. 원시 오류/SQL/파라미터는 저장하지 않고 같은 실패는 5분간 중복 기록하지 않는다.
6. 제공받은 PC 로그에서 수동 1회와 자동 2회가 모두 6개 영역을 성공한 뒤 `fetch failed`로 완료 기록만 실패한 것을 확인했다. 동기 자식 작업 중 이벤트 루프가 오래 막히면 로컬 HTTP 연결 종료를 제때 처리하지 못한다. 로컬 브로커 요청/응답의 연결을 재사용하지 않도록 하고, 통합 앱의 메이크에듀 자식 실행은 비동기로 순서를 유지하며 stdout/stderr를 실시간 수집한다. 이미 처리됐을 수 있는 쓰기를 자동 재시도하지 않는다.

## 운영 이력 복구와 로그 UI

- PC 로그로 완료를 확인한 정확한 실행 3건과 자동 버킷 2건의 누락된 완료 상태만 CLI로 복구했다. 업무 동기화는 재실행하지 않았다. 최초 상담 신규 12건과 뒤 두 회의 신규 0건을 로그에서 대조했다.
- 별도로 2026-08-19부터 완료 기록 없이 남아 있던 이전 실행 1건을 발견했다. 결과가 불명확하므로 성공으로 바꾸지 않고 오류/중단 표시로 정리했다. 실제 종료 시각은 NULL로 유지했다. 확인 후 `running` 이력은 0건이다.
- 전환 이후 JSONB 39개 필드의 형태를 조회해 이중 인코딩된 감사 메타데이터 1건을 확인하고, 같은 지점·기간에 한정해 원래 객체로 복원했다. 다른 정상 JSON/지점은 바꾸지 않았다.
- 웹 `연동 PC → 실행 로그`에서 KST 날짜·연동 종류·오류 필터, 100건 단위 이전 기록과 20초 갱신을 지원한다. 필터와 페이지 이동도 서버에서 로그인 계정 지점으로 제한한다. 늦게 도착한 응답이 선택한 날짜를 덮지 않도록 검사한다.
- 웹으로는 고정 코드로 만든 처리 단계·실패 요약만 보낸다. 학생 이름·상담 본문·비밀번호나 원시 stdout을 필드에 넣을 수 없다.
- PC는 `%LOCALAPPDATA%/AYWA/Sync/tenants/<tenant-id>/log/YYYY-MM-DD/`에 `app.log`, `classnote.log`, `makeedu.log`를 둔다. 날짜와 행 시각은 KST, 긴 줄과 파일 크기는 제한하고 알려진 자격증명은 마스킹한다. 상세 학생 기록은 PC 로컬에만 남긴다. 앱의 `로그 폴더 열기`로 접근한다.
- sequence 3는 로컬 검증용으로만 준비했다가 추가 결함/요청으로 게시하지 않았다. 최종 1.0.2는 sequence 4로 새로 준비한다. 1.0.1 / sequence 2는 그대로 유지한다.

## 운영 PC 최종 확인

- 사용자에게 웹 관리 코드 → PC 설정 잠금 해제 → 새 버전 확인 → 지금 업데이트를 안내했다. 기기 버전·heartbeat와 새 실행 로그는 적용 완료 후 다시 확인한다. 다운로드만으로 자동 적용하지 않는다.
- 마지막 조회(2026-10-09 07:12 KST)에서 운영 PC는 1.0.1이고 정식 게시판은 1.0.2 / sequence 4다. PC 업데이트 확인은 아직 대기 중이며, 새 버전의 실제 운영 결과까지 완료됐다고 표시하지 않는다.
- 일반 대상 큐가 대기 중이므로 ClassNote OFF를 시험 중 임의로 ON으로 되돌리지 않는다. `학원이` 시험을 하더라도 일반 큐를 실행해서는 안 된다.

HTTP 연결 종료 동작은 [Node.js 24 HTTP 문서](https://nodejs.org/download/release/latest-v24.x/docs/api/http.html#serverkeepalivetimeout)를 참고했다. PC 로그에는 `fetch failed`만 있어 원래 오류의 cause 코드까지 단정하지 않는다. 새 경로는 유휴 연결을 재사용하지 않고, 쓰기를 반복하지 않는 방식으로 해당 위험을 제거한다.

운영 학생명, 게시글 본문, 계정 암호, 기기 토큰은 이 문서에 기록하지 않는다. 상세 검사 자료는 무시된 `work/` 및 작업 전용 비공개 검수 폴더에 둔다.
