# 발송 PC 워커 수정 적용 (2026-07-21) — 읽음 '미매칭' 오경보 + 경고칸 잠식

## 왜 지금 옮기나

발송 PC 알림에 이런 경고가 계속 떴습니다:

> ⚠️ 후보 578건이 eywa 행과 매칭되지 않음 — edutrix_share_token 임포트 여부 확인 필요

**동기화는 정상이었습니다.** 실측으로 워커가 직전 폴에서 1건을 갱신했고, eywa DB에 읽음이 308행 반영돼
있습니다(마지막 07-21 19:01). 문제는 **워커가 옛 코드로 돌고 있다는 것**뿐입니다 —

| | 시각 |
|---|---|
| 워커 프로세스 기동 | **14:53** |
| 오경보 수리 커밋 | **15:14** |

**21분 차이**로 수정 직전 버전이 계속 돌고 있습니다. 워커는 zip 물리 이관이라 eywa 웹을 배포해도 따라오지 않습니다.

## 무엇이 바뀌었나 (2건)

**① 읽음 '미매칭' 경고가 오경보였다** — `classnote-read-core.mjs`
창 안의 후보를 **매 폴 다시 훑는** 구조라, 이미 전부 반영된 정상 상태에서도 `읽음이 비어 있는 행만 갱신` 필터에
걸려 갱신 0건이 됩니다. 옛 코드는 그걸 "매칭 실패"로 오판했습니다. 이제는 **후보 토큰이 eywa에 아예 없을 때만**
경고하고, 아니면 이렇게 남깁니다:

> 새로 반영할 읽음 없음 — 후보 578건 중 eywa 대응 308행은 이미 반영됨(정상)

**② '실패 0' 정상 로그가 경고칸을 잠식했다** — `watch-classnote-queue.mjs` + `worker-issue-filter.mjs`(신규)
발송 PC 알림은 5칸뿐인데, 경고 판정이 단순히 "실패/오류/error 글자가 있으면"이라
`처리 완료 — 성공 2 / 실패 0 / 재큐 0` 같은 **정상 로그가 '실패'라는 글자 때문에** 경고로 잡혔습니다
(실측 5칸 중 2칸 점유). 진짜 문제가 밀려나면 연동 PC를 들여다볼 유일한 창구가 무용지물이 됩니다.
이제 **실패·오류 뒤의 수가 0이면 정상**으로 보고, ⚠와 영문 error/exception만 경고로 잡습니다.

> 자격증명·주소(`.env.local`)는 **그대로 두세요.** 이번엔 코드만 교체하면 됩니다.

## 적용 방법 (약 2분)

1. 이 zip을 연동 PC(`학원동기화-PC`)의 **eywa 저장소 폴더**(`C:\eywa-sync-pc`)에서
   **"여기에 압축 풀기"** → 기존 파일 덮어쓰기.
   > ⚠️ 반드시 **폴더 전체**를 풀어야 합니다. 파일을 골라 복사하면 코어가 import하는 모듈이 빠져
   > 워커가 기동조차 못 합니다(이번엔 `worker-issue-filter.mjs`가 **새 파일**이라 특히 그렇습니다).
2. `발송PC-지정.bat` 더블클릭 → 워커가 새 코드로 **재시작 + dry-run 자가검사**를 자동 실행합니다.
3. "dry-run 파이프라인 검사" 통과하면 완료입니다.

## 적용 후 확인

eywa **수업보고서 > 발송 큐** 카드의 '발송 PC 알림'을 보세요. 30분 안에 읽음 폴러가 한 번 돌면:

- ✅ **정상**: `⚠️ 후보 …건이 eywa 행과 매칭되지 않음` 경고가 **더 이상 안 뜹니다.**
  (`처리 완료 — 성공 N / 실패 0` 같은 정상 로그도 알림칸에서 사라집니다.)
- ❌ 그래도 같은 ⚠️ 경고가 뜬다면 → 그땐 **진짜로** eywa에 토큰이 없는 것이니 알려주세요
  (eywa 야간 동기화가 `edutrix_share_token`을 못 채우고 있다는 뜻).
